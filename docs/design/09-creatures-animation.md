# 09 生き物・アニメーション・プレイヤー(L4 詳細設計)

対応する決定: D-101(三人称+一人称)/ D-105(実在する生態系、敵、ダンジョン)/ D-113(骨格アニメ+物理・手続き)/ D-208(生き物は近くで個体、遠くで数と密度)/ D-311 / D-318(行動は Luau で書いてベイク)/
D-584(生き物 = 体 + 表・口「生まれる」「群れ」。claude/32 S24)/ ADR-0387 /
D-603(プレイヤーの体は法則の中・動きは操作で作る。claude/36 S47)/ D-602・D-606(袋と体を置き直す口。15 §1.1)

**役割分担**: どんな生き物が、どう生き、何を食べ、どう襲うか(生態の中身)は**ユーザーが決める**。ここは、それを載せる仕組み。

## 0. 生き物 = 体 + 表(D-584・claude/32 S24。§0.1〜§0.3 が全部の生き物を覆う一つの形)
| 生き物 | 体(反応する物質) | 表 |
|---|---|---|
| 動物・人・敵 | 粗い塊の中の反応(呼吸・熱・蓄え) | 行動表(§2) |
| 木・作物 | 骨格(据わる固体。切ると支えの法則で倒れる。22)+ 中の水・糖 | **育ち方の表**(どこに枝・根・実を伸ばすか。光・水・温度を読む) |
| 草・苔・カビ・酵母・病気のもと | 反応する物質(セルの中で増える・隣へ広がる) | **無し**(ただの反応する物質。発酵も病気も反応) |
| 群れ(魚群・虫・一面の花) | 普段は 1 つの物 | 群れの表(§1.1) |
- **死ぬ = 体を保てなくなった状態**(旗ではなく状態で決まる)。生きている間は蓄えで坂を上らせて体を保ち、保てなくなると表が止まり、体はただの物質として腐り始める。
- 表は体の法則を書き換えない(D-469)。表は体の状態(温度・成分・エネルギー・まわりの物質)を読み、決まった命令(動く・掴む・伸ばす・物質を出す・押す)を出すだけ。
- 体の中で増える・溜まる物(病気・体内の石など)も、体の中の反応として書く(中身は非公開側)。

### 0.1 口「生まれる」(物質 → 個体)
- **条件(状態)を満たすと、物質の塊が表を持つ個体(物)に移る**: 種が芽を出す・卵が孵る・胞子・ある物質が濃い所から生き物が生まれる、が全部この口。
- 移し方はセル → 物の受け渡し(割れた欠片がセル以上なら物になる。claude/27 K9・刻みの順の段 10)と同じで、**物質とエネルギーの帳簿が合う**。
- 条件は状態だけで書く(温度・水・物質の量・時間の蓄え。D-465 の「法則は状態だけで決まる」)。条件と生まれる種類は作り手の表(Luau でベイク)。
- **親の値を受け継ぐ口も兼ねる**: 生まれる時に、親(卵・種を作った個体)の値を**変異の表**に従って受け継ぐ。変異の選び方は状態のハッシュから(決定的)。
  世代を重ねる遺伝と進化の道筋は「選ばれやすさと変異の表」という法則の形で作り手が書く(D-451 の研究。駄目なら「1 体ごとの変化はシミュ・種の変化は条件で現れる設計」に戻す)。
  エンジンは、どの値を受け継ぐか・どう変わるかの表を読むだけで、種の値を固定しない。

- (2026-10-21 本体のマージで T-0870 の渡し物を当てた)「生まれる」は D-567 のセル → 物と同じ移し方(08 §8。刻みの 10・帳簿の理由「物との受け渡し」)。木・作物の骨格は据わる固体で、切ると支えの法則で倒れる(22)。

### 0.2 口「群れ」(§1.1 に詳しく)
- D-408(群れは 1 つの物、近づけば一体ずつ)と体 + 表をつなぐ口。群れの体は「1 つの物の中の物質の和」、表は群れの表。一体ずつに分ける時は 0.1 と同じ受け渡しで帳簿が合う。

### 0.3 体は法則、心は行動表(D-469)
- **体は法則**: 体は多重解像度の粗い塊(成分とエネルギーを持つ大きなセル。17)で、呼吸・魔素の蓄え・体内に石ができること(D-451)・燃えることは、
  その中の反応(02)と輸送(07)。体に特別な規則は足さない。魔素を押す・体を動かす力は、体に蓄えたエネルギーを使う仕事(坂の原理。02 §5・D-466)。
- **魔素を操る = 押す + 解く**(D-481): 体はもともと両方をしている(酵素 = 解く、ナトリウム・カリウムポンプや筋肉 = 押す)。押すは体のエネルギーを
  使う仕事で、疲れ・反動・熱になる。解くは押した先で魔素の反応の壁を下げる触媒(02 §2 の一般の触媒)。押す手応え(坂に沿うと軽く、逆らうと重い)は
  状態から決まり、操作に返す(D-483 ②・02 §5)。
- 細部(石の位置・傷・中身の並び)は、解体・観察の時に状態から決定的に生成する(見るだけなら変わらない。D-403)。
- **心は行動表**(中身): 逃げる・戦うを決める心は行動表(§2)で、体の状態(温度・成分・エネルギー・魔素)を読む。心は体の法則を書き換えない。
- 重さ: 近くに 1 万体でも火事 1 つの数分の 1 の見込み(**未確認**。M8 で実測。ROADMAP の研究「体の化学の重さ」)。

## 1. 個体(近くの生き物)
| 項目 | 型 | 意味 |
|---|---|---|
| ID | uint32 | 生まれたときに決定的に決まる(粗い層から出てきた時: 柱 ID + 番号のハッシュ) |
| 種類 | uint16 | 生き物の種類(Luau で定義) |
| 物 | uint32 | 体(08 の物)の ID |
| 欲求・状態 ×16 | int32 ×16 | 空腹・恐れ・疲れ・魔素の量…(何を持つかは種類ごとに Luau で定義) |
| 行動 | uint16 ×2 | 状態機械の状態・今の行動 |
| 目標 | int64 ×3 + uint32 | 目標の場所・目標の物/個体 |
| 記憶 ×4 | 小さな構造体 | 最後に見た敵・食べ物のある場所など |

- **個体の数に固定の上限を置かない**(D-408)。普段は群れ(魚群・虫・草食動物の群れ)を「集まり」(17 §2)として 1 つの物で扱い、
  アクセス(触る・捕まえる・攻撃する・近くで見る)した所を一体一体にする。見るだけなら影の計算(17 §3 B)、触れば本物(C)。
  予算に収めるのはゲームの責任(D-468)。超えた時の世界の時間の遅れは安全網で、エディタと開発ビルドで警告する(D-202 改訂)。

### 1.1 群れ(口「群れ」。D-584)
- 群れの物は、群れの体(個体の体の和: 物質・エネルギー・数)と群れの表(群れとしての動き・餌・逃げる)を持つ。
- アクセスされた所を一体ずつにする: 群れの物から、数と物質を個体へ移す(0.1 の受け渡し。帳簿が合う)。一体ずつの値(大きさ・受け継いだ値)は群れの状態と個体の番号から決定的に作る。
- 離れたら個体を群れへ戻す(和を足し戻す。数と物質は正確に保存)。§5 の遠くの数と同じ約束。

## 2. 行動の選び方(GPU)
- 種類ごとに、Luau で書いた「状態機械 + 効用」を表にベイクする:
  - 状態(例: 休む・探す・食べる・逃げる・襲う)と、状態の間の移り方の条件
  - 各行動の効用 = 欲求と知覚から、区分線形の曲線(整数)で計算した点数の合計
  - 行動 = 決まった命令の列(移動する・向く・アニメを再生する・物を掴む・物質を出す(排泄・毒・粘液)・反応を起こす)
- 行動の選び直しは毎刻みではなく、ID のハッシュで分散させて 1 秒に数回(負荷を平らにする)。行動の実行(移動など)は毎刻み。
- 生き物が物質を出す・食べる・燃える・溶けるのも、反応と輸送の仕組み(02・07)を通る。体の中の物質(消化・排泄)も部品の成分として持てる。

## 3. 知覚
- **場を読む**: 近くのセルの温度・物質の濃さ(におい = 気体の物質)・光・魔素・水。
- **他の個体を見る**: 空間ハッシュで近くの個体を引き、見えるかどうかは整数のボクセル DDA で判定(DXR は使わない。07 と同じ理由)。
- **音を聞く**: 反応や物理のイベント(音の種類・大きさ・場所)を近くの個体に配る。

## 4. 移動
- 歩ける所の判定はセルの成分から(固体の上で、上に空間がある)。
- 目的地の種類(水・食べ物・巣・プレイヤー)ごとに、格子の上の**フロー場**(各セルから目的地への方向)を必要な範囲だけ作る(Work Graphs で波のように広げる)。
- 飛ぶ・泳ぐ・壁や天井に張り付く(スライム)は、移動の種類として Luau で定義し、歩ける所の判定を差し替える。

## 5. 遠くの生き物(粗い層)
- 8m の柱ごとに、種類ごとの数と状態の平均(空腹など)を持つ。
- 増える・死ぬ・移る・食べる/食べられるを、粗い層の更新(1 秒に 1 回)で進める。規則は Luau で書いてベイク(生態の中身はユーザー)。
- 個体 ↔ 数の受け渡し: 近づいたら数から個体を決定的に作り、離れたら個体を数に戻す(数は正確に保存)。

## 6. アニメーション
- **体の姿勢は Model(D-107)なので、アニメーションの評価も整数で行う**(物理の目標になるため。04)。見た目のスキニングは描画側で浮動小数点。
- クリップ: glTF から取り込み、ベイクで整数の姿勢の列(関節ごとの Q1.30 の回転と位置)にする。
- ブレンド: 行動の表に書いたブレンドの木(速度で歩き/走りを混ぜる など)。
- IK: 足を地面に合わせる(2 関節の解析解を整数で)、手を掴む物に合わせる。
- 手続き的な体(スライム・ゴーレムのように岩を動かす生き物): 骨格を持たず、行動が部品(08)に直接力を出す種類として定義できる。
- ラグドール: 倒れた・死んだ・吹き飛んだときは、アニメーションの目標を外して物理だけにする(08 §5)。

## 7. プレイヤー(D-603・claude/36 S47)
- **プレイヤーの体は法則の中、動きはキャラクターの操作で作る**。体は生き物と同じ「体 + 表」(§0)で、**表の代わりにプレイヤーの操作**(入力のコマンド。06 §3)が入る。
- **法則で扱うのは世界とのやり取り**(体に特別な規則は足さない。§0.3 と同じ):
  | やり取り | 法則のどこで |
  |---|---|
  | 蓄えの出し入れ(食べる・押す・疲れる) | 体の中の反応(02)。押すは体に蓄えたエネルギーを使う仕事(坂の原理。02 §5) |
  | 体温と熱 | 体と周りのセルの熱のやり取り(物と場の結合。06 の結合の段・08 §4)・放射(23) |
  | 息の O₂ と CO | 体と周りの気体の物質のやり取り(物と場の結合)。CO の密室・山の上の薄い空気(05 §5.1)が生き物と同じ法則で効く |
  | 押す・踏む・反動の力 | 物の物理(08)。足が地面・物を押す力と反動・魔法の反動(D-420) |
- **走る・登る・泳ぐ・滑空の手触りは操作の作りで決める**(キャラクターの操作。法則で歩かせない)。操作は**世界の状態を読む**: 水の深さ・風・足元の形(claude/34 S44。表面の細かい形)。
  読むのは真実と導かれる値(読むだけで世界を書き換えない)。操作が世界に返すのは上の「押す・踏む・反動の力」だけ(帳簿が合う)。
- **サバイバルの度合いはゲームの値で収める**(蓄えの減り方・戻り方など。D-006)。エンジンは値を受けるだけ。
- 持ち物: 手に持つ物・身に着けた物は世界の中、袋の中は世界の外の止まった棚(D-602・15 §1.1)。持ち物の重さを体に効かせるかはゲームの値(既定は効かせない)。
- 体を置き直す出来事(D-606 (1)・15 §1.1)は世界の外との出入りの口。死んだ時どうなるかはゲームの中身(D-607)。
- 仮(ユーザー未確認): 操作が出す力の形は「目標の速さ → 足と地面の間の力(上限つき)」(08 の物の物理に力として入れる)。上限はゲームの値。【エンジン】取り消しやすい。
- カメラは View(CPU)だが、カメラの向きは入力のコマンドとして記録する(何を見ていたかで結果が変わる操作があるため)。
- 三人称と一人称の切り替えは View の仕事(D-101)。一人称の手と道具の見た目は描画側(10)。
- 入力への即時の反応(足音・アニメの出だし)は、CPU で見込みで出し、GPU の結果で確定する(01-architecture)。

## テスト
- 生まれる: 物質の塊 → 個体の前後で、物質とエネルギーの和が一致(CPU と GPU でビット一致)。同じ状態なら同じ種類・同じ受け継いだ値。
- 群れ: 群れ → 一体ずつ → 群れ、で数と物質が一致。
- 小さい場面(捕食者 1・獲物 10・食べ物)で、CPU リファレンスとビット一致。
- 個体 ↔ 数の往復で数が保存される。
- アニメーションの整数評価が、同じ入力でビット一致。見た目の破綻(関節の飛び)がない。
- プレイヤーの体: CO の密室で体の O₂ が減る・熱い空気で体温が上がる・押した分の蓄えが減って熱になる、が生き物と同じ式で出る(帳簿が合う・CPU と GPU でビット一致)。

## 研究(時間の打ち切りなし。D-411)
成功の基準と、うまくいかない時に試す代案の順を書く。諦めるのは原理的に無理と分かった時だけ(ユーザーと判断)。
- R-CREA-1 整数のアニメーション: 基準は、ブレンドで見た目が荒れないこと。代案: 回転を int64 に。
- R-CREA-2 個体の数と速さ: 基準は、多くの個体(目安を研究の中で測る)が動いても世界の時間がほとんど遅くならないこと。代案の順: 行動の選び直しの頻度を下げる → 集まりのままでいる範囲を広げる(アクセスされていない群れは集まりのまま)。
- R-CREA-3 フロー場: 基準は、目的の種類が多くても移動が破綻せず遅くならないこと。代案: フロー場を粗いレベルで作り、近くだけ細かくする(17)。
