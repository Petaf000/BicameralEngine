# 18 魔法具: 造形・魔石・性能・共有(L4 詳細設計)

対応する決定: D-418(魔素は元素)/ D-419(魔法も原則は保存則の中)/ D-420(反動と熱が返る)/ D-421(魔法具を自由に作る・性能はシミュで決まる)/
D-422(設計が商人を通して他のプレイヤーの店に並ぶ)/ D-107(Model は GPU)/ D-205(決定性)

**役割分担**: どんな魔石・素材・魔法があり、作るのに何が要るか(中身)は**ユーザーが決める**。ここは、それを載せる仕組み。

## 1. 設計データ(魔法具の「設計図」)
- **形**: SDF の演算の木。基本形(箱・円柱・球・カプセル・輪・押し出し・回転体など)と演算(和・差・積・なめらかな結合・変形)。
- **素材**: 形の領域ごとに物質(02)を割り当てる(柄は木、芯は金属、など)。
- **魔石**: はめ込む位置・向き・魔石の種類(魔石も物質の一つ。魔素を多く含む/通すなどの性質は物質の値で決まる)。
- **版**: 表の版(元素・物質・反応則)とパッケージのハッシュ(15 §4)。
- 設計データは決まった形式(版つき)で保存・共有できる。

## 2. 設計から物へ(決定的)
- 設計 → 物の体積(08 §1 のボクセルの木)を、**GPU の整数の SDF 評価**で作る(同じ設計からは、どの機械でもビット単位で同じ物ができる)。
- 作るのに使う素材の量は、体積 × 密度から整数で決まる。世界の中で作る時は、持っている素材からその量を消費する(保存則。どこで・何を使って作れるかは中身)。
- 作る操作は、UI(CPU の View)で設計を組み、「作る」コマンド(06 §3)を出す → GPU が刻みの境界で物を生成する。

## 3. 性能はシミュレーションで決まる(決め打ちの数値にしない)
- 魔法を使うと、魔石から魔素が素材の中を通って(07 §5 の輸送)、放出する所で反応(02)が起き、熱・力・物質になる。
- したがって性能(同じ魔素で出せる力・熱のこもり方・反動の受け方・壊れやすさ)は、**形・素材・魔石の配置から自然に決まる**:
  - 魔素の通り道が短く太い形は効率がよい、熱が逃げない形は持ち手が熱くなる、細すぎる所は反動や熱で割れる(08 §3)、など。
  - どの形が最高効率かは、エンジンの一般則の結果として存在する(設計者が数値で決めない)。
- 性能を測る道具(試験台・測定器)は、観測の道具の一つとして作る(中身)。

## 4. 造形の UI(CPU の View)
- 設計の編集は UI(自作。12 §4)で行う。SDF の木を直接編集する形(基本形を置く・削る・なめらかにつなぐ)+ 素材を塗る + 魔石をはめる。
- 編集中の見た目は、設計を描画用に評価した仮の表示(View。決定性は要らない)。「作る」まで世界は変わらない。
- 同じ UI をエディタ(14)でも使い、買える魔法具の設計をゲーム側で作る。

## 5. 共有: 商人を通して他のプレイヤーの店に並ぶ(D-422)
- 共有するのは設計データだけ(§1)。世界は別々で、非同期。
- 受け取った側は、自分の機械で設計から物を作り、同じ物理と化学で動かす → **性能を偽れない**(改ざんした数値は意味を持たない。形と素材が全て)。
- 表の版が違う(Mod の有無など)設計は、並べない/注意を出す(15 §4)。
- 送る仕組み(自前のサーバーか Steam ワークショップか)・並べ方(誰の設計がどの店に)・値段・不適切な設計の扱いは、早期アクセスの前に決める(保留)。

## テスト
- 同じ設計から、CPU と GPU・2 回・(AMD の機械)で、同じ物の体積(ハッシュ一致)。
- 設計 → 保存 → 読み込み → 物、で同じ物になる。
- 性能の差が形から出ることを確かめる場面: 形だけが違う 2 本の杖で、同じ魔素から出る力と、持ち手の温度が違う。

## 研究(時間の打ち切りなし。D-411)
- R-ITEM-1 整数の SDF 評価(なめらかな結合など)を決定的に、十分細かく行えるか。基準は、造形の見た目どおりの形が物になること。
- R-ITEM-2 魔素の輸送と反応だけで、形による性能の差が「意味のある差」として出るか(基準は、プレイヤーが工夫して性能を上げられること。中身のユーザーと一緒に判定)。
