# 01 アーキテクチャ

## CPU と GPU の分担
```
CPU(ランタイム): 窓 / 入力 / コマンドリスト投入 / Present / 音の出力 / セーブ I/O
                  + 入力への即時の見込み発音(確定は GPU の結果で行う)
                  ループ中は「投げて Present する」だけ。GPU の完了を待ってスピンしない(1〜2 フレーム先行)
CPU(エディタ・ツール): 何でも使ってよい。CPU のデータで編集し、GPU 用バイナリにベイクする
GPU: 世界の状態すべて。VRAM に常駐し、CPU に戻らない
```
CPU に構造的に残るもの(DX12 の仕様上 GPU からはできない): コマンドリストの submit、Present、
OS の入力イベント、オーディオデバイスへの出力、DirectStorage のリクエスト発行。

## データの流れ
```
エディタ(CPU, Luau で反応則を記述) → ベイク → Circuit Table / 世界データ(バイナリ)
  → 起動時: DirectStorage で VRAM へ、Work Graphs のバッキングメモリ確保
  → 毎フレーム: 入力を GPU へ → 反応・物理・描画・音の種類決定 → Present / 音の出力
  → GPU → CPU はノンブロッキングのリングバッファ(音イベント・UI 表示・デバッグ出力)
```

## 動作環境
SM 6.8 + Work Graphs + DXR 1.1 + Mesh Shader → 実質 RTX 30/40 以降・RDNA3 以降の Windows PC。コンソールは対象外。

## 要件にまだ無いもの(いずれ要る)
アニメーション(IK・ラグドール遷移を含む)/ ブロードフェーズ / セーブ(GPU 構造体の読み戻しとバージョン管理)/
エディタ / VRAM 予算 / フレームペーシング / プロシージャル生成

## 保留(やるかどうかユーザーが決める)
- 3D Gaussian Splatting: VisBuffer の不透明パイプラインと相性が悪く、ライティングが焼き込み。制作パイプラインも無い
- Neural Post-process: 学習データが要り、DLSS に品質で勝ちにくい
- Mesh Nodes(Work Graphs から描画を起動): ベンダー対応が動いている領域。前提にしない

## 見積もり前に測るもの
- 近傍検索: ノード数十万で毎フレームのハッシュ再構築コストと VRAM
- Work Graphs のバッキングメモリ: 最悪ケースの活性ノード数から逆算(溢れると Spawn が失敗する)
- AVBD: 論文の数値は条件を確認してから予算に入れる(ブロードフェーズ込みか、シーンの性質)
