# 01 アーキテクチャ(全体像と文書の地図)

決定の一覧は docs/plan/DECISIONS.md、道筋は docs/plan/ROADMAP.md。この文書は全体像と、詳細設計(L4)の入口。

## 一文で
**世界の状態と因果(反応・生き物・魔法・物理・進行)はすべて GPU の中で完結し、機種が違っても完全に同じ結果になる。
CPU はそれを見て(View)、入力をコマンドとして頼む(Controller)だけ。**(D-107・D-205)

## エンジンとゲームの境界(D-464)
- **エンジン**: 法則の形(書き方)と、それをどんな規模でも正確に走らせること、法則を調べる道具(D-470)。中身は持たない(D-454・ADR-0151)。
- **ゲーム**: シミュの法則については形を作らず、**「何があるか・何が何になるか(反応の網)・値」**を決める。現実の直感との向き(火は空気を使う・水は低い方へ)、
  面白さ、見つけやすさはゲームが保証する。シミュの外(地形と配置・行動表・NPC・発見の導線・UI)もゲーム。
- 例「バックドラフト作戦」(密室に魔物を誘い込み火を放って扉を閉め、遠くから扉を開けて一気に燃やす): エンジンは反応の評価・気体の流れ・速い反応の細分・
  圧力が扉を押す・測れて再生できること。ゲームは燃焼の速さ・酸素不足で CO ができる法則・CO が燃える温度・蝶番の強さ・魔物の呼吸と弱り方・前触れの見せ方。
  **作戦専用の法則は 0 で、一般の法則の組み合わせから作戦が生まれる**のが目指す形。
- 世界のすべての流れは**坂の原理**(D-466。02 §5・07)の上に置く。魔法も筋肉と同じ法則で、エンジンに魔法専用の形は足さない。

## エンジンの約束(D-465)
| 約束 | 意味 |
|---|---|
| 決定性 | 機種が違っても同じ入力で同じ結果(D-205・ADR-0008) |
| 保存則 | 質量・エネルギー・元素を正確に保つ。出入りはすべて帳簿に載る(D-206・D-419) |
| 細かさによらない一貫性 | どの解像度で計算しても同じ法則(D-208・D-402) |
| 見るだけなら変わらない | 観察のために細かくしても世界に返さない(D-403) |
| 重くても結果を変えない | 計算は必ず最後まで正しく行う。遅れは安全網で、超えたら警告(D-468) |
| 法則は状態だけで決まる | 場所や誰が起こしたかで変わる隠れた場合分けがない(D-463) |
| 何でも測れる・記録できる・再生できる | エディタの「神の目」・写しの早送り・再生ファイル(D-470・15) |
| 中身を持たない | 名前と値はパッケージに(D-454) |

ゲームの約束(面白さ・探究心など)はこれとは別で、ゲームが守る(D-462)。

## CPU と GPU の分担
```
GPU(Model)  : 世界のすべて。多重解像度の疎な木(場: 0.5m を基本に、粗くも分子までも細かくもなる)+ 体積の物 + 生き物 + 進行。整数で計算
              1 刻み = 世界時間 1/60 秒。現実の時間との比は演出でだけ変える(D-468。重くて遅くなるのは安全網)。エンジンに固定の上限なし
GPU(View)   : 描画(PBR・Visibility Buffer・仮想化したジオメトリで遠くまで精細・DXR の ReSTIR DI + GI)。浮動小数点でよい
CPU(View)   : 窓・Present・UI(自作)・音(自作ミキサー + XAudio2)・文字・会話の表示と流れ(Luau)
CPU(Ctrl)   : 入力 → コマンド(適用する刻みつき)→ GPU のキュー。GPU の世界は書き換えない
CPU(ツール) : エディタ(同じ exe の編集モード)・ベイク(Luau → 整数の表)・セーブ I/O。CPU を自由に使う
GPU → CPU   : 待たないリング(イベント・スナップショット・デバッグ出力)。1〜3 フレーム遅れで読む
```

## 1 刻みの流れ(06 の要約)
コマンド適用 → 活性の整理 → 輸送 → 反応 → 物理 → 生き物 → 結合(物 ↔ 場)→ 粗い層(1 秒に 1 回)→ 検査と出力

## Work Graphs と Compute(D-302)
できる限り Work Graphs。反復回数が決まっていて、どちらでも結果が同じものは、両方測って安い方。
Work Graphs はレコードの処理順を保証しないので、結果が順番に依存しない書き方をする(04 の規則)。深さの上限 32 は、連鎖を刻みをまたいで進めることで避ける。

## 動作環境
Windows・Work Graphs 必須(RTX 30 以降・RX 7000 以降)。最低機・推奨機の性能の線は、研究の結果を見て決める(D-005・D-210。理想を下げない: D-414)。
