# 15 セーブ・再生・発見の共有・Mod の読み込み(L4 詳細設計)

対応する決定: D-110(発見の共有だけ)/ D-111(変化は残る)/ D-205(完全な再現)/ D-312(生成+差分)/ D-320(Mod)/
D-586(セーブは初めの状態 + 真実の差分。claude/33 S36)/ ADR-0386 /
D-602(袋の中は世界の外の止まった棚。claude/36 S46)/ D-605(法則の版はいつも最新。S51)/ D-606(ゲームの中身に依らない口 2 つ。S52)/ ADR-0391・ADR-0392

## 1. セーブ
**形(D-586)**: セーブ = **初めの状態(生成の種 + 生成手順の版 + 法則の版)+ 変えた所の差分**。20 km の世界を全部書かないので、軽く・何度でもセーブできる。
- 前提: 初めの状態(生成して落ち着かせた世界。05 §6)が、どの GPU でもビット単位で同じに作り直せること(研究 R-G1。05 §6.1)。
  **R-G1 が落ちた時の退く道**: 初めの状態も差分と一緒にセーブに持つ(セーブが大きくなる)。セーブの形式は、初めの状態を「種から作る」か「ファイルに持つ」かを
  見出しの 1 つの値で選べる形にしておく(退いてもセーブの形式は変えない)。
- **差分に入るのは真実だけ**(claude/34 S41): 物質の量・エネルギー・勢い(起きている所)・電荷・割れの進み・変わった形・表面の細かい形の差分(S44)。
  導かれる値(圧力・温度・電位・磁場・放射の場など)は入れず、読み込んで起きた時に真実から解き直す。読み込み → N 刻みが、セーブせずに N 刻みとビット一致すること(テスト)は、
  導かれる値を解き直しても変わらない(導かれる値は真実だけで決まる)ことで成り立つ。眠った所の「粗くして残した導かれる値」を差分に入れるかは R-F1 の結果で決める(05 §7)。
- 中身: 刻みの番号 / 初めの状態の決め方(種・生成手順の版・法則の版。退く道では初めの状態そのもの)/ 粗い層の全体(05 §4)/ 変化したページの差分(05 §7)/ 物と生き物の全部 /
  止まった棚の中身(§1.1。真実だけ)/
  進行(13 §3)/ 表の版(パッケージとそのハッシュ)/ 天候の予定表のどこまで進んだか(05 §5)。
- セーブとロードは自由(何度でも・どこでも)で、エンジンはロードの回数や時間の巻き戻しに特別な仕組みを持たない(時間の輪は作らない。claude/31 S1)。
  ゲームの状態の一部(ノートなど)をセーブと一緒に戻すかはゲームの中身で、エンジンから見ればセーブの中の状態の一つ。
- 取り方: セーブ要求のコマンド → GPU が刻みの境界で、セーブ用の領域に書き出す(差分の圧縮も GPU)→ 待たないリングで CPU へ → ファイル。セーブ中もゲームは止めない(書き出しは数フレームに分けてよい。その刻みの状態を別領域に固定してから)。
- 版: ファイルの先頭に形式の版。古い形式を読むための変換を、形式を変えるたびに書く(形式の版と法則の版 §1.2 は別)。

### 1.1 世界の外の「止まった棚」と、外との出入りの口(D-602・D-606 (1)・ADR-0391)
- **手に持つ物・身に着けた物は世界の中**(法則がそのまま効く)。**袋の中は世界の外の止まった棚**: 物の真実(claude/34 S41)を入れた刻みのまま凍らせて持ち、
  出すと入れた時の続きから動く。札に作り直さない(物 ⇄ 札の変換規則を持たない)。導かれる値は持たず、出した時に解き直す(セーブと同じ)。袋の中の費用は 0(刻みで計算しない)。
- **出し入れは世界の出入りとして帳簿に載る**: 「外への出入り」の列(天候の境目 05 §5・魔素の湧き出し D-419 と同じ)に、物質の量とエネルギーを刻みと一緒に記録する。
  保存則の検査は外への出入りを差し引いて 0。出し入れはコマンド(06 §3)で刻みの境界で起きる。
- **体を置き直す出来事の口**(D-606 (1)): 体(や物)を世界から外へ出し、外から世界のある場所へ入れる出来事。袋の出し入れと同じ口。いつ・どこへはゲームが決める。
- エンジンは値で受けるだけ(ゲームの中身。D-006): 何を袋に入れられるか・持ち物の重さを体に効かせるか(既定は効かせない)・死んだ時どうなるか。
- 仮(ユーザー未確認。ADR-0391): 袋の中の勢いは既定で 0(静かに出る)・出す場所が塞がっていたら既定で断る。どちらもゲームの値で変えられる。
- 未確認: 棚の大きさの上限(VRAM か主メモリか)・出す時に導かれる値を解き直す費用。

### 1.2 法則の版(D-605・ADR-0392)
- **いつも最新の法則で動かす。過去の版は持たない**。セーブ・設計(D-422)・記録(§2)に法則の版を書く。
- 法則の版 = 表の版(`TableVersion`。§4)+ エンジンの解き方の版(仮: 整数 1 つ)。読み込んだ時にどちらかが違えば「法則が変わった」と出し、**変わった行を見せる**:
  セーブと再生ファイルは表の中身を持つ(§2.2)ので、今の表と行ごと(分類・鍵・値)に比べた差分を出す。解き方の版だけが変わった時は変更の記録(人が書く注記)を見せる(仮)。
- **開発中の記録・再生・試験は、版が変わったら期待の幅を自動で取り直す**(claude/30): 版が違う記録はハッシュの一致を求めず、新しい版で再生した結果を新しい期待として書き直す道を用意する
  (コマンドラインの選択肢。遊びの指標〔14・ADR-0206〕の「前に測った版との差」と同じ形)。
- §2.2 の「版が書いてあって中身が無く、今の表と版が違えば起動を止める」は再生(バグの再現)の時の約束のまま。セーブの読み込みは止めずに差分を見せる(仮)。

## 2. 再生ファイル(決定性の土台)
- 初期状態(セーブ or シード + 差分)+ 表の版 + コマンドの列 + 刻みごとのハッシュ(検査用。間引いてよい)。
- 使い道: バグの再現 / 機種間の比較(04 §5)/ 発見の共有(§3)/ デモ映像の撮影。
- 直前の操作を繰り返す「型」(D-483 ④・12 §3)は、繰り返したコマンドがそのまま列に入る(再生に特別な扱いは要らない)。

### 2.1 実装(T-0086。`engine/src/save/replay_file`・`replay_session`)
- 形式の版 1(リトルエンディアン): 見出し 64 バイト(`BCRP`・形式の版・世界の種類・表の版・シード・初期状態の刻み・差分のバイト数・コマンドの数・ハッシュの数)
  → 初期状態の差分(8 バイトの境界まで埋める)→ コマンド × 64 バイト(06 §3)→ ハッシュ × 16 バイト(刻み・値)。詳しい表は replay_file.h の先頭。
- 読むときに大きさ・並び(コマンドは (targetTick, sequence) の昇順、ハッシュは刻みの昇順)を確かめ、合わなければ理由を返す(`replay_file_test`)。
- 仮の世界(T-0004 の `probe_sim`)は初期状態が刻み 0 の全部 0 なので、差分は空・表の版は 0。本物の世界では初期状態 = シード + 差分 + 表の版になる。
- ランタイム: `bicameral --record <path>` が GPU のキューへ足したコマンドと読み戻したハッシュを集め、終わるときに書く
  (最後にハッシュを読み戻した刻みまでに適用されるコマンドだけ)。`bicameral --replay <path>` は窓のクリックを無視して、コマンドを刻みに間に合うように
  (8 刻み先まで)キューへ足し、読み戻したハッシュを突き合わせ、最後のハッシュまで確かめたら終わる(全部一致で終了コード 0)。
- ハッシュは今は全部の刻みを持つ(60 刻み/秒 × 16 バイト = 約 1 KB/秒)。長い記録で大きくなったら間引く(読む側は間引いた列を扱える)。

### 2.2 表の中身(形式の版 2。T-0170・T-0193・ADR-0050)
- 見出しの表の版 = 初期状態の表の版。ハッシュの後ろに、記録に使った表(初期状態の表 + 差し替えの印の版の表)を版の昇順に並べる:
  版・読んだパッケージ(読んだ順)・「改造された世界」の印・合わせた表の中身(`script::TableBytes`)。
- 再生は中身から表を作り直す(`script::RebuildReactionTable`: 中身のハッシュ = 版を確かめ → 読み戻し → 定義 → ベイク。Luau は走らせない)。
  **パッケージのフォルダが無くても同じ表で再生できる**(`reaction_replay_table`・ctest `window_replay_no_packages`)。
- 表の中身が無いファイル(版 1)は、今のパッケージの表で再生し警告する。版が書いてあって中身が無く、今の表と版が違えば起動を止める。

### 2.3 時間を飛ばす(D-600・ADR-0390)
- 時間を飛ばす = 世界全体の早送り(刻みの規則は変えない)。だから記録・再生には特別な扱いが要らない: 早送りの間もコマンドの列と刻みのハッシュはそのまま。
  早送りの速さ(時間の操作)は世界のコマンドにも再生ファイルにも入れない(ADR-0035 と同じ)。

## 3. 発見の共有(D-110)
- 共有するもの = 「実験」: 場所(ページの範囲)とその時点の状態(差分)+ 表の版 + その実験で出したコマンドの列 + 結果のハッシュ。
- 受け取った側は、自分の機械で再シミュレーションして、同じ結果(ハッシュ一致)を見る。完全な再現(D-205)があるから成り立つ。
- 表の版(Mod の有無を含む)が違えば、再現できないことを表示する。
- 送り方(サーバー・Steam のワークショップ・ファイル)は後で決める(保留: 早期アクセスの前)。

### 3.1 法則の行の「ここで起きた」出来事の口(D-606 (2)・ADR-0392)
- 法則の行(反応の規則・流れの家族など)が、どこで・いつ・どれだけ働いたかを出来事として出す口。刻みの終わりのイベントのリング(06 §3)に種類を 1 つ足す
  (中身 = 法則の行の鍵・場所・働いた量の目安)。**出す行と間引き方はゲームが登録する**(登録が無ければ出さない。ブランクの世界は 0)。
- 何を「見た」と数えるか(視界・距離・計器)・ノートに何が書かれるかはゲームの中身(D-607)。出来事は View に渡すだけで世界の結果に入らない。
- 未確認: 出来事の量が多い時のリングの大きさ・間引きの形(本物の段で測る)。

## 4. Mod の読み込み
- パッケージ(13 §2)の一覧と順番を、起動時とセーブの読み込み時に決める。表の版にパッケージの一覧とハッシュを含める。
  - 実装(T-0138・ADR-0031): 順番は依存 → 名前で決まる(`LoadPackages` の `loadOrder`)。ハッシュは合わせた表の中身だけの `TableVersion`
    (誰が書いたかは入れない)。保存するときは `loadOrder` と `TableVersion` と「改造された世界」の印(`modifiedWorld`)を並べて残す。
    再生ファイルはこの 3 つと表の中身を持つ(§2.2・ADR-0050)。
- 実績や共有の扱い(Mod ありのセーブを区別するか)は後で決める。

## テスト
- 再生ファイルを書いて読むと同じものに戻り、壊れたものを拒否する(`replay_file_test`。T-0086)。
- 記録 → 別の分け方で再生して刻みごとのハッシュが一致(`gpu_probe_sim_test`・`window_replay_*`。T-0086)。
- 再生ファイルの表の中身だけで(パッケージのフォルダを消して)、差し替えをまたいだ記録を再生してハッシュ列が一致(`reaction_replay_table`。T-0193)。
  版 1 の再生ファイルを表の無い形で読む(`replay_file_test`。T-0170)。
- セーブ → 読み込み → N 刻み、が、セーブせずに N 刻み進めたのとハッシュ一致(導かれる値を差分に入れずに解き直しても一致)。
- 種から作り直した初めの状態 + 差分 = セーブした時の世界(ブロックのハッシュ一致)。別の GPU で読んでも同じ(R-G1)。
- 古い形式のセーブを読める(形式を変えたら、変換のテストを足す)。
- 止まった棚: 入れる → N 刻み → 出す、の後の物の真実が、入れた時とビット一致・帳簿の外への出入りを差し引いて保存則が 0・棚の中身をセーブ → 読み込みでビット一致。
- 法則の版: 表の 1 行を変えて読み込むと、変わった行だけが差分に出る。版が違う記録の期待の取り直しで、新しい版の再生がその期待と一致する。
- 法則の行の出来事: 登録した行だけが出る・同じ記録の再生で同じ出来事の列(キーの順)・出来事を落としても世界のハッシュが変わらない。
