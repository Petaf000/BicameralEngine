# 05 世界のデータ(L4 詳細設計)

対応する決定: D-102(シームレス)/ D-108(3D の地形・洞窟)/ D-111(変化は残る)/ D-112・D-208(粗と細、観測者で変わらない)/ D-203(8km 四方)/ D-204(0.5m のセル)/ D-301(場と物の二本立て)/ D-312(生成+差分)

## 目的
世界の「真実」をどこに・どの形で持つかを決める。ここが全サブシステムの土台。

## 1. 世界の範囲と座標
- 水平 8192m × 8192m、鉛直 -512m 〜 +1536m(2048m)。原点は南西の最下端。
- 位置は int64(04 の単位 2^-20 m)。描画は、カメラを原点にした相対座標の浮動小数点に直して使う(大座標の精度問題を描画だけに閉じ込める)。

## 2. 二本立て(D-301)
| | 場(Field) | 物(Body) |
|---|---|---|
| 何を表す | 地形・土・岩・空気・水・熱・魔素・草などの「地面を覆うもの」 | 木・岩の塊・建物の部品・道具・生き物とプレイヤーの体 |
| 形 | 0.5m の疎な格子 | 素材を持った部品の集まり(08 を参照) |
| 動き | 輸送(熱・気体・水)と反応 | 剛体と関節の物理(08)、生き物の行動(09) |
| つながり | 物の部品が重なるセルと、熱・物質をやり取りする(06 の「結合」段) | |

草は個体ではなく、セルの成分(草のバイオマス)として場で持つ。木 1 本は物。境目の目安は「動く・倒れる・持てる」かどうか。

## 3. 細かい層(0.5m の疎な格子)

### 階層
```
ページ 64m 角(= 16×16×16 ブロック) … ストリーミングと差分セーブの単位
  └ ブロック 4m 角(= 8×8×8 セル = 512 セル) … 活性と割り当ての単位
      └ セル 0.5m 角
```
- ページ表: 128 × 128 × 32 ページ(= 524,288 項目)。各項目 = そのページのブロック表への参照 or「生成器のまま(未読み込み)」。
- ブロック表: 4096 項目。各項目 = ブロックプール内の番号 or「一様ブロック」(中身が全部同じ: 岩の中・空の空気。値を 1 つだけ持つ)。
- ブロックプール: VRAM に確保した固定長のブロックの配列。空きはフリーリストで管理する。空きの取り出し順は決定的に行う(04 の R5: 要求をキーで並べてから配る)。

### セルの中身(1 セル 48 バイト、構造体の配列ではなく種類ごとの配列 SoA)
| 項目 | 型 | バイト | 意味 |
|---|---|---|---|
| 成分の種類 ×4 | uint16 ×4 | 8 | 物質(species)の ID。0 は空き |
| 成分の質量 ×4 | uint32 ×4 | 16 | mg |
| エネルギー | int64 | 8 | mJ(熱 + 化学) |
| 面の流量 ×3 | int32 ×3 | 12 | +x・+y・+z の面を通る気体/液体の流れ(面の持ち主はマイナス側のセル) |
| 補助 | uint32 | 4 | 相の状態・細分の段・活性の残り時間など(ビットの割り当ては実装時に表にする) |

- 1 セルに入る成分は 4 種類まで。5 種類目が来たら**セルの拡張領域**(別のプール、成分 4 つ分)を付ける。保存則のために、捨てたり混ぜたりはしない。
- 読む世代と書く世代の 2 組を持つ(06 の世代同期)。1 ブロック = 512 × 48 × 2 = 48KB。
- 予算(D-209 の 1.5GB)で約 3 万ブロック = 1500 万セル。見積もり: プレイヤーの周り(描画と操作のため)約 1 万ブロック + 活性の領域 + 洞窟。

### 活性(D-208)
- ブロックは「活性」か「静か」。活性 = このブロックで何かが変わっている(反応中・流れがある・物が動いている・温度が周りと違う)。
- 活性のブロックは、場所に関係なく毎刻み計算する。**プレイヤーとの距離では決めない。**
- 静かになった判定: 一定刻み(例 60)の間、ブロック内のどの量も変化量が閾値未満。閾値は量ごとに表で決める(整数)。
- 境界を越える流れがあれば、隣のブロックを活性にする(06 の段 2)。

## 4. 粗い層(8m 格子・世界全体)
- 8m × 8m の柱(1024 × 1024 = 約 100 万本)。各柱に:
  地表の高さ・土の水分・雪の量・水の体積・草と植物のバイオマス(種類ごと)・焼け跡の状態・温度・魔素・生き物の密度(種類ごと)・天候の入力。
- 大きさは 1 柱 64〜128 バイトを目安(= 64〜128MB)。常に全体を VRAM に持つ(D-312)。
- 天候は別の粗い 3D 格子(64m × 64m × 高さ 16 層)で、風・気温・湿度・雲を持つ。
- 更新は 60 刻みに 1 回(= 世界時間 1 秒)。成長・回復(D-111)・季節・生き物の数の増減はここで進む。

### 粗と細の受け渡し(保存量を正確に)
- **細 → 粗(静かになった時)**: ブロックの保存量を合計して柱に足す。細かい形の情報のうち、粗い層で表せないもの(焼け跡の模様・掘った穴)は、ページの差分として残す(§6)。
- **粗 → 細(活性になる時・プレイヤーが近づいた時)**: 生成器(§5)で形を作り、差分を当て、柱の保存量をセルに**整数で割り振る**(ハッシュで重みを付け、合計が柱の値と完全に一致するよう端数を配る)。
- この受け渡しで「観測者で結果が変わる」のは、粗い層で進んだ部分の細かさだけ。反応・物理・水が動いている所は必ず細かい層にいる(D-208)。

## 5. 生成器(決定的)
- 世界は「シード + 生成手順(Luau で書き、表にベイク)+ 手で直した差分」から作る(D-312)。
- 生成は GPU の整数シェーダーで、ページを読み込むときに行う(8km の細かい層を全部配ると大きすぎるため)。CPU リファレンスの生成器でビット一致を確かめる。
- 手順の例(中身はユーザーが決める): 大地の高さ → 洞窟(3D のノイズ)→ 地層と素材 → 水 → 気候帯 → 植生の密度 → 生き物の密度 → 手で置いたもの(ダンジョン・遺跡)。

## 6. 差分(セーブと手直し)
- ページ単位で「生成器が作るもの」との差分を持つ。差分は変化したブロックだけ(ブロックの丸ごとの値を圧縮して保存)。
- エディタの手直し(地形を削る・ダンジョンを置く)も同じ形式の差分として持つ(ゲームのデータ)。セーブの差分はその上に重なる。
- 生態系の回復(D-111)で差分が意味を失ったら(焼け跡が完全に戻った)、差分を消してよい(生成器と一致したブロックは差分から外す)。

## 7. ストリーミング
- ページは VRAM のページキャッシュに載る。読み込み = 生成器で作る → 差分を当てる。差分のファイルは DirectStorage で読む。
- 追い出すのは静かなページだけ。追い出す前に、変化があれば差分として書き出す(GPU → CPU の読み戻しは待たないリングで、セーブ I/O は CPU の役目)。
- 活性のページは追い出さない。活性の量が VRAM を超えた場合は、主メモリに退避しながら分割して計算する(世界の時間がさらに遅くなる。D-202)。これは極端な場合の正しさの保険で、性能は求めない。

## テスト
- 生成器: CPU と GPU でページのハッシュがビット一致。
- 粗 ↔ 細: 往復して保存量が一致。割り振りの端数が決定的(同じ入力で同じ結果)。
- 差分: 生成 → 変更 → 差分を保存 → 生成 → 差分を当てる、で元の状態とビット一致。
- 追い出しと読み込みを繰り返しても、状態のハッシュが変わらない。

## 研究と打ち切り条件
- R-WORLD-1 セルの成分 4 つ + 拡張で足りるか: 典型の場面(燃える草原・洞窟の空気・溶岩)で拡張が使われる割合を測る。10% を超えたら 6 つに増やす(1 セル 60 バイト)。
- R-WORLD-2 ブロック 4m・ページ 64m の大きさ: 活性の粒度として粗すぎ/細かすぎないか。活性ブロックの中で実際に変化しているセルの割合が 20% 未満なら、ブロックを 2m(4³)に下げる。

## 未確認
- DirectStorage で小さいファイルを大量に読むときの速さ(ページの差分は小さい)。まとめて 1 つのパックにする必要があるかを測る。
