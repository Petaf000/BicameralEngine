# 05 世界のデータ(L4 詳細設計)

対応する決定: D-102(シームレス)/ D-108(3D の地形・洞窟)/ D-111(変化は残る)/ D-301(場と物)/ D-312(生成+差分)/
D-401(上限なし)/ D-402(多重解像度)/ D-406(高さの目安 TotK)/ D-418(成分は可変)/
D-583(魔素は普通の物質の形で足りる)/ D-585(初めの状態は落ち着かせてから)/ D-586(セーブは真実の差分)/ D-587(天候は混ぜる形)/ ADR-0386 /
D-600(刻みの長さは状態が変わる速さで。ADR-0390)/ D-604(高さと深さ。claude/36 S48)

## 目的
世界の「真実」をどこに・どの形で持つかを決める。多重解像度の仕組みそのものは 17。ここは、その上に載る世界の範囲・中身・生成・差分・ストリーミング。

## 1. 世界の範囲と座標
- **エンジンは範囲を制限しない**(D-401)。範囲はゲーム側(C2)が決める。目安は TotK: 地表の広さは TotK と同程度(数字は未確認)、上空 約 3,000m、地下 約 1,100m(D-406)。
- 位置は (レベル k, int64 の座標)(17 §1)。基本のレベル 0 で 1 = 0.5m のセル、セルの中の位置は 04 の単位(2^-20 m)。
- 描画は、カメラを原点にした相対座標の浮動小数点に直して使う(大座標の精度問題を描画だけに閉じ込める)。

## 2. 二本立て(D-301)
| | 場(Field) | 物(Body) |
|---|---|---|
| 何を表す | 地形・土・岩・空気・水・熱・魔素・草むらなど、空間を埋めるもの | 木・岩の塊・建物の部品・道具・魔法具・生き物とプレイヤーの体 |
| 形 | ブロックの疎な木(17) | 物の局所座標の体積(ボクセルの木。08) |
| 動き | 輸送(07)と反応(02) | 物理(08)と生き物の行動(09) |
| つながり | 物の体積が重なるセルと、熱・物質・運動量をやり取りする(06 の「結合」段) | |

- 草むらは普段「場の成分(バイオマス)」だが、触る・抜く・近くで見ると、1 本ずつの個体になる(17 §2・§3)。場 ↔ 物の境目は固定ではない。

## 3. セルの中身(連続体の表現、レベルに関係なく同じ形)
| 項目 | 型 | 意味 |
|---|---|---|
| 成分 | 可変長の一覧(物質 ID uint32 + 物質量 uint64。ADR-0012)| インラインに N 個 + 溢れたら連鎖。N は測って決める(R-MULTI-4)。**上限なし**(D-418) |
| エネルギー | int64 | mJ(熱 + 化学。レベルが細かいほど単位を細かくする: 単位はレベルの関数として 04 に書く) |
| 面の流れ ×3 | int32 ×3 | +x・+y・+z の面を通る流れ(面の持ち主はマイナス側のセル) |
| 補助 | uint32 | 相の状態・細分の種類(A/B/C)・子ブロックの有無・活性の残り時間 |

- 読む世代と書く世代の 2 組(06 の世代同期)。
- **持つのは「真実」だけ**(claude/34 S41。持ち主は 20): 物質の量(匂い・魔素・濡れの水を含む)・エネルギー・勢い(起きている所だけ)・電荷・割れの進み・
  ねばい物の変わった形(ある所にだけ)・表面の細かい形の差分(S44。変えた所だけ)。圧力・温度・電位・磁場・放射の場などは導かれる値で、起きている所で計算する。
  上の表の「面の流れ」もこの分け方で持ち方が変わる(20 と C-1 の試作で決める)。
  (2026-10-21 本体のマージで T-0860 の渡し物を当てた)1 セルの持ち方は 20 §10(真実だけ・ある所にだけ・導かれる値は起きている所で計算・眠った所は粗くして残す)に従って C-1 で書き直す。上の表は前の版の形(M-0 で 1 セルの大きさを測り直す)。
  釣り合いの解き始め(温めた始まり)は状態の一部(20 §10.4・D-549 仮・Q137)。
- **魔素は普通の物質の形で足りる**(D-583・claude/33 S31 のエンジンへの要求): 欄・法則・特別扱いなし。中身はゲームの側(非公開側。D-006)。
- **どの物質にも書ける一般の能力**(D-583): 重さ(どの物質にも質量がある)・染み通りやすさ・吸い付き(特定の物質に溜まる)・湧き出し(明示的な出入り。帳簿の「外との出入り」)は、
  どれも物質の値と世界のデータで書け、運ぶ・広がる・反応・押すの家族に普通に乗る。特定の物質のための欄・法則は作らない。
- 一様なブロック(岩の中・空の空気)は値を 1 つだけ持つ(プールを使わない)。見出しの枠とセルの頁は別のプール(T-0102。17 §5「一様なブロック」)。静かで一様に戻った頁は畳んで返す(T-0103。17 §5「頁を畳む」)。計器で測れない差しかない頁も平均で畳む(T-0104。D-428。17 §5「ほぼ同じ頁を畳む」)。

## 4. 活性
- ブロックは「活性」か「静か」。活性のブロックは、場所に関係なく毎刻み計算する(プレイヤーとの距離では決めない。D-208)。
- 静かなブロックは粗いレベルにまとめてよい(合計して親に戻す。17 §2)。粗い所では、成長・回復・天候・生き物の数だけを、粗い刻み(例: 1 秒に 1 回)で進める。
- **刻みの長さは場所ごとに「状態が変わる速さ」で選ぶ**(D-600・ADR-0390): 一定に流れる川・天候の風は動いていても長い刻みで進む。選ぶのは局所の状態だけで、
  起きている時も寝ている時も同じ規則(時間を飛ばす = 世界全体の早送り。結果は待ったのとビット一致)。上の「粗い刻み」もこの規則の一つの場合として書き直す(R-T2 の後。仮)。
- 境界を越える流れがあれば隣を活性にする。

## 5. 天候の層(D-587・claude/32 S25。混ぜる形)
世界は有限(20 km 程度。外の大気の大きな流れは持たない)なので、天候は 2 つに分ける。**入った後はどちらも法則どおり**(濡らす・池に溜まる・風が煙を運ぶ)。
| | 何 | どう作るか |
|---|---|---|
| 大きな天候 | 季節・前線の雨・雪・風・日差し・青空の光・雲の電荷 | **世界のデータの予定**(天候の予定表)として、世界の**上の境目と端の境目**から入れる。決定的で、作り手が「いつ・どこに雨か」を書ける |
| 小さな天候 | 霧・谷の風・焚き火の上の雲・蒸発と結露 | 世界の中で法則から出る(運ぶ・広がる・反応の家族)。特別な仕組みは足さない |
- **境目の条件として入れる**: 雨・雪は上の境目から入る水・雪の質量、風は端の境目の空気の流れ、日差しと青空の光は放射の上の境目(まっすぐ運ぶ家族。持ち主は 23)、
  雷のもとは雲に入れる電荷(24 §2.5)。どれも外からの出入りとして帳簿に載る(07 §4。保存則の検査で差し引く)。
- 予定表は世界のデータ(天候の予定・季節の暦。整数の時刻で引く)。書かなければ「晴れ・無風・既定の気温」で、ブランクの世界は何も読まずに動く(D-455)。
- 蒸発した水は、上の境目に届いたら天候の層へ出る(出入りとして数える)。外で雲になって戻すかは予定表が決める(中で循環させない = 20 km の大気を解かない)。
- 前の版の「天候は粗いレベルの気体の場そのもの」は、小さな天候の側に残る(世界の中の空気は粗くても同じ法則。粗い所の天候は粗い刻みで進めてよい = §4)。
- 高さで変わる空気(上空で薄く寒い)は §5.1。
- **地域の印**(D-594・11 §3.2。仮): 場所から地域の番号を引く世界のデータ(粗い格子・生成の関数のどちらでも。作り手が書く)。法則は読まない(状態ではない)。サウンドエンジン・UI・ゲームの規則が読む(今いる地域を読む口)。書かなければ地域 0 だけ。
- (2026-10-21 本体のマージで T-0875 の渡し物を当てた)天候の層は**太陽の向き・強さ・帯の割合**と、**青空の上の境目**(短い帯の散らばった光・長い帯の空の温度 = 夜に地面が冷える)を出す(23 §3.1・§3.2)。
  セーブの差分には変えた表面の形が入る(S36・D-575・15 §1)。

### 5.1 高さと深さ(D-604・claude/36 S48)
| 何 | どう出るか |
|---|---|
| 空気の薄さ(上ほど圧が低い・O₂ が薄い) | **法則**: 重力 × 気体の法則(圧力の釣り合い)。山の上は火が弱く息が苦しい(体に効く。09 §7) |
| 深い水の圧 | **法則**: 陰の圧力(claude/29 Q1 の解き方) |
| 地熱(深いほど熱い) | **法則**: 地の底の境目から入る熱(世界のデータ。外との出入りとして帳簿に載る)+ 岩の伝導。深さの温度の形は、生成して落ち着かせた初めの状態(§6・D-585)で決まる |
| 上空の温度と湿りの大きな形 | **天候の層の予定**(§5)。上の境目から入れ、世界との出入りは帳簿に載る。作り手が「この山の頂は雪」を狙って書ける |
- **上空もセルを置く**(高い所は粗く。多重解像度の静かな所と同じ)。上空の小さな天候(雲・霧)は世界の中で法則から出る(§5 の小さな天候)。
- エンジンは高さの特別な規則を持たない: 薄さ・水圧・地熱はどれも今の法則(重力・気体・圧力・伝導)と世界のデータ(地の底の境目の熱・天候の予定)から出る。
- **未確認(M-0 に足す。claude/36 §1)**: 10 km の空気の柱で、整数の圧力の精度が上空まで足りるか・柱の費用と VRAM が線の内か。
  退く道: 上空を基準の圧(高さの関数)からのずれで持つ。
- 経緯(1 行): 一度「上空の大きな形も全部法則(日差し・赤外・対流の釣り合い)」を選んだが、狙って作りにくく釣り合いがずれていく恐れから、ユーザーが天候の層に持たせる形に直した。

## 6. 生成器(決定的)
- 世界は「シード + 生成手順(Luau で書き、表にベイク)+ 手で直した差分」から作る(D-312)。
- **初めの状態は、生成して法則で落ち着かせてから始める**(D-585・claude/33 S34): 生成したままでは始まった途端に崩れる・流れる(地形・川・植生が法則と食い違う)。
  生成 → 法則で早送りして釣り合わせる → その結果を「初めの状態」とする。プレイヤーが崩した所だけが動く世界で始まる。手で決めた形が少し動くことはある(落ち着かせの結果)。
  - 落ち着かせも**決定的**(同じ種・同じ生成手順・同じ法則の版から、どの GPU でも同じ初めの状態。R-G1)。法則の版(表の版)が変われば初めの状態も変わるので、
    落ち着かせた結果はセーブではなく「種 + 生成手順の版 + 法則の版」から作り直せる物として扱う(配るデータに焼いて持ってもよい。費用で決める。未確認)。
  - 落ち着かせの刻みの数・止める条件(帳簿の動きが計器で測れない差になったら、など)は世界のデータ(既定値あり)。落ち着かせの費用は未確認。
- **生成器は堆積・浸食を真似る作りにする**(地層が読める)。生成器そのものを法則の早送りにはしない(作る時間が長く、形を手で決めにくいため。採らなかった案)。
  生成器の中身(どう真似るか)はゲームの生成手順(Luau)で、エンジンは「層を重ねる・削る」を書ける手順の部品を用意する。
- 生成は GPU の整数シェーダーで、ブロックが要るときに、要るレベルで行う(粗いレベルも細かいレベルも同じ手順から。細かくした時の細部も生成器が決める)。CPU リファレンスの生成器でビット一致を確かめる。
- 手順の例(中身はユーザーが決める): 大地の形 → 洞窟 → 地層と素材 → 水 → 気候帯 → 魔素の濃淡 → 植生 → 生き物の密度 → 手で置いたもの(ダンジョン・遺跡)→ **落ち着かせ**。
- 表面の約 2 cm〜0.5 m の細かい形も、物質と場所の種から決まった関数で生成する(記録しない。claude/34 S44。持ち主は 23・10)。同じ一致の約束(R-G1)に入る。

### 6.1 研究 R-G1: 生成のビット一致(試作の列 6。claude/35 §3)
| | 中身 |
|---|---|
| 確かめること | 同じ種から、**違う GPU(少なくとも 2 社)**で、落ち着かせまで含めて同じ世界がビット単位で出るか |
| 合格 | NVIDIA と AMD(D-207)の 2 台で、同じ種・同じ版から作った初めの状態のブロックのハッシュが、どのレベルでも全部一致・CPU リファレンスとも一致。表面の細かい形の関数も同じ。WARP(Microsoft のソフトウェアの実装)は 3 台目として足す |
| 打ち切り | 生成の手順の整数化を 2 本試して(①整数だけの雑音と演算に絞る ②ずれる段だけ CPU リファレンスの値を焼いて配る)まだずれる時は、**初めの状態も差分と一緒にセーブに持つ**(セーブが大きくなる。D-586 の退く道) |

## 7. 差分(セーブと手直し)
- 「生成器が作るもの(落ち着かせた初めの状態)」との差分を、ページ(ある粗いレベルのブロック。例: 64m 角)単位で持つ。差分は変化したブロックだけ(細かいレベルの変化も、その部分木ごと)。
- **差分に入るのは真実だけ**(D-586・S41): 物質の量・エネルギー・勢い・電荷・割れの進み・変わった形・表面の形の差分。導かれる値は入れない(読み込んで起きた時に解き直す)。
  眠った所の「粗くして残した導かれる値」は、入れるかを R-F1(試作の列 6)の結果で決める(使えなければ捨てる形に下げるので、その時は入れない)。
- エディタの手直しも同じ形式の差分(ゲームのデータ)。セーブの差分はその上に重なる。
- 回復(D-111)で生成器と一致に戻ったブロックは、差分から外す。

## 8. ストリーミングとメモリ
- ブロックは VRAM のブロックプールに載る。無ければ生成器で作り、差分を当てる。差分のファイルは DirectStorage で読む。
- **未確認(D-585 と合わせた時の食い違い)**: 落ち着かせは周りのブロックに依る(水は低い方へ流れ、崩れは隣へ伝わる)ので、「要る時に要るブロックだけ生成する」と
  落ち着かせた初めの状態が出せない。案: (a) 落ち着かせた初めの状態を配るデータに焼き、ストリーミングはそれを読む(生成器はエディタとベイクの側)/
  (b) 落ち着かせをページ単位の決まった手順(端は生成のまま固定)にして、要る時に作れる形にする(ページの境目で少し食い違う)。どちらでもセーブの形(D-586)は同じ。
  R-G1 の試作で費用と食い違いを測って決める(チケット T-0880「仮」)。
- 追い出すのは静かなブロックだけ(粗いレベルにまとめてから)。変化があれば差分として書き出す(待たないリングで CPU へ)。
- 活性の量が VRAM を超えたら、主メモリに退避しながら分割して計算する(世界の時間がさらに遅くなる。D-202)。**正しさは落とさない。**

## テスト
- 生成器: CPU と GPU でブロックのハッシュがビット一致(どのレベルでも)。
- 高さと深さ: 静かな空気の柱で上ほど圧が下がり(重力 × 気体の法則)、刻みを進めても変わらない(釣り合い)・水の柱の底の圧が深さに比例・地の底の熱が伝導で上がり、帳簿の外への出入りと合う。
- 差分: 生成 → 変更 → 差分を保存 → 生成 → 差分を当てる、で元の状態とビット一致。
- 追い出しと読み込み・粗くして細かくするを繰り返しても、保存量が一致し、活性の所の結果が変わらない。
