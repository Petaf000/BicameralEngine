# 04 数値と決定性(L4 詳細設計)

対応する決定: D-205(機種が違っても完全に同じ結果)/ D-206(SI 単位と保存則)/ D-306(シミュで浮動小数点を禁止)/ D-307(CPU と GPU のビット一致)

## 目的
「同じ条件・同じ環境・同じ場所なら、どの機械でも同じ結果」をコードの規則で保証する。
論文にできる水準の再現性を、テストで毎回確かめられる形にする。

## 1. 規則(シミュのコードはすべてこれに従う)

| # | 規則 | 理由 |
|---|---|---|
| R1 | シミュのシェーダー(`shaders/sim/**`)とシミュの CPU コードで浮動小数点を使わない | GPU の浮動小数点はメーカー・ドライバ・コンパイラの最適化(FMA 化・非正規数の扱い・超越関数の近似)で結果が変わる |
| R2 | 保存量(質量・エネルギー・運動量・元素の数)は整数で持ち、**「受け渡し」でしか変えない**(A から引いた値をそのまま B に足す) | 丸めがあっても、合計は構造的に保存される |
| R3 | 処理の順番に結果が依存しない。Work Graphs のレコードの処理順は保証されない(仕様: "unordered / unpredictable") | 並列の実行順は毎回・機種ごとに違う |
| R4 | atomic は可換な整数演算(add・min・max・and・or)だけ。atomic のカウンタで ID や順番を決めない | カウンタの値は実行順で変わる |
| R5 | 新しく生まれる物の ID は「親の ID + 親の中の番号」から決める。まとめて詰めるときは、キーで並べてから(プレフィックス和)詰める | 同上 |
| R6 | 乱数はカウンタ型(ハッシュ)で、(世界のシード, 刻み, セル/物の ID, 用途)から作る。状態を持つ乱数生成器を使わない | 実行順に依存しない |
| R7 | ベイク(Luau → 表)も同じ整数の数学ライブラリで行う。CPU の浮動小数点(CRT の exp など)を使わない | Mod やホットリロードは利用者の機械でベイクされる |
| R8 | 桁あふれはバグ。飽和(上限で止める)はしない(保存則が壊れる)。デバッグビルドでは検出して GPU の assert に出す | 黙って結果が変わるのを防ぐ |

## 3. 整数の数学ライブラリ(`shaders/common/fixed.hlsli`。T-0010 で実装)
- **1 つのソースを HLSL と C++ の両方でコンパイルする**(共通部分だけで書き、型の違いはマクロで吸収)。CPU リファレンスとベイクと GPU が同じ式を使う。
  C++ では関数が constexpr になるので、コンパイル時にも使える。単位の定数は `shaders/common/units.hlsli`(§2 の表と同じ値)。
- 64bit 同士の掛け算は 128bit の中間値が要る(HLSL に int128 は無い)→ 32bit に分けて計算する `FxMulU64Full` / `FxMulS64Full`。
- 割り算: 64bit は整数の `/`(DXIL の整数除算は厳密)。128bit ÷ 64bit は 1 ビットずつ引く `FxDivU128By64`。丸めは 0 方向の切り捨てで統一(Q 形式の積 `FxMulShiftS64` も)。
- 逆数の掛け算: `FxMakeRecipU64` / `FxMakeRecipU32` / `FxMakeRecipS64` で除数から逆数(乗数とシフト)を作り、`FxDivRecip*` で割る。
  Granlund & Montgomery(1994)の方法で、どの被除数でもふつうの割り算とビット単位で同じ商(近似ではない)。費用は §6。
- 平方根: 整数の桁ごとの方法(ビット単位で決定的)`FxSqrtU64` / `FxSqrtU32`。
- log2・exp2: ビットごとに決める方法(log2 は仮数の 2 乗の繰り返し、exp2 は 2^(2^-k) の定数表。表はソースに書いた定数)。ln・exp は定数を掛けて作る。
  実測(2026-09-30): log2 の誤差 ≤ 1 × 2^-32、ln ≤ 1.7 × 2^-32、exp2 の相対誤差 ≤ 2.2e-16、exp ≤ 1.6e-10(入力の Q32 への切り捨てが効く)。
- 三角関数: CORDIC `FxSinCosTurn32`(角度は 1 周 = 2^32、30 回)。実測の誤差 ≤ 17.6 × 2^-30。
- 乱数: `FxHash64(seed, tick, id, purpose)`(SplitMix64 の混ぜ合わせを 4 回)。雪崩(平均 32.0 ビット)とカイ 2 乗で確認。
- 自己テスト `shaders/common/fixed_selftest.hlsli`: 全部の関数を番号から作った入力で呼ぶ。CPU(tests/fixed_test.cpp)と GPU(shaders/sim/fixed_selftest.hlsl、T-0013)が同じ列を計算し、要約のハッシュで比べる。

## 4. 浮動小数点の禁止を機械的に守る(T-0011 で実装)
- シェーダーをシミュ用(`shaders/sim/`)と描画用(`shaders/render/`)に分ける。描画は浮動小数点を使ってよい(D-205 の範囲外)。
  `shaders/common/` はシミュから読む共通のヘッダ(C++ からも読む)なので、浮動小数点は禁止。描画だけの共通部品は `shaders/render/` に置く。
  シェーダーは `shaders/CMakeLists.txt` の `bicameral_add_shader(<sim|render>/x.hlsl PROFILE cs_6_8 [ENTRY Main])` で足す。
- **DXIL の検査**(`tools/float_check/dxil_float_check.py`): シミュのシェーダーはコンパイルの直後に逆アセンブル(`dxc -Fc`)を調べ、
  浮動小数点の型(half・float・double。`<N x float>`・`dx.op.*.f32` も)と命令(fadd・fmul・fdiv・fcmp・sitofp・fptosi など)があれば
  **ビルドを落とし、.cso を消す**。ソースに型を書かない抜け道(`asfloat` → bitcast、整数を渡した `sqrt` → uitofp)も捕まる。
- **ソースの検査**(`tools/float_check/source_float_check.py`): `shaders/common/`・`shaders/sim/`・`engine/src/sim/`(CPU リファレンス・ベイク)の
  浮動小数点の型・小数のリテラル(`0.5`・`1e3`・`0x1.8p3`)・浮動小数点になる関数(`<cmath>` の関数・`asfloat` など)・`<cmath>` の include で
  ビルドを落とす。コメントと文字列の中は見ない。
  - 最初は「clang-tidy のカスタム検査」の予定だったが、カスタム検査はプラグインのビルドが要り、HLSL も読めない。
    共通のヘッダを HLSL と C++ の両方の目で同じ規則で見るため、トークンの検査にした(2026-09-30)。
- 検査が何も捕まえなくなっていないかは ctest の `float_check_*`(tests/float_check/ のわざと違反する入力)で確かめる。

## 5. 決定性の確かめ方
- **状態のハッシュ**: 毎刻み(デバッグ)または N 刻みごと(リリース)に、世界の状態全体の 64bit ハッシュを取る(順番に依存しない合成: 各ブロックのハッシュを XOR ではなく「ブロック ID で並べた順の合成」)。
- **CPU と GPU のビット一致**: 小さい世界で両方を走らせ、全状態のハッシュが一致すること(テストの合格条件)。
- **2 回走らせて一致**: 同じ入力の再生で、刻みごとのハッシュ列が一致する。
- **機種間の一致**: 同じ再生ファイルを NVIDIA と AMD(D-207)で走らせ、ハッシュ列を比べる。ずれた最初の刻みとブロックを報告する道具を作る。
- **保存則**: 毎刻み(デバッグ)、全体の質量(元素ごと)・エネルギーの合計が「明示的な出入り(魔法・境界)」を除いて完全に一致する。

## 6. 整数の演算の費用(T-0010 で計測)
GPU は浮動小数点が得意に作られている。シミュを整数で書くと、どこが高くつくかを測って、書き方を決める。
AMD での実測は D-207 で機械を用意した時に追記する。

**使い道**: (1) 割り算を逆数の掛け算(掛け算とシフト)に置き換える所を決める。(2) int64 を使う範囲を決める(32bit で足りる所は 32bit に)。

### 測り方
- `tests/gpu_fixed_bench.cpp`(`job.py run -Preset release -Exe gpu_fixed_bench`)。`shaders/bench/fixed_bench.hlsl` を演算ごとにコンパイルした .cso を順に走らせる。
  約 100 万スレッドが「x = 演算(x) → 混ぜる(xor とシフト)」を前の結果に依存させて繰り返し、1 回の時間をタイムスタンプで測る(40ms 前後に合わせ、5 回の中央値)。
- **費用** = 1 回の時間(GPU 全体の処理量の逆数)から「混ぜるだけ」(base32 / base64)を引いたもの。**fmul の何回分**で比べる(float の掛け算 = 1)。
- 割り算は、除数が毎回変わるようにした(ループの外で逆数を作られないように)。浮動小数点は -Gis(IEEE に厳密)でまとめ直しを防ぐ。
- DXIL の命令数は `tools/fixed_bench/dxil_count.py`(逆アセンブルから数える)。動的な数は、内側のループを回数だけ数えた見積もり。
  DXIL の 64bit の命令は 1 つと数える(GPU では 32bit の命令が複数になる)ので、int64 の費用は実測の方を見る。
- GPU のクロックは固定していない(ブーストのまま)。同じ条件の 2 回の実行で差は数 % 以内。

### 結果から言えること(書き方の方針の案。決めるのはユーザー)
1. **割り算**: 除数が決まっている所(ベイクの定数・ブロックごとに共有する値)は逆数の掛け算にする(int64 で約 1/3.4、32bit で約 1/2.4)。
   逆数を GPU で作るのは今は割り算の約 13 回分(128÷64 が遅いため)なので、GPU で作るなら同じ除数を十数回以上使う所だけ。ベイクで作れば費用は 0。
2. **Q 形式の割り算(`FxDivShiftS64`)と 128÷64 は、セルごとの毎刻みの計算で使わない**(fmul の約 1900 回分)。
   使う所が出たら、128÷64 を速い方法(32bit ずつの 2 回の 64bit 割り算で商を見積もって直す Knuth の方法など)に替える研究をする(BACKLOG)。
3. **int64** は足し算・掛け算で float の 3〜4 倍。位置(int64)と状態量(int32)を分ける D-306 の方針で足りる。32bit で足りる量は 32bit に。
4. **exp・log は 1 回で fmul の 550〜1200 回分**。反応の速さは温度ごとの表にベイクする(02 §1)方針を守り、セルごとの反応の評価で exp を呼ばない。
   呼ぶ必要が出たら、04「研究」の代案(表 + 多項式)を試す。
5. 格子のシミュは多くの場合、演算よりメモリの帯域で詰まる。どちらで詰まるかは T-0016 で Nsight で 1 回記録する(変わらず)。

## 研究(時間の打ち切りなし。D-411)
成功の基準と、うまくいかない時に試す代案の順を書く。諦めるのは原理的に無理と分かった時だけ(ユーザーと判断)。
- exp・log の精度と速さ: 相対誤差 1e-4 以内・シミュ全体の時間の 5% 以内。精度は T-0010 で満たした(§3)。1 回の費用は fmul の 550〜1200 回分(§6)。
  シミュ全体の 5% 以内かは、反応の評価(T-0014・T-0022)ができてから測る。
  遅ければ代案の順: 表(ベイク時に整数で作る)+ 多項式 → 区間を分ける → 精度の要らない所に粗い版を足す。
- 物理の整数化は 08-bodies-physics.md の研究(R-PHYS)。

## 未確認
- 64bit 整数演算(Int64ShaderOps)と 64bit atomic のうち typed・groupshared・ヒープの記述子経由は、機能として任意。
  開発機(RTX 3070 Ti)と WARP は全部 yes(`--caps`、2026-09-30、docs/perf.md)。最低機の条件は ADR-0009(D-211): Int64ShaderOps と raw バッファの 64bit atomic を必須、他の 64bit atomic は使わない。
  raw / structured バッファへの 64bit atomic は SM 6.6 以上で必須(gpu_work_graph_test で動作を確認)。
- DXC の最適化で整数演算の結果が変わることはない(整数演算は厳密)はずだが、ビット一致テストで確かめ続ける。
  → T-0013 で確かめた: fixed の自己テスト(65536 case)が RTX 3070 Ti と WARP の両方で、debug(-Od)と release の
  どちらでも CPU とビット一致(18 値で要約 85c154e666febd92。逆数の掛け算を足した 21 値で 605bc2e41947d188)。`ctest -R gpu_fixed` で毎回確かめる。DXC は vcpkg の 1.9.2602.24(ADR-0004)。
- AMD(D-207)での一致は未確認。
