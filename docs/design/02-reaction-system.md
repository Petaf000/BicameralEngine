# 02 反応システム(Chemical Circuit)(L4 詳細設計)

対応する決定: D-205(決定性)/ D-206(SI 単位と保存則、魔法は明示的な出入り)/ D-301(場と物が同じ表で反応)/ D-313・D-318(Luau で書いてベイク)/ D-320(Mod)

**役割分担**: 物質・元素・反応の中身(何が何と反応するか・例外・魔法の体系・発見の導線)は**ユーザーが決める**(T-0002)。
ここで決めるのは、その中身を正確に・決定的に・速く走らせる仕組み。

## 1. データモデル
### 元素(element)
- 保存される最小単位。**現実の元素すべて + 魔素**(人間が生身でも操作できる安定した元素。D-418)。ほかの元素も Luau で足せる。
- ID は uint16。**上限なし**(足りなくなれば型を広げる。D-401)。

### 物質(species)
- ID は uint32。**上限なし**。1 セルの成分は可変長(05 §3)。物質も反応則も Luau で増やせる(D-418)。
- 持つ値(すべて整数、単位は 04):
  - 組成: 元素ごとの数(物質 1 mol あたり)と、モル質量
  - 相: 固体・液体・気体(・プラズマ・その他は Luau で定義できる種類)
  - 熱: 相ごとの比熱、相変化の温度と潜熱、熱伝導率
  - 生成エンタルピー(化学エネルギーの基準)
  - 力学: 密度、硬さ・強さ(壊れるかどうか。D-108)、粘性(液体)
  - 見た目・音への対応(描画と音が読む。シミュは使わない)

### 反応規則(rule)
```
反応物 (物質, 係数)… → 生成物 (物質, 係数)…
速度: 速度式(Arrhenius: A·exp(-Ea/RT)、濃度の次数)を温度ごとの表にベイクしたもの
条件: 温度の範囲・触媒(ある物質がセルにあること)・場の条件(魔素の濃さ など)
熱: 反応エンタルピー(生成エンタルピーの差から自動で決まる)
出力: 音・光・物の発生(破片・炭の塊)のイベント
```
- 相変化(蒸発・凝固・融解)も反応規則として同じ仕組みで書く(潜熱つき)。

## 2. ベイク時の検査(保存則を守らせる)
ベイク(Luau → 表)は整数で行い(04 R7)、次を検査して通らなければエラー:
1. **元素の釣り合い**: 反応物と生成物で、元素ごとの数が完全に一致する。
2. **エネルギーの釣り合い**: 反応熱は生成エンタルピーの差と完全に一致する(自動で決めるので、手で書いた値との食い違いは警告)。
3. **魔法も原則は保存則の中**(D-419): 魔素は元素なので、魔法の熱・力・物質は魔素の消費として釣り合う。
   保存則の例外(中身として置く「保存則を破る何か」)は `source`(湧き出し)/ `sink`(吸い込み)として明示したものだけ許す。出入りした量は毎刻み集計され、保存則の検査はこれを差し引いて行う。
4. 速度の表が整数の範囲に収まる(桁あふれしない)。

### 2.1 実装(T-0021。`engine/src/script/reaction_package.cpp`・`engine/src/sim/reaction_table.cpp`・ADR-0032)
- 流れ: パッケージ(13 §2.2)→ 分類 `elements`・`species`・`reactions` を `ReadReactionTableDefinition` が定義に読む → `BakeReactionTable`。
  C++ に手で書いた定義(`MakeCombustionTestTable`)も同じベイクを通る。
- **読むときに落とすもの(形)**: 知らない欄・表でない値・整数でない数(小数・±2^53 の外)・範囲の外(係数 0 など)・A の書き方。
  値は整数だけで、単位は欄の名前に書く(倍精度の丸めで機械ごとに値が変わる余地を作らない)。A は 10 進の文字列("2.8e19")でも書ける。
- **ベイクが落とすもの(中身)**: 元素の釣り合い(1)・知らない元素と物質・反応物と生成物の数(1〜3)・次数 1 の反応物の数(1〜2)・名前の重なり・速度の範囲(4)。
- **エネルギー(2)**: 反応熱は生成エンタルピーの差から自動で決まるので、構造的に保存される。文献の反応熱を書いた規則(`reaction_enthalpy_j_per_mol`)は、
  生成エンタルピーの差(298.15 K)と 1 kJ/mol より違えば警告(`BakedReactionTable::warnings`)。表は生成エンタルピーの差を使う。
- **並びに依らない**: 元素・物質・規則・規則の項を名前のバイト順に並べてから ID を振る。A の仮数の末尾の 0 は指数へ移す。
  同じ中身なら、C++ の配列の順・Luau の表の順・Mod を入れた順に依らず同じバイト列の表になる。
- 試験の表(公開用。現実の元素と化学だけ): `data/packages/combustion_test`。ベイクすると C++ の試験の表とビットで同じ(`reaction_package_test`)。
- **ランタイムが読む表(T-0157・ADR-0033)**: ゲーム本体・エディタは C++ の表ではなく、exe の横の `data/packages`(ビルドがリポジトリの `data/` を写す。
  `--packages <dir>` で変えられる)のパッケージを起動時にベイクして GPU へ上げる(`script::LoadReactionTable`)。ゲーム本体のパッケージは今は `combustion_test`。
  フォルダが無い・ゲーム本体が読めない・形の誤り・ベイクの検査で落ちる → 窓を開く前に起動を止める(半端な表で世界を動かさない)。
  Luau として読めない Mod だけは除いて続け、ログに警告を出す(ADR-0031 の 3)。文献の反応熱の食い違いもログの警告。
  C++ の試験の表はテストの比較用に残す(`reaction_package_scene` が今の場面を両方で進めて毎刻みビットで同じことを確かめる)。
- 残り: 魔素とその反応(ユーザーの中身待ち)・湧き出しと吸い込み(3。T-0024)。

## 3. 1 セルでの評価(06 の段 4)
1. セルにある物質から、候補の規則を引く(物質 → その物質が反応物になる規則の一覧、の索引をベイクで作る)。反応物が全部そろった規則だけ評価する。
2. 各規則の「この刻みで進みたい量」(反応の進行度)を、速度の表(温度で引く)と濃度から整数で計算する。
3. **取り合いの解決(順番に依存しない)**: 同じ物質を複数の規則が使う場合、物質ごとに「要求の合計」と「ある量」を比べ、足りなければ全規則の進行度を同じ比率で縮める(端数は決定的な乱数で丸める。T-0106・D-431)。規則の並び順は結果に影響しない。
4. 進行度に応じて、成分の物質量を更新する(セルの中で閉じる。隣のセルには書かない)。エネルギーの合計は変えない(化学のエネルギーが熱に変わるだけ)。
5. 出力のイベントをレコードとして出す(06 の段 9 で並べてから使う)。
- 隣のセルへの影響(熱が伝わる・煙が流れる)は、次の刻みの輸送(07)で起きる。

### 3.1 実装(T-0014。`shaders/common/reaction.hlsli`・`engine/src/sim/reaction_table.cpp`)
- **量と熱**: 成分は物質量(uint64、1 = 1 µmol。ADR-0012)。セルのエネルギー(int64、mJ)= 熱 + 化学。化学 = Σ 物質量 × H0(µJ)、
  H0 = 生成エンタルピー − 比熱 × 298.15 K(0 K 基準、J/mol。ベイクで作る)。熱(µJ)= エネルギー × 1000 − 化学、
  温度(mK)= 熱 × 1e6 ÷ Σ 物質量 × 比熱(128bit で)。反応はエネルギーを変えないので、**エネルギーは構造的に保存**され、
  係数 × 進行度で増減するので**元素の数も完全に保存**される(36,000 刻みで確認)。
- **索引**: 規則は「反応物のうち物質 ID が最小のもの」の一覧にだけ入れる。成分を順に見れば、どの規則も 1 回だけ引ける。
- **速度**: 反応物ごとに次数 0 か 1(次数 1 は 1〜2 個)。進行度 = k(T) × 次数 1 の反応物の物質量の積。
  k(T) はベイクで ln k = ln A − Ea/RT − ln 60 + (n−1)(ln 1e-6 − ln V) を整数の ln・exp で計算し、0〜4095 K の 1 K ごとの表に
  「仮数 32bit × 2^指数」で置く(double との相対誤差 1.3e-9)。4095 K より熱いと 4095 K の値。
- **遅すぎる反応は 0**(T-0089・ユーザー 2026-10-01。**D-429 で置き換えた**〔T-0122 で世界のどこも使わなくなり、T-0130 でコードを消した〕。以下は置き換える前の規則): 1 刻みの進みの期待値が 2^-16 µmol 未満(端数だけ)なら、その規則は進まない
  (`RX_EXTENT_CUTOFF_FRACTION`)。`RxStepCell` は「進める規則があったか」(possible)も返す。possible が 0 で何も変わらなかったセルは、
  刻み(乱数)が変わっても変わらないので、眠らせても全部を計算した場合とビット一致する(06 §2 の活性)。室温の木と空気は進めない。
- **端数**(今までの丸め。D-429 の待ちの丸めで置き換え、T-0130 で消した。以下は置き換える前の規則): 進行度の 1 µmol 未満の端数(32bit)は、カウンタ型の乱数(世界のシード・刻み・セル・規則の名前の鍵。R6)と比べて丸める。
  1 刻み 0.007 µmol の遅い反応も期待どおりの速さで進む(36,000 刻みで期待 243 / 実際 271、±5σ の中)。鍵を規則の ID ではなく名前から作るので、表の並びを変えても結果は同じ。
- **待ちの丸め**(T-0105・D-429・ADR-0018。多重解像度の CPU は T-0115、GPU は T-0121・T-0124・T-0125、仮の世界と覗き窓は T-0122 で切り替え済み。今の世界の規則): 下限を外し、遅い規則も起きるようにする。
  進行度 = 整数部 + [刻み ≥ tc + n](tc = ブロックが最後に変わった刻み、n = 幾何分布の待ち。乱数は (シード, tc, セル, 規則の鍵) だけで決まる)。
  変わらなかったセルは「次に評価の要る刻み」= min(tc + n) を返すので、ブロックをその刻みまで眠らせても全部を計算した場合とビット一致する。
  幾何分布は記憶が無いので、ブロックが変わるたびに引き直しても速さは偏らない。速さを変えるもの(魔法のパッチ)は tc を書いてから評価する。
  `RxStepCellWait`(C++ は `StepReactionCellWait`)。端数と刻みは 64bit。待ちが約 2^61 刻み(約 12 億年)を超える引きは起きない。
- **取り合い**: 望む進行度をまず反応物それぞれの「ある量 ÷ 係数」で抑え、物質ごとの要求の合計がある量を超えたら、
  各規則を min(元の進行度 × ある量 ÷ 要求)に縮める。**縮めた端数も確率的に丸める**(T-0106・D-431。規則ごとの乱数は望む進行度と同じハッシュの上位 32bit。
  丸めは単調なので、資源ごとに丸めた最小 = 比の最小を丸めた値)。丸め上げで足りなくなった資源があれば、その資源を使う丸め上げた規則のうち
  **進行度が最も大きいものから**丸め上げを戻す(`RxRevokeRoundUps`)。切り捨ての値はある量以下なので、縮めた後の消費は必ずある量以下。
  - 切り捨てだった頃(T-0106 の測定、`tests/reaction_contention_test.cpp`): 900 K・O2 50 µmol の木箱のセルで CO(炭の部分燃焼)が **0%**(1 刻み 0.11 が毎刻み 0)、
    炭の燃焼 86%、木の燃焼 74〜93%。O2 2000 µmol でも 900 K の CO は 88%。丸めにしてからは、消えていた規則は ±5σ の中(CO 100.3%)。
  - 残る偏り: 係数の大きい規則(木の燃焼は O2 × 6)は、丸め上げに要る量が残り(端数の合計)に入らない刻みがあり少し遅れる。
    資源がほぼ尽きた場面(O2 50 µmol)だけ数 %(木の燃焼 93%、戻す丸め上げを受ける大きい規則 96%)。残った資源は次の刻みに使われる。
    戻す順を「ランダム」にすると小さい脇の反応が 74% に落ちた(試算)ので、大きい規則に寄せている。
- **吸熱の上限**: 吸熱の規則は熱も資源として縮める。1 刻みに使える熱は**今の熱の 1/8 まで**(`RX_ENDOTHERMIC_HEAT_SHIFT`)。
  1 刻みに 1 回の評価(陽的)では、速い吸熱の反応が始めの温度の速さのまま進み、1 刻みで 0 K まで冷えた(T-0014 で確認)。
  1/8 に抑えると温度が下がるにつれて速さが指数的に落ち、自然に止まる(Boudouard: 2000 K → 10 刻みで 877 K → 600 刻みで 777 K)。R-REACT-1 で見直す。
- **成分の持ち方**: インラインに 8 個(物質 ID の昇順、0 になった物質は消す = 同じ中身なら同じ並び)。溢れは T-0017 / R-MULTI-4。
  - (T-0175)核(reaction.hlsli)はセルの形を Cell 型で受け取る: RxCell(インライン 8。GPU と今の多重解像度の世界)と
    RxWideCell(C++ だけ。成分の数に上限なし。engine/src/sim/reaction_wide_cell.h)。形ごとに違うのは「成分を増やせるか・場所を用意する・空のセル・使う量の入れ物」
    の 4 つの道具だけで、8 種以下の間はどちらもビット単位で同じ結果。RxWideCell では 9 種目の生成物を待たせない(RX_LIMIT_PRODUCTS が立たない)。
    多重解像度の世界(CPU)の溢れは T-0187、GPU の頁ごとの溢れ領域は T-0176。候補の上限 16 は残る(T-0164)。
  - (T-0187)多重解像度の世界(CPU)は `EnableWideCells` で「インライン 8(nest.cells・nest.fractions。GPU と同じ並び)+ 頁ごと・端数の枠ごとの溢れ」
    (MultiresOverflowArea: セルの番号の順に詰め、セル i の溢れは offsets[i]〜offsets[i+1]。GPU の頁ごとの溢れ領域〔グループ内のプレフィックス和〕と同じ並び)。
    読み書きは LoadWideNestCell・StoreWidePageCell(RxWideCell)と LoadWideFraction・StoreWideFraction(MrWideFraction)。
    反応・伝導の熱・細かくする・粗くする(和集合は MrCoarsenCellOf〔結果の形と子の形のテンプレート〕)・影を作る・要約・保存量が溢れを読む。
    9 種目の生成物を待たせず、8 種ずつ違う子を粗くするのも断らない。溢れのある頁・端数の枠は一様・畳む扱いにしない(保存を守る)。
    既定は使わない(GPU と比べるテストは今のまま)。溢れのある影の引き戻し・畳む・覗き窓は T-0199。
  - (T-0176・ADR-0052)GPU の多重解像度の世界も `GpuMultiresOptions::wideCells` で同じ「インライン 8 + 頁ごとの溢れ」(u6 の後ろ・頁ごとに 2 面を入れ替える。
    並びは shaders/common/multires_wide.hlsli)。全部を刻む Compute(伝導なし)は 8 種に収まるセルをインラインの核で刻み、溢れるセルだけ上限なしの形
    (RxGpuWideCell・24 種まで)で数える → プレフィックス和 → 刻み直す。CPU の EnableWideCells の世界と HW・WARP で毎刻みビット一致。
    当座の上限(頁の溢れ 1024 成分・1 セル 24 種)・伝導・要求の処理(粗くする和集合・細かくする・畳む)・覗き窓は T-0211、活性のグラフは T-0212。
- **GPU**: `shaders/sim/reaction_cells.hlsl`(1 スレッド = 1 セルの compute)で、4096 セル × 400 刻みが CPU とビット一致(HW・WARP)。
  各セルを 1 セルだけのブロックとして待ちの丸めで進める(`RxAdvanceLoneCell`。50 刻みの区間の初めに「直前の刻みに変わった」とみなす。T-0130)。
  表は Table 型(テンプレート)で渡す: C++ は span、HLSL はバッファを読む構造体。
- **仮の世界の段**(T-0089): `shaders/common/probe_world.hlsli` の `ProbeStepCell` が伝導(07 §1.1)→ その場で `RxStepCellWait`(T-0122 から待ちの丸め。ブロックごとの tc と起こす刻み)。
  Work Graphs の ConductBlock(1 ブロック = 4³ セル = 1 グループ)が呼ぶ(§6 の BlockNode の最小形)。反応はセルの中で閉じるので、
  段を分けた場合と結果は同じ。WARP はこのノードを含むグラフを作れない(ADR-0013)。
- イベント(音・光・物の発生)の出力はまだ無い(M2 以降)。

## 4. 物(Body)の部品での反応
- 部品は、成分(物質と質量)・エネルギーを持つ「大きなセル」として同じ評価をする。
- 部品の表面が触れているセル(空気の酸素など)との受け渡しは、結合の段(06 の段 7)で行う。
- 燃えて質量が減ると部品の強さが落ち、関節が外れる(倒れる木)。強さの式は物質の値から決まる(08)。

## 5. 魔法 = 反応則への介入と、魔素を使う物理的な行為
- **魔法の発動**(杖から炎を出すなど)は、魔素を消費する反応と、物質・エネルギー・運動量の放出として起きる。反動と熱は術者と杖に返る(08 §4、D-420)。
  閉じた空間で炎を出して酸素を減らす、のような掛け合わせは、反応(02)と輸送(07)の一般則から特別な処理なしに起きる。
- 魔法は「表へのパッチ」をコマンドとして出す(06 §3)。刻みの境界で適用され、再生ファイルに記録される。
- パッチの種類(中身の使い方はユーザーが決める):
  - 触媒: 規則の活性化エネルギーを下げる / 阻害: 規則を止める / 転換: 規則の生成物を差し替える / 増幅: 速度係数を上げる / 湧き出し・吸い込み
- パッチには範囲(ブロックの集合か、中心と半径)と期間(刻み数)がある。範囲内のセルは、評価の前に「そのセルに効いているパッチ」を表に重ねて使う。
- 速度の表を差し替えるパッチは、ベイクと同じ整数の計算で GPU 上で表を作り直す(CPU は関わらない)。

## 6. Work Graphs の形
```
[活性ブロックの一覧] → BlockNode(broadcasting: 1 ブロック = 1 グループ = 512 スレッド)
     → セルごとに評価(候補の規則は索引から)
     → 出力: EventNode(音・光)/ SpawnNode(物の発生)/ ActivateNode(隣のブロックを起こす)
```
- ノードごとのカウンタ・printf・上限の検出は 16(デバッグ)に従う。

## 7. Luau での書き方(T-0021 で決めた形。ADR-0032・`engine/src/script/reaction_package.h`)
パッケージの entry が「分類 → 鍵 → 値」の表を返す(13 §2.2)。1 つの鍵 = 1 つの元素・物質・規則で、Mod は鍵を足して増やす。
```lua
return {
  elements = { C = { atomic_mass_mg_per_mol = 12011 }, O = { atomic_mass_mg_per_mol = 15999 } },
  species = {
    oxygen = { composition = { O = 2 }, formation_enthalpy_j_per_mol = 0,
               heat_capacity_mj_per_mol_k = 29378, thermal_conductivity_mw_per_m_k = 135000 },
  },
  reactions = {
    carbon_combustion = {
```
