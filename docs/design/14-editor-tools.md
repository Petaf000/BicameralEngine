# 14 エディタとツール(L4 詳細設計)

対応する決定: ADR-0001(エディタは CPU を自由に使う)/ D-304(最終的に UE のような統合エディタ・ホットリロード・UI は ImGui から始めて最後に仕上げる)/ D-315(glTF)/ D-318

## 目的
広い世界・反応表・生き物・魔法具・進行を、**GPU で実際に動かしながら**作れる道具にする。

## 1. 形
- 同じ exe の編集モード(`--editor`)。ゲームのランタイムをそのまま中で動かし、周りに編集の UI を置く。
- 編集するのは CPU 側の「文書」(Luau のパッケージ・世界の差分・置いた物)。文書を変える → 必要な分だけベイク → コマンドで GPU に適用(ホットリロードと同じ道)。
- 元に戻す・やり直しは CPU の文書の上で行う。GPU の世界は、文書と「ここからの再生」で作り直せる(決定性があるので、途中の状態を保存しておけば速く戻れる)。

## 2. パネル(段階的に足す)
| パネル | 役割 | いつ要るか(L5 の段) |
|---|---|---|
| ビューポート | 世界を見る・飛ぶ・選ぶ | 最初から |
| 世界の状態の表示 | セルの成分・温度・活性・流れを色で見る(デバッグの表示の切り替え) | 最初から |
| 実験室 | 小さな箱の世界で反応を試す。CPU リファレンスと並べて比べる | 反応表を書き始める時 |
| 反応表 | 物質と規則の一覧・検索・ベイクの検査の結果 | 同上 |
| 時間の操作 | 止める・1 刻み進める・巻き戻す(保存点 + 再生)・速くする | 最初から |
| 地形 | 生成手順の調整・削る/盛る/素材を塗るブラシ(差分として保存) | 世界を作り始める時 |
| 配置 | 物・ダンジョン・生き物の巣を置く | 同上 |
| 生き物 | 行動の状態・欲求・知覚の表示、行動の表の編集 | 生き物を作る時 |
| Work Graphs と性能 | ノードごとの起動数・時間・上限の余裕(16) | 最初から |
| Luau コンソール | 式を評価・コマンドを送る | 最初から |
| 素材 | glTF の取り込み・見た目の確認 | 素材が来始める時 |

## 3. UI の仕上げ
- 最初は Dear ImGui の標準の見た目。仕上げの段(L5 の後半)で、テーマ・アイコン・レイアウトを整え、UE のような見た目にする(自作のウィジェットを足す)。

## 4. 素材の取り込み
- glTF 2.0 を正にする。FBX は Blender で glTF に変換して受け取る(外注との約束事として文書にする)。
- 取り込みで、メッシュ(描画用)・物理の形(球の集まり。08)・部品の分け方・骨格とクリップ(09 の整数の姿勢)を作る。

## 5. コマンドラインのツール(CI とランナーで使う)
- `bicameral --bake <package>` ベイクだけ
- `bicameral --replay <file> --frames N --hash-log <out>` 再生してハッシュを記録(決定性の検査・機種間の比較)
- `bicameral --frames N --screenshot` 画像比較
- `tools/dxil_float_check` シミュのシェーダーの浮動小数点の検査(04)
- `tools/archmap` 図(既存)

## テスト
- 文書 → ベイク → 適用 → 元に戻す、で世界の状態のハッシュが元に戻る。
