# 14 エディタとツール(L4 詳細設計)

対応する決定: ADR-0001(エディタは CPU を自由に使う)/ D-304(最終的に UE のような統合エディタ・ホットリロード・UI は ImGui から始めて最後に仕上げる)/ D-315(glTF)/ D-318

## 目的
広い世界・反応表・生き物・魔法具・進行を、**GPU で実際に動かしながら**作れる道具にする。

## 1. 形
- 同じ exe の編集モード(`--editor`)。ゲームのランタイムをそのまま中で動かし、周りに編集の UI を置く。
- 編集するのは CPU 側の「文書」(Luau のパッケージ・世界の差分・置いた物)。文書を変える → 必要な分だけベイク → コマンドで GPU に適用(ホットリロードと同じ道)。
- 元に戻す・やり直しは CPU の文書の上で行う。GPU の世界は、文書と「ここからの再生」で作り直せる(決定性があるので、途中の状態を保存しておけば速く戻れる)。

## 2. パネル(段階的に足す)
| パネル | 役割 | いつ要るか(L5 の段) |
|---|---|---|
| ビューポート | 世界を見る・飛ぶ・選ぶ | 最初から |
| 世界の状態の表示 | セルの成分・温度・活性・流れを色で見る(デバッグの表示の切り替え) | 最初から |
| 実験室 | 小さな箱の世界で反応を試す。CPU リファレンスと並べて比べる | 反応表を書き始める時 |
| 反応表 | 物質と規則の一覧・検索・ベイクの検査の結果 | 同上 |
| 時間の操作 | 止める・1 刻み進める・巻き戻す(保存点 + 再生)・速くする | 最初から |
| 地形 | 生成手順の調整・削る/盛る/素材を塗るブラシ(差分として保存) | 世界を作り始める時 |
| 配置 | 物・ダンジョン・生き物の巣を置く | 同上 |
| 生き物 | 行動の状態・欲求・知覚の表示、行動の表の編集 | 生き物を作る時 |
| Work Graphs と性能 | ノードごとの起動数・時間・上限の余裕(16) | 最初から |

### 実装(T-0015): ビューポートと世界の状態の表示の最初の形
M1 の仮の世界(64³ の熱)を立体のまま見る道具。エディタの UI(ImGui)は無く、窓の入力とキーだけで操作する。
- **抽出**(06 §4 の 3 組)は全部のセル + ブロックごとの活性の印(`PROBE_EXTRACTION_WORDS`。印 = 境界の前の刻みで伝導を計算した)。
  描画は抽出だけを読む。gpu_probe_sim が、最後の抽出のセルのハッシュと印の数を CPU リファレンスと突き合わせる。
- **描画**(shaders/render/probe_view.hlsl): 画面いっぱいの三角形 1 枚で、画素ごとにカメラの光線を作り、格子をセル単位で辿る(DDA)。
  表示は 吸収と発光(`1`)・光線の上の最大値(`2`)・断面(`3`)。色は熱の対数(`L` で線形。つつき 1 回 = 1)、左下に凡例の帯
  (対数なら目盛りは 2^0・2^8・2^16・2^24)。重ね書き: 格子の枠・断面の枠(黄)・活性なブロック(水色、`B`)。
  1280×720 で 0.06〜0.56 ms(docs/perf.md)。
- **カメラ**(engine/src/render/debug_camera): 格子の周りを回る。右ドラッグ = 回る・中ドラッグ = 平行移動・ホイール = 寄る・`O` = 透視/平行・`R` = 戻す。
  View の状態で、世界にもコマンドにも入らない(D-107)。描画と CPU は同じ式で光線を作る。
- **つつく**: 左クリックの光線が断面(`X`/`Y`/`Z` で軸、`Q`/`E` で位置、Shift で 8)に当たったセル。つつきは今までどおり整数のコマンド(再生で再現できる)。
- **自動の確認**: `--view <volume|mip|slice>`・`--camera <yaw>,<pitch>,<距離>`・`--screenshot <path>`(最後のフレームを BMP に)。
  絵の比較(10「テスト」)の入口。基準画像との比較の仕組みはまだ無い。
- まだ無いもの: カーソルの下のセルの数値・画面の文字(12 §5)・時間の操作(止める・1 刻み)・Work Graphs のパネル(T-0008)。

### 実装(T-0023): エディタの殻(ImGui・時間の操作・状態の表示)
`bicameral --editor` で、仮の世界の窓に Dear ImGui(vcpkg の imgui 1.92・Win32 と DX12 の backend)のパネルを重ねる。
- **重ね方**(engine/src/editor/editor_overlay): シーンの描画のリスト(作るときに 1 度だけ記録)の後ろに、毎フレーム記録するパネルのリストを
  direct キューへ投げる(PRESENT → 描く → PRESENT)。リストの枠は ImGui の頂点のバッファと同じ順に回す。SRV の記述子は 64 個の山から渡す
  (1.92 からフォントの画像が増える)。日本語は Windows の標準のフォント(メイリオ → 游ゴシック → MS ゴシック)。
- **入力**: 窓の WndProc の前に ImGui が見る(Window::SetMessageHook)。パネルの上で押した・回したものはカメラとつつきに渡さない
  (離す・動かすは渡す。パネルの外で始めたドラッグを終わらせるため)。文字を打っている間はキーも渡さない。
- **時間の操作**(engine/src/editor/time_control・ADR-0035): 止める(Space)・1 刻み(N。押しっぱなしで続く)・60 刻み・速さ ×1/8〜×8・等速。
  SimScheduler の「始めてよい刻み」だけを変え、世界のコマンドには入らない。始めた刻みは最後の単位まで進み、刻みの境界で止まる。
- **状態の表示**: 刻み(単位)・未処理・捨てた刻み・最後に読み戻した S(t) とエネルギーと計算したブロック・fps・世界の刻み/秒・CPU と GPU の時間・
  予算・表示の設定・再生中/記録中・GPU に渡す前のコマンド・操作の一覧。
- **自動の確認**: `--auto-time` が決まったフレームで止める → 止まったまま → 1 刻みを 3 回 → ちょうど 3 刻み → ×2 で動かす → ×1/2 → 等速、を入れて確かめる。
  ctest `window_replay_editor`(パネルを重ね、時間を操作しながら再生してハッシュ列が一致)・`time_control`(CPU)。
- まだ無いもの: 反応表のパネル。実験室は T-0142(下)、巻き戻しと性能のパネルは T-0143(下)。

### 実装(T-0143): 巻き戻し(保存点 + 再生)と Work Graphs の性能のパネル
- **保存点**(engine/src/sim/probe_save_point.cpp・ADR-0036): 刻み t の境界の状態(セルと熱のキャッシュは S(t) の世代だけ・予定の印・活性の一覧・
  ハッシュの表・刻みのイベントの置き場・物理の u0〜u13)を VRAM の写しへ GPU → GPU でコピーする。フレームのリストの先頭でだけ写す・戻す。
  仮の世界 + 積み木で 1 つ 33.2 MiB。`--save-points n`(--editor の既定 6)・`--save-interval t`(既定 120 刻み)。SimScheduler がその倍数の境界でフレームを切る。
- **戻す**: GPU を待ち、読み戻しを全部読んでから、世界を保存点へ戻し、コマンドキューを空にして、刻み t 以降のコマンドを足し直す
  (再生ファイルなら ReplayPlayer::Rewind、窓の操作なら今の流れで足したコマンドの控え)。戻した刻みより先の保存点は捨てる。
  「時間」のパネルに保存点の一覧と「1 つ前の保存点へ」。止めたまま戻すと、戻した状態を抽出だけのリストで見せる。
  記録中・--check-physics・トレース中は戻さない。
- **性能のパネル**(engine/src/editor/graph_panel): 直近 1 秒の、刻みの中の単位ごとの GPU 時間(ms/刻み。どれが Work Graph か)、伝導のグラフのノードごとの
  起動・入力・出力/刻み、1 回の出力の最大 / 上限、再帰の深さ / 上限、計器(一覧・キュー)の最大 / 容量、上限の警告(T-0008 の判定)。
  Work Graphs はノードごとの時間を測れない(タイムスタンプは DispatchGraph の前後だけ)ので、時間は単位ごと。
- **確かめ方**: gpu_probe_rewind(写しながら進み、戻して足し直すと最初から流した時とハッシュ列が一致。足し直さないと違う)・
  window_replay_rewind(再生中に戻しても記録のハッシュ列と一致)・sim_scheduler_test(保存点の境界と Rewind)。

### 実装(T-0142): 実験室(小さな箱で反応を試し、GPU と CPU リファレンスを比べる)
- **箱**(engine/src/sim/lab_box・ADR-0037): 多重解像度の木の本物の根 1 つ(8³ セル、0.5 m 角 = 4 m 角。初めは 300 K の空気。外とは熱も物も通さない)。
  刻みは木の刻みそのもの(反応は待ちの丸め + 熱の伝導。`RecordStep` / `StepNest`)。仮の世界(ProbeSim)とは別の世界で、
  自分の compute キューで 1 刻みずつ待って進める。根はいつも頁を持つ。
- **置く操作はコマンド**(common/lab_box.hlsli): `LAB_COMMAND_TYPE_FILL`(セルを物質 3 つまでと温度で置き換える)・`LAB_COMMAND_TYPE_TEMPERATURE`
  (温度を決める)。GPU は刻みの前に shaders/sim/lab_box.hlsl が 1 スレッドで列の順に当て、CPU リファレンスは ApplyLabCommands が同じ関数で当てる。
  当てたブロックは「つつかれた」にする。
- **比べる**(sim/lab_session): 刻みごとに GPU の箱を読み戻し、CPU の箱と状態の全部を比べる。違えば最初に違ったセル(セルが同じなら違う欄)を出して止まる。
- **記録と再生**: コマンドの列 + 刻みごとのハッシュ(`BLAB`)。読み込んで初めの箱から流し直し、ハッシュの列が記録と違えば最初の刻みを出す。
- **パネル**(engine/src/editor/lab_panel)「実験室」: 箱を作る(押した時に GPU の箱を作る)・セル / 材料(空気・木・木炭・二酸化炭素・窒素)/ 温度を選んで
  置く・温度だけ・1 / 10 / 60 刻み・流し続ける・最初に戻す・断面 z の温度(押すとセルを選ぶ)・選んだセルの温度と成分を CPU と GPU で並べる・記録の保存と再生。
- **確かめ方**: lab_box(CPU)・gpu_lab_box(木を置いて火を付け 200 刻み毎刻みビット一致・記録から再生して同じ)・window_lab(`--editor --auto-lab`)。
- まだ無いもの: パッケージの反応表を読む(T-0172)・大きな箱 / 細かくした箱(T-0173)・反応表のパネル。

## 3. UI の仕上げ
- 最初は Dear ImGui の標準の見た目。仕上げの段(L5 の後半)で、テーマ・アイコン・レイアウトを整え、UE のような見た目にする(自作のウィジェットを足す)。

## 4. 素材の取り込み
- glTF 2.0 を正にする。FBX は Blender で glTF に変換して受け取る(外注との約束事として文書にする)。
- 取り込みで、メッシュ(描画用)・物理の形(球の集まり。08)・部品の分け方・骨格とクリップ(09 の整数の姿勢)を作る。

## 5. コマンドラインのツール(CI とランナーで使う)
- `bicameral --bake <package>` ベイクだけ
- `bicameral --replay <file> --frames N --hash-log <out>` 再生してハッシュを記録(決定性の検査・機種間の比較)
- `bicameral --frames N --screenshot` 画像比較
- `tools/dxil_float_check` シミュのシェーダーの浮動小数点の検査(04)
- `tools/archmap` 図(既存)

## テスト
- 文書 → ベイク → 適用 → 元に戻す、で世界の状態のハッシュが元に戻る。
