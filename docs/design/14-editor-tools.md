# 14 エディタとツール(L4 詳細設計)

対応する決定: ADR-0001(エディタは CPU を自由に使う)/ D-304(最終的に UE のような統合エディタ・ホットリロード・UI は ImGui から始めて最後に仕上げる)/ D-315(glTF)/ D-318

## 目的
広い世界・反応表・生き物・魔法具・進行を、**GPU で実際に動かしながら**作れる道具にする。

## 1. 形
- 同じ exe の編集モード(`--editor`)。ゲームのランタイムをそのまま中で動かし、周りに編集の UI を置く。
- 編集するのは CPU 側の「文書」(Luau のパッケージ・世界の差分・置いた物)。文書を変える → 必要な分だけベイク → コマンドで GPU に適用(ホットリロードと同じ道)。
- 元に戻す・やり直しは CPU の文書の上で行う。GPU の世界は、文書と「ここからの再生」で作り直せる(決定性があるので、途中の状態を保存しておけば速く戻れる)。

## 2. パネル(段階的に足す)
| パネル | 役割 | いつ要るか(L5 の段) |
|---|---|---|
| ビューポート | 世界を見る・飛ぶ・選ぶ | 最初から |
| 世界の状態の表示 | セルの成分・温度・活性・流れを色で見る(デバッグの表示の切り替え) | 最初から |
| 実験室 | 小さな箱の世界で反応を試す。CPU リファレンスと並べて比べる | 反応表を書き始める時 |
| 反応表 | 物質と規則の一覧・検索・ベイクの検査の結果 | 同上 |
| 時間の操作 | 止める・1 刻み進める・巻き戻す(保存点 + 再生)・速くする | 最初から |
| 地形 | 生成手順の調整・削る/盛る/素材を塗るブラシ(差分として保存) | 世界を作り始める時 |
| 配置 | 物・ダンジョン・生き物の巣を置く | 同上 |
| 生き物 | 行動の状態・欲求・知覚の表示、行動の表の編集 | 生き物を作る時 |
| Work Graphs と性能 | ノードごとの起動数・時間・上限の余裕(16) | 最初から |

### 実装(T-0015): ビューポートと世界の状態の表示の最初の形
M1 の仮の世界(64³ の熱)を立体のまま見る道具。エディタの UI(ImGui)は無く、窓の入力とキーだけで操作する。
- **抽出**(06 §4 の 3 組)は全部のセル + ブロックごとの活性の印(`PROBE_EXTRACTION_WORDS`。印 = 境界の前の刻みで伝導を計算した)。
  描画は抽出だけを読む。gpu_probe_sim が、最後の抽出のセルのハッシュと印の数を CPU リファレンスと突き合わせる。
- **描画**(shaders/render/probe_view.hlsl): 画面いっぱいの三角形 1 枚で、画素ごとにカメラの光線を作り、格子をセル単位で辿る(DDA)。
  表示は 吸収と発光(`1`)・光線の上の最大値(`2`)・断面(`3`)。色は熱の対数(`L` で線形。つつき 1 回 = 1)、左下に凡例の帯
  (対数なら目盛りは 2^0・2^8・2^16・2^24)。重ね書き: 格子の枠・断面の枠(黄)・活性なブロック(水色、`B`)。
  1280×720 で 0.06〜0.56 ms(docs/perf.md)。
- **カメラ**(engine/src/render/debug_camera): 格子の周りを回る。右ドラッグ = 回る・中ドラッグ = 平行移動・ホイール = 寄る・`O` = 透視/平行・`R` = 戻す。
  View の状態で、世界にもコマンドにも入らない(D-107)。描画と CPU は同じ式で光線を作る。
- **つつく**: 左クリックの光線が断面(`X`/`Y`/`Z` で軸、`Q`/`E` で位置、Shift で 8)に当たったセル。つつきは今までどおり整数のコマンド(再生で再現できる)。
- **自動の確認**: `--view <volume|mip|slice>`・`--camera <yaw>,<pitch>,<距離>`・`--screenshot <path>`(最後のフレームを BMP に)。
  絵の比較(10「テスト」)の入口。基準画像との比較の仕組みはまだ無い。
- まだ無いもの: カーソルの下のセルの数値・画面の文字(12 §5)・時間の操作(止める・1 刻み)・Work Graphs のパネル(T-0008)。

### 実装(T-0023): エディタの殻(ImGui・時間の操作・状態の表示)
`bicameral --editor` で、仮の世界の窓に Dear ImGui(vcpkg の imgui 1.92・Win32 と DX12 の backend)のパネルを重ねる。
- **重ね方**(engine/src/editor/editor_overlay): シーンの描画のリスト(作るときに 1 度だけ記録)の後ろに、毎フレーム記録するパネルのリストを
  direct キューへ投げる(PRESENT → 描く → PRESENT)。リストの枠は ImGui の頂点のバッファと同じ順に回す。SRV の記述子は 64 個の山から渡す
  (1.92 からフォントの画像が増える)。日本語は Windows の標準のフォント(メイリオ → 游ゴシック → MS ゴシック)。
- **入力**: 窓の WndProc の前に ImGui が見る(Window::SetMessageHook)。パネルの上で押した・回したものはカメラとつつきに渡さない
  (離す・動かすは渡す。パネルの外で始めたドラッグを終わらせるため)。文字を打っている間はキーも渡さない。
- **時間の操作**(engine/src/editor/time_control・ADR-0035): 止める(Space)・1 刻み(N。押しっぱなしで続く)・60 刻み・速さ ×1/8〜×8・等速。
  SimScheduler の「始めてよい刻み」だけを変え、世界のコマンドには入らない。始めた刻みは最後の単位まで進み、刻みの境界で止まる。
- **状態の表示**: 刻み(単位)・未処理・捨てた刻み・最後に読み戻した S(t) とエネルギーと計算したブロック・fps・世界の刻み/秒・CPU と GPU の時間・
  予算・表示の設定・再生中/記録中・GPU に渡す前のコマンド・操作の一覧。
- **自動の確認**: `--auto-time` が決まったフレームで止める → 止まったまま → 1 刻みを 3 回 → ちょうど 3 刻み → ×2 で動かす → ×1/2 → 等速、を入れて確かめる。
  ctest `window_replay_editor`(パネルを重ね、時間を操作しながら再生してハッシュ列が一致)・`time_control`(CPU)。
- まだ無いもの: 反応表のパネル。実験室は T-0142(下)、巻き戻しと性能のパネルは T-0143(下)。

### 実装(T-0143): 巻き戻し(保存点 + 再生)と Work Graphs の性能のパネル
- **保存点**(engine/src/sim/probe_save_point.cpp・ADR-0036): 刻み t の境界の状態(セルと熱のキャッシュは S(t) の世代だけ・予定の印・活性の一覧・
  ハッシュの表・刻みのイベントの置き場・物理の u0〜u13)を VRAM の写しへ GPU → GPU でコピーする。フレームのリストの先頭でだけ写す・戻す。
  仮の世界 + 積み木で 1 つ 33.2 MiB。`--save-points n`(--editor の既定 6)・`--save-interval t`(既定 120 刻み)。SimScheduler がその倍数の境界でフレームを切る。
  n が 1 以上なら、刻み 0 の保存点を別に 1 つ足して捨てない(T-0411。下の「実装(T-0411)」)。
- **戻す**: GPU を待ち、読み戻しを全部読んでから、世界を保存点へ戻し、コマンドキューを空にして、刻み t 以降のコマンドを足し直す
  (再生ファイルなら ReplayPlayer::Rewind、窓の操作なら今の流れで足したコマンドの控え)。戻した刻みより先の保存点は捨てる。
  「時間」のパネルに保存点の一覧と「1 つ前の保存点へ」。止めたまま戻すと、戻した状態を抽出だけのリストで見せる。
  記録中・--check-physics・トレース中は戻さない。
- **性能のパネル**(engine/src/editor/graph_panel): 直近 1 秒の、刻みの中の単位ごとの GPU 時間(ms/刻み。どれが Work Graph か)、伝導のグラフのノードごとの
  起動・入力・出力/刻み、1 回の出力の最大 / 上限、再帰の深さ / 上限、計器(一覧・キュー)の最大 / 容量、上限の警告(T-0008 の判定)。
  Work Graphs はノードごとの時間を測れない(タイムスタンプは DispatchGraph の前後だけ)ので、時間は単位ごと。
- **確かめ方**: gpu_probe_rewind(写しながら進み、戻して足し直すと最初から流した時とハッシュ列が一致。足し直さないと違う)・
  window_replay_rewind(再生中に戻しても記録のハッシュ列と一致)・sim_scheduler_test(保存点の境界と Rewind)。

### 実装(T-0142): 実験室(小さな箱で反応を試し、GPU と CPU リファレンスを比べる)
- **箱**(engine/src/sim/lab_box・ADR-0037): 多重解像度の木の本物の根 1 つ(8³ セル、0.5 m 角 = 4 m 角。初めは 300 K の空気。外とは熱も物も通さない)。
  刻みは木の刻みそのもの(反応は待ちの丸め + 熱の伝導。`RecordStep` / `StepNest`)。仮の世界(ProbeSim)とは別の世界で、
  自分の compute キューで 1 刻みずつ待って進める。根はいつも頁を持つ。
- **置く操作はコマンド**(common/lab_box.hlsli): `LAB_COMMAND_TYPE_FILL`(セルを物質 3 つまでと温度で置き換える)・`LAB_COMMAND_TYPE_TEMPERATURE`
  (温度を決める)。GPU は刻みの前に shaders/sim/lab_box.hlsl が 1 スレッドで列の順に当て、CPU リファレンスは ApplyLabCommands が同じ関数で当てる。
  当てたブロックは「つつかれた」にする。
- **比べる**(sim/lab_session): 刻みごとに GPU の箱を読み戻し、CPU の箱と状態の全部を比べる。違えば最初に違ったセル(セルが同じなら違う欄)を出して止まる。
- **記録と再生**: コマンドの列 + 刻みごとのハッシュ(`BLAB`)。読み込んで初めの箱から流し直し、ハッシュの列が記録と違えば最初の刻みを出す。
- **パネル**(engine/src/editor/lab_panel)「実験室」: 箱を作る(押した時に GPU の箱を作る)・セル / 材料(空気・木・木炭・二酸化炭素・窒素)/ 温度を選んで
  置く・温度だけ・1 / 10 / 60 刻み・流し続ける・最初に戻す・断面 z の温度(押すとセルを選ぶ)・選んだセルの温度と成分を CPU と GPU で並べる・記録の保存と再生。
- **確かめ方**: lab_box(CPU)・gpu_lab_box(木を置いて火を付け 200 刻み毎刻みビット一致・記録から再生して同じ)・window_lab(`--editor --auto-lab`)。
- まだ無いもの: 細かくした箱(T-0314)・反応表のパネル(T-0219 で入った)。大きな箱は T-0173(下)。

### 実装(T-0194・T-0195): 覗き窓と実験室もホットリロードの表へ・窓の自動の確認
- **実験室の表 = 世界の表**(T-0172 の中身を含む): フレームのループが毎フレーム `LabPanel::UseTable` で世界が今使っている表(TableHotReload の当てた版)を渡す。

  **T-0218 で「次の刻みから新しい表で続ける」に替えた(ADR-0055。下)。流し直しはボタンに残した。**

- **覗き窓**: 世界が刻み s の始めに表を替えたら `ProbePeek::QueueTableSwap(s, 表)`。s より後の境界を初めて抽出する時に表を替え、影の鎖を捨てて
  今の世界の写しから作り直す(前の表で作った影を持ち越さない。ADR-0054)。CPU リファレンス(ProbePeekReference)も同じ。前の表のバッファは

- **`--auto-reload`**(frame/auto_reload。`--editor --packages <写し>` と一緒に): 刻み 10 で reactions.luau を壊す → 読み直しに失敗して古い表のまま

  ctest: window_hot_reload_copy(写す)→ window_hot_reload_record(覗きながら記録)→ window_hot_reload_play(写しのフォルダ無しで再生ファイルの表だけで再生。
  同じ刻みに差し替わり、ハッシュ列が一致)。

### 実装(T-0218): 実験室で刻みの途中に表を替える(D-439・ADR-0055)
- **替え方**: 表が替わったら `LabSession::ChangeTable` は「表を替えた印」のコマンド(`LAB_COMMAND_TYPE_TABLE`・payload は表の版)を次の刻みに置く。
  印のある刻みは、その刻みのコマンドを当てる前に GPU(GpuMultires::ReplaceTable)と CPU リファレンスの両方の表を替え、印そのものは箱を
  つつく(`busyTick = MR_BUSY_POKED`。待ちの予定を新しい表で求め直す = ADR-0018 の「表を変えるものは『変わった』にしてから評価する」)。
  入れ子の表に依る状態は待ちの予定(wakeTick)だけ(熱はエネルギーから毎回求める)なので、つつけば足りる。刻む前に何度替えても印は最後の 1 つ。
- **記録**: `BLAB` 版 3。刻み 0 の表の版 + コマンドの列の中の印(形は版 2 と同じ。版 1・2 も読める)。実験室は今まで見た表を版ごとに持ち、
  途中で表を替えた記録も、この実験室が持つ表なら再生できる(持たない版があれば流さずに断る)。表の中身を記録に残すのは T-0217。
  流し終えて最新の表(世界の表)と違えば、次の刻みから最新の表に戻す印を置く。
- **初めから流し直す**(T-0194 の案 A)はボタン「最新の表で初めから」(`RerunWithLatestTable`)に残した(同じ置き方で法則だけ比べる)。
- 確認: gpu_lab_box(刻み 200 で替えて 100 刻み毎刻みビット一致・替える前の刻みは同じ・替えない時と違う・記録の再生・持たない表は断る・案 A)・
  lab_box(印はセルを変えずにつつく・CPU だけの途中の差し替え・版 3 と 2 の読み書き)・window_lab(`--auto-lab` が火を付けた刻みに同じ中身の別の版へ替える)。

### 実装(T-0219): 反応表のパネル(一覧・検索・保存則の検査・Luau への書き戻し。D-449)
- **一覧は表の中身から**: 世界が今使っている表(ホットリロードで当てた版。フレームのループが毎フレーム `ReactionTablePanel::UseTable`)の
  TableBytes → 定義(Luau は走らせない)→ 元素・物質・規則の行(script/reaction_table_edit)。版が変わった時だけ作り直す。
- **書き戻しはリテラルの字面だけ**: パッケージのフォルダの .luau を字句だけ読み(コメント・長い括弧・関数の本体は飛ばす)、
  表の構築子の入れ子の鍵の並びが `[分類,] 鍵, 欄…` で終わる「鍵 = リテラル」を探して、そのバイトの範囲だけ差し替える(script/luau_literal_edit)。
  値が式(`solid(120)`)・2 か所にある・フォルダが無い(再生ファイルの表)値は書き戻せない(理由を出す)。同じ値("2.8e19" と "28e18")なら書かない。
  探すのは読んだ順の後ろのパッケージから(後のパッケージが上書きした値を直す)。
- **当てるのはホットリロード**: パネルはファイルを書くだけ。型検査・ベイクの検査(元素の釣り合いなど)を通れば刻みの境界で当たり、
  落ちたら古い表のまま、理由がパネルの上に出る(ADR-0047)。書き戻すのは `--packages` のフォルダ(無ければ exe の横の data/packages =
  ビルドの写し。リポジトリを直すならリポジトリの data/packages を渡す)。「最後の書き戻しを戻す」も同じ道。
- **保存則の検査**: 規則ごとの元素の釣り合い・生成エンタルピーの差(反応熱。ベイクが使う値。02 §2)・書いた反応熱(検査用)・ベイクの警告。
- **始まる温度**(表示の定義。仮): k = A·exp(−Ea/RT) が 0.01 /s になる温度。入れると A はそのままで Ea を決めて(整数に丸めて)書く。
- **`--auto-table-edit`**(`--editor --packages <写し>` と一緒に): パネルの書き戻しで木の燃焼の A を 4e10 にする → 当たった表で値を確かめる
  → 戻す(ファイルが元の中身か確かめる)→ 元の版の表に戻ったら終える。ctest window_table_edit_copy → window_table_edit。
- **一覧を作るのはパネルを開いた時だけ**(統合の時に足した): パネルは初め畳んでおき、開いた時(と `--auto-table-edit` の時)に一覧を作る。
  窓の最初のフレームで作ると debug 版ではそのフレームが重く、刻みを捨てる(window_hot_reload_play が落ちた引き金という仮説で直したが、外れた。T-0239)。

### 実装(T-0220): 実験室を広げる(材料を全物質から・量・温度・圧力。D-449)
- **材料**: 表の全物質から 3 つまで組む(1 つのコマンドの上限 LAB_MAX_FILL_SPECIES)。ひな形(空気・木・木炭・二酸化炭素・窒素)を読み込んで直せる。
- **量**: mol・g(表の分子量)・kPa(1 セル 0.125 m³ を置く温度の理想気体で満たした分圧)。入力は表示の浮動小数点、コマンドに入るのは整数の µmol
  (換算は sim::LabGasMicromoles・LabMassMicromoles。整数だけ。R = 8.314462618)。箱は圧力を状態に持たない(気体の流れ〔07〕は箱に無い)。
  固体・液体の体積は引かない(表に相が無い)ので、kPa を固体に使うと「気体として 0.125 m³ に詰めた量」になる。

### 実装(T-0412): 世界の写しの早送り(ADR-0198)
- **写し**(engine/src/sim/world_copy の `sim::WorldCopy`): 本物と同じ形の ProbeSim をもう 1 つ(本物が今使っている表 `ProbeSim::Table()` と、

- **使い方**(T-0413・T-0432 が乗る API): `Create` → `RecordInitialization` → `RecordStart(本物, t, 問い)` → `RecordNext(最大の刻み数)` を投げて

  読み戻しの間隔・当てるコマンド(本物と同じ列なら本物と同じ結果)・条件(刻みの要約と、間隔ごとのセル + 熱のキャッシュを見て真なら止める)。

- **回す場所**(engine/src/frame/world_copy_runner): 本物のリストの後ろに同じ compute キューで投げる。写しを取るのは本物のカーソルが刻みの境界の時。
  早送りの量は、そのフレームのシミュの予算の余り(`SimScheduler::SpareMilliseconds`)に入る刻みの数だけ(D-468。余りが無いフレームは待つ)。

  測る間隔(刻み)→「今の世界の写しで早送り」。写しにはコマンドを当てない(今から何もしなければ)。進み・着いた時間(分 秒)・測った値の線・

  600 刻み早送りし、写しの刻みごとのハッシュ = 本物の同じ刻み。記録を写し無しの起動で再生して同じハッシュ列)。

### 実装(T-0413): 重さの検査と、本物の刻みの見張り(ADR-0204)
- **1 刻みの重さ** = その刻みの単位の GPU 時間の和 + 活性のブロック数(`ProbeTickHash::scheduledBlocks`)。集めるのは
  `sim::TickCostAccumulator`(engine/src/sim/tick_cost): 投げた順の読み戻しを渡すと、刻みがフレームをまたいでも終えた刻みを要約と組にする。
  写し(`WorldCopyResult::tickGpuTimestampTicks`。hashes と同じ並び)と本物の見張りが同じ部品で集める。
- **判定**(engine/src/frame/weight_check の `CheckWeight`。純粋な計算): 重さ ÷ 使ってよい時間。使ってよい時間 = 等速の 1 刻みの予算
  (既定 = この機械の今のシミュの予算 × 目標 fps ÷ 60)、演出のスローの窓の中は 予算 ÷ 速さ。1 を超えたら「予算を超える」(D-468 の不具合)、
  注意の割合(既定 80%)を超えたら「注意」。続けて超えた区間・いちばん重い刻み(時間と活性のブロック数)・安全網で捨てる刻みの見込み。
- **パネル**「写しの早送り」の「重さの検査」: 1 刻みの予算(0 = この機械の今の予算)・注意の割合・演出のスローの窓(始め・長さ・速さ)。
  早送りが終わると判定・超えた区間・1 刻みの GPU 時間の線(真ん中の高さ = 予算)を出す。予算を超えたらログにも警告。
  マッチ 1 本の延焼なら、筆で火を付けてから「今の世界の写しで早送り」(写しにはコマンドを当てない)。
- **本物の見張り**(frame/frame_loop の WatchWeight): 本物の刻みが等速の予算を超えたら、1 秒ごとに 1 行の警告(刻みの範囲・いちばん重い刻み・
  ブロック)。エディタの「状態」に累計と最後の区間を赤で。製品のビルドの区別はまだ無いので、どのビルドでも出す。
- **確かめ方**: weight_check(CPU。判定とまとめ方)/ gpu_world_copy(本物は刻みがフレームをまたいでも全部の刻みの重さを集める・
  写しの全部の刻みに GPU の時間がある・活性のブロック数が写し = 本物 = 基準)/ window_copy_record(`--auto-copy` に、写しの刻みごとの
  活性のブロック数が本物と同じ・全部の刻みの重さを測った・本物の見張りが刻みを測った、を足した)。GPU の時間は揺れるので比べない。
- 判断待ち(ADR-0204): 予算の値の置き場(仮: エディタの設定。⑥ の後にパッケージへ)・警告のしきい値(仮: 1 刻みでも超えたら)。
- 未実装(T-0485): 重い場所(どのブロック)と段(伝導・反応・物理)ごとの内訳。

### 調整の負担を減らす道具(D-482。未実装)
法則が一つの表でつながっている(D-463)ので、一つの値が関係する全部に効き、予想外の抜け道が出る。その調整の負担をエンジンの道具で減らす(神の目の延長)。
- **遊びの指標の自動テスト**(D-471 ④・T-0432): 「密室の火が何分で消えるか」のような指標をゲームが登録し、法則(表)を変えるたびに写しの早送り(T-0412)で測る。
  決定性があるので毎回同じに測れ、前の版との差を出す。
  - **実装(T-0432・ADR-0206 Proposed)**: 指標はパッケージの分類 `play_metrics`(1 つの鍵 = 1 つの指標。反応表と同じ読み込み)に
    上限・測る間隔・つつき・測る量(最高温度・しきい値以上のセルの数・物質の量)・止め方(`at_most` / `at_least`。無ければ上限の量)で書く。
    量を測る範囲は `min_cell`・`size_cells`(セルの箱。world_cells と同じ書き方。省けば世界全体。T-0559・ADR-0251 Proposed)。
    指標ごとの場面の違い(world_cells の差分)は T-0580。
    場面は表の世界の組み立ての初めの世界 S(0)。sim::PlayMetricMeasurer が S(0) を持つ元の世界と写しを作り、指標ごとに写して早送りする
    (判定はつつきを全部当てた後だけ)。CPU リファレンス(MeasurePlayMetricReference)とビット一致。
    見る所: エディタのパネル「遊びの指標」(表を変えたら測る〔既定〕・ボタン。本物の刻みの余りの予算で。前に測った版との差)と、
    `bicameral --measure-metrics [--metrics-baseline <file>] [--metrics-save]`(窓なし。差をログへ。`--log-level debug` で量の道のり)。
    判断待ち(ADR-0206): 書き方(仮: パッケージ)・いつ測るか(仮: 表を変えたら自動 + ボタン)・前の版の置き場所(仮: エディタはその起動の中・
    コマンドラインは指定のファイル)。
- **影響の見える化**(⑤ で要る順に・T-0433): 値を変えると、関係する法則(規則・物質)と、影響を受ける現象・遊びの指標と、どう変わるかが見える。
- **法則のノード表示**(⑤・T-0434): 物質・反応の網・引きずり・坂のつながりをノードで見せる(反応表のパネル T-0219 の延長)。
- **組み合わせの導出**(⑤・T-0435): 法則から「何と何がどの条件で何になるか」・連鎖の候補を導き、安くて強すぎる行動(抜け道)を自動で探す。
- **中身を書く手間を減らす道具**(D-485。⑤ で要る順に): 作り手が手で決めるのは「何があり、何が何になるか」だけにする。
  - 係数の自動計算: 反応物と生成物を書けば、元素の数が合う係数を連立方程式で計算する。
  - 足りない物の下書き: 表に無い物質・元素が反応に出たら、標準パッケージ「現実」から値ごと持ってくるか、組成から値を見積もった下書きを作る
    (原子団寄与法・ReaxFF などが使えるかは未確認)。下書きはファイルに書き出して見せ、作り手の承認で確定する(ファイルと表を食い違わせない。D-484)。
  - 類で書く補助: 「炭素と水素を含み燃える印の物質はすべて酸素と反応して CO2 と水に」のように一度書けば該当する物質すべてに反応を展開する
    補助関数を標準パッケージ(Luau)に置く。エンジンに形は足さない。
- ⑤ の場面の中身はこの道具とパッケージで作り、面倒だった所・できなかった所を記録して道具の優先順位を決める(D-486)。
- ほかにも要るものは追々足す。どれも状態と表を読むだけで、世界を変えない(D-403)。

### 実装(T-0399): 材料のひな形・抽出の物質・既定をパッケージから(ADR-0174・D-454・D-486)
- 実験室・筆のパネルの材料のひな形は、表の `material_templates`(sim::MakeLabMaterials が表の templates を写す。並び = order → 鍵)。
