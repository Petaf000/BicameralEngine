# 17 多重解像度: どんな細かさでもシームレスに(L4 詳細設計・中心の研究 R-MULTI)

対応する決定: D-401(上限なし)/ D-402(分子まででもシームレス、粒度は動的)/ D-403(見るだけなら変わらない、触れば変わる)/
D-208(活動で決まる細かさは観測者に依存しない)/ D-408(群れ ↔ 一体一体)/ D-205(決定性)/ D-206(保存則)/ D-411(研究に時間の打ち切りなし)

## 目的
同じ世界を、必要な所だけ必要な細かさで表す。粗い所(遠くの山)から、0.5m のセル、1mm、分子まで、**同じ木構造の中で連続的に**扱う。
「研究がはかどる」= プレイヤーが道具しだいでどこまでも細かく調べられることを、エンジンの一般の仕組みとして持つ。

## 1. 解像度の段(レベル)
- レベル k のセルの一辺 = 0.5m × 2^-k。k = 0 が基本の 0.5m。k < 0 は粗い(k = -4 で 8m)、k > 0 は細かい(k = 12 で約 0.12mm、k = 32 で約 0.1nm)。
- **k に上限も下限も置かない**(D-401)。座標は (k, 整数の座標 int64 ×3)。int64 で足りない深さに入る時は、その部分木に局所の原点を置いて座標をつなぐ。
- 世界は**ブロック(8×8×8 セル)の疎な木**で、**比 2**(ADR-0015): 子ブロック(k+1)は親ブロックの 4³ セル(1/8 の範囲)を覆い、親のセル 1 つ = 子のセル 2³。
  細かくする = 親ブロックの八分の一を子ブロック 1 つに置き換える(覆われた親のセルは空になる)。粗くする = 逆。粗密の境界は常に 1:2。
- **量の単位はレベルの関数**: 物質量 8^-k µmol・エネルギー 8^-k mJ(体積と同じ比)。同じ濃度・温度ならどのレベルのセルも同じ数で、反応の核はレベルを知らない。
  細かくする = 子は親と同じ数(余りなし)。粗くする = 子 2³ の合計 ÷ 8 で、余りは **64bit の端数**として持つ(ADR-0015。21 段の往復までビット一致)。
  → 05 の「粗い 8m の層」と「0.5m の層」は、この木の k = -4 と k = 0 にすぎない(1 つの仕組みにまとまる)。

## 2. 表現の種類(どのレベルでも、領域ごとに選ぶ)
| 表現 | 中身 | 向いている範囲 |
|---|---|---|
| 連続体 | セルの成分(物質と量の可変長の一覧)・エネルギー・面の流れ | 分子が十分に多い所(ほとんどの世界) |
| 個体 | 1 つずつの物(草 1 本・小石・魚 1 匹)。08・09 の物と生き物 | 触れる・切る・食べる対象 |
| 集まり | 群れ・草むら・砂の山を 1 つの物として(数と平均の状態) | 普段の生き物や植物 |
| 粒子 | 分子・原子 1 つずつ(整数の位置と速度、局所の座標) | 顕微鏡・分子を操る器具で見る/触るごく小さな範囲 |

表現の切り替え(すべて決定的・保存量は正確):
- **連続体 → 個体/粒子**: 成分の量から、個数と一つずつの状態を決定的な乱数(04 R6)で生成する。例: 草のバイオマス → 草の本数と長さ、気体の量と温度 → 分子の数と速度(温度に合う分布)。
  個数は整数に丸めた端数を決定的に配り、**質量・元素・エネルギー・運動量の合計が元とビット単位で一致する**ように最後の 1 つで合わせる。
- **個体/粒子 → 連続体**: 合計して戻す(整数の足し算なので正確)。
- **集まり ↔ 個体**: 同じ考え方(09 §5)。

## 3. 何が細かさを決めるか(3 種類)
| 種類 | きっかけ | 世界に返るか | 観測者に依存するか |
|---|---|---|---|
| A 状態による細分 | 反応の前線・破断の先端・強い勾配など、**状態の関数**で決める(決定的) | 返る(物理の一部) | しない(D-208) |
| B 観察による細分 | プレイヤーが近くで見る・顕微鏡などの器具で覗く | **返さない**(D-403) | する(が、世界の結果は変えない) |
| C 介入による細分 | 分子をつまむ・切る・細かい所に物質を加えるなど、細かいレベルで操作する | **返る**(入力のコマンドとして記録され、再現できる) | 介入は入力なので、再生で再現される |

### B「見るだけなら変わらない」の仕組み
- 観察で細かくした部分木は**影の計算**: 親(粗い側)の状態を境界条件と「合計の拘束」として受け、細部だけを動かす。
- 影の計算の結果は、親のセルに書き戻さない。親は、観察していない時とビット単位で同じ計算をする。
- 影の細部が親の合計からずれていったら、合計に合うよう引き戻す(細部は親に従う)。
- テスト: 同じ再生ファイルを「顕微鏡で覗いた場合」と「覗かない場合」で走らせ、世界(影以外)のハッシュ列が一致する。

### C「触れば変わる」の仕組み
- 介入のコマンド(例:「この分子を 1 つ取り出す」)は、その刻みで影の部分木を**本物の部分木**に変え(A と同じ扱い)、結果を親に返す。
- 以後、その部分木は状態による細分(A)と同じく、細かさの基準を満たさなくなるまで本物として計算され、やがて粗くなる(合計して戻る)。

## 4. 時間の段(細かいほど刻みが短い)
- 細かいセルは、安定に計算するために短い刻みが要る(拡散なら刻みは一辺の 2 乗に比例)。分子の運動は、さらにずっと短い刻みが要る。
- **局所の時間刻み**(06 §1 の第 2 段)は、多重解像度では必須になる: レベルごとに刻みを細分し、レベルの境界では粗い方の刻みでまとめて受け渡す(保存則を守る)。
- 分子のように、現実の時間で追いかけきれない細かさ(例: 10nm の水の中の分子を 1/60 秒追うには約 1.7×10^13 回の計算が要る)は、
  - 観察(B)の場合: 器具の中の時間を**ゆっくり流して見せる**(影の計算なので、世界の時間とずれてよい)。
  - 介入(C)の場合: 介入の直後の短い時間だけ細かく解き、その結果(何が何個どう変わったか)を親へ返し、親は通常の刻みで続ける(時間の段の分離)。
  - どこまでを細かく解き、どこから統計(速度式)に任せるかが研究の中心(§6)。

## 5. データ
- ブロックの木: ハッシュ表(キー = (k, ブロック座標))+ ブロックプール。親セルには「子ブロックの番号」または「表現の種類と中身の参照」を持たせる。
- 端数(ADR-0015): 端数が 0 でないブロックだけが端数のブロック(セルごとに エネルギーの端数 + 物質 ID と端数)を別の配列に持つ。1 世代(細かく/粗くする時しか変わらない)。
  反応・輸送は整数部だけを使う。21 段より深くから粗くして落ちた端数は世界の帳簿へ(T-0018)。
- セルの成分は**可変長**(D-418: 上限なし): インラインに N 個(N は測って決める。R-MULTI-4)+ 溢れた分は成分の連鎖(プール)。
- 粒子の表現: 部分木ごとに局所の原点を持つ粒子の配列(位置 int32/int64 の局所座標・速度・物質の ID)。

### 木の管理(T-0018。ADR-0016)
- **枠の範囲**: 世界の枠 [0, W) は空きのスタックから取り、観察の枠 [W, W + O)(影・世界の写し)は呼ぶ側が直接決める(覗いても世界の枠の番号が変わらない)。
  端数の枠も空きのスタック。スタックは最初「上から 0, 1, 2…」(取ると小さい番号から出る)。
- **索引**: 開番地法(線形探査)のハッシュ表。項目は枠の番号(空 / 墓石は印)、キーは見出しの (レベル, 原点) を読んで比べる。
  入れる = 空の所に compare-exchange(墓石は使い回さない)、消す = 墓石。墓石が表の 1/4 を超えたら次の要求の処理の終わりに作り直す。
  索引は見出しから作れるので状態のハッシュに入れない(GPU の並列の挿入で並びは変わってよい)。本物のブロックだけを入れる。
- **要求**(1 件 40 バイト。一覧は決定的な順に並べて渡す。1 刻み最大 MR_MAX_REQUESTS 件):
  - 細かくする(L, 点): 根(rootLevel)から子の番号をたどって点を含む最も深い本物のブロック D へ。D のレベル = L なら済み。でなければ D の下に L まで鎖で作る(1 刻みで何段でも)。
  - 粗くする(L, 点): 点を含むレベル L の本物のブロック B(索引で引く)を親へ戻す。B に子があるか根なら無効。1 刻みに 1 段。
- **1 刻みの処理**(Compute の段 + 細かくする鎖は Work Graph の再帰):
  1. 解決(要求ごと): D / B を求め、取り合いの枠(細かくする = D、粗くする = B の親)に自分の番号を atomic の最小で書く。
  2. 確定(要求ごと): 取り合いに負けた・B 自身が誰かに取られた(子が作られる)なら却下。要る枠の数を書く
     (ブロック = 段の数、端数 = D に端数があれば段の数・粗くする親に端数が無ければ 1。控えめに取り、適用の後で 0 なら返す)。
  3. 割り当て(1 グループ): 要求の順の累積和が空きの数以下なら許可、空きのスタックの上から順に配る。
  4. 適用: 細かくする鎖(1 段 = 1 グループ、Work Graph の再帰)と粗くする(1 要求 = 1 グループ)。1 刻みに 1 つの親は 1 つの要求だけが触るので、
     書き込みは重ならない。新しい本物のブロックを索引に入れ、戻したブロックを墓石に。端数のブロックが全部 0 になったら返す印。
  5. 解放(1 グループ): 返す枠を要求の順の累積和でスタックに積む。取り合いの印を消す。結果を数える。墓石が多ければ作り直しの印。
  6. 索引の作り直し(印がある時だけ): 表を空にして、使っている本物のブロックを全部入れ直す。
- **世界の帳簿**: 粗くした時に端数の下から落ちた下位 3bit(子のレベル c の単位 × 2^-64)を、帳簿 [c − MR_LEDGER_LEVEL_MIN][列] に足す
  (列 0 = エネルギー、1 + 物質 ID)。帳簿の外のレベルは数えるだけ。保存量の検査は「世界 + 帳簿」。

### 活性(T-0100。05 §4・06 §2「2 活性の整理」)
- **刻むのは「種」とその面の隣だけ**(仮の世界の T-0005・T-0089 の規則を木に広げた)。種 = 前の刻みに進める反応の規則があったブロック
  (D-424 により、無ければ刻みが変わっても変わらない)+ この刻みに木の変更でつつかれたブロック(細かくした親と子・粗くした親・置いた根)。
  観察の枠(影)は活性に入れず毎刻み全部刻む(D-403)。全部を刻む CPU(StepNest)とセル・端数がビット一致する。
- **面の隣はレベルをまたぐ**: 木は「ブロックの覆われていない八分の一(4³ セル)」で世界を隙間なく分けるので、隣は (八分の一, 面) の 48 組ごとに求まる。
  先が同じブロックの中なら、覆われていなければ自分・覆われていれば子へ。外なら、先の 4³ の箱を含む最も細かい本物のブロックを
  索引でレベルを上へ引き(自分のレベル → 根)、粗ければそのブロック、同じレベルなら八分の一が覆われていなければそのブロック・覆われていれば子へ。
  子へ降りる時は「面の向きに入った時の手前の 4 つの八分の一」を見て、覆われていなければ自分を起こし、覆われていれば更に子へ(再帰。上限 MR_MAX_WAKE_DEPTH = 28。
  超えたら数える)。テストは「覆われていない八分の一の箱どうしの面の接触」の総当たりと毎刻み同じ集合になることを確かめる。
- **印と一覧**: 刻んだブロックは見出しの activeTick に刻みの印(MrActivityMark = 刻み + 1)を交換で書き、前と違えば初めてなので刻む(順に依存しない)。
  印は状態の全部の要約(HashWholeNest)に入れ、世界の要約(HashRealLeaves)には入れない。
  種は GPU では順の決まらない一覧(Work Graph の GPU の入力そのもの。空のレコード 0 を先頭に)を 2 本、刻みごとに入れ替える:
  要求の処理はこの刻みの一覧へ、刻むノードは次の刻みの一覧へ書き足す(u13 に結ぶ一覧を切り替える。T-0107 で u14 → u13)。CPU は世界の枠ごとの 0 / 1 で、集合として比べる。
- GPU の形: ActivitySeedNode(種 1 つ = 1 グループ、スレッド = (八分の一, 面))→ WakeFaceNode(スレッド起動、再帰)→ ActivityStepNode(1 ブロック = 1 グループ)。
  観察の枠は ObserverStepNode(CPU の入力、枠の数のグループ)。
- 粗い所の遅い刻み(05 §4 の「成長・回復・天候」)はまだ。段をまたぐ輸送(熱の伝導。T-0019)が入って、隣を起こすことが結果に効くようになった
  (種は「進める規則があった、またはセルが変わった」ブロック。下の「熱の伝導」)。

### 静かなブロックを粗くする(T-0101。05 §4)
- **N 刻み続けて変わらない本物の葉を親へ戻す**(N = MR_QUIET_TICKS、今は 16。2026-10-04 ユーザー決定: 定数で、後から測って調整)。
  状態の関数なので観測者に依存しない(D-208)。粗くするのは T-0018 の「粗くする要求」で、保存量は端数と帳簿で正確に合う。
- **忙しさの印** busyTick(見出し)= ブロックが最後に変わった刻みの印。書くのは 2 か所: 刻んでセルが 1 つでも変わった時(ActivityStepNode)と、
  木の変更でつつかれた時(要求の処理が MR_BUSY_POKED を書き、種として起こす ActivitySeedNode がその刻みの印にする。要求の処理は刻みを知らないため)。
  同じ刻みの書き手は同じ値なので順に依存しない。状態の全部の要約(HashWholeNest)に入れ、世界の要約には入れない。
- **「進める規則がある」(種)とは分ける**: 規則が進めると言っても、セルが変わらないまま毎刻み種になり続けることがある(進行度が丸めで 0 になると思われる。未確認。BACKLOG)
  (燃え尽きかけの木箱。T-0101 で見つけた。種で忙しさを決めると 4000 刻みたっても粗くならなかった)。そういうブロックは毎刻み刻まれるが、
  変わらないので N 刻みで粗くなる(粗くして混ぜると、この場面では種も 0 になった)。
- **静かな葉** = 世界の本物のブロックで、根でない・本物の子が無い・つつかれたままでない・印が N 刻みより古い(MrIsQuietLeaf)。
  同じ親の兄弟で静かなものは八分の一の番号の小さい 1 つだけが要求を出す(1 刻みに 1 つの親は 1 つの要求しか通らないので、負ける要求で一覧を埋めない。MrWantsQuietCoarsen)。
- **順**: 刻み t の要求の処理の前に、外から渡された要求の後ろへ世界の枠の順に足す(GPU は 1 グループの Compute の TreeQuiet。枠を 512 個ずつ区切って累積和)。
  一覧(MR_MAX_REQUESTS)が一杯なら足さずに数え(MR_COUNTER_QUIET_DEFERRED)、次の刻みにまた作られる。CPU は SubmitQuietCoarsenRequests。
- 制限: 印は 2^32 刻みで一周する(それより長く静かな葉は忙しく見えるが、その前に粗くなっている)。観察の影の親になっている本物の葉も粗くなる
  (見出しは影を知らない。今の影の親は根か世界の写しだけ。観察の枠の管理が親を付け替える約束にする)。活性で刻む木(StepActive)でだけ使う
  (全部を刻む StepNest ではつつかれた印が刻みの印にならず、粗くならない)。TreeQuiet は世界の枠の数に比例して 1 グループで回るので、枠が非常に多くなったら並列の累積和にする。

### 一様なブロック(T-0102。05 §3。畳むのは下の「頁を畳む」)
- **見出しの枠とセルの頁(512 セル)は別のプール**。見出しの page(MR_NO_PAGE = 頁なし)。セルのバッファは [一様の値 × 枠][頁 × 512]、
  頁の空きのスタックは世界の枠の空きのスタックの後ろ(ルート署名を増やさないため。63 / 64 語のまま)。数える欄 19 MR_COUNTER_FREE_PAGES。
- **一様** = 覆われていないセルが全部同じ値・覆われたセルは空・端数のブロックなし(2026-10-05 ユーザー決定。1 点だけ細かくした大きな空気の親も一様のまま)。
  頁なしのブロックのセルは MrUniformCell(覆われていれば空、でなければ値)で読む(CPU は LoadNestCell、GPU は LoadBlockCell)。
- **観察の枠はいつも頁を持つ**(頁 = 枠 − 世界の枠の数。世界の頁はその後ろの番号)。
- **木の変更**: 根は 512 セルが全部同じなら一様で置く。一様な親の本物の子は一様(鎖は全部一様か全部頁を持つので、要る頁の数は確定の段で決まる)。
  粗くする: 一様な親へ、一様で端数なしの子を粗くして親の値とビット単位で同じに戻る(MrCoarsenKeepsUniform)なら一様のまま、でなければ
  親を頁に広げる(1 頁。八分の一の外は一様の値で埋める)。頁は枠・端数と同じく要求の順の累積和で配り、返す(粗くした子の頁)。
- **刻む**: 一様なブロックは値 1 つで「進める規則があるか」を調べる(RxCellStep::possible は乱数によらない)。無ければ D-424 により
  どのセルも変わらないので刻まない。あれば印(MR_PAGE_WANTED)を付けるだけにし、刻んだ後に TreeExpand(1 グループ)が
  **世界の枠の順**に頁を配って一覧(u12 の後ろ。GPU の入力。T-0107 で u13 → u12)に書き、ExpandStepNode(活性)/ StepExpanded(全部を刻む)が埋めて刻む。
  順の決まらないグラフの中で配らないのは、頁の番号を決定的にするため。
- **頁が足りない**(2026-10-05 ユーザー決定): 頁を配れなかったブロックはその刻みは刻まず、一様に戻して数え(MR_COUNTER_PAGE_SHORTAGE)、
  種に残して次の刻みにまた試す(決定的。テストは 0 を確かめる)。世界の時間を遅らせる本来の扱いはメモリの管理(05 §8)で。
  要求の処理で頁が足りなければ、枠と同じく後回し(MR_COUNTER_NO_SPACE)。
- 要約: 世界の要約(HashRealLeaves)と保存量は論理のセルで計算する(一様か頁かによらない)。状態の全部の要約(HashWholeNest)は頁の番号も含む。
- 頁が返るのは、粗くした子の頁と、静かで一様になった頁を畳んだ時(T-0103。次の節)。

### 頁を畳む(T-0103。05 §3)
- **調べる時**: 頁を持つ世界の本物のブロックが**ちょうど静かになった刻み**(忙しさの印が N 刻みを初めて超えた刻み。MrWantsFoldCheck)に 1 回だけ。
  根・子のある親も調べる。端数を持つブロックは一様でないので調べない。頁のセル・子・端数を変える所(刻んで変わった・木の変更でつつかれた・
  頁に広げた)は全部忙しさの印を書くので、変われば N 刻み後にまた 1 回調べる。静かなまま一様でないブロックを毎刻み調べ直さない
  (512 セルを読む費用を、静かになる時の 1 回に限る)。全部を刻む StepNest だけの木では印が刻みにならないので畳まない(静かな葉と同じ)。
- **頁に広げたら忙しい**(Claude が決めた): 広げて刻んでもセルが変わらないブロック(進める規則があるのに進まない。BACKLOG)も N 刻み後に畳める。
  そういうブロックは種のままなので、畳んだ次の刻みにまた広がる(N + 2 刻みごとに広げて畳むのを繰り返す。結果のセルは変わらない)。
- **一様か**: 覆われていない最初の八分の一の最初のセルを値とし(全部覆われていれば空のセル。MrFoldValueCell)、全部のセルが
  MrUniformCell(値) とビット単位で同じ(MrFoldsCell)。
- **順**: 刻み t の初め、外からの要求の後・静かな葉の要求(TreeQuiet)の前。畳んでも論理のセルは変わらないので忙しさの印は書かない
  (同じ刻みに静かな葉として粗くできる。一様な子を一様な親へ粗くして同じ値に戻れば、親も一様のまま)。
  頁は**世界の枠の順**に空きのスタックへ積む(頁の番号を決定的にするため)。CPU は FoldQuietPages。
  GPU は TreeFoldCheck(1 グループ = 世界の枠 1 つ、スレッド = セル。結果は取り合いの印 [枠] に MR_CLAIM_FOLD として置く。
  取り合いの印は要求の処理の中でしか使わず、その外では全部 MR_NO_CLAIM なので借りる。ルート署名は 63 / 64 語のまま)→ TreeFold
  (1 グループの累積和。値を書き、頁を積み、印を戻す)。数える欄 22 MR_COUNTER_FOLDED。
- **一様に戻るかは反応による**: 900 K の木箱は数刻みで燃え尽きてどのセルも同じ値になる。600 K の木箱は O2 が 1 単位残るセルが
  確率で分かれ(512 セル中 219)、4000 刻みでは一様に戻らない。残った 1 単位は止まっているのではなく、1 刻みの期待値が 1 未満の
  遅い尾で、確率で時々進む(reaction.hlsli の RxScaleExtent。いずれ燃え切る)。ビット単位で同じに戻るのは、岩・空気のように
  最初から同じ所と、反応物が尽きて同じ終わりに着く所。
- **ほぼ同じ所を畳む**(2026-10-05 ユーザー決定 D-428。T-0104): 許容差 = ゲーム内の計器で測れない差。合計はビット一致(余りは端数か帳簿へ)。
  遅い反応の丸めは変えない。許容差の値は T-0019 の後に頁の残り方を測って決める。

### 熱の伝導(T-0019。07 §1。ADR-0017)
- 式と面の隣は shaders/common/multires_conduction.hlsli(CPU は multires_conduction.cpp と multires_nest.cpp の StepBlocks。
  GPU は shaders/sim/multires_conduct.hlsli と gpu_multires.cpp の RecordConduction。T-0107)。
  `MultiresStepOptions{.conduction = true}` で StepNest・StepActive(GPU は RecordStep・RecordStepActive)が反応の前に伝導する(既定は切る)。
- **GPU の段**(T-0107): ConductMark(印)→ TreeExpand(頁。凍らせた・配った印)→ TreeFractions(端数の枠を枠の順に)→ ConductPrepare(埋める・空にする)
  → ConductFlows(面の流れを変化に。64bit の atomic の足し算)→ ConductApply(変化を足して反応)。1 グループ = 1 ブロック。
  印と変化は伝導の作業場(u11: 枠ごとの刻みの印 + 頁のセルごとの変化。印は刻みの印なので消さない、変化は足したら 0 に戻す)。
  活性の刻みでは、Work Graph の ActivityStepNode が刻まずに伝導の一覧(u12 の後ろ)に足し、段はその一覧のブロック(+ 観察の枠・粗い側の相手)だけを受け持つ
  (Compute は全部の枠の数だけグループを投げ、一覧の数を超えたグループは何もしない。Work Graph 版は GPU の入力 = 一覧)。
  ルート署名にバッファを足すため、uint32 の表(世界の枠の空き・取り合いの印・索引・世界の頁の空き)を u6 の 1 本にまとめた(62 / 64 語)。
- **面の隣**(MrFindFaceNeighbor): 同じブロックの中なら、覆われていればその面は細かい側のもの(細かい側が計算する)。外なら、先のセルを含む最も細かい
  本物のブロックを索引で上へ引く(活性の MrFindContaining)。同じレベルなら同じく覆われているかで分け、粗ければその覆われていないセル(差 d)。
  影のブロックは自分の中だけ(外は断熱。親との受け渡しは引き戻し)。
- **レベルの係数**: レベル k の面の係数の上限 = min(G の係数 × 4^k, C ÷ 8)(単位が 8^-k mJ、面積 ÷ 距離 ∝ 2^-k)。熱容量の数はレベルによらない。
  違うレベルの面は細かい側の単位で、粗い側の上限 = min(粗い側の G の係数 × 4^kf, 粗い側の C ÷ 8 × 2^d)。
- **違うレベルの面の受け渡し**(ADR-0017): 細かい側だけが計算し、送った F(細かい単位)を粗い側は整数部 + 2^-64 単位の端数(端数のブロックのエネルギー)で受ける。
  3d > 64 は表せない下位を細かい側に残す。粗い側に端数の枠が無ければ整数の単位の倍数だけ送る(MR_COUNTER_FRACTION_SHORTAGE)。保存はビット単位。
- **1 刻みの順**: 一様なブロックの「変わるか」(反応・自分の面の流れ・細かい側から送られてくる面。一様なブロックは面に接するセルだけ調べる)→
  頁を枠の順に配る(足りなかったブロックは凍らせる: 刻まず、そのブロックとの面も流れない)→ 端数の枠を枠の順に配る → 面の流れ(刻みの初めのセルから。Jacobi 型)
  → 変化を足す → 反応。温度は整数部だけから求める。
- **活性**: 種 = 進める規則があった、またはセル(か端数)が変わったブロック。流れは刻みの初めのセルだけで決まるので、変わらないブロックどうしの面は前の刻みと同じ
  (0 なら 0)。流れのある面は少なくとも片側が前の刻みに変わっている(種)ので、両側とも刻まれる。違うレベルの面で送れない量は送らない(変わらなければ眠る)。
- 制限: 面の係数が熱容量の上限で止まるレベルより細かい所では、熱の伝わり方が本当より遅い(試験の表で k ≥ 3。T-0108 の局所の時間刻み)。
  整数の流れは温度差がほぼ 1 mK 未満になるまで止まらないので、熱が通った所はビット単位で同じに戻らず、静かにもならない(T-0104・D-430)。

## 6. 研究 R-MULTI(時間の打ち切りなし・D-411)
成功の基準(順に確かめる):
1. **入れ子の細分の往復**: 0.5m から 1mm まで(k = 0〜9)を 1 点の周りで入れ子に細かくし、戻す。保存量がビット単位で一致。GPU で 1 刻みの中に収まる。
2. **見るだけなら変わらない**: 観察(B)の影の計算があってもなくても、世界のハッシュ列が一致。
3. **状態による細分(A)の効果**: 延焼の前線・割れ目の先端を細かくすると、粗いままより現実に近い形になる(見た目と測定の両方)。境界で保存則が破れない。
4. **連続体 ↔ 粒子**: 気体・液体の成分と温度から分子を生成し、分子の計算で出る温度・圧力・濃度が元の連続体の値と一致する(許容差は研究の中で決める)。
5. **介入(C)が世界に返る**: 分子レベルの操作(取り出す・加える・反応させる)の結果が、親の成分とエネルギーに正確に反映される。
6. 深さを伸ばす: 1mm → 1µm → 分子。どこまでを連続体で解き、どこから粒子にするかの境目を決める。

代案の順(うまくいかない時に試す):
- 影の計算が親からずれて不自然 → 親への引き戻しを強める / 影の中は時間を止めた「静止画 + ゆらぎ」にする
- 局所時間刻みの境界で保存則が破れる → 境界の流れを粗い刻みごとに積算して一括で受け渡す(フラックスの帳尻合わせ)
- 粒子の数が多すぎて遅い → 粒子にする範囲を小さくする / 粒子を「代表粒子」(1 つが N 個の分子を代表)にする
諦める条件: 原理的に無理(例: 保存則と決定性を両立する切り替えが存在しない)と分かった時だけ、ユーザーと判断する。

- 面の隣(たくさんの要求の場面、深さ 26 段): 刻むセルの全部の面が、総当たりの幾何(面の中心のすぐ外の点を含むセル)と一致。粗い側との最大の差 10 段。
- 閉じた箱(根 1 つ・1500 K の空気 1 セル): エネルギーの合計が毎刻み一定、温度の幅は広がらずに 200 刻みで 1200 K → 17.9 K。
- 鎖(根 2×2×2 の角に 6 段・いちばん細かいブロックが 1500 K): 熱がレベル 0 の根まで届き、「世界 + 帳簿」が毎刻み最初とビット一致・活性 = 全部。
  端数の枠が無いと整数の単位の倍数だけ送り、細かい所に熱が少しこもる。
- たくさんの要求の場面に伝導を入れても「世界 + 帳簿」が毎刻み一致・活性 = 全部・2 回一致。粗い側が端数の枠(64)を使い切った(ADR-0017「影響」)。
- 計測: 面の係数が熱容量の上限(1/8)で止まる最初のレベルは、試験の表で空気・木箱とも k = 3(現実の伝導率なら空気 k = 9・木箱 約 11)。
  静かになった後の頁: 鎖の場面に頁を畳む・静かな葉を粗くするを入れても、900 刻みで頁を持つブロックは 14 → 13 で全部が種のまま、頁の中の温度の幅 3 mK。

### 結果(T-0107、熱の伝導を GPU に。2026-10-05)
- 鎖(全部・活性)とたくさんの要求の場面(活性 30 刻み・全部 12 刻み。端数の枠が足りなくなる)で、状態の全部と次の刻みの種が毎刻み CPU とビット一致(HW・WARP)。
  活性の伝導の段を Work Graph で投げる版も同じ結果(ただし release の WARP では最初の DispatchGraph でデバイスが失われる。WARP の JIT と推定・未確認)。
- GPU 時間(docs/perf.md): 根 8³ で伝導ありの活性の刻み 0.5〜1.1 ms・全部を刻む 0.8〜1.6 ms(クロックで揺れる)。伝導の段の Compute と Work Graph の差は揺れの中で、
  Compute がわずかに安い → 既定は Compute(D-302)。
- 端数の枠の容量(ADR-0017 追記): 返すのは木の変更の時だけのまま。静かになったら端数のエネルギーを帳簿へ移して返すのは T-0104。
