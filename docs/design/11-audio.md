# 11 音(L4 詳細設計)

対応する決定: D-107(View は CPU)/ D-317(自作・XAudio2 の上)/ 01-architecture(入力への即時の見込み発音)

## 目的
反応・物理・生き物の出来事から、素材ごとの音を鳴らす。音の「種類と発生」は GPU の世界から来る。鳴らすのは CPU。

## 1. 流れ
```
GPU: 反応・物理・生き物のイベント(種類・素材・場所・強さ・刻み)→ キーで並べてリングへ(06 §3)
GPU: 音の場 … 連続する音(燃えている・流れている・風)は、ブロックごとに強さを合計して毎刻み出す
CPU: リングを読む(1〜3 フレーム遅れ)→ 音の対応表(Luau)で音素材を選ぶ → 自作ミキサー → XAudio2
```
- 音の対応表: (イベントの種類, 素材) → 音素材の組(ランダムに選ぶ候補・音量と高さの幅)。ゲームの中身なので Luau(D-318)。
- 1 つずつ鳴らす音(はじける・割れる・倒れる)と、場として鳴らす音(炎の音・川の音)を分ける。数万の炎のセルを 1 つずつ鳴らさない。

## 2. ミキサー
- 声の数の上限(例 128)。優先度 = 大きさ × 距離の減衰。上限を超えたら優先度の低いものから止める。
- 空間化: 第 1 段は距離の減衰 + 左右のパン + 前後の低域カット。HRTF は研究(後回し)。
- 遮り: 描画の DXR で、聞き手から主な音源へ光線を飛ばして遮りの量を出し、リングで返す(View 同士のやり取りなので決定性は要らない)。
- 残響: 場所の広さ(洞窟・屋外)を粗い層と細かい層の占有から見積もり、残響の設定を切り替える。

## 3. 入力への即時の反応
- 足音・道具を振る音は、入力を受けた瞬間に CPU が見込みで鳴らす。GPU の結果(実際に何を踏んだか)が届いたら、次からそれに合わせる。

## テスト
- イベントの並びとミキサーの選び方が、同じイベント列で同じになる(音の再現。決定性は必須ではないがデバッグのため)。
- 大量の炎で声の数が上限に張り付いても、途切れやポップノイズが出ない。

## 研究と打ち切り条件
- R-AUDIO-1 RT Audio(音の伝播を DXR で): 第 1 段の遮りと残響で足りなければ着手。1 チャット分で効果が聞き分けられなければ見送る。
