## 1. 今の支えの法則の組み方(確かめた)
- **3 次元の支えの法則は無い**。sim/support_law は縦の面(x と上)・奥行 1 セル・節 3 成分(x・上・回り φ)だけ(support_law.h の冒頭・`SUPPORT_COMPONENTS = 3`)。
  3 次元(変位 3 + 回り 3・ねじれ)は **T-0960(Todo。ROADMAP の試作の列 3・T-0944 から分けた)**。共通部品の側は 3 次元を受けられる
  (equilibrium_block・GPU 版とも k = 6 まで〔`EQB_MAX_COMPONENTS = 6`〕・色は (x, y, z) の奇偶 8 色 × レベル 16 色)。
  → 「3 次元の CPU で形 A を選べる形にし 3 次元の場面で測る」は、3 次元の場面が今は作れないので **できない**(並走の作業役が T-0960 を代わりに作るのは範囲の外)。
  代わりに、項の 3 次元の読み方を下に書き、T-0960 の完了条件へ足すよう司令塔へ回す。
- **GPU 版はある(解くところだけ)**: 支えの系(SupportLaw の Coupled。k = 3)を成分を持つ節の GPU 版 GpuEquilibriumBlock(T-0970・ADR-0422)で解く。
  段 0 の係数(面の 3 × 3 のブロック・固定した面・重さ)は CPU の系(`SupportLaw::BlockSystem()`)を写す(RecordUpload)。GPU が自分で段 0 を組むのは
  **T-0981(Todo)**。形 A の項は CPU が組む面(C の隣 N と対の細かいセル L・U の間の斜めの面。T-1278)に入るだけなので、GPU の側に足す式は無い。

## 2. 形 A の項の 3 次元の読み方(机の上。T-0960 で入れる形)
2 次元(T-1278): 粗いセル C の面(法線 n)に並ぶ対 L・U(並ぶ向き p。n ⊥ p)。面の点の p の向きの相対の動き P = (t_U + 回りの分) − (t_L + 回りの分)。
C の p の向きの隣 N(両側。固定した面の側は壁)の中心の差から、C の面の高さ(C の中心から n の向きへ ± s)の繊維の p の向きの歪み m を読み、
側ごとに ½ (K_q ÷ 読める側の数) (P − 側 × m)²(K_q = 対の負の項で外した硬さ K と C の材料の硬さ 6 b_p の直列)。
- **3 次元の対**: C の面(法線 n)には細かいセルが 2 × 2 = 4 つ並ぶ(並ぶ向きは面の中の 2 つ p・q)。ADR-0485 の対のずれの負の項は、面の中の 2 つの向きの
  隣り合う 2 つずつ = p の向きの対 2 組(q = −・+ の列)と q の向きの対 2 組(4 つの辺)に置く(ROADMAP の T-0960 の行の「対は 2 × 2 の 4 つ」)。
  形 A の項はこの**対ごと**に、2 次元と同じ式で置く:
  - p の向きの対(L・U が p の向きに並ぶ): P = 面の点の p の向きの相対の動き(変位 p 成分の差 + 回りの分。面の点は C の中心から n へ ± s・q へ ± s/2 にあるので、
    面の点の p の動きは t_p + (ω × r)_p = t_p + ω_q r_n − ω_n r_q。2 次元の σ ε φ が ω_q r_n にあたり、3 次元では **ω_n r_q(q の列の位置 ± s/2 の分。面の中のねじれ)**が増える)。
    目標 m = C の p の向きの隣 N(両側)から読む繊維の歪み: 繊維 f = t_p + ω_q r_n − ω_n r_q を C と N で同じ (r_n, r_q) で読み、m = d (f_N − f_C) ÷ 2(固定した面は −d f_C)。
    同じ (r_n, r_q) で読むので、一様な歪み 6 つ・回り 3 つ・一様な曲げ・ねじれでは P = 側 × m(今と同じ = つぎはぎの検査を壊さない)。
  - q の向きの対: p と q を入れ替える(隣は q の向き)。
- **どの隣・どの面**: 隣は C の p(または q)の向きの 2 つの粗いセルだけ(n の向きの隣は読まない。対の相対の動きは面の中の向きの歪み)。
  項の節は L・U・C・N の 4 つ。L・U の親(粗い座標。C の n の向きの隣)と N は、n と p(q)の 2 つの軸で 1 ずつずれた**辺の斜め**(粗い座標の 27 点の中・レベルの差 1。
  近い方の細かいセルは N と辺で接し、遠い方は接しない)。2 次元と同じく共通部品の面の約束(隣のレベルの差 1)の中に入り、レベルが違うので色も違う
  (混ざる段は座標の奇偶 8 色 × レベルの奇偶。同じ色の節が隣にならないことは GPU の試験の SameColorLink が 2 次元で確かめている)。
- **面の数**: 2 次元は対ごとに 側 2 × 節の組 6 = 最大 12 の面(実際は C–L・C–U・L–U が既にあり、足すのは N–L・N–U・N–C の分)。3 次元は対が面ごとに 4 組
  (2 次元の 2 倍)なので、C の面 1 つあたり最大 48 の面の項(新しい節の組は N–L・N–U の斜め。N–C は軸の面で既にある)。系の節の数・解く回数は同じ。
- **曲げ(形 B)は 3 次元でも入れない**(T-1278 で外れ)。対の曲げの差の負の項(ADR-0501)は回り 3 成分の差に T-0960 で(ROADMAP の T-0960 の行のまま)。
- 未確認(T-0960 で測る): 3 次元の根の角・洞窟の天井・自重の塊での縁の力とつぎはぎの検査。ねじれ(ω_n r_q)の分は 2 次元に無いので、
  ねじれの一様な場面(片持ち梁の先にねじりの荷)でも P = 側 × m になることを試験に足す(机の上ではなる: f を同じ (r_n, r_q) で読むので)。

## 3. GPU と CPU のビット一致(形 A。2026-10-30・wt3・release)
- gpu_equilibrium_block_test の違う大きさのセルの場面を **None と NeighborStrain の両方**で流すようにし、壁と梁の根の線の両側の 2 場面を足した(7 場面 × 2 形)。
  場面の壁と梁(WallBeam)は support_mixed_test から tests/support_scenes.h へ移した(GPU の試験と共有)。
- **HW(RTX 3070 Ti・compute キュー)**: 7 場面 × 2 形が毎刻み CPU とビット一致(逆順に積んだ GPU も・ハッシュ一致)。ctest gpu_equilibrium_block 合格(12.6 秒)。
- **WARP**: 同じ 7 場面 × 2 形が 10 刻み毎刻みビット一致(逆順も。57 秒)。
- 新しい GPU の式は無い(CPU が組んだ面のブロックを写すだけ)ので、64bit の引き算などの注意に当たる所は増えていない。
- **費用(GPU・RTX 3070 Ti。`--measure`)**: 洞窟 0.5 m の天井と空洞の縁を 0.25 m(1288 節): None 1.884 ms(V 2 回)/ 1.955 ms(支えの既定 = V 2 回 + 刻みをまたぐ共役勾配)・
  隣 9092 → 形 A 2.156 / 2.232 ms(**+14 %**)・隣 9736(+7 %)・段を作る 0.870 → 1.128 ms・VRAM 1.5 → 1.6 MB。Dispatch の数は同じ(298)。
  増えるのは粗い段の隣(Galerkin で斜めの面が粗い段へ広がる)の分と見ている(未確認)。全部 0.5 m の 832 節の洞窟は 1.384 ms(T-1104)。

## 4. 既定を形 A にした時の CPU の試験(仮に既定を変えて流した。コミットはしていない)

  _refine 156 s・_refine_scenes 466 s・_settle 252 s・warm_start_save 80 s。並べて流した時間)。

  既定を変えれば ctest support_mixed も形 A で流れ、根の線の 2 場面の線 5 %(T-1278)が効く(今は support_mixed_neighbor_strain が `--pair 3` で同じものを流す。
  既定を変えたら support_mixed_neighbor_strain は support_mixed と同じになるので、`--pair 0` 〔今の形の記録〕に変えるか消す)。
