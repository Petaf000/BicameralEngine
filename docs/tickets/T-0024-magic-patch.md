## 目的
魔法 = 反応則そのものへの介入(CLAUDE.md §0)の最初の形として、空間の範囲と時間に限って規則の速さを変える(止める・速める)パッチを、
コマンドとして記録・再生でき、GPU と CPU が毎刻みビット一致し、保存則を壊さない形で入れる。**値はすべて試験用の仮のもの(D-006)。**

## 分け方(始める前に機能単位で分けた。順は 02 §5 の並び〔パッチ → 発動〕に従う)
1. **T-0024(この段)**: パッチの核(形・範囲・期間・速さの倍率と止める)+ 多重解像度の刻みへの組み込み(CPU と GPU)+ 実験室のコマンド + 試験
2. T-0287: 世界のコマンドの段にパッチ(仮の世界・ゲーム本体のコマンド・境のつつきを刻みの段に・活性の種・保存点・規則を名前の鍵で)+ エディタの UI
3. T-0288: 触媒(活性化エネルギーを下げる = 速さの表を GPU で作り直す)と転換(生成物の差し替え。保存則の検査をベイクと同じに)
4. T-0289: 湧き出し・吸い込み(明示的な出入りと帳簿)と魔法の発動(魔素の消費・物質とエネルギーと運動量の放出・反動と熱を物へ。08 §4・D-420)

## 作業ログ
- 2026-10-11(作業役・wt3): 設計の §5 の順(パッチ → 発動)に従い、最初の段をパッチにした(おすすめの順と同じ)。速さの表が「仮数 × 2^指数」
  なので、増幅は指数に足すだけ・阻害は 0 にするだけで、どの機械でも同じ整数になる。核(reaction.hlsli)は変えず、Table の包みで重ねた。
  ルート署名に空きがないので、u5(外のバッファの枠)を刻みの間だけパッチの列に結ぶ(外のバッファを使う Compute は今までどおり)。
- ビルドは debug で 1 回目から通った(HLSL のテンプレートの構造体の包みも DXC 2021 で通る)。
- テスト: (下の「テストの結果」)。HW の食い違いの切り分けに範囲の比べを符号なしの比べにして試したが変わらず(戻した)。2 時間の約束で止めた。
- 2026-10-11(作業役・wt3、2 体目): **HW の食い違いの原因 = lab_box.hlsl が規則の数を `g_rules.GetDimensions` で読んでいた**。g_rules はルートの SRV
  (記述子の表ではない)で大きさを持たず、読むと未定義(WARP は正しく読め、NVIDIA は 0 などを返す)→ GPU だけパッチが「規則が表の外」で断られ、
  止める範囲の最初のセル (1,1,1) が刻み 0 から燃えていた。Work Graph の仮説は外れ(実験室の刻みは伝導つき・活性でない = Compute だけ)。
  直し方: GpuLabBox が表の規則の数を g_external3 で渡す(表の差し替えでも持ち替える)。シェーダーで GetDimensions を使う所は他に無い。
- 同じ回: 状態の要約(HashWholeNest)に効いているパッチの語を入れた(列が空なら前と同じ値 = 今までの記録のハッシュは変わらない)。
  食い違いの欄の名前に「魔法のパッチの列」を足した。lab_box_test の TestMagicPatch に要約の確かめを足した。
- 同じ回(別のコミット。T-0287 の最初の一部を前倒し): **パッチは規則を名前の鍵(RxRule::key・64bit)で持つ**ようにした。列の 1 つ分は 13 語、
  コマンドの payload は 10 語。足す時は表に同じ鍵の規則があるかを調べ(無ければ断る)、評価は Rule(id).key と比べる(覆うパッチがあるセルだけ)。
  LabSession::ApplyPatch は今の表の規則の ID を受け、鍵にしてコマンドに入れる。lab_box_test に「規則の並びを逆にした表でも同じ名前の規則にだけ効く」を足した。

## テストの結果
- debug・6 ランナーが同じ GPU を使う中: multires・multires_wide・multires_activity・multires_uniform・lab_box(TestMagicPatch を含む)・
  gpu_lab_box_warp(RunPatch を含め WARP で毎刻み CPU とビット一致・止める / 速めるが効く)は通過(6 / 7)。
- **gpu_lab_box(HW)は RunPatch だけ落ちる**: 「刻み 0 のセル (1, 1, 1) が違う」(止めるパッチの範囲の最初のセル)。RunPatch より前の場面(火・再生・
  表の差し替え・物質の差し替え・仮の魔素)は HW でも通る = パッチが無い時の刻みは HW でも今までどおり。
- (解決済み)HW の食い違いの仮説は 3 つ立てたが、どれでもなかった。原因と直し方は作業ログの 2 体目の行。

## 引き継ぎメモ
- パッチは規則を**名前の鍵**(RxRule::key)で持つ(T-0287 の最初の一部を済ませた)。替えた表に無い名前の規則のパッチは何にも効かないまま期間が終わる。
  GPU で表を替えた刻みを跨ぐパッチの場面(gpu_lab_box で刻みの途中の差し替え + パッチ)はまだ試験していない(T-0287 で足す)。
- 状態の要約(HashWholeNest)・記録のハッシュに効いているパッチの語が入った(列が空なら前と同じ値)。
- **ルートの SRV / UAV に GetDimensions を使わない**(大きさは定数で渡す。WARP だけ通って HW で落ちる)。
- 粗いセルはパッチの範囲に少しでも重なれば丸ごと効く。範囲がセルより小さい魔法を正しく効かせるには、範囲を細かくする要求を出す(T-0287)。
- 多重解像度の世界(実験室以外)では、境でつつく段がまだ無い = パッチの始まり・終わりに眠っているブロックは、次に起きるまで変わった速さを
  使わない(実験室の箱はつつくので正しい)。T-0287 で世界のコマンドの段に入れる。
- 列が一杯(16)の時は断る(CPU と GPU で同じ)。断ったことを数える欄はまだ無い(実験室は当てた数で分かる)。

## 判断待ち
- **魔法の強さの刻み(倍率を 2 の冪にするか)**(仮・ユーザー未確認。取り消しやすいので仮で進めた)
  - 案 A(仮で採用): 速さを 2^shift 倍(×2・×4・…・×1/2…)と止める。遊びへの影響: 魔法の強さが倍々の段で決まる(「2 段強い触媒」)。
    プレイヤーは強さを段で比べて法則を見つけやすい。細かい強さ(×1.5)は作れない。
  - 案 B: 有理数の倍率(仮数に掛ける)。遊びへの影響: 強さを連続に作れる(魔石の質で ×1.3 など)。決定性は同じに守れるが、端数の丸めが増える。
  - おすすめ: A で始め、魔法具の性能(18 §3)が「形から連続に決まる」必要が出たら B を足す(列の語は空きがあるので形を変えずに足せる)。
- **範囲の当て方**(仮): セルが範囲に少しでも重なれば効く。遊びへの影響: 遠く(粗い所)で小さい魔法を使うと、粗いセル丸ごとに効く(効く範囲が広く見える)。
  案: 範囲を細かくする要求を出して細かいセルにだけ効かせる(T-0287)。おすすめ: 細かくする要求(D-428 に近い)。
