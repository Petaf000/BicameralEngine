## 目的(1〜2 行)
多重解像度の木の上で、セルどうしの熱の伝導を 3D で計算する。レベルの違う面(粗いセルと細かいセル)でもエネルギーをビット単位で保存し、
活性(種とその面の隣だけ刻む)でも全部を刻んだ時とビット一致する。まず CPU リファレンス(GPU は T-0107)。

## 分けたもの(2026-10-05。CLAUDE.md §3「始める前に機能単位で分ける」)
- **T-0019(これ)**: CPU リファレンス・式(shaders/common/multires_conduction.hlsli。GPU も同じ関数を呼ぶ)・テスト・計測。
- **T-0107**: 熱の伝導を GPU に(活性の Work Graph と全部を刻む Compute。CPU と HW・WARP でビット一致。ルート署名が 63 / 64 語なのでバッファをまとめる)。
- **T-0108**: 細かいレベルの刻み(17 §4「局所の時間刻み」)。面の係数が熱容量の上限(1/8)で止まるレベル(下の計測)より細かい所で、熱の伝わり方が遅くならないようにする。

## 完了条件(チェックできる形で)
- [x] セルの 6 面の先を木から探す(同じブロックの中・外は索引で上へ。細かい側に覆われた面は細かい側が計算する)。総当たりの幾何と一致
- [x] 面の係数をレベルの単位にする(コンダクタンス × 4^k、熱容量の上限はそのまま)。違うレベルの面は細かい側の単位で、粗い側の上限 × 2^d

- [x] 閉じた箱: エネルギーの合計が毎刻み一定・温度の幅が広がらずに縮む

- [x] 計測: 面の係数が熱容量の上限で止まるレベル・静かになった後に残る頁(T-0104・T-0108 の材料)

## メモ・参考
- 式と面の隣: shaders/common/multires_conduction.hlsli。CPU: engine/src/sim/multires_conduction.cpp(MarkConductionWants・ComputeConduction)と
  multires_nest.cpp の StepBlocks(StepNest・StepActive が共有)。選択は `MultiresStepOptions{.conduction = true}`(GPU と比べる刻みは切ったまま)。
- 1 刻みの順: 一様なブロックの「変わるか」(反応・伝導の流れ・細かい側から送られてくる面)→ 頁を枠の順に配る(足りなければ凍らせる)→
  端数の枠を枠の順に配る → 面の流れ(刻みの初めのセルから。Jacobi 型)→ 変化を足す → 反応。
- 違うレベルの面の扱いの比較(Claude が決めた。ADR-0017): (A) 木を 2:1 に保つ(隣のレベル差を 1 以下)= 木の管理と GPU を作り直す /
  (B) 粗い側の端数で受ける = 採用 / (C) 粗い側の単位で切り捨て = 細かい所との間で熱が止まる(嘘)/ (D) 確率的な丸め = d ≥ 7 くらいで 1 単位が細かいセルの熱より大きく、壊れる。
- 種(活性): 進める規則があった、またはセル(か端数)が変わったブロック。違うレベルの面で送れない量(端数の枠なし・3d > 64)は送らないので、変わらなければ眠る。
  「流れがあるのに眠る」は起きない(流れは刻みの初めのセルだけで決まり、変わったセルは種になって隣を起こす)。

## 計測(2026-10-05、debug の CPU。tests/multires_conduction_test.cpp のログ)
- 面の係数が熱容量の上限(1/8)で止まる最初のレベル: **試験の表では空気・木箱とも k = 3(6.25 cm)**。現実の伝導率なら空気 k = 9(1 mm)・木箱 約 k = 11。
  それより細かいセルでは、1 刻みに隣へ渡せる熱が 1/8 で頭打ちになり、熱の伝わり方が本当より遅い(T-0108)。
- 鎖(6 段・いちばん細かいブロックが 1500 K): 120 刻みで根(レベル 0)のセルまで熱が届く。端数の枠なしだと細かい所に熱がこもる(世界の最高 313.7 K ↔ 枠あり 304.7 K。160 刻み)。
- 静かになった後に残る頁(鎖 + 頁を畳む + 静かな葉を粗くする): 1200 刻み(20 秒)たっても 14 → 10 ブロックが頁を持ち、どれも種のまま(流れが 0 にならない)。
  頁の中の温度の幅は 300 刻みで 47 mK、900 刻みで 3 mK、1200 刻みで 2 mK(エネルギーで 443 単位)。整数の流れは ΔT がほぼ 1 mK 未満になるまで止まらないので、
  ビット単位で同じには戻らず、静かにもならない(T-0104 の許容差・D-430 の判定で扱う)。
- たくさんの要求の場面では、粗い側が端数の枠を全部使い切った(64 枠・不足 3481 回)。端数の枠は伝導で増え、木の変更でしか返らない(T-0107 で容量の考え方を決める)。
