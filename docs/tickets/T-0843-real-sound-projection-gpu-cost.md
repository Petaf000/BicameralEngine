# T-0843 本物の音速の投影(V 2 回固定・外側 0)の 1 刻みを GPU で測る(設計の賭け 1 の T-β)

- Status: Done(測った。採るかは司令塔 → ユーザー)
- 種類: 工学(測り)
- PC: 必須(ランナーで release のビルドと GPU の実行)
- 見積もり: チャット 1 回分(2 時間)
- 関係: T-0842(CPU の模型で有界を確かめた)・T-0531(投影の解く部分の GPU)・T-0587・T-0606(V の段ごと)・T-0226(陽解法の気体の費用)・docs/design/07 §2.6

## 目的
T-0842 で「本物の音速 340 m/s(C = V/c²)の陰解法を V 2 回固定・外側の反復 0 回で解いても発散しない」と分かった。
この 1 刻み(式を作る・V 2 回固定・当てる・運ぶ)が GPU で何 ns/セルかを測り、陽解法(小刻み 24。約 230〜290 ns/セル)と比べる。合格の目安(設計役の紙の値)は箱で ≤ 60 ns/セル。

## 完了条件
- [x] GPU の投影の解き(GpuImplicit::RecordSolve)に、V を判定で止めずちょうど回す口(GpuImplicitRecordShape::fixedCycles)を足す。既定の値・既定の道は変えない
- [x] CPU の模型(StepGasProjection。fixedCycles・solver.cycles = 2・outerIterations = 1・音速 340 m/s)の解きを GPU で解き直し、値と V の回数がビット一致
- [x] 箱 32³・64³・128³ で V 2 回の時間、計画の表を毎回作り直す固定費を別に記録
- [x] 比べ: 陽解法の気体(gpu_gas の箱・小刻み 24)と、小刻み 1 つの段を前から足した時間(式を作る・運ぶの見積もりに使う)
- [x] docs/perf.md に記録

## 足した口(既定は切ってある。既定の道は前のまま)
- `GpuImplicitRecordShape::fixedCycles`(engine/src/sim/gpu_implicit.h): V の前と各 V の後の止める判定(ImSolveConverged・ImSolveCheckEnd)を積まず、
  ImCycleEnd は数えるだけ(tolerance 0)。CPU の `GasProjectionOptions::fixedCycles`(T-0842)と同じ回し方。
- `GpuImplicit::InvalidatePlan()`(計測用): 次の解きで段ごとの計画の表(ImPlanLevels・ImPlanColors)を作り直させる。
- `gpu_gas_projection_test --t0843 [--edge n] [--ticks n] [--stages]`: 5 場面(泡・扉・爆発・孔のある壁・細孔の板)× 音速 340 だけ、一辺 32・64(--edge で 1 つ)。
  1 刻みに解き 1 回(外側 0)・V 2 回。暖機 12 回の後 16 回の最小。「V なし」= cycles 0(計画の引数と初めの状態だけ)、「計画」= 解きのたびに計画の表を作り直した時の差。
- `gpu_gas_test --t0843`: 32³・64³ で 小刻み 24(全部の段)と 小刻み 1 の段 1・3・9(`--passes`。Profile でも効くようにした)。

## 結論
1. **GPU の 1 刻みは 64³ で約 21〜30 ns/セル、32³ で約 28〜40 ns/セル(見込みを含む)。合格の目安 ≤ 60 ns/セルに入る。**
   測った部分だけで 64³ 18・32³ 25 ns/セル。陽解法(小刻み 24)の 228 / 263 ns/セルに比べて **約 8〜10 倍速い**。最適化は要らなかった(試していない)。
2. V 2 回は 64³ 以上で 5〜7 ns/セル(最も細かい段の赤黒の掃き出しが 6 割強)。32³ は段の数(Dispatch とバリアの床)と ImTail(T2 62.5 µs/V)で 12.5 ns/セル。
3. 運ぶ部分(約 9〜10 ns/セル)は陽解法の小刻み 1 つ分と同じで、1 刻みの最大の部分の一つ。T-0842 版 2 の局所の小刻み(上限 8)を入れると、
   出ていく量の多いブロックだけこれが増える(CPU の模型で +3〜16 %)。
4. 計画の表は系の形(セルの空き・つながり)だけで決まるので、形が同じ刻みは作り直さない(T-0606 のまま)。形が変わる刻みは 64³ で +1〜2.5 ms。

## CPU とのビット一致
- V 2 回固定の解き: **一致**(32³・64³・128³ × 5 場面の全部の解き。値と V の回数)。
- 式を作る・当てる・運ぶ: **確かめられない**。投影の式を作る段・当てる段の GPU 版はまだ無い(T-0531 の残り)。運ぶ部分の代わりに測った陽解法の段は
  陽解法の CPU リファレンスとビット一致する(gpu_gas の試験)が、投影の刻みとしての一致ではない。

## 残り(司令塔へ。採るなら別チケット)
- 投影の 1 刻みの GPU 版(式を作る〔係数・右辺・多重格子の段の重みを GPU で〕・当てる)を書いて、通しの ns/セルと CPU とのビット一致を取る。
  未測の 3 つのうち一番大きくなりうるのは多重格子の段の重みの作り直し(GpuImplicitLevels の形。T-0135 の小さい場面では節あたり 20 ns 前後と遅延に縛られていた)。
  これが 64³ で 8 ns/セルを超えても合計は約 30〜40 ns/セルで目安の内。
- GpuGas が 128³ で作れない理由(未確認)。
