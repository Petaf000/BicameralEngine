# T-0558 1 セルに書ける量の上限(セルの器)

> **司令塔がマージで見る所(セルの形は変えていない)**
> - 量の型・単位・VRAM・ハッシュ・GPU のセルの形は**変えていない**。上限の定数を `shaders/common/units.hlsli` に 2 つ足した
>   (`CELL_AMOUNT_LIMIT_MICROMOLES` = 2^36・`CELL_GAS_AMOUNT_LIMIT_MICROMOLES` = 2^31)。
> - `engine/src/sim/gas_internal.h` の `MAX_CELL_AMOUNT` を 1 行だけ別名に(値は同じ)。**wt2 T-0591(気体の成分の上限)が同じファイルを触るなら衝突は 1 行**。
> - `shaders/common/probe_place.hlsli`: 置くコマンドの上限が「1 物質 2^36」→「合計 2^36」(GPU のシェーダーが変わる)。
> - `sim::CheckCellAmounts`(reaction_table.h/.cpp)を world_layout.cpp・material_templates.cpp が呼ぶ。
> - **wt6 T-0027(水)へ**: 量の上限は「合計 2^36 µmol・気体のぶん(condensed でない物質の合計)2^31 µmol 未満」。水が湯気(condensed でない)になると
>   1 セルいっぱいの水 6917 mol は気体の器 2147 mol を超える → 気体の式の assert(T-0601)。

## 目的(1〜2 行)
1 セルに書ける量を、凝縮相の現実の密度(水 6917 mol・砂 3121 mol / 0.5 m 角)まで広げる。上限を入口ごとにばらばらに持たず、1 つの芯(セルの器)にする。

- [x] 誤りの試験(合計・1 物質・気体のぶん・材料)= world_layout_test。置くコマンドの合計 = gpu_probe_place_test(CPU と GPU)
- [x] release のビルド(警告 0)・archmap --check

## 根っこから見た所(調べた結果)
| 見た所 | 結果 |
|---|---|
| 量の型 | セル(RxCell・RxWideCell・多重解像度)は全部 uint64 µmol。2^31 は **world_cells を読む所の上限だけ**(気体の式の器を写したもの) |
| 気体の式 | 2^31 は「移す量を Q32 の 64bit で」の器。気体はセルの condensed でない物質だけ(ADR-0256)→ 凝縮相に掛かる理由は無い |
| 反応の評価 | 反応物の量の積は 128bit(RxSplitRate)・望む進行度は RX_EXTENT_SATURATION(2^62)で頭打ち・自分の量で上限 → 2^36 で溢れない |
| 熱・化学の和 | 熱容量 Σ 量 × 比熱(uint64。確かめなし)・化学 Σ 量 × H0(int64。assert)。合計 2^36 なら比熱 2^27・|H0| 2^26 まで入る(現実の値は比熱 < 2^20・|H0| < 2^23) |
| 伝導 | 伝導率の重み Σ 量 × 伝導率は 128bit。合計は uint64 |
| 多重解像度 | 親 → 子の分配は量 << 3 が溢れないことを assert(< 2^61) |
| ハッシュ・VRAM・GPU との一致 | 量は前から uint64 で入っている → 変わらない |
| 置くコマンド | 前から 1 物質 2^36(ADR-0067)。材料のひな形は 2^53 で実質なし |

## 案と作り手から見た違い(判断待ち A)
- **A(おすすめ・仮で採った)セルの器 1 つ・合計で数える**: 合計 2^36(68,719 mol)・気体のぶん 2^31(2147 mol)。
  作り手: 凝縮相は「1 セルに約 6.9 万 mol まで」の 1 文で読める(混ぜた中身も同じ)。気体は今まで通り。置くコマンドは合計で数えるので少し厳しくなる。
- B 相で分けて 1 物質ごと(凝縮相 1 物質 2^36・気体 1 物質 2^31): 作り手: 物質ごとに上限を覚える。気体を何種類も混ぜると 1 物質ごとには守っても気体の式の器を超える。
- C 上限なし(和を 128bit に): 作り手: 何でも書けるが、物理的に意味の無い密度まで通る。反応・伝導・GPU の熱の和の型が全部変わる。
- D 凝縮相だけ単位を mmol に: 作り手: 物質の相で量の単位が変わる(world_cells の数の意味が相で違う)。保存の帳簿が崩れる。

## 判断待ち(仮で進めた。ユーザー未確認)
- A. 上の案 A(ADR-0260)。
- B. **器の大きさ 2^36(約 1.9 × ダイヤモンド)でよいか**。作り手から見た違い: ゲームの物質に現実より詰まった物(ダイヤモンドの 2 倍を超える mol/L)を書くなら足りない。
  広げる道は、物質の表の比熱・H0 の上限を締めて(T-0600)器を 2^38〜2^40 にすること。おすすめ: 2^36 のまま(現実のどの固体も入り、和の見積もりに余裕がある)。

## 分けたもの
- **T-0600**(工学・約 1 時間)物質の表の上限をセルの器に合わせる: 比熱は 2^32 mJ/(mol·K)・H0 は 2^53 J/mol まで書けるが、合計 2^36 の和が 64bit に収まるのは
  比熱 2^27・|H0| 2^26 まで。物質の表の読む所で締める(作り手: 比熱 134 kJ/(mol·K)・|H0| 67 MJ/mol を超える物質が書けなくなる。現実の値は十分下)。
  RxHeatCapacity に溢れの assert を足す。
- **T-0601**(工学・設計あり)走っている間に気体のぶんがセルの器(2^31)を超える場合: 凝縮相が気体になる反応(水の蒸発・燃焼の生成物)で、
  セルいっぱいの水 6917 mol が湯気になると 2147 mol を超え、気体の式の assert(release では Q32 の溢れ)になる。現実では蒸気圧で止まる。
  案: 反応の速さに気体のぶんの圧力の上限を効かせる(相変化の規則の中身)/ 気体の式の器を 128bit に広げる / 器を超えた分を流れで先に逃がす。T-0027(水)と一緒に決める。
  置くコマンドも気体のぶんは確かめていない(GPU の表に相が無い)ので同じチケットで。
- 名前だけ: エディタの材料の行(material_rows の入力の上限 1e9 mol)と実験室の詰める量(lab_box)はセルの器を見ていない(置く・詰める時に飛ぶだけ)。表示で器を出す。
