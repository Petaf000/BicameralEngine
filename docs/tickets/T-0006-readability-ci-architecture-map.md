# T-0006 見せられるリポジトリにする(規約・CI・クリックできるアーキテクチャ図)

- Status: Done
- 種類: 工学
- PC: 必須(方針の相談だけなら不要)
- 見積もり: チャット 2〜3 回分

## 目的
他人に見せたりポートフォリオにしたりできるように、コードの読みやすさ・自動検証・全体像の見えやすさを整える。
ユーザーの要望(2026-09-29): 改行やコメントで読みやすく / CI/CD を考える / システムの流れをグラフで詳細まで /
グラフの機能をクリックするとそのコードに飛べると尚良し。

## 決めること(ユーザー)
1. GitHub に置くか・公開するか(CI と図の公開先が決まる)。push はユーザーが行う。
2. 図の作り方(下の案から)。
3. 整形の流儀(.clang-format のベース。今のコードは 2 スペース・Google 風)。

## 案(Claude の提案。未確認のものは確かめてから使う)
### コード規約
- `.clang-format` と `.clang-tidy` を置き、CI で整形ずれと警告を落とす。規約の要点は CLAUDE.md §4 と docs/style.md に。

### CI(GitHub Actions)
- windows-latest でビルド(release/debug)+ CPU テスト(ctest)+ 整形チェック。
- GPU を使うテスト: ホストのランナーには GPU が無い。
  - 案 1: WARP(ソフトウェアの D3D12)で回す。WARP が Work Graphs に対応しているかは**未確認**。
  - 案 2: ユーザーの PC をセルフホストランナーにする(常時起動が要る)。
- CD: タグを付けたらビルド済み zip を Releases に、ドキュメントサイトを GitHub Pages に出す。

### クリックできるアーキテクチャ図
- 案 A: Doxygen + Graphviz。クラス・インクルード・呼び出しの図を自動で作り、図のノードがソースのページへリンクする。
  手間が少なく詳細まで出るが、「システムの流れ」(フレームの中で何がどの順に走るか)は描けない。
- 案 B: 手書きの流れ図(Mermaid)を docs サイトに置き、各ノードを GitHub のソース行へのリンクにする。
  GitHub の README 上の Mermaid はクリックが効かない(**未確認**)ので、Pages のサイトで見せる。
- 案 C(推し): B の図の定義を `docs/architecture/map.yaml`(ノード → ファイル:シンボル)に書き、
  CI がシンボルの行番号を解決して図を生成、リンク切れ(関数の移動・改名)を検出して落とす。A の自動図も併設。
  → 図がコードとずれない。見せるときに一番効く。
