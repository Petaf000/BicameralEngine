## 目的(1〜2 行)
層の流れの GPU(object_shell_flow.hlsl)は、1 つのセルに燃える物が 2 つ以上あると ⑨ ExchangeWithCell が g_cells[object.cell] を物のグループごとに同時に読み書きして決定的でなかった。
司令塔の照らし(docs/design/21 §3・ADR-0500)の通り、新しい口を足さず「書き手の作業 → 集めて書く段」の形で直し、CPU とビット一致にする。

## 完了条件(チェックできる形で)
- [ ] 1 つのセルに物 2・3・8 個(2 セル + 1 個・物ごとに熱い層の温度を変える)で CPU と GPU HW / WARP がビット一致
- [ ] GPU を 2 回回して状態のハッシュが同じ(回ごとに変わらない)
- [ ] 今の比べ(物ごとに別のセル 2 枚 × 圧力の規則 4 × 置き場 2)がビット一致のまま・object_shell(CPU)が通る
- [ ] release ビルド警告 0・float_check・dxil_alloca_check・archmap --check

## 形(作り手から見た違い)
- **物の刻み**(OhShellFlowTick・CPU の StepShellFlow): 囲むセルを読むだけ。刻みの初めにセルを物ごとの見立て(g_cellViews・OhShellFlow::cellView)へ写し、
  小刻みごとの自分の粗い量だけをそこへ当てて次の小刻みが読む。セルへ渡す粗い量は物ごとに貯める(g_exchanges・OhShellFlow::toCellCoarse)。
- **集めて書く段**(OhShellApplyCells・CPU の ApplyShellFlowToCells): セル 1 つ = 1 スレッドで、物の順(g_ranges = 登録の順。物の熱の OhApplyCells と同じ並び)に足して 1 回だけ当てる。
  変わったセルの段の番号は刻みの最後の段(g_passBase + 物の数 = CPU の world.pass)。セルが実際に変わった時だけ(粗い量の和が 0 でない時。物の熱の ④ と同じ)。
- 作り手から見た違い: **同じセルの物どうしは、同じ刻みの中では互いの出し入れを見ない**(刻みの初めのセル + 自分の分。世代同期 ADR-0003 と同じ)。前の CPU は物の順に当てていたので、
  後ろの物が前の物の出し入れを見ていた(= 物の登録の順で結果が変わる形)。物 1 つのセルでは見る値は前と同じで、セルへ当てる時だけ「小刻みごと 4 回」→「刻みの終わりに和を 1 回」。
  整数の足し算なので、和の結果は物の順にも依らない(順が効くのは、セルに無かった気体を 2 つ以上同じ刻みに足す時の成分の並びと、量が負になった時の数え上げだけ)。
- 費用: 刻みに Dispatch 1 回(セルの数 ÷ 64 グループ)とバリア 1 回が増える。ルート署名 52 → 59 語(u12 u13・t8・ルート定数 1)。

## 土台の印(司令塔へ)
- 研究の形の平らなセルでは、集めて書く段 = 物の熱の ④ と同じ「セルごとの物の範囲(OhCellRange)を回る段」。エンジン(多重解像度の木)へ入れる時は、物ごとの粗い量を
  ADR-0500 の「この刻みだけ」の欄(エネルギー + 気体 8 = 9 値。SF_MAX_COMPONENTS 12 の内)へ書き手の作業として足し、共通の集めて書く段 → 当てる段で当てる形になる見込み。
  共通の段は触っていない(この研究の形の中だけ)。物の熱の ④(OhApplyCells)と層の流れの集めて書く段は同じ形なので、エンジンへ入れる時に 1 つにまとめられる(T-1331 の段 2 で一緒に見る)。
