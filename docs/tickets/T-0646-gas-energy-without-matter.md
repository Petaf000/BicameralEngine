# T-0646 気体の区画で、物質の無い負のエネルギーが残る(強い流れの押し出す仕事)・段の外で気体の質量が変わった時の運動量

- PC: 必須

- マイルストーン: ROADMAP の T-0027(水)・T-0611(相変化)・⑤ の場面
- 設計: docs/design/07-transport.md §2(共通の形の 4)/ 決定: ADR-0286(この チケット。Proposed)・ADR-0256・D-465(保存則)

## 目的(1〜2 行)
T-0611 の湯気の場面で、気体の区画のエネルギーの合計が +54 kJ ずれた(元素は保存)。根っこを探して一つの芯で直し、毎刻みビット単位の保存に加えて
「どのセルも熱が負にならない・物質の無いセルはエネルギーを持たない」を確かめる試験を足す。GPU の仮の世界の気体も CPU と一致させる。

## 完了条件(チェックできる形で)
- [x] main の上で再現する場面(probe_gas_test の 8: 露になる試験の規則 + 燃える木箱・熱い湯気の塊。2・6 の木箱も)
- [x] 根っこ: 出ていく割合の上限を、押し出す仕事のぶん引く側の熱が負にならない値に(CPU gas_reference の EffectiveOutflow・GPU gas_step の GasOutflow)
- [x] 段の外で気体の質量が変わった時の運動量(減ったら速さを保つ・増えたら運動量を保つ・気体の無いセルの運動量は帳簿へ。CPU probe_gas・GPU probe_gas_tick)
- [ ] probe_gas(CPU)・gas_reference・gas_projection・gpu_gas・gpu_probe_gas(GPU。毎刻み CPU とビット一致・気体の欄の質量も)
- [ ] release のビルド(警告 0)・archmap --check

## 調べたこと(2026-10-15)
- **見立て(反応が気体の質量を変えても運動量が残る)は崩れの原因ではなかった**。t-0611 の probe_phase に診断を足して測った:
  気体の段は毎刻みビット単位で保存していた(段の前後の「セル + 運動エネルギーのぶん − 帳簿」が一致)。崩れた刻みには必ず、区画の天井の近くに
  **物質がほぼ無いのに −54〜−75 kJ を持つセル**(空気 0.03 mol・熱が負)があり、probe_phase の合計が物質の無いセル(speciesCount 0)を
  数えていなかったので +54 kJ に見えた(ずれ = そのセルのエネルギーとぴったり同じ)。
- 根っこ: 気体の塊は熱の分け前に加えて押し出す仕事 n R T を持って出る(MovedEnergy)。出ていく割合の合計を 1 までしか抑えていなかったので、
  1 小刻みで 7 割(空気の c_v ÷ (c_v + R))より多く出ると引く側の熱が負になる。全部出ると物質の無いセルに −n R T が残る。
  熱が負のセルは温度 0・圧力 0 の「冷たい穴」になって、まわりを吸い込んで冷やす。
- **main の燃える木箱(probe_gas_test の 2。セルロースが 1 刻みで熱分解して気体が急に増える)でも起きていた**: 直す前は 2 秒で
  熱が負のセルが 1638(区画 3456 セルのうち)。保存の合計は全部のセルを数えるので崩れて見えなかった。
- 直した後の main の燃える木箱: 物質の無いエネルギーのセルは 0、熱が負のセルは 1638 → 22(2 秒)・20(露 10 /s・4 秒)。残りは強い爆発で、
  力積(圧力の力)が運動量を変えた後の熱が刻みの初めの温度より小さいセル(上限は刻みの初めの温度の押し出す仕事で数えている)と見ている(未確認)→ T-0647。
  煙の高さの表示(CO2 1 mol 以上の最も高い層)は 17〜18 → 2 に下がった(重心は 9292 → 8234 ミリセル。爆発の最初の刻みで押し出す量が抑えられ、
  煙が薄く広がる)。
- 運動量の合わせ直し(見立ての方)だけでは湯気の場面の崩れは 894 → 1145 刻みに遅れただけ。出ていく割合の上限を足すと 20 秒崩れない
  (t-0611 の probe_phase。液体を重ねた記録も 660 刻みまで保存。ただし下の「重なり」の 3)。

## 判断待ち(仮で進めたもの)
1. **ADR-0286(Proposed)**。作り手から見た違い: 強い爆発・急な蒸発で、セルの気体が 1 刻みで抜けきらず少し遅れて抜ける(空気なら 1 小刻みに 7 割まで)。
   雲(気体の中で凝縮した露)の運動量は、凝縮した時に世界の外(帳簿)へ出る(凝縮相は運動量を持たない。液体の区画があっても今は液体の勢いにならない → T-0648)。
   おすすめ: このまま(数値の正しさで、作り手が選ぶものではない)。凝縮した露の運動量を液体へ渡すかは T-0648 で。

## 重なり(並走)
1. **wt5 T-0598(GPU の気体)**: gas_step.hlsl の GasOutflow(段 5)の最後と、probe_gas_tick.hlsl の GasGather・GasScatter、probe_gas_gpu.hlsli の
   ProbeGasCellState(32 → 40 バイト。mass を足した)を触った。T-0598 はこれらを大きく書き換えているので、マージの時に
   「GasOutflow の合計を EffectiveOutflow で換算」「GasGather で質量が減ったら運動量を縮める・GasScatter で質量を書き、気体が無ければ運動量を帳簿へ」を載せ直す。
2. **wt2 T-0593 の載せ直し(probe_liquid)**: probe_liquid は触っていない。液体にも同じ形(反応で液体が減ったら面の運動量が残り、速さ・運動のエネルギーが増える。
   速さの上限で抑えられてはいる)がある → T-0648。
3. **wt4 T-0611(probe_phase)**: (a) 湯気の場面の崩れはこのチケットで直る(probe_phase の `energyHolds = false` と ReportSteamWithLiquid の見立ては外せる)。
   (b) probe_phase の Sum は物質の無いセルを飛ばしている(このチケットの後は 0 のはず)。(c) **氷の場面も t-0611 の今の HEAD では 552 刻み目から崩れる**
   (+2 mJ → 600 刻みで −2509 mJ。気体の段は保存)。原因: Sum が液体の位置・運動のエネルギーと液体の帳簿(T-0610 で足した)を数えていない。
   `totals.energy += liquid->KineticEnergySum() + liquid->PotentialEnergySum() - liquid->Ledger().energy` を足すと、このチケットの直しと合わせて probe_phase が全部通った。
