# T-0290 上限 64 種で「溢れを使う世界の刻み(伝導 あり)」が HW で本当に止まる(T-0273 から分けた)

- Status: Todo(T-0272 で上限を 32 より上げる前に)
- 種類: 研究(原因が読めない)
- PC: 必須(HW)
- 見積もり: チャット 1 回分
- 設計: 02 §3・ADR-0052(追記 4)。関係: T-0248・T-0272・T-0273

## 見つけたこと(T-0273、RTX 3070 Ti / 32.0.15.9597、release)
- RX_GPU_WIDE_SPECIES = 64 にすると、gpu_multires(HW)の「溢れを使う世界の刻み(伝導 あり)」(RunLimitsStepWide。上限の場面・12 刻み・
  1 刻みずつのリスト・毎刻み CPU と比べる)が DEVICE_HUNG。10-10 の 2 回と 10-11 の 1 回で 3 回中 3 回(10-11 は作ってから約 145 秒後。
  伝導なしの同じ場面は 1 秒で通る)。WARP は通る(10-10)。ログは wt4 の runner/logs/20261011-012602-test。
- 同じ場面を 1 つだけ流す(`gpu_multires_test --queue compute --diagnose-wide 1 --diagnose-limits --diagnose-conduct`。段ごとのタイムスタンプあり・
  CPU と比べない)と 1 刻み 4 ms(32 種で 2.5 ms)で 12 刻み通る。= 1 刻みの時間切れではない。前の場面(同じデバイスで先に走る場面)の後でだけ、
  またはタイムスタンプが無い時だけ止まる疑い。

## やること
1. 64 にして、--diagnose-wide に「伝導なしの上限の場面 → 伝導ありの上限の場面」を 1 つのプロセスで続けて流す・段ごとのタイムスタンプを切る・CPU と比べる、
   を足して、止まる組み合わせを絞る。
2. debug プリセット(GPU の FX_ASSERT・DRED)で同じ組み合わせを流し、LoadGpuWideCell の溢れの範囲(FX_ASSERT)・伝導の段の溢れの変種
   (512 スレッドが上限の無い形のセル約 800 B を持つ)に壊れた値が入っていないか見る。
3. 打ち切り条件: 1.5 時間で止まる段の見当がつかなければ、分かったことを書いて T-0272 の「伝導の段から上限の無い形のセルを無くす」を先にやり、直るかを見る。
