  トレース・決定性のテスト・CPU リファレンスとの突き合わせ・PIX は T-0087

## 目的
反応の連鎖を Work Graphs で GPU の中だけで走り切らせると、CPU からは途中が見えない(ユーザーの指摘 2026-09-29)。
「どのノードが何回起動し、どこで連鎖が止まり・溢れ・食い違ったか」を GPU 側で記録し、CPU のログ(ADR-0006)とツールで見られるようにする。
これが無いと、自走する化学を書いても症状から原因に辿れない。

## やること(案)
- **ノードごとのカウンタ**: 起動数・入力レコード数・出力レコード数・最大の再帰の深さ。UAV の atomic で数え、フレームごとに読み戻して
  `Log(Channel::WorkGraph, ...)` に要約を出す。
- **ノードからの printf / assert**: T-0003 のリングバッファをノードのシェーダーから書けるようにする(ノード名・世代・レコードの ID つき)。
- **上限の検出**: 再帰の深さ(MaxRecursionDepth)・出力レコード数・バッキングメモリの上限に近づいた/超えそうなことを検出して Warning。
  上限を超えた時の振る舞いは仕様上 未定義のはず(未確認。仕様を読んで確かめる)なので、超える前にノード側で止めて数える。
- **連鎖の記録(トレース)**: 「どのレコードがどのレコードを生んだか」を、選んだ範囲(セル・世代)だけ記録してファイルに落とす。
  ツール側(CPU)で世代ごとの木として見る。
- **決定性の確認**: 同じ入力・シードで 2 回走らせ、カウンタとトレースが一致するかを比べるテスト(ADR-0003)。
- **CPU リファレンスとの突き合わせ**: T-0005 の「1 次元の燃え広がり」を対象に、食い違った最初の世代・セルを報告する。
- **外部ツール**: PIX の Work Graphs 対応の範囲(ノードごとの時間・レコードが見られるか)を調べる(未確認)。

## 研究の部分と打ち切り条件
- トレースの記録が重すぎる場合(伝播の時間が 2 倍を超える)は、全記録をやめて「サンプリング(N セルに 1 つ)」と
  「カウンタだけ」に落とす。それでも重ければ debug プリセットだけで有効にする。
