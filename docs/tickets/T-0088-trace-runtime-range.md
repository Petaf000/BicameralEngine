## 目的
窓で試しながら連鎖を追えるようにする。今は範囲(刻み・場所の箱)を起動時に決め、途中で変えられない(`gpu::GraphTrace` が最初の
`RecordBegin` で 1 回だけ写す)。T-0014(化学)から、燃える・反応の連鎖を「クリックした所の周りを、今から N 刻み」追いたい。

## やること(案)
- **範囲を毎フレーム渡す**: フレームの枠ごとのアップロードのバッファに範囲(48 バイト)を書き、`RecordBegin` で写す(`SetFilter` で次のフレームから効く)。
  シェーダー(graph_trace.hlsli)は見出しから読んでいるので変えない。
- **容量は作った時に固定**(上限ぶんを確保。例 1 MiB)。範囲が無効のフレームは見出しだけを読み戻す(今の ReadbackRing は丸ごと写すので、
  写す大きさを渡せるようにする)。無効のときの費用が 0 のままであることを gpu_conduct_bench で確かめる。
- **窓の操作**: デバッグ表示(render/debug_view_controller。T-0015)のキーで「断面で選んでいるセルの周り(既定 ±8 セル)を、今の刻みから N 刻み(既定 60)」
  トレースし、終わったらファイル(`--trace-dir` か exe の横の traces/)に刻みごとの木を書いてログに場所を出す。空いているキーを使う(1〜3・X/Y/Z・Q/E・B・L・O・R は使用中)。
- `--trace` の起動時の範囲はそのまま残す(自動の確認用)。

## 完了条件
- [ ] 実行中に範囲を変えると、次のフレームから新しい範囲だけが記録される(テスト: 途中で範囲を変えて、前後の記録がそれぞれの範囲に入る。CPU の予想と一致)
- [ ] 範囲が無効のときの費用が変わらない(docs/perf.md)
- [ ] 窓でキーを押すと、選んだセルの周りの N 刻みの木がファイルに出る(`job.py run --auto-click` の自動の確認でも通る形)
