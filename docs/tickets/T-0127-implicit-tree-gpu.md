# T-0127 木につないだ陰解法(方式②)を GPU に — 解く段(この版)

- Status: Done(範囲を絞った: 木の本物の系を GPU の GpuImplicit で解いて CPU と毎刻みビット一致・計測。系を GPU で作るのは T-0129、伝導の段から呼ぶのは T-0132、空の V サイクルの費用は T-0133)
- 種類: 工学
- PC: 必須
- 見積もり: 作業役 2 時間以内(始める前の見積もり: 系の作り方〔多重格子の段の形と 128bit の割り算の重み・段の数が値で決まる〕を GPU に載せて伝導の段から呼ぶまでは
  2 時間に入らない → 「木の本物の系を GPU が解けること + 費用の測り直し」に絞り、残りを分けた。実際は約 1.5 時間)
- マイルストーン: M2 の並走(D-432)
- 設計: docs/design/17-multiresolution.md §6 / 決定: D-428・D-432・D-434・D-436 / ADR-0019

## 目的(1〜2 行)
T-0119 で木につないだ方式②(CPU)を GPU に載せる道の 1 段目: 木が作る本物の系(刻みの初めの温度・端数の枠の無い粗い側・境のセルの長い行・
相変化で変わる熱容量)を GPU の段がそのまま解けることを確かめ、本物の系での費用(鎖・熱い点・たくさんの要求)と ImTail の境を測り直す。

## 完了条件(チェックできる形で)
- [x] GPU の段が木の系の約束を持つ: セルの「刻みの初めの温度」(ImGpuCell.startTemperature)・面の粗い側の端数の枠(ImGpuFace.coarseFraction。
      無ければ MrSplitCrossFlow が整数の単位の倍数だけ送る)
- [x] 熱い点・鎖・たくさんの要求の場面で、刻みごとの系(MultiresNest::captureImplicitGrid で写す)を GPU で解き、セルのエネルギー・端数・V の回数・
      安全網の数が CPU の StepImplicit と毎刻みビット一致。CPU が木の中で解いた費用(nest.implicitCost)とも一致(tests/gpu_multires_implicit_tree_test.cpp。
      HW・WARP、debug・release)
- [x] 鎖と熱い点の ms/刻みを測る(下の「結果」)・ImTail の境を測り直す(GpuImplicitTuning で切り替え)
- [ ] 系(未知数・境のセル・面・多重格子の段)を GPU で作る → **T-0129**
- [ ] GpuImplicit を GPU の伝導の段(gpu_multires の RecordConduction)から呼び、全部を刻む Compute・活性の刻みで CPU の StepNest / StepActive とビット一致 → **T-0132**
- [ ] V サイクルの上限 64(D-436)まで積んだ空の回の費用を減らす → **T-0133**

## 何をしたか(形。決めたのは Claude〔実装の細部〕)
- shaders/common/implicit_conduction.hlsli: ImGpuCell に startTemperature(0 以上ならその温度から始める。CPU の Temperatures と同じ)、ImGpuFace の padding を
  coarseFraction に。shaders/sim/implicit_conduct.hlsl の ImStart・ImApply がそれを使う。試作の場面(startTemperature = −1・端数の枠あり)は今までと同じ。
- engine/src/sim/gpu_implicit.*: GpuImplicitTuning(ImTail の境〔節 1024・隣 32〕と「最も粗い段はいつも ImTail」を Create の引数に。既定は今までと同じ)。
  最も粗い段を ImTail で回さない形(coarsestInTail = false)も足した(掃き出しの Dispatch で回す)。計測用に TailDepth()・LevelCount()。
- engine/src/sim/multires_nest.h・multires_implicit_conduction.cpp: MultiresNest::captureImplicitGrid(既定 false。状態に入らない計測・試験用)で、
  陰解法を入れた刻みの系(解く前)を nest.implicitGrid に写す。
- tests/gpu_multires_implicit_tree_test.cpp(新): CPU の木で場面を刻んで系を集め、刻みごとに CPU で解き直し(木の中の費用と一致)・GPU で解いて比べる。
  release の HW では計測(暖機 100 刻みの後、同じ系を写し直して 5 回解いた最小)。

## 結果(2026-10-06、release、RTX 3070 Ti。本体のランナーが idle の時。系は CPU の木が作ったもの・GPU の解く段だけの時間)
測り方: 刻みごとの系を GPU に写し、暖機(V 1 回の刻み 100 回)の後、同じ系を写し直して 5 回解いた最小(タイムスタンプ)。① 分けない(0.21 ms)は入っていない。
| 場面(系のセル・多重格子の段 [節, 隣の最大]) | V の上限 64(木の既定・D-436) | V の上限 16 |
|---|---|---|
| 熱い点(512 セル・[512, 6] [64, 6] [8, 3] [1, 0]。V 4 → 2) | 0.49 → 0.36 ms | 0.35 → 0.23 ms |
| **鎖**(1907 セル・[1907, 208] [1459, 160] [1011, 112] [563, 64] [115, 16]): 1 刻み目 / 2 刻み目 / 初めの 12 刻みの平均 / 後の 24 刻みの平均 | 2.52 / 3.90 / 2.98 / **2.91** ms | 1.85 / 2.71 / **1.84** / **1.48** ms(V 5 で 1.50〜1.53・V 4 で 1.33) |
| たくさんの要求(20996 セル・8 段・隣 最大 304。V 12〜16) | 10.3〜12.7 ms | 8.6〜10.8 ms(最も粗い段を ImTail に入れない既定で 7.4〜9.0 ms) |
- **T-0119 の見込みとの比べ**(② だけ): 初めの刻み 1.7〜3.1 ms の見込み → 1.85(1 刻み目)・2.71(2 刻み目)・初めの 12 刻みの平均 1.84 ms(上限 16)で見込みの中。
  落ち着いた後 0.7〜1.3 ms の見込み → **1.48 ms(上限 16)/ 2.91 ms(上限 64)で見込みより重い**。① 分けない 0.21 ms を足すと案 a は 約 1.7 / 3.1 ms/刻み(Q3 の目標 5 ms の中)。
  重い理由: 境のセルの長い行(1 節の隣 208・粗い段も 64〜160)で ImTail に入る段が最後の 1 段だけになり、V 1 回 43 Dispatch。
- **V の上限まで積んだ空の回**: 鎖の後の刻みで上限 64 と 16 の差 1.2 ms = 空の V 約 48 回 × 43 Dispatch(約 0.58 µs/Dispatch。述語で飛ばしてもバリアが残る。T-0120 と同じ)。
  上限 64 は D-436(解き切る)の安全のための値なので下げず、工学で減らす → T-0133。
- **ImTail の境の測り直し**(上限 16。ms/刻み。鎖は初めの 12 刻み / 後の平均):
  | 節 / 隣 | ImTail の最初の段 / 段の数 | 鎖 | たくさんの要求(平均) | 熱い点(初めの 12 刻み) |
  |---|---|---|---|---|
  | 1024 / 32(T-0120 の既定) | 鎖 4 / 5・要求 7 / 8 | 1.84 / 1.48 | 9.4 | 0.26 |
  | 1024 / 128 | 鎖 2 / 5 | 2.19 / 1.67 | 9.4 | 0.26 |
  | 2048 / 256 | 鎖 0 / 5 | 3.81 / 3.03 | 9.7 | 0.26 |
  | 256 / 32 | 熱い点 1 / 4 | 1.84 / 1.49 | 9.4 | 0.37 |
  | 1024 / 32・最も粗い段を ImTail に入れない | 要求 8 / 8 | 1.84 / 1.49 | **8.1** | 0.26 |
  → 境は 1024 / 32 のまま。隣 64〜112 の 563〜1011 節の段は ImTail に入れると重い(1 スレッドが長い行を回す)。**最も粗い段は節 1024 以下の時だけ ImTail**
  (隣の数によらない。試作の熱い点の小さく隣が多い最も粗い段は ImTail の方が軽かった〔T-0120〕。木のたくさんの要求の 3396 節は入れない方が 14% 軽い)
  を既定にした(GpuImplicitTuning::coarsestTailMaxNodes)。
- たくさんの要求の場面(深さ 26 段・Δk ≤ 8 で 2 万セル)は 1 刻み 7.4〜9.0 ms(上限 16)と重い(予算: シミュに約 12 ms)。D-434 の「重い場面が頻発すると
  見込まれるなら分ける段を減らす」の材料(この場面は試験のための極端な深さ。ゲームで頻発するかは未確認)。

- なし(V の上限 64 の空の回の費用は工学で減らす → T-0133。上限を下げると D-436「解き切る」に触れるので、下げる案は出さない)。

## 分けたもの(新しいチケット。ROADMAP には司令塔が足す)
- **T-0129**(工学): 陰解法の系を GPU で作る。未知数(基準より細かい本物のブロックのセル。枠の順の番号は接頭和で)・境のセル・面(MrFindFaceNeighbor)・
  面の係数、多重格子の段(親のセルへの縮約・行の係数の和・重み = 128bit の割り算・段の数は「自分の重み < 1/2 の節があるか」で GPU が決める)、
  節の並び(長い行・ImTail の段)と間接の Dispatch の引数。形が変わらない刻みは作り直さない(重みだけ毎刻み)を測って決める。CPU とは番号でなく
  「(枠, セル) ごとの値」で比べる(面の順は安全網の頭打ちの足し算で効くので、面の番号の順は CPU と揃える)。
- **T-0132**(工学): GpuImplicit を GPU の伝導の段から呼ぶ(RecordConduction の流れの後・ConductEnd の前に変化の表へ足す)。全部を刻む Compute と活性の刻みで
  CPU の StepNest / StepActive と毎刻みビット一致・2 回一致・保存。鎖と熱い点の ms/刻み(① 分けない + ②)を測る。T-0125(伝導の段の tc)の後。
- **T-0133**(工学): V サイクルの上限まで積んだ空の回の費用を減らす(鎖の後の刻みで上限 64 は 2.91 ms・上限 16 は 1.48 ms。差は空の V 約 48 回 × 43 Dispatch)。
  案: 止める判定と CycleEnd を 1 Dispatch に・V を数回ずつ束ねて「止めた」で束ごと飛ばす(バリアは述語で飛ばない)・Work Graphs で回す。
  あわせて、境のセルの長い行(隣 64〜208)のある段の V 1 回の Dispatch(鎖 43)を減らす形も測る。

## 作業ログ(チャットごとに 3〜5 行、新しいものを下に)
- 2026-10-06(作業役、wt2・約 1.5 時間): 始める前の見積もりで、系の作り方まで GPU に載せるのは 2 時間に入らないと判断し、「木の本物の系を GPU が解く + 計測」に
  絞った(残りは T-0129・T-0132・T-0133)。GPU の段に刻みの初めの温度と粗い側の端数の枠を足し、木の系を写して比べる試験を書いた。最初のビルドで
  HW・WARP ともビット一致(熱い点 12・鎖 36・たくさんの要求 8 刻み)。計測で V の上限 64 まで積んだ空の回が鎖の後の刻みで 1.2 ms(2.9 ms 中)と分かった(T-0133)。最初の計測は本体のランナーのビルドと重なって 3 倍ほどぶれたので、idle の時に測り直した。最も粗い段を ImTail に入れる条件を節の数だけにした。
