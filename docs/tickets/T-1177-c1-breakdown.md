## 目的(1〜2 行)
積もった層の量のように「保存量の欄の内訳」を持つ欄を、登録の 1 行の印で書けるようにする(物質は 1 つのまま。作り手の書く値は増えない)。

## 完了条件
- [x] 登録の印「内訳」と親の保存量の欄の番号(SfFieldDesc に欄を 1 つ)。0 ≤ 内訳 ≤ 親 の検査(SfDescValid と状態の検査)
- [x] 保存の列は親だけ・ハッシュと保存点に入る
- [x] 細かくする時は層は置かれ方の凝縮相(2-1)・舞う粒は空きに同じ濃さで・粗くする時は和
- [x] 眠る判定: 層は止まっていれば眠れる・舞う粒は濃さ 0 まで起きている
- [x] 形は wt3 T-1136 の 2 本目(層は落ちても層のまま)の結果に合わせる(2-6 の置き場を足すかも同じ時に)→ T-1138 の ② + 見直し 2 が合格したので、
  内訳 1 つ + 運動量の置き場 2 つ(層・舞う粒)の形。運動量の置き場は内訳ではなく、それぞれ独立の保存量の欄(下の「2-6」)

## 入れた形(2026-10-26。shaders/common/state_field.hlsli・sim/multires_fields)
- 印 `SF_FLAG_BREAKDOWN`(128)と `SfFieldDesc::parent`(親の欄の番号。内訳でない欄は `SF_NO_PARENT`)。登録は `SfMakeBreakdownDesc(place, type, phase, 置かれ方の印, 値の数, 親)`
  (真実・SAME・HASHED が付く)。`SfDescValid`: 内訳 ⇔ 親を持つ・内訳は真実のセル / 面の欄・SAME・HASHED。`SfBreakdownPairValid`: 親は保存量の欄・内訳でない・置き場と値の数が同じ。
  `RegisterNestField`: 親は先に登録した欄・親 1 つに内訳は 1 つ(内訳の内訳は無い)。
- 状態の検査: `SfBreakdownFits`(0 ≤ 内訳 ≤ 親。引き算をしない = HLSL の 64bit の約束)・`CountBreakdownMisfits(nest)`(世界と観察の枠の全部)。
- 保存の列は親だけ(内訳は SAME = 列を持たない)。ハッシュと保存点は HASHED の真実なので今の一覧のまま入る。
- 細かくする: 内訳は**内訳の置かれ方の印**で、残り(親 − 内訳)は**親の置かれ方の印**で配り、子の親 = 子の内訳 + 子の残り(`RefinePlaced` の `BreakdownSource`)。
  砂なら「粒の量 = PLACE_OPEN の保存量・層 = PLACE_CONDENSED の内訳」で、層は置かれ方の凝縮相・舞う粒は空きに同じ濃さ(子の空きの重み)。
  子でも 0 ≤ 内訳 ≤ 親(子の親 = 内訳 + 残り・残り ≥ 0)。口が無い・一様な親・重みの和が 0 は今まで通り子は親と同じ数。内訳の無い欄は今とビット単位で同じ。
- 粗くする: 今の規則のまま(親 = 和 ÷ 8 + 端数を帳簿・内訳 = 和 ÷ 8 の切り捨て)。切り捨ては単調なので 0 ≤ 内訳 ≤ 親 のまま。
- 眠る(頁を畳む)判定 `PageFoldable`: 残りのある(`SfBreakdownKeepsAwake` = 内訳 ≠ 親)頁は畳まない。止まれる側(層)だけなら畳める。
- 2-6(運動量の置き場): 内訳にはしない(運動量は符号を持ち、層と舞う粒の和を親にする意味が無い)。土台に粒が来る時は
  面の欄 2 つ(層の運動量 = PLACE_CONDENSED・舞う粒の運動量 = PLACE_OPEN。どちらも VOLUME の保存量 ×3)を登録する(T-1138 の「土台へ入れる時の形」)。今の土台には粒の欄がまだ無いので足していない。

## 確かめ
- `placement_refine_test` の「5. 内訳」: 傾いた口で子の親の和 = 8 × 親・子の内訳の和 = 8 × 内訳・子でも 0 ≤ 内訳 ≤ 親・凝縮相の無い子に内訳が入らない・
  残りは空きの重みで配る・口の無い世界は子は親と同じ数・細かくした後の検査 0・親を超えた値 / 負の値を検査が数える・ハッシュに入る・登録の検査・
  残りのある頁は畳まない / 層だけの頁は畳める。今の欄の試験(field_storage・multires_state・placement_refine の 1〜4・case_b_box)は合格。
- `multires_sparse_test` は前と同じ要約の束の値で 6 件落ちる(**main の 14:51 のビルドの実行ファイルでも同じ値で落ちる** = この変更の前から。T-0931 の前の値と比べる場面。司令塔へ)。

## 残り(司令塔へ)
- **案 B の箱(case_b)へつなぐのは、粒が土台(多重解像度の欄)に来る時**(今の試作の箱は `Box::grainLayerMg` で持つ。箱は登録の欄を使わない)。
- 土台に足りないもの: **粒の量はセルの成分(物質ごと)で、登録の欄ではない**。今の内訳は「登録した保存量の欄」の内訳だけを書ける。
  砂の層を「物質ごとの量の内訳」で持つには、(a) 成分の量の内訳(物質ごとに層の量。セルの頁の成分の並びに 1 つ足す)か、
  (b) セルの粒の量の和を保存量の欄にして内訳を付ける(層の物質の割合は粒の全部と同じとする)のどちらかが要る。
  作り手から見た違い: (a) は砂と灰が混ざったセルで、層と舞う粒の物質の割合が別々になれる(灰だけが舞う)。(b) は層と舞う粒の割合が同じ(灰と砂が同じ割合で舞う)。
  おすすめ (a)(D-659 の「物質は 1 つのまま・書く値は増えない」を保ち、舞いやすい粉だけが舞う現象 #37 粉じん・#38 すすに要る)。成分の並び(セルの頁・RxCell)に当たるので司令塔へ。
  → 2026-10-26 T-1209 の作業役が (a) を一旦の決定(仮・ユーザー未確認)にし、形を ADR-0481 の 5 に書いた。土台の変更は T-1210(未着手)。
