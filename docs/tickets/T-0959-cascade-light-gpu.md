## GPU の作り(ADR-0432)
- 1 刻み = 頭の語 → セルごとの放つ量 → 持ち越しを足す → 放つ面の列 → 段 0 の分け方 → 段 0 の光線 → 段ごとに(袋の光線 → 袋の表を空に → 袋の数を 0 に)→ 照り返しを疎な表へ。
- 袋は段ごとの開いた番地の hash の表 2 つを交互に。溜めは鍵の符号 18bit + 出どころ 45bit の 1 語の min(世界の箱は 1 辺 127 セルまで)。
- 照り返しの持ち越しは疎な表(鍵 + 量)で刻みをまたぐ(D-619)。刻みの中の受けは密。
- 食い違いの記録: (1) 帯がレーンごとに違う帳簿の足し算を波の和にしていた(持ち越しの帳簿が帯の間で混ざった)→ 帯ごとに呼ぶ。
  (2) 溜めの鍵の −ln(u) を FxLnU64 で作ると GPU と CPU(MSVC)で鍵だけ食い違った(原因は未確認。gpu_fixed_test の FxLnU64 は通っている)→
  −log2(u) を 256 の表 + 直線の補いで作る形(RcMinusLog2Q32)にした。−ln と −log2 は全部の鍵が同じ倍率になるだけで選ばれ方は同じ。

## 仮(ユーザー未確認)
- 【エンジン】(b)「光線約 8 倍」は「袋 1 つから 8 本(量を等分し、升目の中のずらしの巡りの続きを使う)」で測った(n0 = 8 は光線 4 倍で瞬間の筋は同じ)。
  作り手から見た違いは無い(費用の比べのための形。既定は 1 本)。
- 【エンジン】溜めの鍵の分解能を 2^−11 にし、出どころを 15bit × 3 に詰めた(ADR-0432)。作り手から見た違い: この研究の作りでは世界の箱が 127 セルまで。

## 問い(Q147 の材料。司令塔がユーザーへ)
- 【エンジン】筋の合格を瞬間で見るなら、距離ごとの段のままでは光線を増やしても届かない(瞬間の二乗平均 45〜54 %)。段なしで向きを細かくする形なら焚き火 1 つは
  届く見込みだが、熱い面の数に比例して重い。数秒の平均で見るなら、今の形は 250〜500 刻みの平均で(上の表の値)。費用はどちらにしても照り返す地面があると 1 ms を超える。

## 分けたもの
- **T-1010** 距離ごとの段の GPU を速くする(Q147 で段を続けると決まったら): 間接の起動(放つ面・袋の数で起動の大きさを決める)・袋の表を使った数に合わせる・
  段 0 の分け方をグループで並べる・照り返しの密な受けを疎にする。1 ms の線との差(照り返す地面で 2.7〜7.7 ms)を詰められるかの測り。
- **T-1011** 溜めの鍵で FxLnU64 が GPU と CPU(MSVC)で食い違った原因を調べる(fixed の共通の関数の信頼の問題。gpu_fixed_test に足す)。
