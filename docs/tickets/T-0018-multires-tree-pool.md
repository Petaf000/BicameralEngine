## 目的(1〜2 行)
T-0017 の入れ子(呼ぶ側が枠を決める・端数の枠は返さない・帳簿なし)を、世界の木として自分で管理できるようにする:
(レベル, 座標) の索引・ブロックと端数の枠の割り当てと解放・同じ刻みの多数の細分/粗くする要求の決定的な処理・落ちた端数の帳簿。
活性(一覧・レベルをまたぐ隣・静かなブロックを粗くする)と一様なブロックは T-0100(2026-10-04 ユーザー決定で分けた)。

## 完了条件(チェックできる形で)
- [x] 索引: (レベル, ブロックの座標) → 枠。開番地法・墓石・作り直し。見出しから作り直せる「索引」なので状態のハッシュに入れない(引いた結果だけ CPU と比べる)
- [x] プール: 世界の枠と端数の枠の空きのスタック。割り当てと解放は要求の順の累積和で決め、枠の番号が CPU と GPU で一致(ADR-0016)。観察(影・写し)の枠は別の範囲
- [x] 要求: 「点を含むレベル L のブロックを作る」(細かくする。途中の段も 1 刻みで)・「点を含むレベル L のブロックを親へ戻す」(粗くする。1 刻み 1 段)。
      1 刻みに 1 つの親につき 1 つの変更(取り合いは要求の番号の小さい方)。足りない・取り合いに負けた・無効な要求は数える
- [x] 世界の帳簿: 粗くした時に端数の下から落ちた分を (レベル, 物質) ごとに足す。「世界 + 帳簿」の保存量が毎刻み最初とビット一致(24 段まで潜る場面)
- [x] 全部の状態(見出し・セル・端数・数える欄・空きのスタック・帳簿)が毎刻み CPU と GPU でビット一致・2 回の実行で一致・索引の引いた結果が一致
- [x] T-0017 / T-0096 の場面(本物の鎖・影の鎖・覗き窓)がそのまま通る(影は観察の枠で、世界のハッシュ列は影の有無で一致)
- [x] build(debug / release)・tidy 警告なし・archmap OK・1 刻みの要求の処理の GPU 時間を perf.md に

## メモ・参考
- 要求を作る側(状態による細分 A・介入 C のコマンド)は、要求の一覧を決定的な順に並べて渡す約束(GPU で並べるのは作る側ができる時。T-0100 以降)。
- 「速度が気になり始めたら非決定的な割り当て(atomic)を考える」(ユーザー、2026-10-04)。その時は世界のハッシュを (レベル, 座標) の順に作り直す。
