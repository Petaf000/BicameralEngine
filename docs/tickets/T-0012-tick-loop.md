## 目的(1〜2 行)
1 刻みを「単位」(Dispatch のまとまり)の列にし、CPU が毎フレーム予算ぶんの単位だけを compute に投げる(ADR-0011)。刻みはフレームをまたいでよい。
刻みごとに GPU で状態のハッシュを取って CPU へ返し、「投げ方を変えても世界の結果が同じ」を確かめられるようにする。
(元の T-0012 のうち、コマンドキュー・イベントを並べて返す・再生ファイルは T-0086 に分けた。)

## 完了条件(チェックできる形で)
- [x] 1 刻みの単位の列(仮の刻み: コマンドの適用 → 拡散 → 重さ × k → ハッシュ)。単位を 1 フレームのリストに記録して投げる(毎フレーム記録)
- [x] 単位の数を決める純粋な計算(`frame::SimScheduler`。予算 = 1000 / 目標 fps − 描画の GPU 時間 − 余裕、単位ごとの GPU 時間の平均、現実の時間で進める刻み、追いつけない分は捨てる)と CPU だけのテスト。TickPacer を置き換える
- [x] フレームのループを置き換える(バッチを 2 つ重ねる形をやめる)。描画用の抽出は刻みの境界の状態を、投げた単位の後ろで写す(3 組の約束を守る)
- [x] GPU で刻みごとの状態のハッシュ(順番に依存しない形)を取り、CPU へ返す。CPU リファレンスと同じ関数
- [x] (シミュのコード)単位の分け方(1 刻みずつ / 何刻みもまとめて / 刻みの途中で切る / 重さを分ける)を変えても、刻みごとのハッシュ列が CPU リファレンスとビット一致(GPU・WARP)
- [x] 重さの試験で、描画が目標 fps(既定 60)を保ち、世界が遅くなる(docs/perf.md)。1 本のリストにまとめて投げても同じか(06 §4.2 の未確認)
- [x] 目標 fps の引数(`--target-fps`、30 未満は拒否)。T-0085 の試験の口(`--split-submit`・`--pieces-per-frame`)は置き換えて消す

## メモ・参考
- 同じコマンドリストは、前の実行が終わるまで投げ直せない(debug layer [553])。単位は何度も投げるので、記録済みのリストを使い回す形ではなく、
  フレームの枠ごとのリストに毎フレーム記録する(CPU の仕事は記録だけ。D-107 の範囲)。
