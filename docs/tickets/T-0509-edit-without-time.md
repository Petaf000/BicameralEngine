## 目的(1〜2 行)
編集の状態(止まった世界)で置く・消す・つつく・押すを、世界の時間を進めずに当てる。置いた物が反応したり燃え広がったり落ちたりしない。
プレイを押すまで刻みの番号は変わらない。

## 完了条件(チェックできる形で)

- [x] Undo/Redo・刻み 0 の保存点・プレイを始めた保存点・やめると戻る・記録と再生(ハッシュ列)と矛盾しない
- [x] 試験: window_play_record/play(--auto-play を時間が進まない形に)・sim_scheduler(止まる場所)
- [x] release のビルド(警告 0)・archmap

## 作り手(エンジンを使う人)から見た違い
| | 前(T-0497・ADR-0214 §2 の仮) | 今(T-0509・ADR-0236) |
|---|---|---|
| 編集の状態で置く 1 回 | 1 刻み(1/60 秒)世界が進む。燃えている所は燃え、積み木は落ちる。刻みの番号が増える | 刻み E の適用の単位だけ。伝導・反応・物理は走らない。刻みの番号は E のまま |
| 2 回目以降に置く・元に戻す・やり直す | 刻み 0 から置いた回数ぶん流し直す | 置く前の S(E) の保存点へ戻し、E に当てる全部を当て直す(保存点 1 つの写し + 適用) |
| プレイを押す | 押した後の最初の境界が P | 置いた後なら P = E(刻み E の残りから続く)。置いていなければ今まで通り |
| やめる | P の境界 (P, 0) に戻る | P へ戻し、プレイ前に置いた分を当て直して (P, 1) |
| 記録と再生 | 置いた分の刻みが記録に入る | 置いたものは「刻み E の始めのコマンド」。再生は刻み E の適用で当てる(ハッシュ列は同じ) |
| 時間のパネルの表示 | 刻み n(単位 0) | 置いた後は「刻み E(単位 1)」 |
| 保存点が無い起動(`--save-points 0` など) | 置くたびに 1 刻み | 最初の置く組は当たる。その後に置いた分はプレイの最初の刻みで当たる(警告 1 回。仮) |

## やったこと
- frame/sim_scheduler: 止まる場所 `HoldAt` / `ClearHold` / `Hold` / `BeforeHold`。止まる場所までは現実の時間を待たず、その刻みの境界でフレームを切り、先へは進まない。
- frame/frame_loop: `UpdateEditHold`(SubmitSim の戻した後・TakeUnits の前に止まる場所を決める)・`ApplyEditCommands` を作り直し
  ((E, 1) の後に置いたら PlanStrokeRewind(E) で戻して当て直す)・`SaveSlotFor`(E > 0 の置く前の S(E) をプレイを始めた保存点へ)・
  `StartPlay`((E, 1) からなら P = E)・置いたものを当てたフレームが抽出を飛ばしたら抽出だけのリストで見せる。GPU のシェーダーは変えていない。
- frame/auto_play: 手順を作り直した(下の試験)。

## 試験
- `sim_scheduler`(CPU): TestHold(止まる場所 (0,0)・(0,1)・流し直して (4,1)・外すと刻みの途中から最後まで)。
- `window_play_record`(`--world sample --editor --auto-play --record`): 起動が (0, 0) で止まっている → 木の球 A・木炭 B を置いても (0, 1) のまま・
  20 フレーム動かない → プレイ 1(P = 0。編集で時間が進んでいたら P が 0 でなく落ちる)→ 60 刻み後に C → 100 刻みでやめる →
  (0, 1) に戻り動かない → B・A を元に戻す((0, 1)→(0, 0))→ A をやり直す → プレイ 2(B が無いので刻み 1〜50 のどこかがプレイ 1 と違う)→
  やめる → B をやり直す → プレイ 3(刻み 1〜50 がプレイ 1 と同じ・60〜100 のどこかが違う = C が消えた)。
- `window_play_play`: その記録(プレイ 3 の流れ。A・B は刻み 0 の始めのコマンド)を別の起動で再生して同じハッシュ列
  = 編集の状態で当てた世界と、刻み 0 の適用で当てた世界が同じ。

## 判断待ち(仮で進めた。ユーザー未確認)
1. **保存点が無い起動で、置いた後にまた置いた時**(作り手から見た違い): 仮 = プレイを押した最初の刻みで当たる(編集の状態では見えない。警告 1 回)。
   代案: 保存点が無い時だけ前の形(1 刻み進めて当てる)。おすすめ: 仮のまま(`--editor` の既定は保存点があるので、作り手が普通に触る所では起きない)。
2. **編集の状態での表の差し替え(Q64 ⑤ の確かめ)**: まだ適用の単位を待つ。置いたものが無ければプレイの最初の刻み、置いた後ならその次の刻みで当たる。
   置き直しの当て直しと重なると刻み E で当たるが、保存点が全部捨てられ、その後の置き直し・元に戻す・やめるで戻るができない。
   - 案 A(仮): このまま(プレイを押すと当たる。作り手は「表を替えたらプレイで確かめる」)。
   - 案 B(おすすめ): 編集の状態の差し替えを「編集」として扱い、置く前の S(E) + 新しい表で E の適用を当て直す
     (表の差し替えの印もやり直しの対象に。保存点を捨てずに「置く前の S(E) は前の表の世界」と控える)。Q64 ④ の代案(プレイ中の差し替えの後にやめると
     プレイ前の世界 + 新しい表で作り直す)と同じ道なので、一緒に作るのがよい → **T-0548** に分けた。

## 分けたもの
- T-0548(案): 表の差し替えを編集として扱う(編集の状態ですぐ当てる・プレイ中に差し替えた後にやめてもプレイ前の世界 + 新しい表に戻る。Q64 ④⑤)。
  ROADMAP には本体が足す。
