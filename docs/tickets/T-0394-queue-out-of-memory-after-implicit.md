# T-0394 陰解法の段を走らせたキューを捨てると次のキューが E_OUTOFMEMORY で作れない件の原因(研究・小さい)

- Status: Todo(2026-10-12 wt6 がファイルだけ作った。T-0410 の GPU の順番待ちで手を付けられなかった)
- 種類: 研究(打ち切り: 2 時間〔ROADMAP〕。作業役への割り当ては 1 時間。分からなければ `sim::PooledImmediateQueue` の使い回しのまま閉じる)
- PC: 必須(NVIDIA・HW・release でだけ起きる。WARP では起きない)
- 関係: ADR-0137 追記 3・T-0351・14 §2・D-453

## 目的
陰解法の段(implicit_*.hlsl)を走らせたキューを捨てると、NVIDIA(RTX 3070 Ti・release・HW)で次の `CreateCommandQueue` が 2〜3 回目から
E_OUTOFMEMORY になる(VRAM・プロセスの確保・コミットは余っている)。原因を確かめ、使い回し以外の直し方が要るかを決める。

## 疑い(未確認)
1. **局所の変数のメモリ(シェーダーのスクラッチ)**: NVIDIA のドライバはキュー(コンテキスト)ごとに「それまでに作ったパイプラインの最大の局所メモリ × 同時に走るスレッドの数」を
   取る、と言われている(未確認)。多重解像度のシェーダーは局所の配列が大きい(multires.hlsli の `RxCell cells[8]`・`MrFraction fractions[8]`・
   物質ごとの 64bit の配列など)。陰解法の PSO を作った後に最大が上がり、捨てたキューの分が返る前に新しいキューが同じ大きさを取ろうとして足りなくなる。
2. 捨てたキューの領域が、GPU が空になる前は返らない(フェンスを待った後でも、ドライバの遅れた解放)。
3. アップロードのヒープの大きなバッファ(T-0410 で反応の表を既定のヒープへ移した。細かくできる箱は表が大きい)— 関係は薄いと見ている。

## 確かめ方(案)
- gpu_lab_box_test に「細かくした箱の後に、キューを作っては捨てるを N 回」の診断(gpu_multires_test の `--repeat-fresh-queue` の形)を足し、
  次を 1 つずつ変えて何回目で止まるかを見る: (a) 陰解法の PSO を作るだけで走らせない (b) 走らせる (c) 捨てる前に `ID3D12Device::Evict`・GPU の空を待つ
  (d) 局所の配列を小さくした陰解法のシェーダー(試験用)。(a) で止まれば 1、(c) で通れば 2。
- 測る値: `IDXGIAdapter3::QueryVideoMemoryInfo`(local・non-local の使用量)をキューを作る前後に出す。

## 完了条件
- [ ] 原因が 1〜3 のどれか(またはどれでもない)を確かめ、ADR-0137 追記 3 に書き足す
- [ ] 使い回しのまま閉じるなら、その理由(世界の側はキューを起動時に 1 回作るので当たらない)を書く
