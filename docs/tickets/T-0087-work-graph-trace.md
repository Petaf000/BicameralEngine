- Status: Done(2026-10-01)

## 目的
反応の連鎖を GPU の中だけで走り切らせても、「どのレコードがどのレコードを生んだか」を後から辿れるようにする。
同じ入力で連鎖が毎回同じになること(ADR-0003)と、CPU リファレンスとずれた最初の場所を、症状から原因へ辿れるようにする。

## やること(案)
- **連鎖の記録(トレース)**: 選んだ範囲(セル・刻み)だけ「親のレコード → 子のレコード」をバッファに書き、読み戻してファイルに落とす。
  レコードの ID は (刻み, ノード, 順番に依存しない値。伝導ならブロックの番号) にする(atomic の順番を ID にすると毎回変わる)。
  CPU 側で刻みごとの木として並べ替えてから比べる。
- **決定性の確認**: 同じ入力で 2 回・フレームの分け方を変えて走らせ、カウンタ(T-0008)とトレースが一致するテスト(ハードウェアと WARP)。
- **CPU リファレンスとの突き合わせ**: 伝導(仮の刻み)を対象に、食い違った最初の刻み・ブロック・セルを報告する(16 §3 の道具の最初の形)。
- **PIX**: Work Graphs のノードごとの時間・レコードがどこまで見られるかを調べて 16 §4 に書く(未確認)。

## 研究の部分と打ち切り条件
- トレースの記録が重すぎる場合(伝播の時間が 2 倍を超える)は、全記録をやめて「サンプリング(N ブロックに 1 つ)」と
  「カウンタだけ」に落とす。それでも重ければ debug プリセットだけで有効にする。
