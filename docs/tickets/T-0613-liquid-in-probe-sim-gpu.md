# T-0613 仮の世界(ProbeSim)の GPU に液体の区画(実行中の世界で水が流れる)

- Status: Done(GPU の液体の段・CPU と毎刻みビット一致。保存点などは T-0620・費用を下げるのは T-0661)
- 種類: 工学・GPU
- PC: 必須
- 見積もり: チャット 1〜2 回分
- マイルストーン: ROADMAP の T-0027(水。T-0609 から分けた)・⑤ の T-0415(氷が溶けて流れる・池を抜く)と T-0414(川が熱を吸う)の下支え
- 設計: docs/design/07-transport.md §3・§3.1 / 決定: ADR-0266・ADR-0276・ADR-0268(いずれも Proposed)・T-0592(気体の単位の形)

## 目的(1〜2 行)
CPU リファレンスの液体の区画(sim/probe_liquid: 列の静水圧・面の運動量の移流・位置と運動のエネルギーの帳簿・空き)を仮の世界の GPU の刻みに載せ、
毎刻み CPU とビット一致させる(段の順は CPU の Advance と同じ: 気体 (1b) → 液体 (1c))。⑤ の水の場面を窓で遊べる形にする下支え。

## 完了条件(チェックできる形で)

- [x] 置き場所は 1 つのバッファ(liquidWork。ルート署名の u19)。ルート署名 61/64 語
- [x] 液体が変えたセルは熱のキャッシュを作り直し、ブロックを起こす(CPU の (1c) と同じ種)

      最後の液体の状態(面の運動量・運動と位置のエネルギー・帳簿)のハッシュ。WARP は ctest に登録

## 形(GPU。shaders/sim/probe_liquid_tick.hlsl・engine/src/sim/probe_sim_liquid.cpp・shaders/common/probe_liquid_gpu.hlsli)
- CPU の 1 刻み(刻みの初めの値 → 圧力 → 面の力 → 質量を動かす → 運動量を運ぶ → エネルギーを熱へ)を 10 段の compute に分け、
  CPU が「面から両側へ配る」所を GPU は「セル・面ごとに自分に関わる面を集める」形に直した(結果は整数で同じ。順番に依存しない)。
  Read(写しとセルの値・位置のエネルギーの出入り)→ Pressure(1 スレッド = 1 列)→ Forces → Outgoing → MoveFaces → Apply(成分とエネルギー)→
  Leaving → Advect(移流)→ SettleFaces → SettleCells(熱・キャッシュ・ブロック)。
- 上流のセルの成分は刻みの初めの写し(作業場)から読む。成分の増減はセルごとの作業場(16 件)に積み、ID の順に 8 つのインラインへ詰める
  (ローカルの配列を動的な添字で読まない。T-0397)。溢れ(CPU は止まる)は数えてそのセルを変えない。
- 帳簿(外から入った運動量・位置のエネルギーの出入り)は波の和 + 64bit の原子的な足し算(整数の和なので順番によらない)。
- 作業場は区画のセルあたり約 0.7 KB(区画 480 セルで約 0.3 MB。64³ の全部なら約 180 MB)。
- 液体の区画が無い世界は何も変わらない(ルート署名に u19 が増えただけ。無ければ重さの捨て場を結ぶ)。

## 判断待ち(仮で進めたもの。作り手から見た違いで)
1. **ルート署名の置き方**: 仮 = 液体の全部(状態・作業の値・帳簿)を 1 つの UAV(u19)に。61/64 語で残り 3 語(UAV 1 つ分)。
   作り手から見た違いは無い。次に GPU の段を足す時(放射 T-0586 など)は、気体の 4 つ(u15〜u18)と液体を 1 つの「区画の作業場」にまとめる案
   (気体の箱のセルと帳簿は GpuGas のルート署名でも結ぶので、ProbeSim 側だけ 1 つにまとめて場所を見出しで持つ)で 2〜3 語あけられる。
2. **液体が無い刻みも 10 段を流す**: CPU は「液体が無く静止」の刻みを飛ばすが、GPU は区画があれば毎刻み流す(結果は同じ。費用だけ)。
   活性の所だけ流す(T-0233 の名前だけの ⑤)まで、区画は場面の大きさに絞って使う。
3. **費用を下げる → T-0661(分けた。行だけ)**: 今の約 75 µs/刻みは区画の大きさによらない固定費(10 段の投げとバリア)。案 = ① Read と Pressure・
   Outgoing と MoveFaces・SettleFaces と SettleCells をグループの中の同期でまとめる(区画が 1 グループに収まる時)② 液体の無い刻みは CPU と同じく飛ばす
   (間接の投げで 0 グループに)③ WG と Compute を比べる(気体の T-0621 と一緒に)。作り手から見た違い: 費用だけ(結果は同じ)。

## 結果(2026-10-16・release・RTX 3070 Ti)
- gpu_probe_liquid(HW): 池に溜まる 120 刻み・堤を消すと抜ける(砂の床 = 孔のある面)120 刻み・ダムの水が押し寄せる 180 刻み・移流なし 60 刻みで、
  毎刻みの状態のハッシュが CPU(ProbeReference::EnableLiquid)と一致。最後の液体の状態(面の運動量・運動と位置のエネルギー・帳簿)のハッシュも一致。
  成分の溢れ 0・assert 0。WARP(各 3〜4 刻み)も一致。
- 既存: gpu_probe_sim・gpu_probe_sim_tables・gpu_probe_gas(と各 WARP)が通る(ルート署名 u19 を足した)。
- 費用: 液体の段 約 75 µs/刻み(480 セル 75.7・192 セル 74.7。docs/perf.md)。CPU リファレンスは 192 セルで 147 µs。
- **最初の版は HW だけ刻み 1 から食い違った(WARP は一致)**: 空き(セル − 固体)と溢れ(体積 − 空き)を `occupied >= C ? 0 : C − occupied`・
  `C − min(solid, C)`・`if (volume > room) … volume − room` と書いていた = 64bit の「0 で止める引き算」で、NVIDIA のドライバが誤って下ろす(T-0185 と同じ)。
  符号付きの差 → 0 以下を 0 にする形に直して一致。試験に、食い違った刻みの GPU と CPU のセルの違いを出す手がかり(LogCellDifferences)を残した。
