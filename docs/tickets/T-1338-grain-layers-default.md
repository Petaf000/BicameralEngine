## メモ・参考
- 作り手から見た違い(D-687): 層を書かずに置いた砂もそのまま積もった層になる(置き忘れて舞う・眠らないことが無い)。舞わせる時だけ層から残りへ移す法則を書く。
- **層を使わない世界は層 0 のまま(Settled でも)**: 前の `Settled` は世界を見ずに層 = 量にしていた。そのまま既定にすると、層を使わない世界の
  砂(試験・パッケージ)も層を持ち、根の頁が層の頁になる・置かれ方の配りの物質が「層の分・残り」の 2 つに割れる・GPU は一様の枠の層と溢れの世界の層を
  まだ写せず断る(T-1240)。層を使わない世界では層は舞う粒を分けない(粒は全部沈む側)ので、層 0 と全部が層は遊びの上で同じ。
  → `Settled` は層を使う世界(`table.environment.cellLayers`。ベイクの前に環境の値は入っている)だけで層 = 量、使わない世界は層 0。どちらも知らせは作らない。
- 記録したハッシュ・期待の取り直し: 要らなかった。層を使う世界を選ぶパッケージは data/ に無く(試験の world_layout_test・environment_package_test だけ)、
  層を使わない世界の組み立ては前と同じ(world_layout_test の層つきの根の置き方とハッシュの比べは前のまま通る)。

  `BakeWorldLayout(…, Floating)` で知らせを確かめる。表の警告に出る所はベイクに読み方の口が無いので試験できない)。(b) のまま ⑤ の場面を越えたら、
  知らせ・警告の道と `Floating` を消してよい(消すのは司令塔の判断)。

## 土台に足りないもの(印。司令塔へ。この作業役は足していない)
ユーザーの答え「置いた粒は全部を層として読む(舞う粒は崩れ・吹き上げの出来事からだけ)」のうち、パッケージの組み立て(world_cells)の外で粒が現れる所は
今も舞う粒になる。どれも土台の共通の規則(CPU と GPU の両方)なので変えていない:
1. **刻みの付け替え**(CPU の StoreCellAt・GPU の層を合わせる段 RecordLayerReconcile): 層 = min(前の層, 今の量)・増えた分は残り(舞う粒)。
   反応で生まれた粒(灰・析出など)は舞う粒として現れる。「出来事からだけ」に合わせるなら、粒の物質の増えた分を層に足す規則(層 = min(前の層 + 増えた粒, 量))
   に変える案がある(層の無い世界には効かない・CPU と GPU の両方・層の試験のハッシュが変わる)。
2. **層なしの根の置き口** `PlaceRootBlock(nest, …, cells)`(と実験室の FILL など、層を書かない置き方): 層 0 で置く = 層を使う世界では舞う粒。
   ADR-0489 の T-1236 の行の「(b) に決まった時に残るのは『層の並びが無い ≠ 層 0』の印」がこれ。今は層を使う世界をエンジンの本体が作る所は無く
   (ApplyCellLayersChoice を呼ぶのは試験だけ)、試験は層つきの置き口で置いている。
- おすすめ(仮・ユーザー未確認): 1 は「反応で生まれた粒は層に足す」(出来事 = 崩れ・吹き上げの法則だけが層 → 残りへ移す)。2 は層を使う世界の層なしの置き口を
  「粒は全部が層」にする(呼ぶ側が層を渡せば今のまま)。どちらも土台 21 §3 と照らしてから(司令塔)。【エンジン】の問いにするなら:
  「層を使う世界で、反応で生まれた砂・灰は積もった側から始まるか、舞った側から始まるか」(作り手から見た違い: 舞った側なら、燃えかすが細かくした時に空中に広がり頁が眠らない)。
