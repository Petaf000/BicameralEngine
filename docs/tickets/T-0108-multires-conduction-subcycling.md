## 目的(1〜2 行)
面の係数が熱容量の上限(1/8)で止まるレベル(試験の表で k ≥ 3)より細かい所で、熱の伝わり方が本当より遅くならないようにする。
レベルごとに 1 刻みを 4^σ 回に分けて進め(σ ≤ Δkmax = 3)、違うレベルの面は粗い刻みの終わりに 1 回で受け渡す。保存はビット単位のまま。

## 分けたもの(2026-10-05。CLAUDE.md §3)
- **T-0108(これ)**: 物差し(レベルごとの実効の拡散率 ÷ 本当の値)・方式①の CPU リファレンス(全部を刻む・活性)・保存と活性 = 全部の検査。
- **T-0109**: 方式①を GPU に(細かい刻みごとに Dispatch を分ける・CPU とビット一致〔HW・WARP〕・空の DispatchGraph の費用・予算〔ADR-0011〕で Δkmax を確かめる)。

## 先行研究の結論(調べ役。2026-10-05)
- **方式①(このチケット)**: レベルごとのサブサイクリングと流れの積算の受け渡し(Berger–Colella の refluxing の形)。レベル k を 1 刻みに
  4^(k−k*) 回に分けて進める(拡散は刻みが一辺の 2 乗に比例するので比は 4)。細かい側は小刻みの流れを合計し、粗い刻みの終わりに 1 回で粗い側へ渡す。
  違うレベルの面は ADR-0017 の形(細かい側が計算・粗い側は整数部 + 端数で受ける)をそのまま使えるので、保存はビット単位・Jacobi 型の決定性も守れる。
  粗い側の値は粗い刻みの初めで固定(時間補間しない)。直列の段数は 4^Δk で増えるので **Δk ≤ 3(64 回)で上限**。
- 注意: 粗いセルが小さい時に、細かい側が 4^d 回引いて負や行き過ぎになりうる → 比例配分の制限(熱容量の上限)を「粗い刻み 1 回分の合計」に掛ける。
  Work Graphs に全体の同期が無いので細かい刻みごとに Dispatch を分け、CPU は最大回数を積み、要らない回は空で抜ける(空の DispatchGraph の費用は未確認 → T-0109 で測る)。
- 試す順: (1) 物差し(解析解と比べ、レベルごとに「実効の拡散率 ÷ 本当の値」。今は k ≥ 3 で約 4^-Δk のはず)→ (2) CPU リファレンス → GPU でビット一致(T-0109)。
  合格: Δk ≤ 3 で実効の拡散率の誤差が小さい・エネルギーがビット保存・刻みの費用が細かい部分の大きさに比例。打ち切り: 予算(ADR-0011)を超えたら Δkmax を下げる。
- 試験の表の伝導率は現実の 5000〜20000 倍(k* が試験では 3、現実の空気では 9)。Δk の上限は両方の条件で評価する。

## 後で(このチケットではやらない。ユーザーの判断待ち: Δk > 3 の細かさが遊びに要るか)
- **方式②**: 陰解法(後退 Euler)+ 回数固定の反復 + 木の多重格子。近似解から面の流れを出せば、反復が収束しなくても保存はビット単位
  (流れは面ごとに 1 つの値を両側で逆向きに足すので)。64bit を超える積に注意(係数 × 温度差 × 反復の重み)。
- **RKL(super-time-stepping)**: 段の数 s で安定な刻みが s² 倍。決定性は保てるが、段の係数が分数なので整数化の設計が要る。

## メモ・参考
- 決めたこと(Claude。ADR-0017 追記): σ(k) = clamp(k − 基準, 0, Δkmax)、基準 = 頭打ちにならない**最後の**レベル(k* − 1)、Δkmax = 3。
  先行研究の 4^(k−k*) のままだと k* のレベル自体が 0.264 倍に遅い(物差しで測った)ので 1 つ下げた。
- **物差しの目標**: Δk ≤ 3 のレベルで |実効の拡散率 ÷ 本当の値 − 1| ≤ 5%(空間の離散化 4sin²(π/16) ÷ (π/8)² = 0.987 の差を含む)。
- 1 刻み = 最も細かい小刻み 4^Δkmax 回。小刻みごとに 印 → 頁 → 端数の枠 → 流れ(その小刻みに始まるレベルだけ)→ 終わるレベルに溜めた変化を足す →
  活性なら変わったブロックの隣を起こす。最後の小刻みの変化は反応と一緒に足す(分けない時は T-0019 と同じ順・同じ結果)。
- 粗い側の上限 = min(G の係数 × 4^(kf − σf), C の上限 × 2^d ÷ 4^(σf − σc))(細かい側が粗い小刻み 1 回の間に引く回数で割る)。
- CPU: engine/src/sim/multires_conduction.cpp の nest_detail::StepConduction。式: shaders/common/multires_conduction.hlsli の MrSubstep*・MrSubcycle*。
