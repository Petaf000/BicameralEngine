## 目的(1〜2 行)
`--editor` の筆で置いた運び(1 回のクリック・1 回のドラッグ)を「元に戻す」で、その運びが無かった世界にする。
記録(再生ファイル)も、元に戻した後の世界が「その操作が無かった世界」と同じになる形で残す。

## 完了条件(チェックできる形で)
- [x] 運び(押してから置き終えるまで)ごとにコマンドの番号を控え、最後の運びを元に戻す(パネルのボタン・Ctrl+Z)
- [x] 元に戻す = その運びが最初に当たる刻み以前の保存点へ戻し、その運びを除いて戻す前の刻みまで流し直す(追いつく。止めていても)
- [x] 記録中も戻せる。記録は元に戻した後の流れだけ(ADR-0101 §3)。戻せない場合の扱い(ADR-0101 §4)
- [x] テスト: brush_undo(CPU)・sim_scheduler(追いつき)・replay_file(記録の切り詰め)・window_place_record/play
      (`--auto-place` に「つつく → 円柱 → 直方体のドラッグの順に元に戻す」を足した。戻す前と違う状態・残って当たった数・
      別の起動の再生が同じハッシュ列 = 置かなかった記録と一致)
- [x] ADR-0101・14 §2・map.yaml

## 引き継ぎメモ(HANDOFF に載せる内容)
- 動いているもの: `bicameral --editor` の筆のパネルの「最後の運びを元に戻す (Ctrl+Z)」。運び = 押してから置き終えるまで
  (ドラッグが 2 フレームに分かれても 1 つ)。64 個まで控える。後の操作(つつき・ほかの運び)は残る。止めていても結果がすぐ見える。
- 注意:
  - 戻せるのは保存点の範囲だけ(`--editor` の既定 6 個 × 120 刻み。起動して刻み 120 より前の運びは戻せない)。
  - 記録中も巻き戻せるようになった(ふつうの巻き戻しも)。記録は最後の流れだけで、元に戻す操作の印は残らない(ADR-0101)。
    記録中は反応表の差し替えより前へは戻さない(差し替えの印を足し直さないため。記録中でないふつうの巻き戻しは前のまま)。
  - window_place_record は `--save-points 8 --save-interval 2` を付けた(debug は 1 フレーム 1 刻み未満で、最初の保存点が 120 刻みでは遅い)。
  - BrushPanel が全部の刻みのハッシュを NoteHash で見る(元に戻す前後の比較。数個の比較だけで軽い)。

## 判断待ち
1. **記録に「元に戻した」を残すか**(仮で A に決めて実装した。ユーザー未確認。取り消しやすい: B は後から別の欄で足せる)
   - A(今): 記録は元に戻した後の流れだけ。プレイヤーと遊びへの影響: 記録を再生すると「間違えた運びが最初から無かった」世界が
     そのまま流れる(実験の記録・不具合の再現が短く、決定性の確認もそのまま)。「何を試して取り消したか」は見返せない。
   - B: 元に戻した運びと、戻した時刻を別の欄(世界の列とは別。ADR-0035 の「見る側の操作の列」と同じ扱い)に残す。影響: 研究の
     試行錯誤の履歴として見返せる(どんな配置を試して捨てたか)。費用: 小〜中(再生ファイルの版を上げる・表示を作る)。
   - おすすめ: A(今は筆はエディタの道具で、記録は「世界の結果の確認」が主な使い道)。ゲームの中でプレイヤーの研究ノートに
     試行の履歴を残すなら、その時に B を世界の列とは別の形で設計する。
2. **起動直後(最初の保存点より前)の運びも戻せるようにするか**(仮: 戻せないまま。分けたものの T-0296 案)
   - 影響: 今はエディタを開いて最初の約 2 秒(刻み 120)に置いた運びは戻せない(パネルに理由が出る)。刻み 0 の保存点を作れば
     いつでも戻せる(保存点 1 つ分の VRAM 約 33 MiB)。おすすめ: 作る(小さい。実装の細部なので次のチケットで Claude が決めてよい)。
