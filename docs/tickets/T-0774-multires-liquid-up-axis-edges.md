## 目的
MR の液体(multires_liquid)の縦を WE_UP_AXIS から読み(D-518 = y。液体の芯と同じ向き)、世界の端の種類と外の柱を MultiresNest::edges から読む。
作り手が環境に world_edges = { sides = "open" } と書くと、池の堤を消した水が開いた横の端から世界の外へ出る(設計 20 例 3)。

## 完了条件
- [x] 縦の面・柱・位置のエネルギーの高さを WE_UP_AXIS から(LiquidGrid の originUp・HeightCells・ComputePressure・ApplyForces の縦の面)
- [x] 液体の端を nest.edges から: 面の先 = WeEdgeNeighbor(T-0771 の世界の Neighbor と一緒に)。開いた端の外は外の柱の行(液体なし = 出ていくだけ・下なら支えない)。
      端の面の運動量は持ち越さず、内側の面の速さを写す(流れ出しの境界)。帳簿の「世界の端」(運動量の入出・物質・エネルギー・位置のエネルギー)
- [x] 試験 multires_liquid は NestPlace 型の写しで仮の世界と比べる(気体の試験と同じ。面の欄・報告・帳簿の軸は NestAxis)。WE_UP_AXIS = 2 にしても毎刻みビット一致(一時的に確かめた)
- [x] 開いた端の場面(MR だけ): 横と上が開いた池・下が開いた世界で落ちる水。毎刻み Σ 保存量 − 帳簿が一定・出た水 = 帳簿の「世界の端」の水の列
- [x] release のビルド警告 0・multires_liquid・^multires_・probe_liquid・rest_return・transport_apply・environment_package・archmap --check

## 作業ログ
- 2026-10-18(wt6・作業役。T-0771・T-0777 と一緒に): 縦を WE_UP_AXIS に、面の先を世界の Neighbor + WeEdgeNeighbor に。開いた端の面は最初「毎刻み 0 から」にしたが、
  下が開いた世界で落ちる水が 3 秒で 19% しか出ない(底の段で滴る)ので、内側の面の速さを写す流れ出しの境界にした(ほぼ全部出る)。
  前の試験は仮の世界と毎刻みビット一致のまま(基準の取り直しなし)。

## 判断待ち(仮〔ユーザー未確認〕。取り消しやすい。ADR-0349)
1. **開いた端の液体の面**: 仮 = 運動量を持ち越さず、刻みの初めに内側の面の速さを写す(端に垂直な速さの勾配 0)。作り手から見た違い: 端から出ていく水は
   内側の流れの速さのまま出る(滝の口・堤の切れ目から勢いよく出る)。端の面の慣性(端の外で加速し続ける分)は持たない。案 B: − 側の端の面に欄を足して持ち越す
   (液体の欄の頁がセルあたり 8 → 14 個の i64)。おすすめ: 仮のまま(差が見えた時に B)。
2. **真空の開いた端**: 仮 = 外の柱が無い(基準の大気が無い)open は液体にも閉じた面(伝導と同じ WeEdgeNeighbor)。作り手から見た違い: 大気を書かない世界で
   端を open にしても水は出ない(ベイクの「注意」は出る)。案: 液体は空の外のセルとして出す(1 か所の場合分け)。おすすめ: 仮のまま(世界を作る段で見直す)。
