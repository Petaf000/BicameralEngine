## 段取り(順に。それぞれ CPU リファレンスと GPU のビット一致・保存・決定的を付ける)
1. **木の見方**: 密な CascadeGrid の代わりに、sun_column の SunBlockView と同じ形で葉を引く口(座標 → その所の葉の細かさ・光の値・温度)。土台の口(LoadNestField・FieldPageValues・MultiresCellStore)だけで読む。
2. **粗い葉の歩き方**: 整数の DDA を葉の大きさで歩く(粗い葉 1 つ = 2^L セルの立方体。通しやすさは葉の量の混ざった値〔ADR-0380〕で)。
3. **粗い葉から放つ**: 面の面積が 4^L 倍。σT⁴ × α の量は面積に比例するので、細かさによらない(R-R0 の 0.04 % と同じ確かめ方: 0.5 m / 1 m の地面で受ける和)。
4. **出どころと袋の鍵を相対に**: 溜めの出どころをブロックからの相対(15bit × 3 のまま)、袋の鍵を起きている所の原点からの相対にして 127 の限りを外す。
5. **受けの置き場**: セルごとの密な受け(吸った・放った)を、葉の頁ごとの疎な置き場へ(T-1010 の 2 本目と同じ考え)。
6. **空との交換の口(ADR-0474・T-1145・T-1147)**: 口の掃きは太陽の影の柱そのままで、木(粗い葉を含む)を前から読む。木へ載せても変えなくてよい見込み。
   費用は箱の上の面の光線の数(向きごとに 一辺 × 2 の 2 乗ほど)で決まる: 64³ で約 0.5 ms(T-1147。帯の正と負を 1 本・向きを 1 回の起動)。
   起きている所を広げると光線は面積に比例して増える(未確認)。粗い輪の上は粗い光線(rayLevel を輪の細かさに)で掃けば本数は輪ごとに同じ見込み。
   それでも線を超える時は向きを刻みで回す値(T-1147。既定は切る)を入れる。
   ただし RC の世界の箱が「起きている所」になると、箱の横の外 = 参照の温度の物は「箱の外の世界」と同じ意味になる(粗い輪の外を参照の温度とみなす)。
7. **参照の温度(ADR-0461)**: 起きている所の環境の温度を参照にし、負の側は参照より冷たい物だけ(T-1102 の測りで、地面全部が参照より冷たいと負の側の光線が 42 万本/刻みに増えた)。

## 費用の見込み(未確認。RTX 3070 Ti・熱も 15 組・照り返す地面)
- 照り返す面 1 つあたり 約 0.2 µs/刻み(64³: 地面 約 4,100 面で 0.58〜0.90 ms から)。決まった費用(起動)約 0.1〜0.2 ms。
- 細かい芯 32³(16 m)+ 粗い輪 4 つ(1・2・4・8 m のセルで 〜256 m): 輪ごとの照り返す面は芯の約 0.75 倍 → 芯 約 0.25 ms + 輪 4 × 約 0.18 ms + 起動 → **約 1.0〜1.2 ms**。
- 芯 48³(24 m)なら 約 1.6〜1.9 ms。1 ms の線(仮)に入れるには、芯 32³ か、照らされても温度が計器の精度より動かない所の照り返しを眠らせる(23 §4)。
- 粗い輪の照り返しは粗い葉の面(大きい)から出るので光線の本数は輪ごとに同じだが、歩くセルは葉の大きさで減る(1 本の歩きは短くなる見込み)。

## 土台に足りないもの(2026-10-29 wt6。司令塔が設計として預かる T-1227・T-1228 へ。ここでは足していない)
写しは「木 → 0.5 m の密な升目」まで GPU でできた。ここから先、RC が木の上で閉じるには次の 3 つが土台に要る(どれも RC だけの都合で作らない):
1. **受け(吸った・放った)を木へ当てる段の源の項(T-1228 / ADR-0469 の芯 4-1)**: 今の受けは升目のセルごとの密な配列(作業の中)で、
   木の葉へ戻す口が無い。要るのは「升目のセル(0.5 m)ごとの熱の出入り → その所の葉(粗い葉なら 2^−3L の和)への源の項」として当てる段の口。
   粗い葉へは升目の 2^−L 角の和を 1 つの源にする(足し算の順で結果が変わらない整数の和。CPU の FoldCascadeToLeaves と同じ)。
   当てる段が「変わったブロックの印」を作る(T-1228)なら、RC の受けがあった葉もその印に載る必要がある(眠った葉を起こす道)。
2. **持ち越しを登録の欄に・偶奇の 2 枚の欄(T-1227)**: RC の持ち越し(刻みをまたいで伝わる光。今は作業の中の 2 枚のハッシュ表 stateCarry0/1)を、
   登録の欄(頁ごとの疎な置き場)の偶奇 2 枚に載せる形。鍵は今 (升目のセル・面・帯) で、升目が木の葉に変わると鍵は (葉の頁・セル・面・帯) になる。
   これが決まると段取り 5(受けの置き場を葉の頁ごとに)と段取り 4(127 の限り = 出どころと袋の鍵の相対化)の形も決まる。
3. **GPU の頁への atomic の足し込み(T-1227)**: 光線が葉の頁へ吸った量を足す時、今は升目の密な配列へ 64bit の atomic。頁が疎になると
   「頁が無い所へ足す」(頁を起こす要求か、溢れの印か)の規則が土台に要る。決定性は整数の和なので順に依らない(今と同じ)。
- このチケットで先に進められるもの(土台に触らない): 段取り 4(出どころ・袋の鍵の相対化。ただし 2 の鍵の形が決まってからの方が手戻りが少ない)・
  段取り 2(粗い葉を葉の大きさで歩く。CPU リファレンスから。結果が変わるので一致の基準を作り直す)。
- 測りで分かったこと: GPU の試験で刻みごとに CPU のリファレンスを待つと、同じ場面の RC が 230〜2700 µs で揺れる(GPU のクロックの状態と見る。未確認)。
  費用を見る時は CPU を挟まずに続けて流す(この試験の 3)。T-1101 の 64³ の値もこの揺れを含むかもしれない(未確認)。
