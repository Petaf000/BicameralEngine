## 目的(1〜2 行)
CPU の模型(gas_projection: 陰的な音を熱の多重格子〔ImplicitGrid の V サイクル〕で解く・外側の反復 上限 4)を GPU に載せて CPU とビット一致させ、
1 レベルの一様な箱(16³〜64³)で泡・扉・強い爆発の 1 刻みの時間を測り、今の陽解法の小刻みの気体(gpu_gas)と比べる。予算は仮 4 ms/刻み。

## 研究の打ち切り条件(始める前に書いた。2026-10-15)
- **時間**: 2 時間で区切る(見積もり 2〜3 チャット)。残りは「引き継ぎメモ」へ。
- **ビット一致しない**: 同じ部品の組み合わせなので一致するはず。解く部分が一致しなければ、違いの出る最初の段(前の判定・V の段・止める判定)を
  2 回まで直す。直らなければ、どこでずれるかを書いて止める(形の誤り。費用の計測には進まない)。
- **費用が予算を大きく超える**(32³ の爆発の刻みで 4 ms の 2 倍〔8 ms〕超、または 64³ の落ち着いた刻みで 4 ms 超): 打ち切りではなく、
  どこに時間が行くか(V サイクル・式を作る・当てる・外側の回数)を分けて測り、作り手に見せる形
  (箱の大きさ・外側の上限・許容差・音速ごとの ms)をチケットに書いて止める。V サイクル 1 回の固定費(T-0494: 16³ で約 0.45 ms)が支配的なら、
  記録の形(ShapeFrom・安い回)の使い回しで下がるかを 1 回だけ試す。
- **GPU が止まる(TDR)**: 大きい箱は 16³ → 32³ → 64³ と段階的に。1 本のリストに積む刻みを減らし、それでも止まるなら 64³ は測らずに残す。

## 進め方(部品と順。費用の大半を先に測る)
1. **解く部分**(このチャット): GpuImplicit に「一般の右辺で解く」形 RecordSolve を足す(ImStart の代わりに呼ぶ側が作業場に右辺・初めの近似・
   セルごとの閾値を書く。止める判定は「|残差| ≥ ⌈(許容差 + 1)× 2^48 ÷ D_i⌉ のセルがあるか」= CPU の floor(|r| D ÷ 2^48) > 許容差 と整数で同じ。
   CPU は V の前にも判定するので、GPU も前の判定を 1 回置く)。CPU の模型に「解いた系を見せる」口(観測)を足し、試験で全部の解きを GPU で解き直して比べ、時間を測る。
2. 式を作る段・当てる段(gas_step.hlsl の Derive〜Transfer を使い回し、圧力を x に替える)・食い違い・右辺を直す段。系の段(多重格子)は、
   最速なら C が一定なので形は刻みによらず同じ(最初に 1 回作る)。音速を選んだ世界は C が温度で変わる → GpuImplicitLevels(T-0134)で GPU が作る。
3. 1 刻み全体のビット一致と計測。

## メモ・参考
