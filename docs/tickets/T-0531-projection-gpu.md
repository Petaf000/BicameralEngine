## 目的(1〜2 行)
CPU の模型(gas_projection: 陰的な音を熱の多重格子〔ImplicitGrid の V サイクル〕で解く・外側の反復 上限 4)を GPU に載せて CPU とビット一致させ、
1 レベルの一様な箱(16³〜64³)で泡・扉・強い爆発の 1 刻みの時間を測り、今の陽解法の小刻みの気体(gpu_gas)と比べる。予算は仮 4 ms/刻み。

## 研究の打ち切り条件(始める前に書いた。2026-10-15)
- **時間**: 2 時間で区切る(見積もり 2〜3 チャット)。残りは「引き継ぎメモ」へ。
- **ビット一致しない**: 同じ部品の組み合わせなので一致するはず。解く部分が一致しなければ、違いの出る最初の段(前の判定・V の段・止める判定)を
  2 回まで直す。直らなければ、どこでずれるかを書いて止める(形の誤り。費用の計測には進まない)。
- **費用が予算を大きく超える**(32³ の爆発の刻みで 4 ms の 2 倍〔8 ms〕超、または 64³ の落ち着いた刻みで 4 ms 超): 打ち切りではなく、
  どこに時間が行くか(V サイクル・式を作る・当てる・外側の回数)を分けて測り、作り手に見せる形
  (箱の大きさ・外側の上限・許容差・音速ごとの ms)をチケットに書いて止める。V サイクル 1 回の固定費(T-0494: 16³ で約 0.45 ms)が支配的なら、
  記録の形(ShapeFrom・安い回)の使い回しで下がるかを 1 回だけ試す。
- **GPU が止まる(TDR)**: 大きい箱は 16³ → 32³ → 64³ と段階的に。1 本のリストに積む刻みを減らし、それでも止まるなら 64³ は測らずに残す。

## 進め方(部品と順。費用の大半を先に測る)
1. **解く部分**(このチャット): GpuImplicit に「一般の右辺で解く」形 RecordSolve を足す(ImStart の代わりに呼ぶ側が作業場に右辺・初めの近似・
   セルごとの閾値を書く。止める判定は「|残差| ≥ ⌈(許容差 + 1)× 2^48 ÷ D_i⌉ のセルがあるか」= CPU の floor(|r| D ÷ 2^48) > 許容差 と整数で同じ。
   CPU は V の前にも判定するので、GPU も前の判定を 1 回置く)。CPU の模型に「解いた系を見せる」口(観測)を足し、試験で全部の解きを GPU で解き直して比べ、時間を測る。
2. 式を作る段・当てる段(gas_step.hlsl の Derive〜Transfer を使い回し、圧力を x に替える)・食い違い・右辺を直す段。系の段(多重格子)は、
   最速なら C が一定なので形は刻みによらず同じ(最初に 1 回作る)。音速を選んだ世界は C が温度で変わる → GpuImplicitLevels(T-0134)で GPU が作る。
3. 1 刻み全体のビット一致と計測。

## メモ・参考
- 陽解法の気体(gpu_gas)の 1 刻み(小刻み 24): 32³ 9.6 ms・64³ 74 ms(T-0226。docs/perf.md)。熱の V サイクル 1 回の GPU: 16³ 約 0.45 ms の固定費・64³ 約 6 ns/セル(T-0494)。

## 結果(2026-10-15。1 チャット目。表は docs/perf.md の T-0531 の行)
- **解く部分は CPU とビット一致**: GpuImplicit::RecordSolve(一般の右辺。implicit_conduct.hlsl の ImSolveConverged・ImSolveCheckEnd を足し、ほかの段は熱のまま使い回し)。
  止める判定はセルごとの閾値 ⌈(許容差 + 1)× 2^48 ÷ D_i⌉(GasPressureThresholds)。V の前にも判定する(CPU の Solve と同じ順)。
  試験 `gpu_gas_projection_test`(ctest の gpu_gas_projection。16³・3 刻み・約 3 秒): CPU の模型の解き(外側の解き直しも)を見る口(GasProjectionOptions::solveObserver)で受け、
  同じ系を GPU で解き直して値と V の回数を比べる。泡・扉・爆発 × 最速・340 m/s、16³ と 32³ で全部一致(記録の形 既定・前の解きの数から の両方)。
- **費用(解く部分だけ。前の解きの数から選ぶ記録の形)**: 16³ 泡 0.35 ms・扉 0.6 ms・爆発 2.8 ms/刻み。32³ 泡 0.9〜1.6 ms・扉 2.6〜6.8 ms・**爆発 11.7〜15.0 ms**。
  爆発の刻みは解き 3.3〜3.8 回(外側の反復)× V 2.3 回 = V 8 回前後。32³ の V 1 回は約 0.9〜1.8 ms(揺れが大きい)。
  既定の形(V を上限 64 回まで段ごとに積み、要らない回は述語で飛ばす)は飛ばした回のバリアで 16³ でも 1 回 約 2 ms かかる → 前の数から選ぶ形が要る(熱と同じ。T-0154)。
- **陽解法の気体(gpu_gas・小刻み 24)との比べ**: 32³ 9.6 ms・16³ 1.36 ms(T-0226。場面によらず一定)。投影は落ち着いた場面(泡・扉)で数分の 1、
  強い爆発の刻みでは解く部分だけで陽解法を超える(式を作る・当てるの段を足すと、外側 1 回あたり陽解法の小刻み 1〜1.3 回分 ≈ 32³ で 0.4〜0.5 ms の見込み。未測)。

### 打ち切りの判定
**「費用が予算を大きく超える」に当たった**(32³ の爆発の刻みで 8 ms 超: 解く部分だけで 11.7〜15 ms)。ビット一致・TDR には当たらなかった。
打ち切り条件どおり、どこに時間が行くかを分けて(解く部分 = V の回数 × V 1 回)作り手に見せる形を下に書いた。64³ はまだ測っていない(下の引き継ぎ)。

## 判断待ち(作り手から見た違いで。仮で進めたもの)
**問い: 「最速を選んだ世界で、強い爆発の刻みの重さ(32³ で解くだけで 12〜15 ms)をどう収めるか」**(D-467・D-468。ADR-0234 の続き)
- 作り手から見た数(32³ = 16 m 角の箱・1 刻み・解く部分だけ): 落ち着いた空気・熱い泡 約 1 ms / 扉を開けた圧力の差 約 3〜7 ms / 5 倍の爆発 約 12〜15 ms。
  陽解法(今の gpu_gas)はどの場面も約 10 ms。
- 案 A(おすすめ・仮〔ユーザー未確認〕): 投影を既定の気体にし、外側の反復の上限と許容差(ADR-0234 の案 A)を世界の設定のまま、**V 1 回を軽くする研究を先に**
  (V の回数ではなく 1 回の重さが熱の箱の約 2 倍。段の分け方〔ImTail の境・最も粗い段〕を圧力の系で測り直す・外側の反復の 2 回目からは
  前の回の x と直す量だけで解く〔右辺の変化が小さい〕)。作り手から見て: 落ち着いた世界は今より約 10 倍軽い。爆発の刻みは研究の結果しだい(下がらなければ案 B か C)。
- 案 B: 爆発の刻みだけ外側の反復の上限を 1〜2 にする(作り手が選ぶ)。作り手から見て: 費用は約半分になるが、強い爆発は 2〜3 刻み(約 50 ms)かけて釣り合う(最速が少し遅れる)。
- 案 C: 爆発の近くだけ解き直す(外側の反復を食い違いの大きい所の近くに絞る)。作り手から見て: 結果は案 A と同じ、費用は爆発の大きさに比例。研究が要る(局所の多重格子)。
- どの案でも保存・決定性・CPU とのビット一致は変わらない。

## 引き継ぎメモ(次のチャット)
1. **64³ を測る**: `job.py run -Preset release -Exe gpu_gas_projection_test -- --no-gbv --measure --edge 64 --ticks 3`(CPU の模型が 1 刻み数十秒かかる見込み。--timeout 長め。
   1 本のリストは 6 回 × V 8 回程度なので TDR の心配は小さい)。
2. **式を作る段・当てる段を GPU に**(進め方の 2): gas_step.hlsl の入口を使い回す形。圧力を x に替える Derive(導く値の scaledPressure = x を GpuImplicit の作業場の値 A から)・
   FaceFlow を F* + K(x_左 − x_右)に替える入口・式を作る入口(C_i・V ÷ c_箱²・p̃・F*〔縦の面の静水圧〕・出ていく量の合計を集める形で)→ 右辺 (E − ΣF*) ÷ D と閾値を
   GpuImplicit の作業場へ直接書く(RecordUploadSolve の代わり)。最速なら C は一定なので多重格子の段は最初に 1 回(RecordUpload)。音速を選んだ世界は C が温度で変わるので
   段の対角・重みを毎回作り直す(GpuImplicitLevels。T-0134)。
3. 外側の反復: セルの写し(仮に当てる先)・E_真 と食い違い・割線の傾き・右辺を直す・止めたら述語で残りの回を飛ばす。採る時に写しを本物へ。
4. 1 刻み全体のビット一致(gpu_gas_projection_test を StepGasProjection 全体と比べる形に広げる)・2 回の実行でハッシュ一致・計測。
5. 範囲外のまま: 多重解像度の木(gas_tree。レベルをまたぐ面は熱の木の陰解法 T-0119 と同じ形)・開いた境界の試験。
