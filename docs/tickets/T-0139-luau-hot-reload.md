## 目的(1〜2 行)
エディタ(`--editor`)で反応表のパッケージのファイルを保存すると、読み直し → 型検査 → ベイク → 刻みの境界で世界の表を差し替える。
差し替えは世界のコマンド(印)として記録に残り、GPU と CPU リファレンスが同じ刻みに同じ表に変わる。落ちたら古い表のまま誤りをパネルに出す。

- 注意:
  - **反応表の GPU 用の形と反応の核には触っていない**。probe_tick.hlsl に入口 RefreshTable を足した(shaders/CMakeLists.txt の probe_tick_refresh_table)。
  - 差し替えの印 PROBE_COMMAND_TYPE_TABLE は GPU の適用では何もしない(イベントも出さない)。差し替えの本体は CPU がそのフレームのリストに記録する。
    だから**再生は表そのものが要る**: 今は起動時の表と、その実行で読み直した表だけを探す(版が違えば「その表を持っていない(T-0193)」で止まる)。
  - 覗き窓(ProbePeek)は起動時の表のまま(見るだけ・世界には入らない。T-0194)。実験室(LabSession)は今も C++ の試験の表(T-0172)。
  - 表を差し替えると保存点は全部捨てる。

## 判断待ち
1. **物質を足す・消す変更を、動いている世界にどう当てるか**(仮で案 A で進めた・ユーザー未確認)
   - 案 A(今): 物質の一覧が変わる変更は当てず、「物質を足す・消すときは起動し直す」と出して今の表のまま。プレイヤーと遊びへの影響: 無し
     (エディタの道具)。反応表を書く人は、新しい物質を足した時だけ起動し直す。規則・速度・熱の値の変更はその場で試せる。
   - 案 B: 物質の名前で今のセルの中身を新しい ID に付け替えて当てる(消えた物質の量は保存則のために警告して残すか、世界を作り直す)。
     影響: 新しい物質を足す実験も止めずに続けられる。費用: 中(GPU の付け替えの段と CPU リファレンス・消えた物質の扱いを決める)。
   - おすすめ: A のまま。足す物質の試しが多くなったら B(取り消しやすい。当てられるかの検査 1 か所)。
2. **ゲーム本体(通常の起動)でもファイルを見るか**(仮: 見ない。`--editor` だけ)
   - 見ない(今): プレイヤーの PC ではパッケージを書き換えても次の起動まで変わらない。遊びへの影響: 無し。Mod を作る人はエディタで試す。
   - 見る: Mod を作る人がゲームのまま試せる。代わりに、遊んでいる最中に表が変わり得る(「改造された世界」の印や記録との関係を決める要がある)。
   - おすすめ: 見ない(取り消しやすい。`TableHotReload` を作る時の watch の 1 か所)。

## 分けたもの(司令塔が ROADMAP に足すか決める)
- **T-0193 再生ファイルに差し替えた表の中身を残す**(T-0170 と一緒に。形式の版 2: 版 → 読んだパッケージのソースかベイクした表)。
  今は同じ実行の中か、起動時と同じ表なら再生できる。ホットリロードをまたぐ記録を後で再生するにはこれが要る(13 §2「再生ファイルには表の版」)。
- **T-0194 覗き窓(ProbePeek)・実験室の表も差し替える**(覗き窓は見るだけなので世界の結果は変わらないが、見える反応が古い表のまま)。
