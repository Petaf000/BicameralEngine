# T-0323 世界のコマンドの段に魔法のパッチ(T-0287 から分けた)

- Status: Done(仮の世界の段。2026-10-11。作業役・wt3。多重解像度の世界の段は T-0341 に分けた)
- 種類: 工学
- PC: 必須
- 設計: docs/design/02-reaction-system.md §5・§5.1 / ADR-0095。関係: T-0024・T-0287

## やること
多重解像度の世界(GpuMultires / StepNest)と仮の世界(ProbeSim)で、パッチを置くコマンド(PROBE の型)・記録と再生・境(始まり・終わり)で範囲に重なる全部のレベルのブロックをつつく段を刻みに(活性の種にも)・世界の保存点(VRAM の写し。T-0143)にパッチの列を含める・列が一杯で断った数を数える。

## 注意
- 仮の世界の反応の評価は Work Graph。反応の核を 1 ノードに 3〜4 か所展開すると HW で DEVICE_HUNG になるので、MpPatchedTable の包みは今の展開の数を増やさない形で入れる。ルート署名は多重解像度で 64 / 64 語(T-0024 と同じく外のバッファの枠を刻みの間だけ結ぶ)。
- 公開リポジトリなので、魔法・魔素の設定や値はゲームの中身として書かない(D-006)。シミュのコードに浮動小数点を書かない。
- ルートの SRV / UAV に GetDimensions を使わない(大きさは定数で渡す。T-0024)。

- 試験 `tests/gpu_probe_patch_test.cpp`: 木箱の左右の壁に火・左の壁のまわりでセルロースの 2 つの規則を止める(12 刻み)・右の壁のまわりで炭の燃焼を 2^10 倍
  (40 刻み = 表の差し替えを跨ぐ)・格子の外だけ・角にはみ出す(眠っている空気のブロックを始まり・終わりに起こす)・表に無い規則(断る)・
  列が一杯(断る)・刻み 16 で規則の ID がずれる表(boudouard を抜く)に替え・刻み 20 に替えた表の名前で止める。
  再生ファイルを SerializeReplay → ParseReplay で往復させ、ReplayPlayer で (1) 1 刻みずつ・刻み 8 に保存点・刻み 15 から刻み 8 へ戻して流し直す
  (2) 刻みの途中で切るばらばらの分け方、で流す → 毎刻み要約・エネルギー・湧き出し・計算したブロックの数・上限・断った数が CPU と一致、
  記録の要約とも一致。CPU では止めている間は左の壁のセルロースが減らない(止めない世界では減る)。
- 多重解像度の世界の段は、今その世界を世界のコマンドで刻む道が無い(刻むのは実験室の箱・覗き窓・暗黙の作り直しだけ。T-0287 の作業ログ)ので、
  T-0341 に分けた。

  (パッチが無ければ状態の要約は今までと同じ = 記録の再生も通る)。release は回していない。

## 引き継ぎメモ
- 仮の世界のパッチの範囲は格子のセルの座標(レベル 0)。格子の外にはみ出してよく、全部外でも足す(どこにも効かず、列の席は使う)。
- 連鎖のトレース(sim/probe_trace)の CPU の予想は、パッチの境で起こしたブロックを知らない(予想の根は置く・つつくだけ)。
  パッチの境の刻みをトレースすると、予想と食い違いうる(トレースは世界の結果に入らない。要るなら予想に足す)。
- エディタ・ゲームからパッチを出す操作はまだ無い(T-0325)。frame_loop は種類を見ずにコマンドを記録・再生するので、出せばそのまま記録に入る。
- 置くコマンドの差し替え(RemapPlaceCommand)と違い、パッチのコマンドは表を替えても付け替えは要らない(名前の鍵)。
