## 今(2026-10-11、T-0312 の作業役が見つけた)
- main(8cbf977。t-0327 と t-0347 を合わせた後)の debug で `gpu_multires_test --queue compute --part coarsen`(HW・WARP)が
  「端数の枠の塊: 刻み 2: 端数の枠の塊 10(要る 8)」で落ちた。本体の 12:50 の release の ctest(gpu_multires_wide・gpu_multires_warp)も
  「粗くした後の空きの塊の数が組ごとに違う(最初 125・最後 119)」で落ちている。t-0347 だけ(T-0327 の前)の wt5 では通っていた。
- 1 つ目は試験の側の読み方の食い違いだった: GpuMultires::ReadWideChunkUse が端数の枠の今の面の溢れの数(論理の語 512)を、最初の塊の
  512 語目から読んでいた(T-0327 で論理の語は最初の塊の表の続きの後ろ = MrWideSideOffset(512) に移った)。T-0312(ブランチ t-0312)で直した。
- 残り: 直した後も HW・WARP とも「粗くした後の空きの塊の数が組ごとに違う(最初 125・最後 119)」で落ちる。毎刻みの「空き + 頁 + 端数 = 全部」
  「端数の枠の塊 = 要る塊」は通るので、塊は漏れておらず、組ごとに頁が塊を 3 つずつ多く持つ(頁は返しても塊を付けたまま・余りは刻みの段の
  WideAllocate が返す。この試験は刻まない)。T-0327 で面に要る塊が「最初の塊の頭(表の続き)」の分だけ増えたのと関係がありそう(未確認)。

## やること
1. 組ごとの WideChunkUse.pageChunks と、頁ごと・面ごとの塊の数を出して、どの頁のどの面が塊を増やすかを見る。
2. 頁が組ごとに塊を増やすのが仕様どおり(返した頁の付けたままの塊・刻まないので WideAllocate が返さない)なら、試験の約束を
   「空き + 頁の今の面に要る塊」で比べる形にする。漏れ(要る数より多く付け続ける)なら TreeWideReserve・TreeWideTrim を直す。
