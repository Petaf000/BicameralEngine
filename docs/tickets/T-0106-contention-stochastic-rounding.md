## 目的(1〜2 行)
反応物の取り合いで縮めた進行度の端数を、切り捨てではなく決定的な乱数で丸める。少ししか進まない脇の反応(酸素不足の火の CO など)が毎刻み 0 になって消えないように。

## 完了条件(チェックできる形で)
- [x] 先に、切り捨てで脇の反応がどれだけ消えているかを測る(tests/reaction_contention_test.cpp。切り捨ての値も並べて出す)
- [x] 縮めた端数を確率的に丸め、どの刻みでも消費がある量以下(熱は 1/8 まで)
- [x] 切り捨てで消えていた規則が期待値の ±5σ に入る。ほかの規則の偏りは 0.2% 以内(資源がほぼ尽きた場面だけ 8% 以内)
- [x] 規則の並びを入れ替えても結果が同じ(reaction_test)・保存則(reaction_test の閉じたセル)
- [x] CPU と GPU(HW・WARP)のビット一致(gpu_reaction・仮の世界・多重解像度のテスト全部。64 本が通る)

## メモ・参考
- 規則ごとに 1 つの乱数(望む進行度の丸めと同じハッシュの上位 32bit)を、足りない資源のどれにも使う。丸めは単調なので、資源ごとに丸めた最小 = 比の最小を丸めた値。
- 丸め上げで足りなくなった資源があれば、その資源を使う丸め上げた規則のうち進行度が最も大きいもの(同じなら鍵が小さいもの)から戻す(RxRevokeRoundUps)。
  戻す順の試算(Python、同じ値の場面): 大きい順 → 脇の反応 100%・大きい規則 96〜100% / ランダム → 脇の反応 74% / 係数の大きい順 → 木の燃焼 74%。大きい順にした。
- 係数の大きい規則(木の燃焼 O2 × 6)は、残り(端数の合計)が係数より小さい刻みに丸め上げられず、少し遅れる(1 刻みの値で 0.01〜7%。O2 がほぼ尽きた所ほど大きい)。
  1 刻みの中で消費の上限と期待値の両方を満たす配り方は一般には無い(残りが 6 未満なら 6 単位の丸め上げは入らない)。残った資源は次の刻みに使われる。
