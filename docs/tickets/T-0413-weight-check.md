## 目的(1〜2 行)
写しの早送り(T-0412)の上で、連鎖(マッチ 1 本の延焼など)や大魔法が予算・演出のスローの長さに収まるかを前もって測る(1 刻みの GPU 時間・
活性のブロック数)。超えたら直すべき不具合として警告する。本物の世界で重さで遅れた刻み(安全網。D-468)も同じ形で警告する。

## 完了条件(チェックできる形で)
- [x] 1 刻みの重さを集める部品(sim::TickCostAccumulator。単位の GPU 時間を刻みごとにまとめ、要約〔活性のブロック数〕と組にする)。写しと本物で同じ部品
- [x] 判定(frame::CheckWeight: 予算・注意の割合・演出のスローの窓 → 超えた刻み・いちばん重い刻み・続けて超えた区間・安全網で捨てる見込み)。CPU の試験 weight_check
- [x] パネル「写しの早送り」に重さの検査(予算・注意・スローの窓・結果・1 刻みの線)。本物の刻みが等速の予算を超えたら 1 秒ごとに警告(ログ + エディタの状態)
- [x] 試験: gpu_world_copy(写しで測っても本物のハッシュ列とブロック数が基準と同じ・刻みがフレームをまたいでも全部の刻みの重さを集める・
      写しのブロック数 = 基準)・window_copy_record/play(`--auto-copy` にブロック数と重さの集め方を足した)・window_weight_warn(重い刻みで警告が出る)
- [x] release のビルドが警告 0・archmap --check・docs/perf.md

## wt3 との分担(WorldCopy の変更)
- **sim::WorldCopy の API は変えない(足すだけ)**。`WorldCopyResult` に欄を 1 つ足す:
  `std::vector<uint64_t> tickGpuTimestampTicks` — `hashes[i]` と同じ並びで、S(hashes[i].tick) を作った刻みの GPU の時間(タイムスタンプの刻み。
  その刻みの単位の和)。活性のブロック数は今まで通り `hashes[i].scheduledBlocks`。今ある欄(gpuTimestampTicks・ticksRun など)はそのまま。
- 単位の時間を刻みにまとめる部品は `sim::TickCostAccumulator`(engine/src/sim/tick_cost.h。新しいファイル)。WorldCopy の中と本物のフレームのループで使う。
- 判定(予算・スロー)は frame/weight_check(新しいファイル)。wt3(T-0432)は使わなくてよい。world_copy_runner・copy_panel は wt2 が触る。
- wt3 が WorldCopy に欄やメソッドを足すのは自由(衝突したら司令塔が両方残す)。

## 判断待ち(仮で進めたもの。ADR-0204「判断待ち」。作り手から見た違い)
- A. 予算の値をどこに書くか: 仮 = エディタの設定(パネルの「1 刻みの予算」。0 = この機械の今の予算)。案 2 = パッケージ(予算がゲームと一緒に配られ、
  T-0432 や CI でも同じ値で検査できるが、数値は機械で変わるので ⑥ の前に書くと書き直しになる)。おすすめ: 今は設定、⑥ の後にパッケージを既定に。
- B. 警告のしきい値: 仮 = 1 刻みでも等速の予算を超えたら警告(注意は 80%)。案 2 = 安全網が刻みを捨てる時だけ(1〜2 刻みの山が見えない)。
  案 3 = 続けて N 刻み超えた時だけ。おすすめ: 仮のまま(見落とさない方へ。うるさければ 3)。

- T-0412 の報告: 写しは VRAM 77 MiB・1 刻み約 2.2 ms(release・64³ の仮の世界で火)。

## メモ(作り手から見て)
- 本物の見張りは、エディタの速さ(2 倍など)では予算を変えない(等速で入るかを見る)。debug + GBV の起動ではほぼ毎秒警告が出る(重いので。ログ 1 行/秒)。
- 写しの 1 刻みの時間は、写しをまとめて回すので本物の刻みと少し違う見込み(同じキュー・同じ処理。差は未確認)。
- 今の窓の確かめ(火を付けたサンプルの世界)の 1 刻みは平均 5.7 ms・最大 8.8 ms で、T-0412 の 2.4 ms より重い(main の変更の分か。未確認)。
