# T-0287 魔法のパッチの続き: 名前の鍵・状態の要約・表を替える刻みを跨ぐ・保存点(T-0024 から分けた)

- Status: 一部完了(2026-10-11。作業役・wt3。残りは「分けたもの」の T-0323〜T-0325)
- 種類: 工学
- PC: 必須
- 設計: docs/design/02-reaction-system.md §5・§5.1 / 06 §3 / ADR-0095 / 決定: D-006・D-428。関係: T-0024・T-0173・T-0288・T-0289

## 目的
T-0024 の魔法のパッチ(範囲と期間で規則 1 つの速さを 2^shift 倍・止める)を、決定性を崩さずに表の差し替え・保存点・記録と再生に載せる。
**値はすべて試験用の仮のもの(D-006)。**

## 完了条件(この段)
- [x] パッチは規則を名前の鍵(RxRule::key)で持つ(T-0024 の作業役が前倒し。表を替えても同じ名前の規則に効く)
- [x] 状態の要約(HashWholeNest)に効いているパッチの語を入れる(T-0024 の作業役が前倒し。列が空なら前と同じ値)
- [x] 表を替える刻みを跨ぐパッチの GPU 試験: gpu_lab_box の RunPatch(swap)。パッチ 2 つの途中(刻み 20)で規則の並びを逆にした表
      (同じ名前・同じ物質・規則の ID が変わる)に替える → 毎刻み GPU と CPU がビット一致・止める / 速めるが同じ名前の規則に効き続ける・元素の数が変わらない
- [x] 保存点: 実験室の保存点(CutLabRecording。パッチの途中・表を替えた後の刻み 30 で切った記録)と記録全体を別の箱で初めから再生 →
      毎刻みビット一致・ハッシュが記録と同じ(パッチは記録のコマンドで、効いている列は状態の要約に入るので、保存点の一致がパッチの列の一致も確かめる)
- [x] 境でつつく段(実験室): T-0024 で済み。T-0173 の大きい箱では範囲が重なる根だけをつつく(T-0024 の載せ直しで合わせた)
- [ ] 世界(多重解像度の世界・仮の世界)のコマンド・境でつつく段・世界の保存点 → T-0323
- [ ] 範囲を細かくする要求 → T-0324(判断待ち Q37)
- [ ] エディタの UI → T-0325

## 作業ログ
- 2026-10-11(作業役・wt3): ブランチ t-0287 を t-0024(main に載せ直した後)から作った。2 時間の約束で、決定性に関わる 3 つ(保存点・境でつつく・表を跨ぐ)のうち
  実験室で確かめられるもの(表を跨ぐ・保存点)を試験にし、世界の段(コマンド・境・保存点)は T-0323 に分けた。
  - 世界でパッチを使う所がまだ無い: 多重解像度の木(GpuMultires)を刻むのは実験室の箱(GpuLabBox)と覗き窓・暗黙の作り直しだけで、
    ゲームの世界(仮の世界 = ProbeSim)は反応の評価にパッチを重ねていない。世界の保存点(ProbeSim の VRAM の写し。T-0143)に含める列はまだ無い。
    よって「世界の保存点に列を含める」は、世界にパッチの列を置く T-0323 で一緒にやる(列は GpuMultires のバッファ 1 本 = 写す物に足すだけ)。
  - 実験室の保存点は記録を切ったもの(初めの箱から決定的に流し直す)なので、パッチのコマンドが記録にあれば列も戻る。試験で確かめた。

## テストの結果
- debug(6 ランナーが同じ GPU を使う中): lab_box・gpu_lab_box(HW。159 秒)・gpu_lab_box_warp は通過。
- 最初は「規則の並びを逆にした表」で ID がずれると考えたが、ベイクは規則を名前の順に並べるので ID は変わらなかった(T-0024 の lab_box_test の
  TestPatchFollowsRuleName も同じ理由で確かめになっていなかった)。名前の順で前の規則(boudouard)を抜いた表に替えて直した。
- release はこのブランチでは回していない(t-0024 で release の 16 本は通過。この段の変更は試験と文書だけ)。

## 引き継ぎメモ
- gpu_lab_box はパッチの場面が 3 つ(根 1 つ・4×1×2 の根・表を跨ぐ + 保存点と記録の再生)。HW の debug で 1 回 2〜3 分。
- 表を替えた刻みに、替えた表に無い名前の規則のパッチは何にも効かないまま期間が終わる(T-0024 の引き継ぎどおり。試験はしていない)。
