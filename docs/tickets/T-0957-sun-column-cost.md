## 目的(1〜2 行)
T-0910 の測りで、0.25 m の光線・斜めの太陽が 2.09〜2.61 ms(RTX 3070 Ti)で仮の線(放射 1 ms/刻み)を超えた。
T-0910 の速くする候補から 2 本まで試して線の内へ入れる。結果は CPU とビット一致のまま(同じ関数 SunWalkRay)。

- [x] 結果は前と同じ語(sun_column の決定的の要約 e57b16543af02f08 が前と同じ)・GPU と CPU がビット一致(15 組。HW・WARP)
- [x] docs/perf.md に前後の値

## 試したもの(1 本目で入った)
1 本目 = T-0910 の候補 (a) の形を変えたもの: **今いるブロックの中は座標から葉を出し、索引を引くのはブロックを出た時だけ**。合わせて (b) の芯。
- `SunBlockView`: 光線が今いるブロック(低い角・大きさ・覆われた八分の一の印)。点がブロックの中で八分の一が覆われていなければ、
  その点を含む最も細かい本物のブロックはこのブロック(細かい本物のブロックは必ず親の children に載る)。→ 前の `SunFindContaining` と同じ葉。
- 一様で 2 つの帯とも吸わないブロック(空気だけ)は丸ごと「素通し」(葉を MR_NO_BLOCK にし、区間を作らない)。吸わないセルは e^−0 = 1 で
  何も足さないので、前と同じ語。セルの吸わない区間も `SunPassSegment` で e^−τ を計算せずに返す。
- 横の 2 軸の位置(`SunCellAcross`)を板ごとの割り算から、繰り上がりの足し算(`SunAcross`)に。同じ番号。
- セルは区間ごとに 1 回だけ読む(前は帯ごとに 2 回)。
- 2 本目(板の順に 2D で進める形・葉の箱の出口まで一気に進む形)は要らなかった。

## 測った値(RTX 3070 Ti・release・2026-10-21・wt6 のランナー。64³ の地形。0 にする段を含む・10 回の平均)
| 向き | 光線の細かさ | 前(T-0910) | 後 |
|---|---|---|---|
| 真上 | 0 / 1 | 0.46 / 0.93 ms | 0.15 / 0.22 ms |
| 斜め 2,−3,0 | 0 / 1 | 0.88 / 2.61 ms | 0.27 / 0.59 ms |
| 3 軸斜め −3,−5,2 | 0 / 1 | 0.79 / 2.09 ms | 0.21 / 0.53 ms |
- CPU(1 スレッド): 真上 105 → 18 ms・498 → 83 ms、3 軸斜め 3,−5,2 で 107 → 23 ms・677 → 119 ms。
- 仮の線(放射 1 ms/刻み)の内。ただし 64³ の場面の値で、世界の大きさに比例して増える(光線の数 × 板の数)。広い世界の線は M-0 の費用の線で見直す。
