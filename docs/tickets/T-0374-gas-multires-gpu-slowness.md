## 目的
T-0358 の計測(負荷あり)で、全部レベル 0 の木の GPU(gpu_gas_tree_test --profile --uniform)が 16³ で 1 刻み 5.9 ms・32³ で約 1350 ms(セル 8 倍で約 230 倍)、
2 レベルの木 16³(7680 セル)が 80 ms(一様な箱 gpu_gas 32³ = 32768 セルは 20 ms)だった。セルの数に対して線形でないので、何かが 1 か所に集まっている。
原因を切り分けて直し、一様な箱と同じ桁(セルあたり)にする。

## 作業ログ
- 2026-10-12: `gpu_gas_tree_test --profile --passes` で最後の 1 刻みの段ごとの時間(GpuGasTree::EnablePassTiming。段の後のバリアの後にタイムスタンプ)と FX_ASSERT の数を出すようにした。
  32³ --uniform で derive(2.7 ms)だけ速く、ほかの 8 段は全部 115〜307 ms。FX_ASSERT は 0 件(release はリングに書かない)。帳簿の原子的な足し算は一様な箱(gpu_gas)も同じ形で 20〜29 ms なので主因ではない。
- 原因: 木の形の 7 本の SRV(t0〜t6。面の一覧 64 B × 面の数・セルの場所・セルの面の並びなど)を**アップロードのヒープ**(CPU のメモリ)に置いたまま読んでいた。
  毎段 PCIe 越しに読み、L2(3070 Ti は 4 MB)に収まる 16³(面の一覧 0.8 MB)は速く、収まらない 32³(6.5 MB)で急に遅くなっていた(超線形に見えた理由)。
- 直し: Create でアップロードのヒープに作った写しの元(m_srvUploads)から、RecordUpload で既定のヒープ(m_srvs)へ CopyResource して NON_PIXEL_SHADER_RESOURCE へ。
  シェーダー・CPU リファレンスは変えていない。32³ --uniform 1306〜1374 ms → 43〜47 ms・2 レベルの木 16³ 80 ms → 11 ms・32³(61440 セル)93〜99 ms(セルに対して線形)。
  一様な箱(同じ時 28〜30 ms)のセルあたり約 1.5〜1.7 倍。値は docs/perf.md(2026-10-12 の T-0374 の行。負荷あり)。release の gpu_gas_tree・gpu_gas_tree_warp が通った(9 場面の毎刻みビット一致)。

## 引き継ぎメモ
- 残りのセルあたり約 1.5〜1.7 倍は、面の形(64 B)を毎段読むこと・セルの面の並び(間接)・端数の 128bit の足し算の分。今は直さない(必要になったら測ってから)。
- 16³ の 5.5 ms は 432 段 × (Dispatch + バリア) の下限(1 段 約 1.3 µs)。小さい木は段の数で決まる。
- 同じ形(大きい SRV をアップロードのヒープから直接読む)がほかにもありうる: gpu_multires.cpp の反応の表(m_tables。CreateFilledUpload のまま結ぶ)。表は小さいので
  影響は未確認 → T-0410 に分けた(測ってから)。
