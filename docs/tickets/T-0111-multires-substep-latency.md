# T-0111 細かいレベルの熱の小刻みの GPU を速くする(小刻み 1 回の遅延を縮める)

- Status: Todo
- 種類: 工学(打ち切り条件つき。下の「打ち切り」)
- PC: 必須
- 見積もり: チャット 1 回分
- マイルストーン: M2 (docs/plan/ROADMAP.md)
- 設計: docs/design/17-multiresolution.md §4・§5「熱の伝導」/ 決定: ADR-0017 追記(T-0108・T-0109)・ADR-0011(予算)・D-302・D-432

## 目的(1〜2 行)
T-0109 の計測で、いちばん細かいレベルが流れる小刻みは 1 回約 0.54 ms(ブロックの数によらない遅延)で、Δkmax 3(64 回)の鎖が 1 刻み 34 ms と
予算(ADR-0011)を大きく超えた。小刻み 1 回の遅延を縮め、Δkmax 3 のまま予算に収める。結果は CPU と毎刻みビット一致のまま。

## 完了条件(チェックできる形で)
- [ ] 鎖(gpu_multires_conduction_test --subcycle の計測)の Δkmax 3 の 1 刻みが 5 ms 以下(小刻み 1 回 約 80 µs 以下)。届かなければ下の「打ち切り」
- [ ] 根 8³ の小刻み 64 回(空の段 63 回)が分けない時の 2 倍以内
- [ ] gpu_multires_conduction(--subcycle を含む)が HW・WARP で毎刻み CPU とビット一致のまま
- [ ] docs/perf.md に前後の値

## メモ・参考
- 遅延の元(推定・未確認。Nsight で確かめる): 1 グループ 64 スレッドで 512 セル(1 スレッド 8 セル)× 面 6 つの MrCellThermal(反応の表から温度を求める)を
  ConductMark と ConductFlows の両方で順に計算している。段は 1 小刻みに Compute 6 つ + 活性なら起こす DispatchGraph 1 回(空でも約 25 µs)。
- 案(安い順に試す): ① 伝導の段を 1 スレッド 1 セル(512 スレッド)に ② 小刻みの初めにセルの熱(MrThermal)を作業場に 1 回だけ書き、印と流れはそれを読む
  (CPU の CellThermals と同じ考え。変えたブロックだけ作り直す)③ 起こすグラフを「変わったブロックがある時だけ」にする(ExecuteIndirect か述語。述語と
  DispatchGraph は組み合わせない約束〔T-0094〕なので、起こす段を Compute にするか数を見て抜ける)④ その小刻みに始まるレベルが無い段を CPU が積まない
  (どのレベルがあるかは前の刻みの読み戻しで分かる。1 刻み遅れても結果は変わらないか確かめる)。
- 空の小刻みの費用(T-0109): 全部 19 µs・活性 Compute 44 µs・活性 Work Graph 91 µs。段は Compute のまま(D-302)。

## 打ち切り
- ①〜④ を試して鎖の Δkmax 3 が 5 ms を超えるなら止める。その時は「Δkmax を下げる(細かい所の熱が本当より遅い)か、世界の速さが落ちるのを許すか」を
  docs/plan/QUESTIONS.md に遊びへの影響の水準で書いてユーザーに聞く(計測: Δkmax 1 = 2.4 ms・2 = 8.6 ms・3 = 34 ms。T-0109)。
