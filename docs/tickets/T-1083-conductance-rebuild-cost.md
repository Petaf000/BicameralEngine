## 目的(1〜2 行)
T-1066 で、セルの伝導率(HcCellConductance。体積の平行の道・気体は ∝ √T)が温度で変わるようになり、仮の世界は「成分が変わった時だけ作り直す」をやめて
本道で毎刻み作り直す形になった。その費用を GPU(RTX 3070 Ti・release)と CPU リファレンスで測り、1 刻みの予算に対して重いかを決める。

## 測り方(捨てる試作。main の共通部分に足さない)
- 式の中身(T-1066 の形を読んだ): HcCellConductance = 成分の回し(体積の和・凝縮相の重み 128bit・気体・場所を取らない物質)+ HcConductanceFromSums
  (整数の平方根 HcGasScaleAt 1 回 + FxDivU128By64 が最大 4 回: 残りの平均・詰め過ぎの判定・÷10^6・÷セルの体積。凝縮相が無いセルは 1 回)。
  チケットの「割り算 1〜2 回/セル」は数え違いで、128bit ÷ 64bit が最大 4 回(各 1 回 = 逆数 + 掛け算 + 直し 2 回。T-0084)。
- 作り直しを「止める」と燃え方(起きるブロックの数)が変わって比べにならないので、逆に **作り直しを 2 回する版**を作って差を見る(結果はビット単位で同じ。
  2 回目の入力に実行時に 0 になる値 z を混ぜ、z で選ぶので、コンパイラは 2 回目を省けない):
  - v1 = HcConductanceFromSums の中身(平方根 + 割り算)を 2 回(z = 気体の物質量 >> 63)
  - v2 = HcCellConductance の全部(成分の回し + 平方根 + 割り算)を 2 回(z = speciesCount >> 31)
  - (v − main)= 作り直し 1 回分の費用。差分の作り方は捨てる(このブランチに入れない。$HOME/wt4-scratch/t1083/variant.py)。
- exe を runner/ab_* に写し、ほかが GPU を使っていない時に main → v1 → v2 → main … の順で交互に流す(揺れを見る。T-1328 の形)。

## 結果(2026-11-12 wt4・release・RTX 3070 Ti・ほかの作業ツリーと並走で揺れる)
**読み違いの直し**: 多重解像度の GPU は HcCellConductance を呼ばない。セルの見立て(cell_view.hlsli の CvCellView)が化学・熱容量・伝導率の和を
1 回の成分の回しで足し、MrThermalFromSums → HcConductanceFromSums(平方根 + 割り算)で作る。だから多重解像度で「作り直し」に当たるのは
v1(FromSums の部分)だけで、和の回しは化学の和と同じ回しに溶けている。v2(HcCellConductance を 2 回)は多重解像度のシェーダーを変えない

## 読み(結論)
- **毎刻み作り直しは重くない**。GPU では 1 セル数十命令の整数の計算(平方根 1 回 + 128bit ÷ 64bit 最大 4 回)が読み書きの待ちに隠れ、
  仮の世界では測れる差が出ず、多重解像度でも空気の伝導の段(約 5 ns/セル)の 1〜2 割・成分の多いセル(145〜390 ns/セル)では 1 % 未満。
  予算の目安(D-209: フレーム 33 ms のうちシミュ約 21 ms)に対して、活性のセル 100 万で 0.5〜0.9 ms/刻み(上限の見積もり。空気の場面の差から)。
- 「変わったセルだけ作り直す」案(結果を変えない形)と見込み: 伝導率は温度で変わる(√T)ので、温度が変わったセルは作り直しが要る。
  仮の世界は熱の出入りも反応も無いセルを既に近道で飛ばしている(= 変わらないセル)。残る削りは「成分の和をキャッシュして平方根と割り算だけやり直す」だが、
  多重解像度では和は化学・熱容量の和と同じ 1 回の回しに溶けている(cell_view.hlsli)ので削れるのは 0 に近く、キャッシュの欄(和の HcConductivitySums は 1 セル 72 B)の読み書きの方が高い見込み。
  → **入れない(仮)**。要るのは活性のセルが 100 万を大きく超えて伝導の段が予算を押した時で、その時は T-1320 の段 1 と同じ形(結果を変えない削り)で測ってから。
- T-1066 の「gpu_probe_gas が 180 → 310 s に延びた」の理由は作り直しではない(CPU リファレンスでも差は揺れの内)。燃えたセルが熱いまま気体の段が強く動く方の見込み(未確認・T-1066 の見立てのもう一方)。
- チケットの「割り算 1〜2 回/セル」は「128bit ÷ 64bit が最大 4 回 + 整数の平方根 1 回」に読み替える(ADR-0454 の 4 の「割り算は 1 セル 1〜2 回」も同じ数え違い。ADR は本体の文書なので、司令塔がマージ後に 1 行直す)。
