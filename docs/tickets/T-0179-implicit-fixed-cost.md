# T-0179 伝導の段から呼んだ時の陰解法の固定費を減らす(多重格子の段の回・V サイクルの回を前の刻みから選ぶ)

- Status: Done
- 種類: 工学
- PC: 必須
- 見積もり: 作業役 2 時間以内(始める前の見積もり: 多重格子の段を作る回を前の刻みの段の数から選ぶ〔LvTail に残りを任せる〕と試験・計測で 1 時間。
  余れば V サイクルの止めた後の回〔T-0154 の続き〕も。T-0137〔形が変わらない刻みは作り直さない〕は効く場面を測ってからなので入れない)
- マイルストーン: M2 の並走(D-432)
- 設計: docs/design/17-multiresolution.md §6 / 決定: D-428・D-432・D-434(案 a)・D-436 / ADR-0019(T-0179 の追記)

## 目的(1〜2 行)
T-0132 の計測で、伝導の段から陰解法を呼ぶと多重格子の段の空の回(上限 64 段まで回を積み、要らない回は述語で飛ばすがバリアが残る)と
V サイクルの止めた後の回(上限 64 回)が固定費になっていた。解いた値を変えずに(CPU と HW・WARP が毎刻みビット一致のまま)これを減らす。

## 完了条件(チェックできる形で)
- [x] 多重格子の段を Dispatch で積む回の数を前の刻みの段の数から選ぶ(GpuImplicitLevels::RoundsFrom。残りの回と小さい段の回は LvTail)
- [x] V サイクルを段ごとの Dispatch で積む回の数を前の刻みの回数から選ぶ(GpuImplicitRecordShape::dispatchCycles。後の回は ImTail が段 0 から)
- [x] 一番安い積み方(前の刻みより深い・回が多い刻みの道)も含めて、熱い点・鎖・たくさんの要求の全部・活性の刻みが CPU と毎刻みビット一致(HW・WARP)
- [x] 前後の ms/刻み(鎖・熱い点・たくさんの要求)を測る(下の「結果」)
- [ ] debug(HW・WARP)と tidy は時間の約束で流していない

## 何をしたか(形。決めたのは Claude〔実装の細部〕。ADR-0019 の T-0179 の追記)
- **多重格子の段を作る回**(gpu_implicit_levels.*): RecordBuild に dispatchRounds(Dispatch で積む回の数)を渡せる。GpuImplicitLevels::RoundsFrom(前の刻みの
  GpuImplicitCost)= 前の刻みの回 + 2。積んだ回より深い系は LvTail が残りを回す(最後に積んだ回の RoundEnd が LvTail の始める回を書くので、作る段は番号まで同じ)。
  LvTail を積まない作り方(既定)では指定を無視する。GpuMultiresImplicit はハードウェアでは小さい段の回(節 ≤ 256)も LvTail にする(T-0135 のおすすめ)。
- **WARP**: LvTail は release の WARP でデバイスが失われる(T-0147)ので、gpu::IsSoftwareDevice(新。device のアダプタの LUID から DXGI の SOFTWARE の印を見る)
  が真なら今まで通り上限まで Dispatch で積む。
- **V サイクル**(gpu_implicit.*・implicit_conduct.hlsl): GpuImplicitRecordShape::dispatchCycles(段ごとの Dispatch で積む回の数)。ShapeFrom が前の刻みの回数 +
  max(回数 / 2, 2) を選ぶ。その後の回は ImTail が段 0 から V サイクル全体を回す安い回(定数の空き語 unused1 → g_wholeTail。ImTail・判定・回の終わりの 3 Dispatch)。
  ImTail は系が空なら何もしない(間接の引数を通らずに 1 グループで呼ぶため)。
- **試験**(gpu_multires_implicit_conduction_test): 上限の形に「一番安い積み方」(GpuMultires::ForceImplicitCheapest: 多重格子の段の回は全部 LvTail〔WARP では
  上限まで Dispatch〕・V は 1 回目の後を全部安い回)を足し、熱い点・鎖・たくさんの要求の全部・活性で CPU と毎刻み比べる(前の刻みより深い・回が多い刻みの道)。
  ふつうの形は前の刻みから選ぶ道(初めの刻みは上限まで)。tree・build の試験の「前の刻みから」の形も新しい ShapeFrom(dispatchCycles つき)で通る。

## 結果(2026-10-09、release、RTX 3070 Ti)
- `-Filter "^gpu_multires_implicit(_conduction|_tree|_build)?(_warp)?$"` の 8 本が最初のビルドで通過(HW: tree 616 s・build 267 s・conduction 759 s /
  WARP: tree 197 s・build 40 s・conduction 861 s。前半は本体のランナーが試験中の負荷あり)。
- 計測(**本体・wt3・wt4 のランナーが idle の時**。ビルド後の 1 回目は捨てた。docs/perf.md)。
  `job.py run -Preset release -Exe gpu_multires_implicit_conduction_test -- --queue compute --measure-only`。前 = T-0132 の idle の値、ms/刻み。
  | 場面 | 刻み方 | 前(初め / 後) | 後(初め / 後) | 内訳(後): 多重格子の段 前 → 後・写して解く 前 → 後 |
  |---|---|---|---|---|
  | 熱い点(512 セル・V 2) | 全部 / 活性 | 1.50 / 1.52 | **0.75 / 0.77** | 0.89〜0.94 → 0.16・0.43〜0.46 → 0.43〜0.46 |
  | 鎖(1907 セル・V 4) | 全部 | 5.16 / 4.31 | 2.98 / **2.40** | 1.11 → 0.50・3.01 → 1.70 |
  | 鎖 | 活性 | 4.57 / 4.22 | 2.86 / **2.31** | 1.06 → 0.47・2.90 → 1.59 |
  | たくさんの要求(2 万セル・V 15) | 全部 / 活性 | 23.5 / 23.9 | **21.1 / 21.3** | 3.0 → 2.7・10.9〜11.0 → 8.8〜9.0 |
  - 同じ版の前(このチケットの前のビルド・本体が試験中の負荷あり)でも 熱い点〔最初の場面は暖機でぶれる〕・鎖の後 4.41 / 4.24・たくさんの要求 23.7 / 23.8 ms で、T-0132 の idle の値と同じ向き。
  - たくさんの要求は 21 ms で予算(シミュに約 12 ms)を超えたまま。残りは陽解法の部分(陰解法なしで 8.2〜8.5 ms)・解く本体(大きい段の掃き出し 8.8 ms)・
    段を作る大きい回(2.7 ms)で、固定費ではなく仕事そのもの。D-434 の「重い場面が頻発するなら分ける段を減らす」の材料は変わらない。
