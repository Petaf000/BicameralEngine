# ADR-0335 当てる段の包み(分数の倍率・TxPacket)と液体の帳簿の列

- Status: Proposed(2026-10-17。T-0770・T-0769。細部は仮〔ユーザー未確認〕で進めた)
- 日付: 2026-10-17
- 決めた人: Claude(wt6 の作業役)
- 関係: ADR-0334(当てる段)・ADR-0331(世界の帳簿の 1 型)・T-0762(帳簿の書き方の約束)・D-487 ③・D-513

## 背景
- 当てる段(T-0714)の包みは熱だけ(MrEnergyDelta)で、上限の倍率は Q32。物質を運ぶ種類(液体・気体)は成分ごとの量・エネルギー・運ぶ欄を運び、
  仮の世界の上限は「流れ × 中身 ÷ 出る合計」(切り捨て 1 回)。Q32 の倍率に丸めてから掛けると 2 回切り捨てて値が変わる。
- 液体の帳簿は世界の欄(liquid.ledger_*)に仮置きで、ComputeConservedTotals は液体の欄の列で釣り合わなかった。

## 決定(仮)
1. **倍率は分数** `TxScale {numerator, denominator}`。比べるのは 128bit の掛け算。縮めるのは「量 × 分子 ÷ 分母」の切り捨て 1 回(TxScaleAmount・TxScaleFlow)。
   仮の世界の液体・気体の上限と同じ式なので、載せ替えても値が変わらない。
2. **包み** `TxPacket`(物質 ID と量 × インラインの成分の数・エネルギー・運ぶ欄 4)。物質を運ぶ種類は「主の量」を面ごとに流して上限を掛け、
   上限の後の主の量から上流のセルの比で包みを作る(Pack)。当てるのは TxApplyPacket → 世界の AddPacket(上流は引く・下流は足す)。
   CPU のセルへの当て方は sim/transport_packet(TxCellChange・ApplyCellChange)。
3. **液体の入る側は器で切らない**(room = TX_ROOM_UNLIMITED)。入る側の安定は液体の模型の溢れの圧力が持つ。器で切る案は T-0770 の判断待ち。
4. **液体の帳簿の列**: 面の運動量の列 ×3 に外から入った運動量を理由ごとに(壁の力積・重さの仕事・摩擦・行き場なし・速さの上限・段の外の質量の変化。正 → 入)。
   位置・運動のエネルギーの欄の列は「熱になった分」を出(位置 = 重さの仕事・運動 = 物理の熱)、同じ量をエネルギーの列(0)の入。
   段の外で液体が現れた・消えた分の位置のエネルギーは「段の外の質量の変化」の入。これで ComputeConservedTotals が液体の刻みで列ごとに変わらない。
5. **理由を 3 つ足す**: WL_REASON_FRICTION(8)・WL_REASON_NO_OUTLET(9)・WL_REASON_FOLLOW_MASS(10)。WL_REASON_COUNT = 11(ADR-0331 4 の「欄はいつも 16 本」は 22 本に)。
   帳簿の語の数は 1.375 倍(GPU の帳簿のバッファも同じ関数で大きさが決まる)。

## 代案
- Q32 の倍率のまま: 仮の世界と値が変わり、基準を取り直す要がある(D-487 ③)。精度も分数より悪い。
- 列ごとに包みの各列を縮める(TxScalePacket だけ): 液体は成分の比を上限の後の質量から取るので、先に縮めると切り捨ての位置が変わる(気体の成分ごとの上限はこちらを使える)。
- 理由を足さず、摩擦・行き場なしを既存の理由に入れる: 帳簿の見出しが嘘になる(壁の力積に摩擦が混ざる)。

## 結果
- multires_liquid_test が仮の世界と毎刻みビット一致のまま、毎刻み ComputeConservedTotals が一定。
- 気体(wt4 T-0720)は同じ包みの型を使う(T-0770 のチケットの先頭)。

- **2026-10-26 本体の棚卸し(QUESTIONS Q122)**: 液体を当てる段に載せた時の仮 2 つ → ① もう要らない(案 B。D-550)・② 閉じた(欄の列ごとに帳簿へ。D-539)。
