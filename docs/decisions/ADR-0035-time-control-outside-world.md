# ADR-0035 エディタの時間の操作(止める・1 刻み・速さ)は世界のコマンドに入れない

- Status: Accepted(実装の細部。ユーザー未確認の点はチケット T-0023 の「判断待ち」)
- 日付: 2026-10-09
- 決めた人: Claude(CLAUDE.md §5。T-0023)

## 背景
- 14 §2 の「時間の操作」(止める・1 刻み進める・速くする)を、決定性(ADR-0008)と再生ファイル(T-0086・15 §2)を壊さずに入れたい。
- 世界の結果は「初期状態 + 刻みの番号の付いたコマンドの列」だけで決まる(06 §1・§3)。1 フレームにいくつ刻みを投げるかは
  SimScheduler(ADR-0011)が現実の時間から決めており、すでに世界の結果に入らない(重いと遅くなる。D-202・D-409)。

## 決定
- 時間の操作は **SimScheduler に「始めてよい刻みの数」を足し引きするだけ**にする(editor/time_control)。
  - 止める = 溜まっている刻みを捨て、現実の時間を足さない。始めた刻みは最後の単位まで進めて、刻みの境界で止まる。
  - 1 刻み = 止めている間に「始めてよい刻み」を 1 足す。
  - 速さ = 現実の時間に掛ける倍率(1/8〜8 の 7 段)。D-409 のゲーム側の速さとも掛け合わせる。
- 時間の操作は**世界のコマンド(sim/command.h)にも再生ファイルにも入れない**。カメラと同じ View / Controller の状態(D-107)。
  止めている間のつつきは CPU で待ち、次に投げる単位の刻みが付く(今までと同じ道)。
- 確かめ方: 再生ファイルを、止める・1 刻みずつ・速さを変えながら再生しても刻みごとのハッシュが全部一致する(ctest window_replay_editor)。

## 検討した代案と、採らなかった理由
- **時間の操作を世界のコマンドにする**: GPU は現実の時間を知らないので、コマンドにしても世界の中でやることが無い(GPU のキューを通る意味が無い)。
  コマンドの列に世界と関係の無いものが混ざり、再生の突き合わせが「操作の時刻」に依存するように見えてしまう。
- **再生ファイルに「見る側の操作の列」(止めた・速さ)を別に記録する**: 不具合の再現の動画を同じ歩調で撮りたい時に役立つが、今は要らない。
  要るようになったら、再生ファイルの別の欄(世界の列とは別)として足す(後から足せる。チケット T-0023 の判断待ち)。

## 影響(何がしやすく/しにくくなるか)
- しやすい: 止めても速くしても、記録・再生・ハッシュの突き合わせはそのまま使える。巻き戻し(保存点 + 再生。14 §2)も同じ考えで足せる。
- しにくい: 再生ファイルだけでは「どこで止めて見ていたか」は再現できない(上の代案で後から足す)。
