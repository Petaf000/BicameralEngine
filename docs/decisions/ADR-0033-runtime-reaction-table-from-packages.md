# ADR-0033 ランタイムは起動時に data/packages のパッケージから反応表をベイクし、読めなければ窓を開く前に止まる

- Status: Accepted(実装の細部。CLAUDE.md §5)
- 日付: 2026-10-09
- 決めた人: Claude。T-0157

## 背景
- T-0021 で Luau のパッケージの反応表をベイクできるようになったが、ランタイム(frame_loop)は C++ に書いた試験の表(MakeCombustionTestTable)を使っていた。
- ゲームの中身(反応表)は Luau で書く(D-318)。Mod もパッケージ(D-320・ADR-0031)なので、Mod の組はプレイヤーの PC で決まり、
  合わせた表はその PC でベイクするしかない。
- 原則 3: 半端な表(検査で落ちた表・一部だけ読めた本体)で世界を動かすと、「実験した通りに世界が反応する」前提(D-428)が崩れる。

## 決定
1. **置き場所と配り方**: ゲームのデータはリポジトリの `data/`(反応表のパッケージは `data/packages/<パッケージ>/`)。
   ビルドが exe の横の `bin/data/` に写す(`bicameral_data`。写す前に消すので、消したファイルは残らない)。
   ランタイムの既定は `<exe のフォルダ>/data/packages`、`--packages <dir>` で変えられる。PC 固有のパスは埋め込まない(ADR-0006 と同じ考え)。
   今のゲーム本体のパッケージは公開用の試験の表 `combustion_test`(T-0021 で tests/packages にあったものを移した)。ゲームの中身の表は T-0002。
2. **起動時にベイクする**: `script::LoadReactionTable`(ReadPackageRoot → LoadPackages → ReadReactionTableDefinition → BakeReactionTable)。
   CPU で 1 回だけ。ベイクしたバイナリのファイル(キャッシュ)は作らない(Mod の組で表が変わるので、どのみち起動時にベイクする道が要る。
   起動時間が問題になったら、表の版をキーにしたキャッシュを足す)。
3. **失敗の扱い**: フォルダが無い・ゲーム本体のパッケージが無いか読めない・形の誤り・ベイクの検査で落ちる → 窓とデバイスを作る前に起動を止め、
   「反応表のパッケージ(フォルダ): どの段の・どのパッケージの・どの欄の誤りか」を 1 行でログに出して終了コード 1。
   Luau として読めない・依存が無い Mod は除いて続け(ADR-0031 の 3)、ログに警告を出す。文献の反応熱の食い違い(02 §2 の 2)も警告で続ける。
   読んだパッケージ・物質と規則の数・表の版・「改造された世界」の印・かかった時間をログに出す。
4. **C++ の試験の表は残す**(テストの比較用)。テストのうち CPU リファレンスと GPU を比べるもの(gpu_*・multires_* など)は今まで通り C++ の表を使う
   (中身はビットで同じ。並走の作業ツリーと衝突しないように、移すのは別にする)。
   パッケージの表で今の場面が前と同じかは `reaction_package_scene`(CPU リファレンスで両方を 60 刻み進め、毎刻みのハッシュと最後のバイトを比べる)で見る。

## 検討した代案と、採らなかった理由
- エディタ・ツールがベイクしたバイナリだけをランタイムが読む(ランタイムに Luau を入れない): Mod の組ごとにプレイヤーがベイクの道具を走らせる手間が増え、
  道具とランタイムの版のずれも起きる。Luau の殻は CPU だけで、起動時に 1 回走るだけ(D-107 の「CPU は世界の状態を書き換えない」には触れない)。
- 読めない Mod があったら起動を止める: 1 つの壊れた Mod でゲームが起動しなくなる。ADR-0031 で「ほかは読む」と決めてあり、理由はログに残る。
  ただし Luau としては読めて表を壊す Mod(釣り合わない反応など)は、合わせた表の検査で落ちるので起動が止まる(どの Mod か、どの規則かが出る)。
- 試験の表を tests/ に置いたままランタイムから読む: 配る物にテストのフォルダが混ざる。

## 影響
- しやすい: 反応表を Luau で書き換えれば、ビルドし直さずに(ビルドの写しを直せば)ゲームとエディタの世界が変わる。壊れた表は起動時に場所つきで分かる。
- しにくい: ゲームの exe が Luau を含む(サイズが少し増える)。起動時間にベイクの分が乗る(今の表で release 約 13 ms。並走の負荷ありの目安で正式な計測ではない。ログに出る)。
- 残り: 再生ファイルに表の版と読んだパッケージを残す(15 §4)・ホットリロード(T-0139)・テストの表もパッケージへ寄せて C++ の表を消す。
