# ADR-0411 釣り合う家族の部品の GPU 版と気体の箱の VRAM を詰める(上限は構造から・解くだけの形・面の件は本当にある面だけ)

- Status: Accepted(値を変えない作りの詰め。ビット一致で確かめた)
- 日付: 2026-10-21
- 決めた人: Claude(wt2 の作業役。T-0918)。根拠の測り: T-0900 M-1(1.78 KB/セル)・T-0915(2.28〜2.34 KB/セル)
- 関係: ADR-0406(部品の GPU 版)・ADR-0397(部品の口)・T-0845(陰の圧力の GPU)・T-0185(気体の箱の GPU)
- 設計書: docs/design/20-transport-substrate.md §9・§13.1

## 決定
1. **部品の上限は「最初の形 × 2 + 64」ではなく、段の形の構造の上限にする**(`GpuEquilibrium::ShapeLimits`): 節がどれも同じレベルの系では、
   段 k の節は「段 0 の座標を k 回 >> 1 した異なるものの数」で、刻みで変わるのは止まる段だけ。節の上限 = この鎖の全部の和(立方体の箱で 1.143 × セル)、
   隣の上限 = 節 × 6(段 0 は面の数 EQ_GPU_FACES_MAX、粗い段は行の上限 ROW_MAX。Supports が確かめる)。どの刻みの形もこれに収まるので、上限を超えて記録できない刻みは起きない。
2. **部品の GpuImplicit は「解くだけ」の形(`GpuImplicitLimits::solveOnly`)**: 熱の陰解法の刻み(RecordStep)が使うセル(ImGpuCell)・面・セルの面の一覧・
   刻みの初めの温度(閾値)の欄・面の流れの欄・安全網の印・解きの写しと読み戻しを持たない。回数を固定した RecordSolve だけ(fixedCycles でない解きは断る)。
   前の答えを 0 にするのは小さい 0 の写しの元を繰り返す `RecordZeroValues`。残差の計器の節ごとの語は meterResiduals の時だけ持つ。
3. **段の形の写しの元(アップロードのヒープ)はバッファごとに持たない**: 全部の像を 1 本の写しの元に詰め、写したリストが終わったら `ReleaseStaging` で捨てられる
   (次に形を写す時に作り直す)。熱の陰解法(GpuMultiresImplicit など)の写しも同じ 1 本の形(写す中身と順は前と同じ)。
4. **気体の箱の面の件は本当にある面だけ置く**(`GasGpuFaceSlot`): 面の番号(セル × 6 + 軸 × 2 + 端の境界の面)は乱数の丸めの鍵と両側の決め方にそのまま使い、
   件の置き場だけを「マイナス側の面 × 3 × セル + 箱の 3 つの端の面」に詰める(前は番号の数だけ取り、半分が空いていた)。面の読み戻し(調べる用)は初めて調べる時に作る。

## 理由
- M-1 の結論(起きた所の上限は約 50 万セル)の大半は、使わない置き場(上限 2 倍・熱の陰解法の欄・空の面の件・写しの元)だった。値の作りは変えずに置き場だけを詰められる。
- 上限を「最初の形の倍」で取ると、形が深くなる場面で足りなくなる危険と、浅い場面での無駄が両方ある。構造から決まる上限は両方を消す。

## 影響
- 値は変わらない: gpu_gas(12 本の組)・gpu_gas_projection・gpu_gas_projection_t0915(32³ × 5 場面 × 300 刻み毎刻み CPU の部品とビット一致・前の GPU の道のハッシュ一致・保存・決定性)が通る。
- GpuEquilibriumOptions の headroomPercent は消した。GpuGas::RecordDebugReadback は const でなくなった(読み戻しを初めに作る)。
- 1 セルの VRAM と起きた所の上限は docs/perf.md(T-0918)。
