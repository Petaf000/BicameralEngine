# ADR-0532 GPU の欄の頁の置き場と、頁の番号を CPU と同じにする取り方(T-1252 段 2。ADR-0500 の 3 (a) の GPU の形)

- 日付: 2026-11-12
- 決めた人: Claude(wt6 の作業役)
- 親: ADR-0500(欄の書き手と寿命)・ADR-0403(疎な頁)・ADR-0329(登録)・T-0930(GPU の疎な欄の頁)
- 実装: shaders/common/multires_field_pages.hlsli・shaders/sim/multires_field_gather.hlsl・engine/src/sim/gpu_multires_fields.{h,cpp}・tests/gpu_field_gather_test.cpp

## 背景
ADR-0500 は「集めて書く段は枠の順のプレフィックス和で頁を取る・CPU と GPU で頁の番号まで同じ」と決めたが、GPU に登録の欄の置き場が無かった。
CPU の疎な頁(MultiresFieldStore)は pageOf・空きのスタック(返した頁を後ろから使う)・頁の並び(足りなければ後ろに足す)で、頁の番号は呼んだ順で決まる。
GPU の段は並べて走るので、同じ番号にするには「1 つの段の中で頁の要る所を決まった順に並べた時の k 番目」が CPU の EnsurePage を同じ順に呼んだのと同じ番号になる形が要る。

## 決定
1. **置き場の並び**(欄 1 つ = uint32 の並び 1 つ): [頭 12 語(セルの頁の数・容量・値の数・予算・空きの数・使った高さ・段の報告 4 語)][pageOf × セルの頁][空きのスタック × 容量][頁 × 512 × 値の数 × 2 語]。
   CPU の置き場をそのまま写す(空きのスタックの並び・使った高さ・空きの頁の古い値まで)。int64 は下位・上位の 2 語(木の段の u4 の置き場と同じ uint32 の並びに載せられる)。
2. **頁の番号の取り方**: 1 つの段の中で頁の要る所を決まった順に並べ、k 番目は空きのスタックの上から k 番目(k < 空きの数)、その後は高さ + (k − 空きの数)。
   取れる数 = min(容量, 予算〔0 = 決めない〕)− 使っている数。超えた所は断る(集めて書く段は書かずに作業に残す = CPU と同じ)。
   CPU の EnsurePage を同じ順に呼んだのと同じ番号になる(EnsurePage は変えない)。容量が尽きるのは GPU だけ(CPU は上限が無い。予算で同じ数に揃えて比べる)。
3. **木の段(細かく・粗く・広げる・畳む・返す)への載せ方(印・まだ作っていない)**: CPU は要求ごとに取る・返すが交互に起きる(粗くする: 親の頁を取る → 子の頁を返す。
   次の要求が返した頁を使う)。GPU の木の段は段ごとに全部の要求を並べて走るので、CPU の順のままでは番号が揃わない。一旦の形:
   - CPU の nest_fields も木の 1 回の処理の中で「取る」を段の順(GPU の段と同じ: 細かくする鎖・粗くする・広げる)に要求の順で・「返す」を処理の終わりに枠の順で行う
     (返すのを遅らせるだけ。値・状態の要約は変わらない = ハッシュは今のまま。頁の番号と空きの並びだけが変わる)。
   - 頁が要るかは値を作る前に決まる形にする(細かくする子は「親の八分の一に 0 でない値がある」で頁を取る。全部 0 の頁は眠る判定で返す = 今の ReleaseZeroPages)。
     CPU の StorePage は「0 でない値を書く時に作る」なので、配り手の欄だけ CPU も同じ規則に揃える。
   これは土台の共通部分(nest_fields)の頁の取り方の変更なので、司令塔へ回す(T-1252 の「段 2 の残り」)。
   - **司令塔の受け取り(2026-11-12 15:10)**: ADR-0500 の集めて書く段の形に CPU を揃えるだけで新しい口を足さない・値とハッシュは変わらず変わるのは頁の番号と空きの並びだけ(作り手から見た違いなし)として受け取った。
     条件: 頁の番号を記録した試験・セーブの写しがあれば取り直しをチケットに書く・欄の無い世界は全部ビット一致。
   - **入った形(CPU。t-1252-tree-gpu)**: multires_tree.cpp の AllocateOwnerPages(Allocate の後。許可した要求の順に: 細かくする = 頁を持つ親が欄の頁を持てば鎖の段の数だけ・
     粗くする = 親が頁を持つ枠になり〔広げる親を含む〕まだ欄の頁が無く、子が欄の頁か 0 でない一様の値を持つか広げる親の一様の値が 0 でない)・
     ReleaseAll が返すセルの頁ごとに ReleaseOwnerPages(要求の順)。RefineOwners・ExpandPage は配り手の欄の頁を返さない(StartPage しない)・Coarsen は配り手の欄の頁を返さない。
     配り手の欄だけ(一般の疎な欄は今のまま「0 でない値を書く時に作る」)。相の層の配り(セルを読む)が「頁の無い所に 0 でない値を作る」時は今の EnsurePage のまま作る(GPU と番号がずれうる = T-1231 の GPU で確かめる)。
4. **集めて書く段の GPU**: 印(作業が 0 でない枠: 頁を持つ = TOUCHED・一様 = WANTED)→ 頁を取る(1 グループ・枠の順の塊ごとのプレフィックス和)→ 書く(1 グループ = 枠 1 つ)。
   一様な枠は木の段(TreeExpand)が広げてから印の段からもう一度(CPU の ExpandGatheredBlocks と同じ枠)。書いた枠をつつく(PokeBlock)のは木の段に載せる時。

## 確かめ
- gpu_field_gather(HW・WARP): 空きのスタックのある置き場に頁を持つ枠・持たない枠へ足す / 予算で尽きる / 根 700 個に乱数(プレフィックス和が塊をまたぐ)/ 一様な枠の印。
  pageOf・空きのスタック・使った高さ・頁の値・作業の残り・報告の数が CPU の GatherNestField とビット一致。
- 新しい形の欄が無い世界: GPU の世界(sim/gpu_multires)の段は何も変えていない(この ADR の段はまだ GpuMultires から呼ばない)。

## 要る現象の一覧(docs/design/21 §3)との照らし
- 今のまま(全部): この ADR は ADR-0500 の 3 の置き場の GPU の形だけで、現象を足しも減らしもしない。使い手(Ec = T-1230・放射の持ち越し = T-1227・源の項 = T-1228)が載った時に ADR-0500 の照らしのとおりに起きる。

## 作り手から見た違い
- 無い(エンジンの中の置き場。頁の予算を超えた時の計器の誤りは ADR-0500 のまま)。

## 退けた案
- GPU は頁の番号を自分で決め、CPU とは密の並びの要約で比べる(T-0930 の初めの形): ADR-0500 の「頁の像で比べる」より弱く、保存点の頁の像が機種で変わる。
- 段の終わりに頁を番号の順に詰め直す(取り方を気にしない): 毎回頁を写す費用が頁の数に比例し、木の段のたびに起きる。
