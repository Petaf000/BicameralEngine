# ADR-0194 環境の値のホットリロード(表の差し替えの刻みで物理の重力・気体の設定を差し替える)

- Status: Proposed(下の 1 を仮で実装。ユーザー未確認。T-0444)
- 日付: 2026-10-13
- 決めた人: ユーザー(Claude が提案した場合も、決めるのはユーザー)

## 背景
- 分類 environment(重力・音速の基準・基準の大気)は反応表と同じ読み込み・同じ表の版に入る(T-0398 の共有の決め事・ADR-0176・ADR-0182)。
  反応表のホットリロード(ADR-0047)と環境ミキサー(ADR-0183)は表を刻みの境界で差し替えるが、物理の重力と気体の設定は
  世界を作った時の値のままで、表を差し替えても世界を作り直すまで変わらなかった。
- エンジンの約束「法則は状態だけで決まる・何でも再生できる」(D-465)から、差し替えた表の法則は差し替えの刻みから全部に効くのが筋。

## 決定
1. **状態はそのまま、法則だけ替える(仮)**: 差し替えの刻みの境目から、物理は新しい重力で、気体は新しい重力・音速の基準・層の基準
   (新しい重力と基準の大気で作り直した静水圧の層)で刻む。物・セルの状態(位置・速度・物質量・エネルギー・運動量)には触れない
   (保存量を変えないので帳簿に何も載らない)。新しい重力と釣り合っていない大気は、次の刻みから法則どおりに流れて落ち着く。
   - 案 B(採らない・未確認): 差し替えの時に大気を新しい重力の釣り合いに並べ直す。保存量を書き換えるので改造による出入りとして帳簿に載せることになり、
     作り手から見ると「重力を変えた瞬間に空気が瞬間移動する」。並べ直したい時は世界を作り直す(T-0453)方が意味がはっきりしている。
2. **同じ刻みの境目・同じ道**: 物理は `ProbeSim` の表の差し替え(`ProbeTableSwap`。記録には表の版の印 `MakeTableCommand`)の中で
   `ApplyEnvironment` が `GpuPhysics::SetGravity` を呼ぶ。重力はルート定数で渡すので、記録した刻みの順に替わる(前に記録した刻みは前の重力のまま)。
   再生は印の版の表を同じ道で当てるので同じになる。CPU リファレンスは `PhysicsWorld::SetGravity` を同じ刻みの `Step` の前に呼ぶ
   (窓の `--check-physics` も)。巻き戻しの保存点は物理の重力を `GpuPhysicsCursor` に持つ(表を差し替えると保存点は全部捨てられるが、念のため自己完結にする)。
3. **変わった値だけ当てる**: 新しい表の環境の重力が今の表と同じなら物理に触れない(作った時の `physicsParameters` のまま)。
4. **気体**: 世界にはまだ載っていない(T-0210)ので、部品だけ作る。`CheckGasEnvironment`(違ってよいのは重力・音速の基準だけ。音速の基準 0・
   安定の上限の外・重力の上限の外は理由を返す)・`SetGasEnvironment`(係数・層の基準・導く値・開いた境界の外・α・頭打ちの温度を作り直し、
   状態は保つ)・`GpuGas::RecordEnvironment`(t0〜t2 を作り直して写す。前のものは呼ぶ側がリストの終わりまで持つ)。気体を世界に載せる時は
   `ProbeSim::ApplyEnvironment` から同じ刻みで呼ぶ。
5. **器が受けられない値は当てない**: `script::CheckHotReloadCompatible` が `sim::CheckWorldPhysics`(重力の上限・既定の小刻みの音速の上限。
   読み込みの範囲の検査と同じ決まり)を通し、外なら理由を返して古い表のまま(コードで作った表やミキサーの組み合わせも同じ検査を通る)。

## 影響(作り手から見た違い)
- パッケージの `gravity_um_per_s2` を書き換えて保存すると、飛んでいる物はその刻みから新しい重力で落ちる(世界を作り直さなくてよい)。
- 気体を世界に載せた後は、音速の基準・基準の大気の書き換えも同じように効く(空気は並べ直さず、新しい法則で落ち着く)。
- 範囲の外の値を書くと、反応表の書き間違いと同じく「古い表のまま + 理由」がエディタに出る。

## 試験
- `gpu_physics_pile_gravity_change`(GpuPhysics と PhysicsWorld が重力を 3 回替えてもビット一致)・`gpu_probe_physics_gravity_swap`
  (表の差し替えの道で重力が替わり、CPU とビット一致・2 回の実行で一致)・`gpu_gas` / `gpu_gas_flow` の `closed_environment_change`・
  `open_environment_change`(GPU と CPU が毎刻みビット一致・保存則)・`gas_reference`(同じ値の当て直しは結果を変えない・検査)・
  `environment_package`(ホットリロードの検査)。
