# ADR-0005 GitHub で公開し、CI と「コードとずれない」アーキテクチャ図を持つ

- Status: Accepted
- 日付: 2026-09-29
- 決めた人: ユーザー(T-0006 で Claude が案を出し、ユーザーが選んだ)

## 背景
他人に見せる・ポートフォリオにする前提で、読みやすさ・自動検証・全体像の見えやすさを整えたい(T-0006)。
ユーザーの要望: システムの流れをグラフで詳細まで見せ、グラフの機能をクリックするとそのコードへ飛べること。

## 決定
1. **GitHub の公開リポジトリ** `Petaf000/BicameralEngine`(ブランチ `main`)。
   - Claude が push してよい(通常の push だけ。force・削除・履歴の書き換えは git ジョブが拒否し、ユーザーが行う)。
   - **ライセンスは付けない**(閲覧は自由、流用は不可 = All rights reserved)。後から付けられる。
   - 公開前に個人的な背景を `CLAUDE.local.md`(git 管理外)へ移し、作者メールを GitHub の noreply にして、
     未 push だった 3 コミットを作り直した。
2. **CI は GitHub Actions**(`.github/workflows/ci.yml`)。
   - Windows(windows-2025)で debug / release をビルドし、ctest を走らせる。vcpkg は `builtin-baseline` の版を使う。
   - GPU を使うテストはホストのランナーでは走らない。その扱い(WARP か、セルフホストか)はテストができたときに決める。
3. **アーキテクチャ図は案 C**。
   - 流れ図を `docs/architecture/map.yaml` に「ノード → ファイル::シンボル」で書く。
   - `tools/archmap/archmap.py` が定義の行を探してリンクにし、GitHub Pages に Mermaid の図として出す
     (リンクはそのコミットの SHA に固定)。**解決できない参照があると CI が落ちる**ので、図とコードがずれない。
   - Doxygen(呼び出し図つき)を同じサイトの `api/` に並べる(案 A の併設)。
4. **整形と名前はユーザーの流儀**(docs/style.md): インデント 4・`{` は同じ行・関数は大文字始まり・class メンバーは `m_`・
   関数内は小文字始まり・enum の値とマクロは大文字スネーク・struct メンバーは小文字始まり・1 行の if は `{}` 省略。
   `.clang-format`(Google ベース、120 桁、コメントを折り返さない)を CI で検査し、名前は `.clang-tidy` に書く(CI での強制はまだ)。
   C++23 に上げ、プリコンパイルヘッダ `engine/src/pch.h` を入れた。
5. 公開用の README は英語(`README.md`)。日本語の開発者向けの説明は `docs/README.ja.md`。

## 検討した代案と、採らなかった理由
- 図 A(Doxygen だけ): 細かい図は自動で出るが、フレームの中で何がどの順に走るかという流れが描けない。→ 併設にとどめる。
- 図 B(手書きの図に手でリンク): 関数を移すとリンクが黙って壊れる。
- 非公開リポジトリ: ポートフォリオとして見せにくい。Pages も無料プランでは公開が前提。
- ライセンス MIT / Apache-2.0: ユーザーが「付けない」を選んだ。

## 影響(何がしやすく/しにくくなるか)
- 関数を移す・改名するときは map.yaml も直す必要がある(CI が教える)。新しいサブシステムを作ったら図にノードを足す。
- 公開なので、鍵・個人情報・PC のパスをコミットしない注意が要る(.gitignore 済み: `.bicameral-runner/`、`CLAUDE.local.md`)。
- CI の Windows ランナーの VS の版は GitHub 側の都合で変わる(ローカルは VS 2026)。
