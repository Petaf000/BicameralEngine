# ADR-0495 熱の放射の段: 両側とも空の刻みを GPU が飛ばし、段 1 からは袋の数で間接に起動する

- Status: Accepted(2026-10-29 Claude・T-1235。作り手から見た違いは無い〔結果はビット単位で同じ・費用だけ〕ので Claude が閉じる。D-539)
- 日付: 2026-10-29
- 決めた人: Claude(T-1235)
- 設計: docs/design/23-radiation.md §4 / 前: T-1229(負の側を飛ばす)・T-1161(段ごとの内訳)・ADR-0484(持ち越しの密な表)・D-428・ADR-0001

## 背景
T-1229 で、参照の温度の形(2 側)の負の側が空の刻みに、負の側の段とハッシュを起動の予告(SetPredication)で飛ばした。
正の側も同じ形で空になる刻み(参照より暖かい物が無い。例: 外 = 世界の温度で何もしない世界・冷たい物だけを置いた世界)があり、固定の費用
(1 側 約 170 µs・持ち越しの密な表を掃く CarryIn と Hash が 95 µs)を払っていた。
また段 1 からの RcLevelWalk・RcClearBags は袋の数によらず置いた数(最大 2048 グループ)で起動し、袋の無い段も 1 側 約 25 µs を払っていた(T-1161 の内訳)。

## 決定
1. **正の側も飛ばす**: 写しの段(RadiationGrid)が、各側の RcSources と同じ値(RcCellEmissionRelative)が 0 でないかを両側について求め、
   放つセルがあればその側の作業の印(RC_GPU_WORK_EMITTERS)を立てる。黒体の量は自分と参照で 1 回ずつ求め、両側は 64bit の比べだけで決める
   (引き算はしない。T-1078)。あとは T-1229 と同じ: 側ごとの RcPlanTick → 予告のバッファ → その側の 11 起動とハッシュを予告で囲む。
   飛ばすのは参照の温度の形だけ(1 側の形は温度のあるセルがほぼいつも放つので、印を求める費用の方が大きい)。
2. **段 1 からを間接の起動に**(仮の世界の自分のルート署名だけ): 段 L の袋の数が決まった直後の 1 スレッドの段(段 1 は RcClearFaces のスレッド 0、
   段 2 からは前の段の RcResetBags)が、段 L の RcLevelWalk(袋 × raysPerBag)と RcClearBags(袋)のグループの数を引数の表へ書き、
   ExecuteIndirect で要る数だけ起動する。歩幅(g_external2)は今までと同じ置いた数のまま渡し、起動する数は置いた数を超えないので、
   番号はどれも 1 スレッドが 1 回だけ読む(足し算はどれも可換。結果は直の起動とビット単位で同じ)。袋の無い段はグループ 0。
   引数の表は u3(木のルート署名では木の数のバッファなので、g_external3 の印 RC_GPU_U3_OUTPUT がある起動だけ結んで書く)。
   表は COMMON に置き、刻みの中で書く間 UAV・読む間 INDIRECT_ARGUMENT にして COMMON へ戻す(予告のバッファと同じく状態を追わない)。
3. ProbeFrameReadback の飛ばした刻みは側ごと(radiationSkippedPositive / Negative)。ProbeSimOptions::radiationSkipIdle は両側をまとめて切る(比べる試験用)。

## 検討した代案と、採らなかった理由
- 正の側の印を 1 側の形でも求める: 1 側の形で空になるのは温度 0 の世界だけ。写しの段に黒体の量を求める費用(288.15 K の場面で +23 µs)が毎刻み増える。
- 段 1 からを起動の予告で段ごとに飛ばす: 袋の数を予告のバッファへ写すのに状態のバッファの遷移(UAV ↔ COPY_SOURCE)が段ごとに要る。
  間接の起動なら 0 でない段も要るグループの数だけになる。
- 引数の表を書く 1 スレッドの段を別に足す: 段ごとに起動が 1 本増える(1〜2 µs)。今ある 1 スレッドの段(RcResetBags)と RcClearFaces のスレッド 0 に乗せた。
- 段 0(Level0Prepare・Level0Walk・ClearFaces。放つ面の数で決まる)も間接に: 面の数は RcCarryIn が終わるまで決まらず、書く段が 1 本増える。
  固定は 1 側 約 9 µs なので見送り(T-1235 の残り)。

## 影響
- 作り手から見た違いは無い(結果・セーブ・ハッシュは同じ)。費用だけ: docs/perf.md(2026-10-29 T-1235)。
  両側とも空の刻み(外 300 K 何もしない)439 → 299 µs/刻み。間接の起動は ±8 µs で差がほぼ無い(飛ばした側は引数の表の遷移が残る)。
  予告の印は RcPlanTick が予告のバッファへ直に書く(状態のバッファから写す形をやめた。4.4 → 1.5 µs/側)。
- **既定の改め(2026-10-29 司令塔の決め・T-1235)**: 段 1 からの間接の起動は **既定を切る**(`ProbeSimOptions::radiationIndirectLevels = false`。
  コードは残す)。64³ の測りで直の起動と ±8 µs で差がほぼ無く(火 731 / 736・既定 736 / 731・外 288.15 K 793 / 798 µs。今 / 直)、
  両側とも空の刻みでは引数の表の遷移が予告の外に残るので 299 / 285 µs と +14 µs 遅かった。D-546「測って速い所だけ」に合わせる。
  袋の数が置いた数より大きく減る大きい世界(T-1117 の粗い輪など)で測り直し、速ければその世界の形で入れる。結果はどちらでもビット単位で同じ
  (gpu_radiation_cost が間接・直の両方で刻みごとのハッシュの一致を見る)。
- 木のルート署名で動かす形(gpu_cascade_light_test)は今まで通り直の起動(u3 は木のバッファなので書かない)。
- 土台の共通部分(登録の欄・当てる段)には触っていない。持ち越しを登録の欄へ(T-1227)・変わったブロックの印(T-1228)はそのまま。
