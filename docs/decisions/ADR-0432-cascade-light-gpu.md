# ADR-0432 距離ごとの段(R-R1)の GPU 版: 段の受け渡しを共通の核へ・袋は hash の表・溜めは 1 語の atomic min

- Status: Proposed(T-0959 の作り方。Claude の案。距離ごとの段を続けるか〔Q147〕はユーザーの答え待ち)
- 日付: 2026-10-22
- 決めた人: Claude(T-0959)
- 設計: docs/design/23-radiation.md §3.3・§10 R-R1 / 前: ADR-0413・ADR-0419・ADR-0424 / 核: shaders/common/cascade_light.hlsli

## 決定
1. **形は T-0972 の「最後の 1 回」(1b + 2)を整数で CPU リファレンスに入れたもの**:
   1b = 升目の中のずらし(16 × 16)を、光線ごとに決まった始まりから刻みごとに歩幅 159 で巡る(256 刻みで一巡。時間の前平均)。
   2 = 袋に「量がどの軸の面から出たか」を 3 つの欄(帯ごと)で持ち越し、子の升目へはその面の Lambert の重み(RcAimedFaceWeight)で分ける。
2. **段の受け渡しの計算は共通の核に置く**(RcLevel0Ray・RcLevel0Weight・RcWalkLevelRay・RcPassToNextLevel・RcBagRay)。CPU と GPU は置き場(袋・持ち越し)だけが違う。
3. **溜め(袋の出どころ)は、鍵の符号 18bit(ビットの長さ 7 + 仮数 11)と出どころ 15bit × 3 を 64bit 1 語に詰めた min**(RcPackReservoir)。
   GPU は InterlockedMin64 1 回で決まる(2 回目の照合の段が要らない)。鍵が相対 2^−11 の内で並んだ候補は出どころの小さい方。
   出どころが 15bit なので**世界の箱は 1 辺 127 セルまで**(CheckCascadeGrid)。木を読む形(T-0973)では出どころをブロックからの相対にするか、2 回の照合に戻す。
4. **GPU の袋は段ごとに開いた番地の hash の表 2 つを交互に**(鍵 = ブロック 14bit × 3・面・升目 9bit × 2。CAS で番地を取り、量・軸の割合は 64bit の atomic の足し算)。
   使った番地の列を持ち、使い終わった表はその列だけ空にする。表の並びは決まらないが、足し算と min は可換なので結果は順によらない(R3・R4)。
5. **照り返しの持ち越しは、刻みの中は密な受け(セル × 面 × 帯)、刻みをまたぐ状態は疎な表**(鍵 = セル × 12 + 面 × 2 + 帯・量。D-619)。
6. 費用の比べのために `raysPerBag`(袋 1 つから出す光線の数。量を等分し、ずらしの巡りの続きを使う)を足した。既定は 1(今の形)。

## 検討した代案
- 溜めを 64bit の鍵の min + 出どころの min の 2 回(CPU の元の形)→ 光線ごとの残りを置く場所と照合の段が要る。鍵の分解能を 2^−11 に落としても選ばれ方の偏りは見えない
  (8 m の円の 60 刻みの平均は T-0972 の 1b + 2 の値〔−18.9 〜 +17.4 %〕と同じ)。
- 袋を密な配列(ブロック × 升目)にする → 64³・n0 = 4 で段 1 だけで 1,260 万個・1 GB。疎な hash にした。
