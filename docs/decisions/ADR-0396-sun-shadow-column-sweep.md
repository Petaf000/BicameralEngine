# ADR-0396 太陽の影の柱: 光線の細かさの格子で木の葉を引き、同じ葉を 1 区間にまとめて掃く

- Status: Accepted(工学の作り方。Claude が決めた。作り手から見て違いが出る所は下の「仮」)
- 日付: 2026-10-21
- 決めた人: Claude(T-0910。23 §3.1・§10 R-R0 の作り方)
- 設計: docs/design/23-radiation.md §3.1。共通の核 shaders/common/sun_column.hlsli

## 背景
- 23 §3.1: 太陽の向きは 1 つ。向きに沿って世界の多重解像度の木を掃き、帯ごとに「どれだけ届いたか」を出す。整数・決定的・保存は厳密。
- 合格(23 §10): 陰はちょうど 0・入った = 吸った + 外へ(ビット単位)・0.5 m と 0.25 m で地面の和 ±1 %・温室・CPU と GPU のビット一致。

## 決定
1. **光線の束**: 光の向き D(整数 3 つ。|成分| ≤ 2^15)の一番大きい軸 A に垂直な面の上で、**光線の細かさ L**(呼ぶ側が決める。木の最も細かい
   本物のブロック以上・0〜20)のセルの間隔の格子。光線はセルの真ん中を通る。1 本の量 = 強さ × 面(0.25 × 4^−L m²)× 1/60 s × cos(整数に切り捨て。
   単位はレベル L のエネルギー 8^−L mJ)。同じ面積なら細かさによらず同じ量。
2. **掃き方**: 光線ごとに A の板(L のセル 1 枚)を順に進み、板の真ん中の点を含む葉のセル(`MrFindContaining` と同じ引き方)を引く。
   同じ葉が続く板は 1 区間にまとめ、区間の τ = 深さ(レベル 0 の式。量の数は密度の比)× 板の数 × |D| ÷ (|D_A| 2^L)、通す割合 e^−τ(Q16)。
   減った分 × 照り返しを「返す」、残りを「吸う」。粗い葉は自分の値で掃く(23 §3.1「粗い所は混ざった箱の値で同じように」)。
3. **保存**: 光線ごとに 入った = 吸った + 返した + 外へ を整数の引き算で分ける(ビット単位)。セルごと・帳簿の足し算は可換な整数の
   足し算だけ(GPU は 64bit の atomic)なので、光線の順によらない(R3・R4)。通さないセル(τ ≥ 32)は全部取る → 陰はちょうど 0。
4. **GPU**: Compute(既定。D-302)。1 スレッド = 光線 1 本。多重解像度の木のルート署名を借り、外のバッファ u4(作業 = SunParams + 光の値。
   既定のヒープ)・u5(出力)に結ぶ(覗き窓と同じ形。ルート署名は増やさない)。木のセルは読むだけ。
5. **出力は渡す口だけ**: セルごとの「吸った・返した」(帯ごと。レベル L の単位)と帯ごとの帳簿。セルのエネルギーへ足す段・粗い葉への換算・
   刻みの順(S42 の 7)への組み込み・帳簿の理由の行(世界の外からの日の光)は使う側の仕事(T-0910 の申し送り)。

## 検討した代案
- **板ごとの 2D の掃き(板の中を並列・板の順に進む)**: 板と板の間に同期が要る(GPU で板の数だけ段)。光線ごとに独立に走らせる方が段が 1 つで、
  向き 1 つなら光線どうしが交わらないので同じ結果。→ 光線ごと。
- **ADR-0262 の平行な線の束の DDA(境を越える所で区切る)をそのまま使う**: セルの細かさが場所で変わる木では、境の位置が葉ごとに違い、
  細かさによる量のずれが出る。板の真ん中の点で葉を引く形なら、光線の細かさ L だけで決まり、細かい葉と粗い葉が混ざっても同じ規則。
- **光線の細かさを葉に合わせて変える(粗い所は太い光線)**: 速いが、細かい葉の境で光線を割る作業が要り、決定的に割る規則が増える。→ 2 周目の候補(費用で要れば)。

## 仮(作り手から見た違い)
- **仮 1【エンジン】光線の細かさ L は呼ぶ側が 1 つ決める**(木の最も細かい本物のブロック以上でないと断る)。作り手から見て: 細かい所を作ると、
  そこに日の光の計算の細かさが合わせられ、世界全体の光線が増える(64³ の地形で L = 0 → 1 で 4 倍)。代案(場所ごとに光線を太くする)は上。
- **仮 2【エンジン】葉は板の真ん中の点で引く**: 斜めの光線が角をかすめるだけのセルは数えない(陰の縁が光線の細かさで階段になる)。描画の影は細かく描く(S12)。
