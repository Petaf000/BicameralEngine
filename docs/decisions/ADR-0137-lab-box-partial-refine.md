# ADR-0137 実験室の箱の一部を細かくするのは「記録に残る細かくする印 → 木の要求の組」で、細かいセルの量は 8^-k の単位のまま置く

- Status: Accepted(実装の細部。ユーザー未確認の点はチケット T-0314 の「判断待ち」)
- 日付: 2026-10-11
- 決めた人: Claude(CLAUDE.md §5。T-0314・D-449)

## 背景
- ADR-0113 で実験室の箱は多重解像度の木の本物の根(8³・レベル 0 = 0.5 m)を並べたものになった。一部を細かくする箱(T-0314)は
  木の「細かくする」要求(17 §5)で子を作る道で、T-0173 から次の 4 点が決まっていなかった:
  (1) 細かくする要求を記録に残す形、(2) 置く操作が細かくしたセルに当たる時の決め方と量の単位、
  (3) 静かになった所を粗くする・畳むを箱で呼ぶか、(4) 細かいレベルの熱の小刻み・陰解法(17 §4)を箱で使うか。
- 木の要求の処理(ProcessRequests / GpuMultires::RecordProcessRequests)は CPU と GPU が同じ結果。取り合いは「細かくする先の親」ごと
  なので、同じ親の子を 1 回の処理で 2 つ作れない(片方が MR_STATUS_CONFLICT)。
- 量の単位はレベルの関数(17 §1: 物質量 8^-k µmol・エネルギー 8^-k mJ)。同じ濃度・温度ならどのレベルのセルも同じ数。

## 決定
1. **細かくする要求はコマンド(LAB_COMMAND_TYPE_REFINE = 0x4C07)として記録に残す**。payload は範囲の語(レベル 0 = 箱のセルの座標。
   範囲のコマンドと同じ 5 ビット × 6)と段の数(1〜LAB_MAX_REFINE_LEVELS = 2)。セルは変えない。
   刻みの初めに、その刻みの印をまとめて木の要求の組に直す(`sim::LabRefineRounds`): 段の浅い方から、段ごとにブロックの座標の偶奇で
   8 組(同じ組の要求は親がみな違う = 取り合わない)。組の中はブロックの座標 z → y → x の順・重なりなし。組は 1 刻みに 16 まで
   (GpuMultires の要求の写しの枠の数 = 16 にちょうど収まる)。1 組は 512 まで(最大の箱 32³ を 2 段でも 16³ ÷ 8 = 512)。
   CPU は組ごとに SubmitRequests → ProcessRequests、GPU は RecordRequests → RecordProcessRequests。
   刻みの順: 細かくする → 魔法のパッチの境 → コマンドを当てる → 刻む(CPU の StepLabBox・GPU の GpuLabBox::RecordTick)。
   要求を CPU で組に直すのは、記録のコマンドから決まる純粋な関数で、世界の状態を読まない(D-107 の「コマンドを投げる」の内)。
2. **箱の形に「細かくする枠の数」(`lab::LabBoxShape::refineBlocks`)を足す**。根の外に足す世界の枠・頁の数(端数の枠は 1 + 根 + 枠)。
   0 = 細かくできない箱で、T-0173 までの箱と記録はそのまま(容量が変わると状態のハッシュが変わるため、0 の箱の容量は今までと同じ)。
   上限は LAB_MAX_REFINE_BLOCKS = 1024(1 枠 = 頁 512 セル + 端数)。パネルが作る細かくできる箱は 128(根 1 つを 2 段全部で 72 枠)。
   枠が足りない所は要求が MR_STATUS_NO_SPACE になり、細かくならない(CPU と GPU で同じ)。
   記録 BLAB 版 6 = 版 5 の形の 4 語目(版 5 では 0 の予約語)が枠の数。版 5 で 0 でなければ壊れている。
3. **細かいセルの指し方と量の単位**: 1 セルのコマンドのセルの語は、レベル 0 は今の LabCellIndex のまま、レベル k(1〜2)は
   `(k << 27) | x | (y << 9) | (z << 18)`(座標は箱の座標 × 2^k)。範囲のコマンドはレベル 0 のまま。
   コマンドは「そのセル(範囲)が覆う空間の、レベル k 以上の葉のセル全部」に当たる(根の木を根 → 子 → 孫の順に見て、覆われたセルには
   書かない)。粗い葉の一部になる所(指したレベルより粗い葉)には当てない(置いた空間より広く変えないため)。
   量はレベルを見ずに同じ数を書く = 同じ濃度・温度(子の単位は 8^-k なので)。だから箱のセルに置くと、細かくした所では細かいセル全部が
   同じ材料になり、合計の物質量は同じ。
4. **つつくのは、当てたセルを含む根の木の全部の枠**(根・子・孫。表を替えた印・魔法のパッチも根ごとに木全部)。
5. **粗くする・畳むは箱では呼ばない**(ADR-0037 の「畳まない」のまま)。細かくした所は細かいまま残る(戻すのは箱を作り直す)。
6. **細かいレベルの熱の小刻み・陰解法は箱では使わない**(LAB_STEP_OPTIONS は変えない)。細かいレベルの面の係数は 17 §4 の上限で
   頭打ちになり、細かい所の熱の伝わりは本当より遅い。仮(ユーザー未確認。T-0314 の判断待ち)。
7. **比べる**: FindLabMismatch は根のセルの後に、細かくした子の枠のセルも枠の順に比べ、違ったセルを細かいセルの語で返す。

## 検討した代案と、採らなかった理由
- **細かくする要求をコマンドにせず、パネルが木の要求を直接出す**: 記録と再生で同じ木にならない(記録は箱のコマンドしか持たない)。
- **GPU のシェーダーがコマンドから要求を作る**: 要求の一覧と数を GPU で書く段が増える。組は記録のコマンドだけで決まるので、
  CPU で同じ関数を通して両方に渡す方が単純で、ビット一致の基準も 1 つ。
- **1 回の ProcessRequests で全部の要求を出す**: 同じ親の子が取り合いで負ける(MR_STATUS_CONFLICT)。負けた要求を次の刻みに回すと、
  細かくなり終わる刻みが箱の形で変わる。偶奇の組に分ければ 1 刻みで終わる。
- **置く操作を粗いセルの座標だけにして、細かくした所は子の 8 セルに分ける**: 細かいセル 1 つに置けない。細かいセルの語を足しても
  レベル 0 の語は変わらず、古い記録の意味も変わらない。
- **粗い葉の一部に当たる細かいセルの指定は、その粗い葉に当てる**: 置いた空間より広い所(8^d 倍の体積)が変わる。当てない方が嘘が無い。
- **細かくする枠を形によらず常に足す**: 0 の箱の状態のハッシュが変わり、版 5 までの記録が再生できなくなる。
- **小刻み(方式①)を箱で使う**: レベル 0 では 1 回なので結果は変わらないはずだが、ビット単位で同じかを確かめておらず、古い記録の再生を
  壊すおそれがある。細かい所の熱を正しくするのは別のチケットで(判断待ちのおすすめ)。

## 影響(何がしやすく/しにくくなるか)
- しやすい: 0.125 m 角までの細かい所で、木・炭の燃え方や細かい所と粗い所の境の熱と物の受け渡しを、毎刻み GPU と CPU のビット一致を
  見ながら試せる。世界の木の「細かくする」要求の道そのものなので、木の不具合も小さな場面で再現できる。
- しにくい: 細かい所の熱は頭打ちで遅い(6)。計器(SampleLabGauge)・パネルの断面は根のセルしか見ない(覆われたセルの古い値を数える)。
  細かいセルを数える計器・断面・見るセルを細かいセルにするのは T-0350。粗く戻す操作は無い(作り直す)。
