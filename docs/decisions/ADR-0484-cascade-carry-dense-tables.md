# ADR-0484 熱の放射の段(RC)の GPU の持ち越しを「鍵で引く密な表 2 つ」にする(溢れない形)

- Status: Accepted(2026-10-26 Claude・T-1164。作り手から見た違いは無い〔結果は CPU と同じ・置き場はほぼ同じ〕ので Claude が閉じる。D-539)
- 日付: 2026-10-26
- 決めた人: Claude(T-1164)
- 設計: docs/design/23-radiation.md §3.3・§4 / 前: ADR-0432(GPU の段)・T-1010(持ち越しの疎な表)・docs/design/04 R3・R4

## 背景
窓の記録 → 再生(window_replay_play・_rewind・_peek)が S(33) から落ち、同じ記録を 3 回再生すると S(33) のハッシュが 3 回とも違った
(main〔82453cf5〕でも同じ。2026-10-17 を最後に main で流しておらず、T-1154 で GPU の仮の世界に放射を入れてから落ちていた)。
release でも見える溢れの読み出し(ProbeFrameReadback::radiationOverflow)を足して流すと、**持ち越しの表が溢れていた**(印 4。放つ面 24,629/刻み・
袋の最大 425,445 は余裕あり)。持ち越しは照り返しと「組の刻みを待つ熱の光」(D-658 の 15 組。14/15 の面が毎刻み待つ)で、
サンプルの世界(空気の中の木箱・積み木・物理)では (セル・面・帯) の数が置き場 2^19 を超えた。疎な表は 0 から増えた鍵を atomic の順に並べるので、
溢れると「どの鍵が落ちるか」が取り合いの順で決まり、結果が回ごとに変わる(R3・R4 の外)。

## 決定
- 持ち越しは (セル・面・帯) の鍵(= (セル × 6 + 面) × 2 + 帯)で引く**密な表を刻みの偶奇で 2 つ**持つ(各 セル × 12 語)。
  刻み t は表 t & 1 を RcCarryIn が全部の鍵を掃いて読み、0 に戻す。照り返し・組を待つ光・組の刻みでない持ち越しは表 1 − (t & 1) へ足す(可換な 64bit の足し算)。
  **鍵の数だけ置き場があるので溢れない**。RcCarryOut(密な受け → 疎な表)は要らなくなったので外した。
- 状態のハッシュ(RadiationHash)と読み戻し(Read)は表の全部の鍵を掃き、0 でない鍵を (セル・面・帯) の順に拾う(CPU の CascadeCarry と同じ形・同じハッシュ)。
- GpuCascadeCapacity::carry は「RecordUpload で写す初めの持ち越しの数の上限」の意味に変わる(仮の世界は空から始めるので 2^10)。
- 放つ面・袋の表はまだ大きさの見込みで、溢れは release でも ProbeFrameReadback::radiationOverflow と Error のログで見える(仮の世界)。

## 結果
- 置き場(64³・側 1 つ): 持ち越し 疎な表 2 つ 16 MiB + 密な受け 24 MiB + 作業の初めの持ち越し 8 MiB → 密な表 2 つ 48 MiB。ほぼ同じ。
- 刻みをまたぐ状態(保存点に写す頭の部分)は 24 → 56 MiB(側 1 つ。密な表 2 つを写す)。
- 掃く量: RcCarryIn と RadiationHash が 1 刻みに 24 MiB ずつ読む(3070 Ti で 0.1 ms 未満の見込み。測りは docs/perf.md)。
- 木(多重解像度)の段で使う時も同じ形(密な表は前から セル × 12 語あった。2 つになる分だけ増える)。

## 検討した代案
- 疎な表を大きくする(鍵の数 セル × 12 まで): 溢れないが、刻みをまたぐ状態が 1 側 104 MiB になり保存点が重い。
- 組を待つ熱の光を放つ面の量(stateSources)に溜めて持ち越しから外す: 持ち越しは減るが、CPU リファレンスとハッシュの形が変わり、面の量が刻みをまたぐ状態になる。今回は見送り。
