# ADR-0251 遊びの指標の範囲は、指標の欄に min_cell・size_cells で書く

- Status: Proposed
- 日付: 2026-10-15
- 決めた人: ユーザー(Claude が提案した場合も、決めるのはユーザー)

## 背景
遊びの指標(ADR-0206)の量は世界全体だけだった。⑤ の場面(T-0414)で「向こう岸の草が残ったか」を、草の世界全体の量と岸ごとの量の暗算で読んだ
(作り心地の記録 4)。

## 決定(仮。ユーザー未確認)
1. 指標に `min_cell = { x, y, z }`・`size_cells = { x, y, z }` を書くと、量(最高温度・しきい値以上のセルの数・物質の量)をその箱の中だけで測る。
   両方書くか両方省く。省けば世界全体(今までどおり)。書き方と意味は world_cells の領域と同じ。
2. 格子に収まらない箱はベイクの誤り。量は読み戻した S(t) から CPU で測る(GPU の写しと CPU リファレンスが同じ関数。値はビット一致のまま)。
3. 箱は 1 つ。箱の和・「初めにその物質を持っていたセル」は今は書かない(要れば箱ごとに指標を分ける)。

## 検討した代案と、採らなかった理由(作り手から見た違い)
- `region = { min_cell, size_cells }` の入れ子: 欄はまとまるが、world_cells と形が違い覚える形が 2 つになる。
- 箱の列(和): L 字などを 1 つの指標で書けるが、今の場面では要らない。後で `regions = { … }` を足しても今の書き方は残せる。

## 影響(何がしやすく/しにくくなるか)
- 岸ごと・部屋ごとの量を指標にでき、場面の面白さ(川で止まったか)を暗算なしで前の版と比べられる。
- 指標ごとの場面の違い(防火帯あり/なし)はまだ書けない(T-0580)。
