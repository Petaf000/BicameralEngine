# ADR-0079 debug のビルドでもシミュのシェーダーは最適化(-O3)して作る(PIX で 1 行ずつ追う時だけ -Od に戻す)

- Status: Accepted(実装の細部。回避であり、ドライバの中の仕組みは未確認)
- 日付: 2026-10-11
- 決めた人: Claude(CLAUDE.md §5。T-0239)

## 背景
- debug のビルドで覗き窓(`--peek 28,32,32 --peek-depth 9`)を開いた窓の再生(window_hot_reload_play・window_replay_peek)が、約半分の起動で
  記録と食い違った。食い違う刻みでは必ず GPU の物理が CPU リファレンスとずれ、ずれ方は「いくつかの決まった別の値」だった。release では起きない(T-0239)。
- 切り分け(T-0239 の 1 回目): 覗き窓の刻みのパイプライン(debug は -Od)を、シミュのリストに **設定してルートを結ぶだけ**(Dispatch もバリアも無し)で
  2/12 の起動が食い違った。刻みを呼ばなければ 0/16。バッファの前後に詰め物を置いても変わらない(範囲外の書き込みではない)。
- 似た症状が前にもあった: T-0098 で、組(3 KB)を局所の変数に持つ物理の Compute が、別のキューの仕事が割り込むと時々違う結果を出した
  (組をバッファの上で読み書きする形に直して消えた。shaders/sim/physics_bindings.hlsli の注)。
- -Od のシェーダーは局所の配列や途中の値をレジスタに置けず、シェーダーの局所メモリ(スクラッチ)を大きく使う。
  「大きい局所メモリのパイプラインを同じキューで設定する・別のキューが割り込む」と、後ろの物理の途中の値が壊れる、というドライバ側の振る舞いと見ている(未確認)。

## 決定
- **debug のビルドでも、シミュのシェーダー(shaders/CMakeLists.txt の kind = sim)は -O3 で作る**(-Zi・-Qembed_debug と BICAMERAL_GPU_DEBUG=1 の
  FX_ASSERT・DEBUG_PRINT は残す)。描画のシェーダーは今までどおり debug は -Od。
- PIX でシミュのシェーダーを 1 行ずつ追う時だけ、CMake の `BICAMERAL_SIM_SHADER_OD=ON` で -Od に戻す(そのビルドでは覗き窓つきの窓の再生が食い違うことがある)。
- 確かめたこと(2026-10-11・RTX 3070 Ti・6 つのランナーが同じ GPU): 覗き窓つきの再生(`--check-physics`)が 10/10 で一致(-Od では約 12/27 が食い違い)・
  GPU の assert 0 件・debug(-O3)の記録を release が、release の記録を debug(-O3)が再生して一致・debug の決めたテスト 33 本が通過。
  -Od で作った古い記録(2026-10-11 0 時台)は、記録した時にもう壊れていたと見る(-O3 の debug と release のどちらで再生しても同じ刻み 4 から食い違う)。

## 検討した代案と、採らなかった理由
- **シェーダーの側で局所メモリを減らす(T-0098 と同じ直し方)**: -Od では局所の配列でない途中の値までスクラッチに落ちるので、書き方では消しきれない。
  release(-O3)で同じことが起きる兆しは無い(release の窓のテストは通り続けている)。重いシェーダーを足す時の注意として残す(下の「影響」)。
- **debug の窓のテストから覗き窓を外す・release だけにする**: 決定性の確かめが減る。debug の FX_ASSERT 付きで流せる方が価値がある。
- **-O1 にする**: -O3 で消えたので、release と同じ最適化にそろえる方が「debug と release で同じシェーダーの形」を保てる(記録を互いに再生できる)。

## 影響(何がしやすく/しにくくなるか)
- しやすい: debug の窓の再生・覗き窓のテストが起動ごとに揺れない。debug と release の記録を互いに再生できる。debug のシミュが速くなる
  (debug の gpu_multires が約 90 秒で DEVICE_HUNG にならなくなった。ただし 6 つのランナーの並走では 1200 秒の上限に届いた → T-0263)。
- しにくい: PIX でシミュのシェーダーの変数を 1 行ずつ見るには `BICAMERAL_SIM_SHADER_OD=ON` でビルドし直す。fixed の自己テスト(gpu_fixed)の
  「-Od でも CPU とビット一致」は、そのビルドでないと確かめられない(04「未確認」)。
- 残る危険: 仕組みはドライバの中で未確認。release でも、局所メモリを大きく使うシミュのシェーダー(大きい局所の配列・展開されないループの中の配列)を足すと
  同じことが起きうる。そういうシェーダーを足したら、覗き窓つきの窓の再生(`--check-physics`)を何回か流して確かめる。新しいドライバでも確かめる(BACKLOG)。
