# ADR-0017 レベルの違う面の熱は、細かい側が計算して粗い側の端数で受ける

- Status: Accepted
- 日付: 2026-10-05
- 決めた人: Claude(実装の細部。CLAUDE.md §5。T-0019)

## 背景
- 多重解像度の木(17 §1・ADR-0015)は隣のブロックのレベル差を制限しない。たくさんの要求の場面では面の先が 10 段粗いこともある(T-0019 の計測)。
- レベル k のエネルギーの単位は 8^-k mJ。細かいセル(kf)が粗いセル(kc = kf − d)へ熱を渡すと、粗い側では 8^-d 単位の端数が出る。
  切り捨てると、細かい所と粗い所の間で熱が止まる(D-428 の「嘘」)。
- 粗いセルの 1 面は細かい面 4^d 枚に分かれるので、粗い側が全部を集めて計算する形は d が大きいと重すぎる。

## 決定
- **面の流れは細かい側だけが計算する**(同じレベルの面は今までどおり両側が同じ式で逆向きを出す)。面の係数は細かい側の単位で、
  粗い側の上限は「G の係数 × 4^kf」と「熱容量の上限 × 2^d」の小さい方(粗いセルの 1 面の重みの和は 1/8 以下のまま)。
- **粗い側は整数部をセルに、2^-64 単位の端数を端数のブロック(ADR-0015)のエネルギーの端数に足す**。3d ≤ 64 なら細かい単位を正確に表せる。
  3d > 64 は表せない下位を細かい側に残す。端数の枠が無い(足りない)時は粗い側の整数の単位の倍数だけ送る(数える: MR_COUNTER_FRACTION_SHORTAGE)。
  どの場合も細かい側が減らした量 = 粗い側が増やした量で、エネルギーはビット単位で保存される。
- 端数の枠は、粗い側で端数が要るブロックに**枠の順**に配る(枠の番号を決定的にする。ADR-0016)。
- 刻みの初めのセルだけから流れを計算する(Jacobi 型)。粗いセルの変化は細かい側から足し込む(GPU は 64bit の足し算。整数なので順に依存しない。T-0107)。

## 検討した代案と、採らなかった理由
- 木を 2:1 に保つ(隣のレベル差を 1 以下にする。AMR でよくある): 粗い側が細かい 4 枚を集めて計算でき、端数も 8 単位で済む。
  ただし細かくする要求のたびに周りも細かくする必要があり、木の管理(T-0018)と GPU の段を作り直す。ブロックも増える。今は採らない。
- 粗い側の単位で切り捨てる: 小さい流れが毎刻み 0 になり、細かい所に熱がこもる(嘘)。
- 粗い側の単位へ確率的に丸める(T-0106 と同じ考え): d が 7 くらいを超えると、粗い側の 1 単位が細かいセルの熱の全部より大きくなり、細かいセルの温度が跳ねて負にもなる。

## 影響
- 粗い側の端数の枠は伝導で増え、木の変更(粗くする・細かくする)でしか返らない。たくさんの要求の場面では 64 枠を使い切った(T-0019)。
  容量の考え方(伝導で取った端数をいつ返すか・足りない時)は T-0107 で GPU に載せる時に決める。
- 端数を持つブロックは一様にならず、頁を畳めない(17 §5「頁を畳む」)。ほぼ同じ所を畳む(T-0104)と合わせて考える。

## 追記(2026-10-05、T-0107。決めた人: Claude〔実装の細部。CLAUDE.md §5〕): 伝導で取った端数の枠の容量
- **GPU も CPU と同じ規則**(枠の順に配る・足りなければ数えて整数の単位の倍数だけ送る)。HW・WARP で毎刻みビット一致を確かめた。
- **返すのは今までどおり木の変更(粗くする・細かくする)の時だけ**にする。伝導の端数は 1 単位(8^-k mJ)未満の熱で、枠を返すにはそれをどこかへ
  移す必要がある(捨てると保存則が破れる)。返し方は「静かになったブロックの端数のエネルギーを世界の帳簿へ移して枠を返す」が筋がよい
  (帳簿は粗くした時に落ちた下位を覚える所で、「世界 + 帳簿」の保存はそのまま。D-428 の「計器で測れない差だけ捨てて畳む」と同じ判定)。
  ほぼ同じ頁を畳む判定と一緒に決めるのが自然なので、**T-0104 で決めて入れる**(ROADMAP の T-0104 の行に足した)。
- **容量の考え方**: 端数の枠は頁と同じ「世界の容量」(MultiresCapacity::fractions)。細かいブロックに面する粗いブロックの数ぶん要る。
  足りない時の振る舞いは頁の不足(T-0102: 凍らせて次の刻みに回す)と同じく「数える欄で見張る容量の不足」として扱う
  (MR_COUNTER_FRACTION_SHORTAGE。保存は守るが、そのブロックへは整数の単位の倍数しか流れず熱がこもる)。テストのたくさんの要求の場面(世界の枠 192・
  端数の枠 64)は、わざと足りなくして不足の道も CPU と GPU で一致することを確かめている。ゲームの世界の容量を決める時(05 のストリーミング)に、
  頁の数と同じ水準で持つ。

## 追記(2026-10-05、T-0108。決めた人: Claude〔実装の細部。先行研究の方式①。CLAUDE.md §5〕): 細かいレベルの刻み(レベルごとの小刻み)
- **レベル k の伝導を 1 刻みに 4^σ(k) 回の小刻みに分ける**。σ(k) = clamp(k − 基準, 0, Δkmax)。基準 = 面の係数が熱容量の上限で頭打ちにならない**最後の**レベル
  (先行研究の「頭打ちになる最初のレベル k*」から 1 つ下げた。k* で 1 回のままだと k* 自体が約 1/4 遅い〔物差しで 0.264〕ため)。Δkmax = 3(64 回)。
- 違うレベルの面はこの ADR の形のまま: 細かい側が小刻みごとに計算し、粗い側は粗い小刻みの終わりに合計を受ける(整数部 + 端数。保存はビット単位)。
  粗い側の値は粗い小刻みの初めのまま。粗い側の上限 = min(粗い側の G の係数 × 4^(kf − σf), 粗い側の C の上限 × 2^d ÷ 4^(σf − σc))。
- 活性: 小刻みで変わったブロックの面の隣を、その刻みの印で起こして以後の小刻みから刻む(刻む集合は刻みの中で増えるだけ)。
- 検討した代案: 方式②(後退 Euler + 回数固定の反復 + 木の多重格子)・RKL(super-time-stepping)は Δk > 3 の細かさが遊びに要るか次第でユーザーの判断待ち
  (docs/plan/QUESTIONS.md)。基準を k*(先行研究のまま)にする案は k* のレベルが約 1/4 遅いので採らなかった。
- 影響: 直列の段数が最大 64 倍(GPU では小刻みごとに Dispatch を分ける。T-0109 で予算〔ADR-0011〕と比べて Δkmax を確かめる)。基準は表から決める値で、
  ゲームでは最も伝わりやすい物質(現実の空気なら基準 8 → レベル 11 ≒ 0.24 mm まで本当の速さ)。
