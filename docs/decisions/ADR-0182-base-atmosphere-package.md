# ADR-0182 基準の大気(成分・温度・地面の圧力)をパッケージに書く形

- Status: Accepted(改訂あり)(2026-10-14 ユーザー決定)
- 日付: 2026-10-13
- 決めた人: ユーザー(Claude が提案した場合も、決めるのはユーザー)

## 背景
- ADR-0176 の 3: 地面の層の基準の温度はエンジンの定数ではなく、世界の基準の大気(成分・温度・地面の圧力)から導く値。
  基準の大気そのものは環境の値だが、成分が物質の名前を指すので、環境ミキサー(T-0373)で足すことにしていた。
- 気体の層の基準(`sim::MakeHydrostaticReference`・`MakeGasTree`)は、成分の割合(Q32)・温度(mK)・地面の圧力(µPa)を引数に取る。
  今は試験だけが呼び、気体を世界に載せる段(T-0210)が世界の値から呼ぶ。

## 決定(案 A。仮)
1. 成分は新しい分類 **`atmosphere`**(1 つの鍵 = 1 つの物質。値は物質量の割合の ppm。足して 1000000)。
   温度と地面の圧力は分類 `environment` の 2 つの鍵 **`atmosphere_temperature_mk`**・**`atmosphere_surface_pressure_pa`**。
2. 検査はベイク(`sim::BakeWorldAtmosphere`。engine/src/sim/world_atmosphere.*): 知らない物質・割合 0・合計が 1000000 でない・
   成分があるのに温度か圧力が無い(か、その逆)は読み込みの誤り。全部書かなければ空(ブランクの世界。D-455)。
   ベイクした表の `atmosphere`(物質 ID の順)に入り、表の版・再生ファイルの表の中身に入る。
3. 読む所は `script::ReadWorldAtmosphere`(environment_package.cpp)、型は data/types/bicameral.d.luau。
4. 地球の値は標準パッケージ `earth_environment`(ISA の海面 15 ℃・101325 Pa・乾いた空気 N2 780780・O2 209460・Ar 9340・CO2 420 ppm)。
5. 基準の大気は「セルを満たす」ことはしない(層の基準の値だけ)。セルを空気で満たすのは別の標準パッケージ `earth_air`(分類 world_cells)。

## 検討した代案と、採らなかった理由(作り手から見た違い)
- **案 A(おすすめ・仮で実装)**: 成分は分類 atmosphere に物質ごとの鍵で、温度と圧力は environment の鍵。
  - 作り手から見た違い: Mod が成分を 1 つずつ足す・上書きできる(例: 魔素の気体を 1 つ足す時は、ほかの成分を減らす鍵の上書きも要る。
    合計が合わなければ読み込みで止まり、どのパッケージの何が違うかが出る)。
- **案 B: environment の中に成分の表を入れ子で書く**(`environment = { atmosphere = { nitrogen = ... } }`)。
  - 作り手から見た違い: 大気がひとまとまりに見えるが、Mod は大気を丸ごと置き換えるしかない(鍵ごとに足せない。ADR-0031 の合わせ方は 1 段)。
- **案 C: 割合ではなく 1 m³ あたりの物質量で書く**(温度と圧力は量から導く)。
  - 作り手から見た違い: 圧力を直接書けず、温度を変えると圧力も変わる。理想気体の計算を作り手がする。

## 影響
- しやすくなる: 気体を世界に載せる段(T-0210)が、表の基準の大気から層の基準を作れる。環境ミキサーで地球の大気を足す・外す。
- しにくくなる: 合計をちょうど 1000000 にする必要がある(端数を作り手が合わせる)。
- 未対応: 基準の大気から音速を導く(ADR-0176 の案 B・T-0443)。環境の値のホットリロード(T-0444)。

## ユーザーの決定(2026-10-14)
- D-490 ②: 基準の大気は高さごとに書けるようにする(高さで成分・温度が変わる)。書き方は T-0499 で決め直す。

## 改訂: 高さの点ごとに書く(T-0499・2026-10-15。Q61 = 案 1 をユーザーが決めた・D-494)
- 状態: Accepted(書き方はユーザー決定。下の細部〔鍵の名前・圧力を書く高さ・端の外の扱い・積む段〕は Claude が決めた仮)
1. **高さの点の列** `environment.atmosphere_profile = { { height_mm, temperature_mk, composition = { 物質 = ppm } }, ... }`。
   高さは世界の絶対の高さ(海面からの mm。±2^40)で、低い順に書く。点の間は直線でつなぐ(温度も成分の割合も。割合は切り捨てて端数を
   余りの大きい順に 1 ppm ずつ配り、足してちょうど 1000000)。一番低い点より下・一番高い点より上は端の点の値のまま。
   列は 1 つの鍵の 1 つの値なので、上書きは列ごと(ゲームは `require("@earth_environment")` で写し、補助の `set_point` で点を足す・
   置き換えて書き直す。T-0498 の形)。
2. **圧力は一番低い点の高さの値だけ** `atmosphere_surface_pressure_pa`。ほかの高さは `sim::AtmospherePressureMicroPascal` が
   重力・温度・成分(表のモル質量の平均)から静水圧で出す: 0.5 m(気体のレベル 0 のセルの高さ)ずつ、段の下の端の温度と成分で
   Δp = p M̄ g Δz ÷ (R T) を整数で引く(下へは足す)。気体の層の基準(`MakeHydrostaticReference` の層ごとの版)と同じ形の積み方なので、
   箱の床の圧力をこれで出せば、層の圧力は高さの静水圧と 0.36 Pa 以内で合う(気体の導く値の丸めの分。world_atmosphere_test)。手で書いた圧力が重力と合わずに
   風が吹き出すことは起きない。地球の分布で ISA の表と 0.05% 以内(11 km −0.013%・20 km −0.027%・32 km −0.045%)。
3. **一様な書き方は今まで通り読める**(分類 `atmosphere` + `atmosphere_temperature_mk` = 高さ 0 の点 1 つ)。点の列と一緒に書いたら
   読み込みの誤り(どちらの値が効くか分からないため)。
4. **ベイクで止める書き間違い**: 高さが低い順に厳密に増えていない・高さの範囲の外・点ごとの知らない物質・同じ物質が 2 回・割合 0・
   合計が 1000000 でない・温度が無い・点があるのに地面の圧力が無い(その逆も)。誤りに点の場所(`environment.atmosphere_profile[i]`)を付ける。
5. **標準パッケージ**: earth_environment の点は U.S. Standard Atmosphere 1976(= ISO 2533:1975)の層の境 8 点(0〜84.852 km)と
   乾いた空気の成分(約 86 km より下はよく混ざって一様)。補助 `earth_environment/atmosphere.luau`: `set_point`(点の上書き・挿入)・
   `molar_masses`(組成と原子量から mg/mol)・`settled`(「重い物ほど下に溜まる」拡散の釣り合いの点を、地面の成分と温度の分布から作る。
   足し算・掛け算・割り算と math.floor だけで決定的)。
6. 気体の層の基準は `GasReferenceLayer`(層ごとの温度と成分)の列から作れる(今の一様な形はそれを呼び、ビット単位で同じ)。
   多重解像度の木(`MakeGasTree`・`SetGasTreeEnvironment`)はまだ一様な形だけ(気体を世界に載せる段 T-0210 で、木のレベルごとの高さで読む形を足す)。

### 検討した代案(作り手から見た違い)
- **案 1(採用。ユーザー決定)**: 高さの点ごとに温度と成分を書き、直線でつなぐ。圧力は地面だけ。
- 案 2: 層(高さの区切り)ごとに一定の値を書く。作り手から見ると、区切りで温度と成分が段になり、山の斜面で段の所に偽の境ができる。
- 案 3: 式(減率・スケールハイト)で書く。作り手から見ると、決まった形の大気しか書けず、逆転層や「谷に溜まる気体」を自由に書けない。
- 圧力を点ごとに書く形は採らない: 手で書いた圧力が重力と温度に合わないと、世界を作った瞬間に風が吹き出す(D-494)。

### 仮で決めたこと(ユーザー未確認・取り消しやすい)
- 列は `environment` の 1 つの鍵(分類を分けると、標準の点と Mod の点が鍵ごとに混ざり、標準の点を消せない。列ごとの上書きにした)。
- 圧力を書く高さ = 一番低い点の高さ(地球なら海面)。
- 端の外は端の値(一番高い点より上も温度と成分は一定。圧力は静水圧で下がり続ける)。
