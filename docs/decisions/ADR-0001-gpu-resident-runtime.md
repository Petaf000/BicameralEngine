# ADR-0001 ランタイムは GPU 常駐、エディタは CPU

- Status: Accepted
- 日付: 2026-09-29
- 決めた人: ユーザー

## 背景
世界(元素・空気・反応の連鎖)を GPU でシミュレートすることがエンジンの存在理由。
一方で、世界の真実が VRAM にあるとエディタ(配置・Undo・保存)が作れないという問題がある。

## 決定
- ランタイム(ゲーム本体)は世界の状態を VRAM に常駐させ、CPU に戻さない。CPU へのフォールバックはしない。
- エディタとツールは CPU を自由に使う。CPU のデータで編集し、GPU 用バイナリにベイクしてランタイムに渡す。

## 検討した代案
- 一部のロジックを CPU に置く / 失敗時に CPU に戻す撤退条件を置く → 採らない。エンジンの存在理由が消える。

## 影響
- エディタ側の反応則評価器が、そのまま GPU との突き合わせ用 CPU リファレンスになる。
- セーブは GPU 構造体の読み戻しとバージョン管理が必要。

## 改訂(2026-09-30、D-107)
- 「GPU に置くもの」を明確にした: **Model(世界の状態と因果: 反応・生き物・敵・魔法・物理・進行)は全部 GPU**。
- View(UI・オプション・タイトル・会話の表示と流れ)と Controller(入力)は CPU。CPU は Model を書き換えず、コマンドとして GPU に頼む。
  GPU の状態は 1〜3 フレーム遅れのスナップショットで読む(06-simulation-loop.md)。
