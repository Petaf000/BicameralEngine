# ADR-0349 多重解像度の液体: 面の先は世界の Neighbor・セルごとに 6 面・上は WE_UP_AXIS・開いた端は流れ出しの境界・静止の丸めは当てる段の後

- Status: Proposed(2026-10-18。T-0774・T-0771・T-0777。① ② ③ は工学の帰結。④ の開いた端の液体の扱いと ⑤ の帳簿の分け方は仮〔ユーザー未確認〕)
- 日付: 2026-10-18
- 決めた人: Claude(wt6 の作業役)
- 関係: D-518(上は y)・ADR-0337 / ADR-0338(世界の端)・ADR-0334 / ADR-0335(当てる段・包み)・ADR-0332(静止の丸めの形)・T-0717 / T-0770(MR の 1 段の液体)・
  設計 20 §2.4・§2.6・§3

## 背景
- MR の液体(sim/multires_liquid)は y を上と決め打ちし、面の隣を根のブロックの索引で引く独自の LiquidGrid で持ち、世界の端はいつも閉じていた。
- 面の欄はセルの + 側 3 面(SF_PLACE_FACE)なので、当てる段の TxFlowCell の「セルごとに 6 面・自分の側だけ」と回し方が違った(面ごとに両側へ当てていた)。
- 開いた世界の端(T-0721・T-0772)を液体も読むと、− 側の端の面(世界の箱の下の面・−x・−z の面)には欄の置き場(持ち主のセル)が無い。

## 決定
1. **縦は WE_UP_AXIS**(D-518 = y)。縦の面(重さ)・柱(圧力を上から積む)・位置のエネルギーの高さを WE_UP_AXIS から読む。上が y なら液体の芯(liquid_flow.hlsli)と同じ向き。
   試験 multires_liquid は仮の世界の格子(y が上)から NestPlace で写して比べる(気体の試験と同じ形。上が y なら恒等)。
   確かめ: WE_UP_AXIS を一時的に 2(z)にしても multires_liquid が毎刻みビット一致で通る(下の「確かめたこと」)。
2. **面の先は世界の Neighbor**: MrFindFaceNeighbor(同じレベルのセル)+ 世界の外なら WeEdgeNeighbor(開いた端 = 外の柱の行、wall・真空 = 閉じた面)。
   LiquidGrid は刻むブロックの一覧と、面ごとの「先」(セル / 開いた端の行 / 閉じた面)の表だけになった。違うレベルの面は断ったまま(1 段の世界だけ)。
3. **6 面の回し方**: 面の力と望む動く質量は面の欄の持ち主(+ 側の面 = − 側のセル)が 1 回決める。当てる段はセルごとに 6 面を回し、面の欄を読む向きは
   transport_apply.hlsli の TxFaceFieldIsOwn(+ の面は自分の欄・− の面は − 側の隣の欄)、当てるのは自分の側だけ(TxApplyPacketSide。開いた端の面は
   外の側を World::AddEdgePacket で帳簿へ)。包みは両側が同じ刻みの初めの値から同じに作る(CPU では Pack が 2 回。GPU では書くのが自分のセルだけになる)。
   値は前とビット単位で同じ(仮の世界との比べがそのまま通る)。
4. **開いた端の液体(仮)**: 外のセル = 外の柱の行(液体が無い = 圧力 0。液体は出ていくだけ)。下が開いていれば外のセルは上の液体を支えない(落ちる)。
   端の面は運動量を持ち越さない(− 側の端の面に置き場が無いので ± の両方を同じに): 刻みの初めに**内側の面の速さを写し**(流れ出しの境界 = 端に垂直な
   速さの勾配 0。運動量 × 端の面の両側の質量 ÷ 内側の面の両側の質量)、力を足して流し、刻みの終わりの値は捨てる。写した分 = 帳簿の「世界の端」の入、
   捨てた分 = 出(運動量の列)。出た液体の物質・エネルギー・位置のエネルギーも「世界の端」の出。外の柱が無い(真空)の開いた端は閉じた面(伝導と同じ)。
5. **静止の丸め**: 当てる段の後(SettleEnergy の速さの上限の直後。上限・当てる・運ぶの後)。形は rest_rounding.hlsli の RrRestMomentum
   (仮の世界の液体の面も同じ関数に替えた。閾値 = 速さ × 刻みの数 × 両側の質量 ÷ 重力)。帳簿は運動量の列を「静止の丸め」、消えた運動のエネルギー → 熱も
   「静止の丸め」(運動のエネルギーの列の出・エネルギーの列の入)。残りの熱は「物理の熱」。既定 0 = 切る(前とビット単位で同じ)。
   気体を当てる段に載せる T-0765 も、置き場(当てる段の後)と帳簿の理由を同じに(気体のセルは 3 軸の最大で RrShouldRest。結果の形 RrRested を使える)。

## 代案(④ の開いた端)
- (a) 端の面を毎刻み 0 から: 置き場が要らず最も簡単。測った: 下が開いた世界で落ちる水が 3 秒で 19% しか出ない(底の段で溜まって滴る)。横の端も遅い。採らない。
- (b) − 側の端の面に欄を足して持ち越す: 慣性はそのまま正しいが、セルあたり i64 × 6(運動量と運動のエネルギー)の欄の頁が液体の全部の頁に増える(今の 8 から 14)。
  端に接するセルだけに要る値のために全体を増やす。採らない(作り手から見て違いが出たら見直す)。
- (c) 世界の箱の外に 1 層の影のブロックを置き、外の柱で毎刻み上書き: 面の欄が自然に持てるが、端の面ごとに 8³ のブロック。採らない。

## 確かめたこと(2026-10-18)
- multires_liquid(release): 前の場面(池 16³ 1800 + 1800・ダムと水の半分/2 倍・液体の無い 64³・池 64³)が仮の世界と毎刻みビット一致・ComputeConservedTotals が一定。
- 静止の丸め 1 mm/s の池(16³ 600 + 600 刻み): 仮の世界と毎刻みビット一致(報告の rested・restedFaces も)・丸めた面 のべ 864。
- 開いた端: 横と上が開いた池(24 × 16 × 8・240 刻み)で水の 47% が端から出る・下が開いた世界で落ちる水(180 刻み)はほぼ全部出る(残り 10^5 µmol / 1.8 × 10^12)。
  どちらも毎刻み Σ 保存量 − 帳簿が変わらず、出た水 = 帳簿の「世界の端」の水の列。
- 費用(池 16³・1 刻み): 仮の世界 5.6 ms・MR 7.0 ms(6 面の回し方で包みを 2 回作る分を含む。前の MR は未計測の版との比べなし)。

## 影響
- 作り手: 環境の world_edges の open が MR の液体にも効く(池の堤を消すと開いた横の端から出る = 設計 20 例 3)。真空の open では液体は出ない(閉じた面)。
- MR の液体の報告 MultiresLiquidStepReport に edge(端の面の運動量の出入り)・edgeMilligrams(外へ出た質量)を足した(仮の世界の報告から派生)。
- 当てる段に TxFaceFieldIsOwn・TxApplyPacketSide・World::AddEdgePacket を足した(TxApplyPacket は残す)。

- **2026-10-26 本体の棚卸し(QUESTIONS Q124)**: 開いた端の液体の面の運動量 → もう要らない(案 B。D-550)。

- **2026-10-26 本体の棚卸し(QUESTIONS Q125)**: 大気の無い世界で端を open にした時の液体 → 閉じた(閉じた面として扱う。D-539)。
