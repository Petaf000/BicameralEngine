# ADR-0032 反応表の Luau での書き方(整数・単位は欄の名前)と、ベイクの並び(名前のバイト順で ID を振る)

- Status: Accepted(実装の細部。CLAUDE.md §5 で Claude が決める範囲)
- 日付: 2026-10-09
- 決めた人: Claude(T-0021)。反応表の中身(物質・反応・魔素)はユーザーが決める

## 背景
- 02 §1〜2・13 §2: 反応表は Luau のパッケージで書き、CPU のベイクで GPU 用の整数の表にする(原則 2・3、04 R7)。
- パッケージは「分類 → 鍵 → 値」で合わせ、鍵はバイト順に並ぶ(ADR-0031)。Luau の表には書いた順番が残らない。
  今までのベイク(T-0014)は定義の配列の順番で物質・規則の ID を振っていたので、同じ中身でも並びが違えば違う表になった。
- Luau の数は倍精度。シミュは整数だけ(ADR-0008)なので、どこで・どう整数に直すかを決める必要がある。

## 決定
1. **ベイクは名前のバイト順に並べ直してから ID を振る**: 元素・物質・規則、規則の反応物と生成物の項。
   定義の並び(C++ の配列・Luau の表・Mod を入れた順)が違っても、中身が同じなら同じバイト列の表になる。
   A(頻度因子)は仮数の末尾の 0 を指数へ移してから使う(28e18 と 280e17 が同じ表)。
   - これで T-0014 の試験の表の物質と規則の ID が変わった(セルロース 1 → 4 など)。結果は物質・規則の ID に依らない作り
     (乱数の鍵は規則の名前、取り合いの戻しの同点は名前のハッシュ、成分は ID の昇順)なので、テストは名前で引いている。
2. **Luau の書き方**(engine/src/script/reaction_package.h): 分類 `elements`・`species`・`reactions`。1 つの鍵 = 1 つの元素・物質・規則
   (Mod は鍵を足して増やす)。値は**整数だけ**で、単位は欄の名前に書く(`heat_capacity_mj_per_mol_k` など)。
   小数・±2^53 の外は誤り(倍精度の丸めで機械ごとに値が変わる余地を作らない)。A だけは 10 進の文字列("2.8e19")でも書け、誤差なしで読む。
   知らない欄は誤り(綴りの誤りを黙って通さない)。ほかの分類(UI の文字列など)は読まない。
3. **読む所と検査する所を分ける**: Luau の値 → 定義(script/reaction_package。形の誤り: 欄・型・整数・範囲)→ ベイク(sim/reaction_table。
   中身の誤り: 元素の釣り合い・知らない元素と物質・係数・次数・名前の重なり・速度の範囲)。C++ に手で書いた表も同じベイクを通る。
4. **エネルギーの検査**: 反応熱は生成エンタルピーの差から自動で決める(今まで通り。エネルギーは構造的に保存)。
   規則に文献の反応熱(`reaction_enthalpy_j_per_mol`)を書いたら、生成エンタルピーの差と比べ、1 kJ/mol より違えば**警告**
   (`BakedReactionTable::warnings`。ベイクは通し、表は生成エンタルピーの差を使う)。02 §2 の 2 のとおり。

## 検討した代案と、採らなかった理由
- 定義の並びのまま ID を振り、Luau 側に順番の欄(`order = 3`)を書かせる: 書く人が番号を管理することになり、Mod どうしで番号がぶつかる。
- パッケージの読み込み順 → 名前の順で ID を振る(本体の ID が Mod で動かない): 本体の中の順番は結局名前の順になり、
  「同じ中身なら同じ表」も崩れる(同じ物質を本体に書くか Mod に書くかで表が変わる)。ID はベイクの内側だけのもので、
  セーブ・再生は表の版(ADR-0031)と名前で結びつくので、ID が Mod で動いても困らない。
- 小数を許して、ベイクで丸める(`heat_capacity = 29.378`): 書きやすいが、10 進 → 倍精度 → 整数の丸めが Luau のパーサと C++ の両方に乗る。
  整数の単位(mJ・mW)にすれば 10 進の小数の桁は単位で吸収できる。要るなら後で「10 進の文字列」を A 以外にも広げる。
- 文献の反応熱の食い違いを誤りにする: 文献の値は丸められていて、生成エンタルピーと 0.1〜1 kJ/mol ずれるのが普通。
  表はどちらにしても生成エンタルピーの差を使うので、エネルギーの保存は壊れない。気付かせるだけでよい。

## 影響(何がしやすく/しにくくなるか)
- しやすい: C++ の表・Luau の表・Mod を足した表を、バイト列で比べられる(reaction_package_test)。並びを変えても表の版が変わらない。
- しにくい: 物質の ID を手で決められない(GPU の固定の物質を ID で決め打ちするコードは書けない。名前から引く)。
- 残り: 湧き出し・吸い込み(02 §2 の 3、魔法の保存則の例外)は T-0024 で。ランタイムがパッケージから表を読むのは T-0157。
