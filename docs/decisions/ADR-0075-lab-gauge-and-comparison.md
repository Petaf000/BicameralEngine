# ADR-0075 実験室の計器は読み戻した GPU の箱から取り、2 つの実験は記録の切り口から同じ箱で順に流して比べる

- Status: Accepted(実装の細部。ユーザー未確認の点はチケット T-0221 の「判断待ち」)
- 日付: 2026-10-10
- 決めた人: Claude(CLAUDE.md §5。T-0221・D-449)

## 背景
- D-449 で、中身(反応表など)を触って決めるために「計器と比べる画面」を足すことにした: セルの中身・温度・反応の速さを時間のグラフで見る・
  保存点から条件を 1 つ変えた 2 つの実験を並べて比べる。
- 実験室の箱(ADR-0037)は 8³ セルで、刻みごとに GPU の箱を読み戻して CPU リファレンスと比べている。記録(コマンドの列 + ハッシュ)から決定的に流し直せる。
- 普通の世界の保存点(ADR-0036)は VRAM の写しで、実験室の箱には無い。GPU の箱(GpuMultires)の作成は debug で数十秒〜数分かかる。

## 決定
- **計器の値は、刻みごとに読み戻した GPU の箱から取る**(sim/lab_gauge の SampleLabGauge。LabSession::StepOne の読み戻しの後)。世界にも箱にも何も返さない
  (ADR-0035 の「見るだけ」)。sim では整数のまま持ち、浮動小数点に直すのはパネル(editor/gauge_panel)の描く時だけ。
  反応の速さは「物質量の刻みごとの差」(µmol/刻み。表示は mol/s)。規則ごとの進み具合は箱の状態に残らないので、今は取らない。
- **実験室の保存点 = 実験の記録を刻み t で切ったもの**(CutLabRecording)。そこへ戻るのは初めの箱から記録を流し直すこと(Replay。保存点までのハッシュを
  元の実験と突き合わせる)。VRAM の写しは作らない(箱が小さく、流し直しで足りる。記録と再生の道をそのまま使える)。
- **2 つの実験は同じ箱で順に流す**: A = 元の実験の続き、B = A に条件を 1 つ(コマンド 1 つ。保存点の刻みに、元の操作の後に当たる番号で)足したもの。
  「並べる」は同じ刻みの値を重ねて描くこと。2 つ目の GPU の箱は作らない。比べた後の箱は B の状態(「元の実験に戻す」で比べる前の記録を流し直す)。

## 検討した代案と、採らなかった理由
- **箱を 2 つ作って同時に刻む**: 見た目は「並べて走らせる」に近いが、GpuMultires の作成が 2 回(debug で数分)・VRAM も 2 倍。
  順に流しても値は同じ(決定性)なので、得るものが無い。大きい箱(T-0173)で流し直しが重くなったら、その時に考え直す。
- **実験室にも VRAM の保存点(ADR-0036 と同じ写し)を作る**: 流し直しが要らず速いが、写す・戻すの道を箱にもう 1 つ作ることになり、
  今の大きさ(512 セル)では流し直しで足りる。
- **計器の値を CPU リファレンスの箱から取る**: 同じ値になる(毎刻みビット一致を確かめている)が、D-449 の「GPU で実際に動かしながら見る」に合わせ、
  描くのは GPU の値にし、CPU の値と一致することを自動の確認(--auto-lab-compare)で見る。

## 影響(何がしやすく/しにくくなるか)
- しやすい: 同じ置き方で「1 つだけ変えたら何が起きるか」を、同じ刻みで重ねて見られる。比べた A・B の記録はそのまま保存・再生できる。
- しにくい: 保存点が後ろの刻みほど、比べるたびに流し直す時間が増える(数千刻みで数秒〜。流している間はフレームが止まる)。
  大きい箱(T-0173)の時に、VRAM の保存点か裏のキューで流すかを決め直す。
