# ADR-0390 刻みの長さを場所ごとに「状態が変わる速さ」で選ぶ・時間を飛ばす = 世界全体の早送り

- Status: Accepted(2026-10-21。形はユーザーの決定 claude/36 S50。長い刻みで正しく進むかは研究 R-T2 で確かめる。合格の線は一旦)
- 日付: 2026-10-21
- 決めた人: ユーザー(claude/36 S50。Claude が案を出した)。§「エンジンの形(仮)」は Claude の案(ユーザー未確認)
- 関係: D-600・D-601(claude/29 Q6)・claude/29 Q10(この ADR で上書き)・claude/30 W11・N1(粗さは局所の状態だけで選ぶ)・D-208・D-428・D-444・D-468・D-470・
  ADR-0018(遅い反応の待ち)・ADR-0198(写しの早送り)・設計 06 §1・20 §2.5・§3

## 背景
- claude/29 Q10 は「流れが眠っている時だけ反応と熱を長い刻みで進める」だった。claude/30 W11 で壁が出た:
  熱い物・くすぶり・発酵・川・天候がある間は流れが眠らないので、飛ばしたい場面(寝る・発酵を待つ・焼け跡の回復)のほとんどで使えない。
  さらに、長い刻みで反応と熱を進めると積分の誤差で「寝て待ったパン」と「起きて待ったパン」が違う(時間の細かさが隠れた変数になる)。一部だけ飛ばすと世界の中で時刻がずれ、境で保存と順が崩れる。
- ユーザーの望み: 普通のゲームと同じ感じで時間を飛ばせること(起きるのに 10 分は嫌)。

## 決定
1. **刻みの長さを、場所ごとに「状態が変わる速さ」で選ぶ**(流れの速さではない)。一定に流れる川・天候の風は、動いていても状態が変わらないので長い刻みで進む。
   短い刻みが要るのは一時の速い出来事(燃えている火・崩れ・洪水の波)だけ。ゆっくり変わる所(発酵・冷める・くすぶり)は、ふだんの遊びでもいつも長い刻みで進む(ふだんも安くなる)。
2. **規則は起きている時も寝ている時も同じ**(N1 の芯「粗さは局所の状態だけで選ぶ」を時間にも)。選ぶのに使うのは局所の状態だけで、
   プレイヤーの位置・見ているか・寝ているか・予算・GPU の速さは入らない(D-208)。
3. **時間を飛ばす = 世界全体の早送り**。世界の時計を速く進めるだけで、刻みの規則は変えない。だから**結果は待ったのとビット単位で同じ**(作りで成り立つ。研究は要らない)。
   局所だけ早送りする道具はゲームに置かない(世界の中で時刻がずれ、一つの宇宙と食い違う)。局所の早送りはエディタの世界の写しの早送り(D-470・ADR-0198)だけ(D-601・claude/29 Q6)。
4. **待つ現実の時間が場面で変わってよい**(ユーザー)。D-468(負荷で遅れない)は世界の中の時間の話で、早送りに掛かる現実の時間はそれに当たらない。
   **合格の線(一旦)**: 静かな夜は 5 秒以内・火事の最中も 30 秒以内。超えた場面は測ってから相談する。測る機械は最低機(Q11 未定。決まるまでは開発機で測り「未確認」と書く)。
5. **研究 R-T2**(試作の列 6。C-1 の後): 下の表。claude/29 Q10 を上書きする。

| | 中身 |
|---|---|
| 確かめること | 一定に流れる所・ゆっくりな反応を長い刻みで進めても、運ばれる熱・溶けた物・反応の進みが短い刻みと**計器の精度内で同じ**か。刻みの長さの選び方が**細かさ(0.5 m と 2 m)によらない**か |
| 合格 | 上の 2 つ + 合格の線(静かな夜 5 秒・火事 30 秒)の内 + 寝て待つ = 起きて待つがビット一致 + 保存が厳密(帳簿が合う) + CPU リファレンスとビット一致 |
| 打ち切り | 2 本(下の形の選び方を変えて)試してだめなら退く |
| 退く道 | **川だけ長い刻みで一気に飛ばす**。その時、川の所だけ「寝ても待っても**精度の内で**同じ」に弱まる(ビット一致ではなくなる)。退いたら司令塔とユーザーに報告する |

- **2026-10-22 注**: T-1013(退く道の 1 本目: 精度は完全だが、池が変わり続けて速くならない)・T-1014(火事の前線の 5.7 mK は前線の緩衝で 0.000 mK)の後、(B) 本筋 + 前線の緩衝 + 予算 1/16 mK へ戻した(司令塔の一旦の決定。退く道は記録として残す)。残る細かさの線は Q154。ADR-0423・ADR-0437 は wt4 のブランチ(t-1013-rt2-jump)。

## エンジンの形(仮。ユーザー未確認。R-T2 で決める)
- 世界の時計は今のまま(1 刻み = 1/60 秒・刻みの番号 uint64。06 §1)。ブロックごとに「刻みの長さ = 2^e 刻み」を持つ。
  e < 0 は今の細分(1/2^k。速い現象)、e > 0 が長い刻み。**細分と長い刻みを一つの規則にする**(短い方にも長い方にも同じ選び方)。
- 長い刻みのブロックは 2^e 刻みごとにまとめて 1 回進む。境の面の流れは、短い側の刻みで面の帳簿に溜め、長い側が自分の刻みで受け取る
  (20 §3 のレベルの小刻みの受け直し〔Berger–Colella〕の時間の向きの版。土台の 1 つの実装に入れる)。保存は面の帳簿で厳密。
- 選び方は真実だけで決まる値(例: 前の自分の刻みでの真実の変化の量 ÷ 計器の精度)から、決まった整数の段で引く。e を変えるのは自分の刻みの境目だけ。
  隣どうしの e の差は 1 段まで(多重解像度の隣の差の決まりと同じ考え)。具体の式は R-T2 で決める(未確認)。
- 遅い反応の待ち(ADR-0018。変化が離散で稀な場合に「次に変わる刻み」を閉じた形で求める)は、この規則の「長さが無限に近い」端としてそのまま残る。
- 早送りは SimScheduler の「始めてよい刻みの数」を増やすだけ(ADR-0035 の速さの操作と同じ道。世界のコマンドには入れない)。上限は予算ではなく、刻みを投げ切れる速さで決まる。

## 検討した代案と、採らなかった理由
- (a) 同じ刻みのまま全体を早送り: 正しいが、川・風を細かく回し続けるので場面によって 10 分かかる(ユーザーが嫌った)。
- (c) 長い刻みで一気に飛ばす: 一番速いが、飛ばした結果と待った結果が精度の内でしか同じにならず、「火が川を越えるか」のような 2 択が寝たかどうかで変わりうる。研究と相性が悪い(退く道として川だけに残す)。
- claude/29 Q10 の「眠っている時だけ長い刻み」: 眠る場面がほぼ無い(claude/30 W11)。
- 時間を飛ばさないゲーム: ユーザーの望みに合わない。

## 影響(何がしやすく/しにくくなるか)
- しやすく: 寝る・発酵を待つ・焼け跡の回復(#88)が普通のゲームのように飛ばせて、結果は待ったのと同じ。ゆっくりな所はふだんの遊びでも安い。作り手は刻みの長さを書かない(法則の値と状態から決まる)。
- しにくく: 境の受け渡し(長い刻みと短い刻みの面の帳簿)を、全部の流れの家族と反応で作る必要がある(20 の土台の 1 つの実装に入れる)。
- D-444 ②(覗いていない所の細かい風・水は鈍くてよい)は見る人で規則が変わる形なので、この ADR と N1 に合わせて見直す(本体へ。T-0890)。
- 未確認: 長い刻みで反応と熱を進める積分の形(1 次の減り方を閉じた形で解く等。整数で)・早送りの速さ(何倍出るか)・合格の線を最低機で満たすか。
