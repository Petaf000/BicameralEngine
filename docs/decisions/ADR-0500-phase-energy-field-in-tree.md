## 背景(3 件は 1 つの根)
司令塔が預かっていた土台の 3 件は、どれも「**今の登録(C-1)は、欄の値を誰がいつ書くかを 1 通り(一般の段が規則で写す・続く状態)しか知らない**」ことから出ている。

| 件 | 今の登録で困ること |
|---|---|
| ADR-0500 初版(Ec) | 細かく/粗くする時の値はセルの中身(熱容量・相)を読む「セルの配り」でしか決まらない。SAME・VOLUME・内訳のどれにも合わない(初版の「背景」)。粗くする時のセルの配りの口も無い |
| T-1227(放射の持ち越し) | 持ち越しは (セル・入った面 6・帯 2) = 12 値。細かく/粗くする時は「その面の側の子だけ」に配る(面の向きを知る配り)。SAME・VOLUME のどちらでも光が向きの違う子の面へ行く。光線は歩く途中で散らばって足すので、疎な頁へ直に足すと「頁の無い所」の規則が要る(T-1117 の (3))。偶奇の 2 枚も要るように見えた |
| T-1228(変わったブロックの印・4-1 源の項) | 吸った分(源の項)は刻みの中だけの値で、続く状態ではない(今の登録に「刻みの中だけ」が無い)。印は当てる段が書くと決めた(ADR-0469 4-4 (a))が、読み手が結果に効くのか費用だけかの約束が無い |

T-1117 の 1 本目(wt6 t-1117-rc-multires-tree 8312073b)で、RC が木の葉から 0.5 m の密な作業の升目を作る所までは GPU でできた。木の上で閉じるには、
(1) 升目の受けを葉の源の項として当てる口(粗い葉は 2^−L 角の和)・受けのあった葉も変わった印に、(2) 持ち越しの鍵 (升目のセル・面・帯) → (葉の頁・セル・面・帯)、
(3) 疎な頁へ足す時に頁が無い所の規則、が要る(docs/tickets/T-1117「土台に足りないもの」)。どれも上の根と同じ。

## 決定(一旦。案 A)
登録の 1 行に「**配り手**」と「**寿命**」の 2 つを足し、「**散らばった書き手は欄へ直に足さない**」約束を 1 つ置く。当てる段は源の項と変わった印の 1 か所になる。

### 1. 配り手: 一般 / 持ち主(SF_SCALE_OWNER)
- 細かく/粗くする時の規則に `SF_SCALE_OWNER` を足す(SAME・VOLUME の隣)。登録の 1 行に**配り手の番号**(エンジンの決まった関数の表の番号。GPU は決まった数の回しで選ぶ = T-0397)を持つ。
- 一般の段(nest_fields::Refine / Coarsen と GPU の木の段)は持ち主の欄を**写さない・平均しない**(子と親の値は 0 で渡す)。値は木の操作の中の「**セルの配り**」の口が書く。
  セルの配りの口は今の細かくする口(MultiresNest::refineCells・PlaceRefineOctantCells・GPU の RefineLevel の置かれ方の段 = ADR-0499)に、**粗くする口**(CPU の Coarsen の後・GPU の木の粗くする段)を足して 2 つにする。
  順は「セルの中身の配り → 持ち主の欄の配り」(持ち主の配りはセルの中身の後の値を読む)。印で決まるので、一般の段との上書きの順に頼らない(初版の (a))。
- 畳む・広げる・眠る・保存点・ハッシュ・写しの早送りは**一般の段のまま**(どれもビット単位で値を変えない操作なので、持ち主の知識が要らない)。
- 保存量: 「保存量 ⇔ VOLUME」(SfDescValid)を「保存量 ⇒ VOLUME か持ち主」「VOLUME ⇒ 保存量」に直す。持ち主の配りは和をビット単位で保つ約束で、検査は今の ComputeConservedTotals の 1 つ(持ち主の欄の列も数える)。
- 最初の配り手 2 つ:
  - **相の層の配り(Ec)**: 初版の決定 2 のまま(細かく = 層の熱を子の凝縮相の熱容量の重み・気体の熱を子の気体の熱容量の重み〔D-674 を 2 回〕/ 粗く = Σ 子の凝縮相のエネルギー ÷ 8 の切り捨て → PlRemixCondensedEnergy)。Ec は保存量でない(セルのエネルギーの内)。
  - **光の配り(持ち越し)**: 細かく = 親のセルの面 f の値を、面 f の側の子 4 つへ同じ重みで(SfPlacedValue・最後の子が残り)・反対側の子 4 つは 0 / 粗く = 面 f の側の子 4 つの和(割らない・端数なし。量は絶対の 2^−16 mJ)。保存量(列 = 光の持ち越し)。
- 観察の影(D-403): 影を細かくする時も同じ配り手の細かくする関数を呼ぶ。影の引き戻しは配り手の粗くする関数(一旦。T-1252 で ADR-0361 の引き戻しと揃うか確かめる)。

### 2. 寿命: 続く / この刻みだけ(SF_FLAG_TICK_ONLY)
- **続く**(今の欄の全部): 状態。ハッシュ・保存点は今の印のまま。
- **この刻みだけ**: 刻みの中で書いて同じ刻みに読む値(**源の項**)。ハッシュ・保存点に入らない。刻みの境目では全部 0(開発ビルドで検査)・頁は使い終わったら返す。真実でも導かれる値でもない種類(SF_KIND_TICK)。細かく/粗くする・畳む・眠るは刻みの境目にしか起きないので、0 の値を扱うだけ。
- **偶奇の 2 枚は登録に足さない**: 持ち越しは「刻みの初めに読んで 0 にする(CarryIn)→ 刻みの終わりに書く(下の 3 の集めて書く段)」の 1 枚で足りる。
  2 枚が要ったのは、光線が歩く途中で次の刻みの表へ足すのと、この刻みの表を読むのが同じ段で重なったから。歩く途中の足し込みは書き手の作業(3)の中なので、登録の欄は 1 枚。
  刻みの境目で状態にあるのは次の刻みに読む持ち越しだけ = 今の「片方の表だけが生きている」と同じ値がハッシュとセーブに入る(D-619)。

### 3. 散らばった書き手は欄へ直に足さない: 書き手の作業 → 集めて書く段(T-1117 の (3) の答え)
- 光線のように順の決まらない書き手は、**自分の作業(刻みの中だけ・密な升目)**へ 64bit の atomic で足し、触ったブロックに印(冪等の OR)を付ける。順によらない(整数の和。R3・R4。今と同じ)。
- 共通の**集めて書く段**(1 つの関数。CPU と GPU の 1 つの源)が、印のブロックだけを枠の順に回り、
  (a) 欄の頁が無ければ**枠の順のプレフィックス和で頁を取る**(T-0930 で決めた GPU の疎な頁の取り方と同じ。CPU と GPU で頁の番号まで同じ)、
  (b) 一様な枠なら「頁が要る」の印を付け、木の決まった段(ExpandWantedPages と同じ枠の順)で頁に広げてから書く(広げるのはビット単位で値を変えない)、
  (c) 升目の値を葉のセルへ移す(粗い葉は 2^L 角の和。足し算の順によらない)。
- **頁の空きが尽きた時**: 頁の数は世界の作りで前もって決める予算(D-468)。尽きたら計器の誤り(開発ビルドは止める)で、D-202 の安全網(世界全体を一様にゆっくり)に回す。量はどこにも捨てない(保存の検査はそのまま)。
  黙って足し込みを落とす・順で勝ち負けの決まる取り合いにする形はとらない。
- 退けたもの: GPU が足す時にその場で頁を取る(取り合いの順で頁の番号と、尽きた時にどの足し込みが落ちるかが決まる = 決定性が崩れる)・溢れの帳(満ちた時のやり直しが、同じ欄へ足すほかの書き手の分と分けられない)。

### 4. 当てる段: 源の項と変わった印の 1 か所(ADR-0469 の 4-1・4-4)
- **源の項**: まっすぐ運ぶ家族(RC・太陽の影の柱・空との交換の口)の吸った − 放ったは「この刻みだけ」の登録の欄(セル・エネルギー 2^−16 mJ)へ集めて書き、当てる段が 1 回の掃きでセルのエネルギーへ足す
  (mJ への丸めの規則と端数の行き先は当てる段の 1 か所。今の RadiationApply の「最も近い mJ」をそこへ移す)。上限・起こす・計器(放射の吸い込みも計器の表に並ぶ)も当てる段の 1 か所。
  受けのあった葉は当てる段が変わった印を付けるので、眠った粗い葉も起きる(T-1117 の (1))。
- **変わったブロックの印 = 今の MrBlock::busyTick(この刻みの印)**。新しい語は足さない。セルの真実を書く全部の道は同じ 1 つの関数で印を書く
  (当てる段・反応の核の書き戻し・木の操作のつつき。今は刻みの段ごとに書いている。仮の世界は PROBE_SCHEDULE_CHANGED_WORD が同じ役)。
- **読み手の約束**: 
  - 結果に効く読み手(起こす・待ちの丸め・R-T2 の刻みの長さ): 今の busyTick のまま(状態・ハッシュに入る)。この ADR で変えない。
  - **費用だけに効く読み手**(放射の写し RadiationGrid・放つセルの一覧 RcSources・光の掃き直し T-1147 案 3・物の囲むセルの変わった検出 OhNestGather): 「最後に読んだ刻み」と比べて、それより後に変わったブロックだけを読み直す。
    多めに拾ってよい(つつかれたブロックも変わったと読む)が、落とさない。読み込んだ直後・眠りから起きた直後は全部を変わったと読む。
    **確かめ**: 印を全部「変わった」にした時と、印で飛ばした時で、刻みごとのハッシュがビット一致(T-1161 の gpu_radiation_cost と同じ形)。
- 前の刻みの値の写し(光の値・温度)は家族の持ち物(ADR-0469 の 4-4 のまま)。

## 確かめ(エンジンの約束)
- **決定性**: 書き手の作業は整数の atomic の和(順によらない)。集めて書く段は枠の順(頁の番号も決まる)。配り手は整数の関数で CPU と GPU の 1 つの源(state_field.hlsli と家族の hlsli)。費用だけの読み手は「全部変わった」とのハッシュ一致で確かめる。
- **保存則**: 持ち主の配りは和をビット単位で保つ(光の配りは割らない和・Ec は保存量でない〔セルのエネルギーの和は今の列〕)。源の項の丸めの端数は当てる段の 1 か所で帳簿か持ち越しへ(T-1228 で決める。今の行き先を変えない)。頁が尽きても量を捨てない。
- **細かさによらない一貫性(D-465)**: Ec は子の部分の温度が親の部分の温度になる配り(D-674)。持ち越しは面の側の子へ同じ重み(粗い葉の面の光は細かい面へ同じ密度で)。粗い葉の源の項は升目の和(T-1117 の段取り 3 の確かめ = R-R0 の 0.04 % と同じ形で測る)。
- **CPU とビット一致**: 配り手・集めて書く段・当てる段は共通の hlsli。頁の番号まで同じなので頁の像で比べられる(T-0930 の「密の並びの要約で比べる」より強い)。
- **ブランクの世界(D-455)・今の世界**: 新しい印を使う欄が無い世界は、どの段も今とビット単位で同じ(持ち主の欄・この刻みだけの欄・集めて書く段は使い手が登録した時だけ動く)。

## 作り手から見た違い
- 無い。Ec・持ち越し・源の項・変わった印はエンジンの中の値で、パッケージや Luau の作り手は書かない・読まない(家族はエンジンの作り。20 §1.5)。
- 見えるのは計器の表に放射の吸い込みが並ぶこと(ADR-0469 4-1 のまま)と、頁の予算を超えた時の誤りの名前だけ(D-468・D-202 のまま)。
- セーブ: Ec 8 B/混ざったセル(初版のまま)・持ち越しは光の当たる頁だけ 48 KiB/頁(今の密な表 2 枚 = 64³ で 2 × 24 MiB の代わり。どれだけ減るかは未確認)。D-619(入れる)のまま。
- → **問いにしない**(D-539)。Q178 は使っていない。

## 実装の割り振り(ROADMAP「土台の変更要求の束」)
1. **T-1252 段 1**(工学・土台・CPU): 登録に SF_SCALE_OWNER + 配り手の番号・SF_FLAG_TICK_ONLY(SF_KIND_TICK)・SF_MAX_COMPONENTS 12・SfDescValid の保存量の規則・一般の段(nest_fields)が持ち主の欄を写さない・
