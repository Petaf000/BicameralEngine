# ADR-0246 表の差し替えを編集として扱う(保存点が表を持つ・差し替えの印を足し直す。T-0548)

- Status: Accepted(形は D-491。「仮」はユーザー未確認。T-0548 の判断待ち 1・2)
- 日付: 2026-10-15
- 決めた人: ユーザー(Claude が提案した場合も、決めるのはユーザー)

## 背景
- ADR-0047 §6・T-0299: 保存点は世界だけを写し表を持たないので、表を差し替えたら保存点を全部捨て、差し替えより前へは戻さなかった。
  そのため編集の状態で表を差し替えると、その後の元に戻す・やり直す・プレイをやめるで戻れなかった(T-0509 の判断待ち ②・Q64 ④⑤)。
- ADR-0236: 編集の状態で置いたものは刻み E の適用の単位で当て、置き直すたびに S(E) の保存点へ戻して当て直す。

## 決定
1. **保存点はその境界の表も持つ**(ProbeSim の SavePoint。差し替えの後の最初の保存だけ表を写す)。戻すとき、その表が今の表と違えば
   表のバッファを結び直す(セルと熱のキャッシュは保存点がその表で作ったものなので、付け替えも作り直しも要らない)。差し替えで保存点を捨てない。
2. **差し替えの印は他のコマンドと同じく足し直す**: 生の操作では印も今の流れの控え(m_commandHistory)に入れ、戻すと足し直す。
   TableHotReload は戻した刻み以降の予定と当てた記録を忘れ(NoteRewound)、足し直す印(控えか再生ファイル)を知っている表から探して積む。
   足し直す印のコマンドはもう新しい表の ID なので、物質の付け替えは新しく作った印だけ。
3. **編集の状態の差し替えは編集の境界 E の印**(frame_loop の ApplyEditTable・SetBoundaryTable・editor/edit_table): 待っている表を受け取り、
   E の印を外し、E 以降と待っているコマンドの物質の ID を付け替え、S(E) の表と違えば新しい印を E に足す。E の適用の後なら S(E) へ戻して当て直す
   (置き直しと同じ道)。E の印は 1 つ。ファイル・反応表のパネル・環境ミキサーはどれもこの道(どれも TableHotReload の待ちの表を作る)。
   S(E) へ戻せない(保存点が無い)時は ADR-0236 §6 と同じく、プレイを押した最初の刻みで当たる。
4. **プレイをやめると、プレイ前の世界 + ファイルの今の中身の表**(仮。T-0548 判断待ち 1): プレイ中の印はプレイ中のコマンドと一緒に捨て、
   E(= P)の表をファイルの今の表にする(3 と同じ SetBoundaryTable)。
5. **Ctrl+Z / Ctrl+Y は世界の編集だけ**(仮。判断待ち 2)。表を戻すのはパネルの「元に戻す」かファイル。
6. 1 つの刻みに差し替えは 1 つ(GPU の約束のまま)。新しい差し替えが足し直す印と同じ刻みに重なれば次の刻みへ。

## 理由
- 根っこは「保存点が表を知らない」ことで、そのために「差し替えたら戻れない」という例外が巻き戻し・元に戻す・やめる・--auto-rewind に散っていた。
  保存点に表を持たせ、印を普通のコマンドとして足し直せば、差し替えは置く・消すと同じ「刻みの始めに当たる編集」になり、例外が消える
  (PlanBrushUndo の差し替えの刻みの引数も消えた)。GPU のシェーダーは変えていない。
- 保存点ごとの表の写しは CPU 側の数十 KB(差し替えた後の最初の保存だけ)。GPU は戻す時に表のバッファ 4 つを写すだけ。

## 影響
- ADR-0047 §6(差し替えたら保存点を捨てる)・T-0299 の「差し替えより前へは戻さない」を置き換えた。ADR-0236 の影響の最後の段落(Q64 ⑤)を解いた。
- window_hot_reload_game の --auto-rewind は、差し替えより前の刻み 0 の保存点へ戻る形になった(表も戻り、印でまた差し替わる)。
- 試験: edit_table(CPU)・window_play_table_record/play(--auto-play-table。手順は frame/auto_play.h)。

- **2026-10-26 本体の棚卸し(QUESTIONS Q76)**: 表の差し替えを編集として扱った時の仮 2 つ → 閉じた(ファイルが正本・Ctrl+Z は世界の編集だけ。D-539)。
