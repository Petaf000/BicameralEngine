# ADR-0392 法則の版はいつも最新・法則の差分を見せる・法則の行の「ここで起きた」出来事の口

- Status: Accepted(2026-10-21。版の扱いはユーザーの決定 claude/36 S51。出来事の口は一旦の決定 S52 (2)。§「エンジンの形(仮)」は Claude の案でユーザー未確認)
- 日付: 2026-10-21
- 決めた人: ユーザー(claude/36 S51・S52。Claude が案を出した)
- 関係: D-605・D-606・D-422(設計は他のプレイヤーの店に並ぶ)・D-470(何でも測れる・記録できる)・D-586・ADR-0031(TableVersion)・ADR-0050(再生ファイルの表の中身)・
  ADR-0206(遊びの指標)・claude/30(版が変わったら期待の幅を取り直す)・設計 13・14・15 §1・§2・06 §3

## 背景
- 発売後に法則(値や形)を直した時、古いセーブと店に並んだ他の人の設計を、どちらの法則で動かすかを決める必要があった。
- 過去の版をビット一致で持ち続けるには、値だけでなく解き方のコードの過去の版も持ち、試験も版の数だけ要る(とても重い)。
- ノートの中身はゲームの中身(S53)。何を「見た」と数えるかに依らない口が要る。

## 決定
1. **いつも最新の法則で動かす**。過去の版は持たない。
2. **セーブ・設計(D-422)・記録に法則の版を書く**。読み込んだ時に版が違えば「法則が変わった」と出し、**変わった行を見せる**(エンジンは法則の差分を出す)。
3. **開発中の記録・再生・試験は、版が変わったら期待の幅を自動で取り直す**(claude/30)。
4. **法則の行ごとに「ここで起きた」という出来事を出す口**(S52 (2)): 反応の規則・流れの家族などの法則の行が、どこで(場所)・いつ(刻み)・どれだけ働いたかを出来事として出す。
   何を「見た」と数えるか(視界・距離・計器)はゲームが決める。何でも測れて記録できる約束(D-470)の延長。

## エンジンの形(仮。ユーザー未確認)
- 法則の版 = 今の表の版(TableVersion。合わせた表の中身のハッシュ)+ エンジンの解き方の版(コードの版。整数 1 つ)。どちらが変わっても「法則が変わった」。
- 法則の差分: 再生ファイルとセーブは表の中身を持つ(ADR-0050)ので、読み込んだ時に今の表と行ごとに比べられる(分類・鍵・値の差)。
  解き方の版だけが変わった時は、変わった行の代わりに「解き方の変更の記録」(リリースの注記。人が書く)を見せる(仮)。
- 期待の幅の取り直し: 再生・試験の突き合わせで版が違えば、ハッシュの一致を求めずに「新しい版で再生した結果」を新しい期待として書き直す道(コマンドラインの選択肢)。
  遊びの指標(ADR-0206)は今も「前に測った版との差」を出すので、同じ形。
- 出来事の口: 刻みの終わりのイベントのリング(06 §3。キー = 刻み・種類・場所で並べる。世界の結果に入らない)に「法則の行の出来事」の種類を足す。
  中身 = 法則の行の鍵・場所(ブロックかセル)・働いた量の目安。全部の行を毎刻み出すと多いので、**出す行と間引き方はゲームが登録する**(登録の無い行は出さない = ブランクの世界は 0)。
  出来事は View に渡すだけで、世界の結果に入らない(落としても結果は変わらない)。

## 検討した代案と、採らなかった理由
- (b) 古いセーブは古い版の法則で動かす: 過去の版の値と解き方のコードを全部持ち続け、試験も版の数だけ要る。
- (c) 選べる: (b) の重さをそのまま持つ。
- 出来事の口を作らずにゲームが状態を読んで推し量る: 反応が「起きた」は状態の差からは一意に分からない(同じ差を別の規則が作れる)。

## 影響(何がしやすく/しにくくなるか)
- しやすく: 持つ法則が 1 組・試験も 1 組。法則を直すと変わった行が見える(遊ぶ側はどの知識が外れたか分かる)。ノートの中身がどう決まっても同じ口で書ける。音・UI の出来事と同じリングで済む。
- しにくく: 古い設計(D-422)が新しい法則で動かなくなることがある(ゲーム側の方針で和らげる: 発売後の変更は不具合の直しを主にする)。
  出来事の量が多い時のリングの大きさ・間引きの形は未確認(本物の段で測る)。
