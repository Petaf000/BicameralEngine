# ADR-0010 整数の演算の書き方の方針(04 §6 の計測から)

- Status: Accepted(2026-09-30、ユーザーが 04 §6 の案をそのまま採用。D-322)
- 日付: 2026-09-30
- 決めた人: ユーザー(Claude の案から)

## 背景
- シミュは整数で計算する(ADR-0008)。GPU は浮動小数点が得意に作られているので、整数のルーチンの費用を測った
  (T-0010 の追加分、04 §6。RTX 3070 Ti、fmul = 1 の相対値)。
- 結果: int64 の割り算 113・逆数の掛け算 33、128÷64(`FxDivU128By64`・`FxDivShiftS64`)約 1900、exp2 553・log2 1190、
  int64 の足し算・掛け算は float の 3〜4 倍。32bit の掛け算は float と同じ速さ。

## 決定
1. **割り算**: 除数が決まっている所(ベイクの定数・ブロックごとに共有する値)は逆数の掛け算(`FxDivRecip*`)にする。
   GPU で逆数を作るのは同じ除数を十数回以上使う所だけ。ベイクで作れば費用は 0。
2. **Q 形式の割り算(`FxDivShiftS64`)と 128÷64 は、セルごとの毎刻みの計算で使わない。**
   128÷64 そのものは M1 のうちに速い方法に替える(T-0084)。
3. **int64** は位置など要る所だけ(D-306)。32bit で足りる量は 32bit に。
4. **exp・log はセルごとの反応の評価で呼ばない。** 反応の速さは温度ごとの表にベイクする(02 §1)。
   呼ぶ必要が出たら、04「研究」の代案(表 + 多項式)を試す。
5. 格子のシミュが演算と帯域のどちらで詰まるかは T-0016 で Nsight で 1 回記録する。その時に NVIDIA の SASS の命令数も 04 §6 の表に足す。
   RDNA3 の ISA は AMD の機械(D-207)で確かめる時に。

## 検討した代案と、採らなかった理由
- 方針を決めずに、その都度測る → 書き方がチケットごとにぶれ、後から直す範囲が広がる。
- 浮動小数点を一部で使う → 決定性(ADR-0008)を壊すので採らない。

## 影響(何がしやすく/しにくくなるか)
- 化学・物理・熱のカーネルを書く時に、割り算・exp・log の置き方が最初から決まる。コードレビューでこの ADR を根拠にできる。
- ベイク(02 §1)の負担が増える(逆数・温度ごとの表を作る)。

## 追記
- 2026-09-30 T-0084: 128÷64 を逆数 + Newton 法に替え、fmul の約 1900 回分 → 約 250 回分になった。決定 2 はそのまま(int64 の割り算の約 2.2 倍なので、セルごとの毎刻みでは使わない)。
