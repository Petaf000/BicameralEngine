# ADR-0014 剛体の AVBD を 64bit の固定小数点で解く(研究 R-PHYS-1 の結論)

- Status: Proposed(2026-10-01。ユーザー: GPU の費用を T-0090 で測ってから判断する)
- 日付: 2026-10-01
- 決めた人: ユーザー(Claude が提案した場合も、決めるのはユーザー)

## 背景
08 §6 の研究 R-PHYS は、整数で決定的に解く方法を R-PHYS-1(64bit の固定小数点の AVBD)→ R-PHYS-2(整数で実装した浮動小数点)→
R-PHYS-3(新しい解き方)の順に試す。R-PHYS-1 の心配は「硬さを上げると値の幅が 64bit を超える」「6×6 の連立方程式の精度」だった。
T-0016 で、double の試作(tools/physics_lab)と整数版(shaders/common/physics_*.hlsli + engine/src/sim/physics_world)を
同じ 3 つの場面(積み木 10 段・質量比 1:100・箱 50 個の山を崩す)で比べた。

## 決定(提案)
**R-PHYS-1 で確定する(R-PHYS-2 には進まない)。** 根拠:
- 整数版は double と同じ振る舞い: 積み木は 60 s で位置の差 49 µm 以下、質量比は 0.11 mm 以下。山はカオスなので軌跡は分かれるが、
  食い込み・速さ・エネルギーの時間変化は同じ形(T-0016 の作業ログの図)。
- 値の幅は 64bit に十分収まる(3 場面の最大): 6×6 の途中の解 49bit(Q62 の尺度)/ H 35 / 勾配 38 / 硬さ 33 / λ 36 / 変位 32。
  release の速さで FX_ASSERT を有効にした実行(physics_*_checked)で、3 場面とも桁あふれ・割り算の範囲外なし。
- 6×6 の解き方: **行と列を同じ 2 の冪で対称にずらして対角を [2^60, 2^62) に揃え、Q62 で Cholesky**。対称正定値で対角 < 1 なら
  Cholesky の因子は |L| ≤ 1 なので、行列の大きさ(硬さ 1〜10^12 N/m と M/h² が混ざる)に関係なく溢れずに 62bit の精度を使える。
  右辺は 30bit に揃え、残り 32bit を条件数の余裕にする。ランダムな接触に似た 6×6(2 万個)で double の解との差は最大 4.4e-7。
- **硬さの上限を「組の軽い方(動く物)の M/h² × 2^20」にする**(PxParameters::penaltyRatioShift)。物ごとの 6×6 の条件数がこれで
  抑えられ、途中の解は最大 55bit(< 62)に収まる(テストで確認)。実際の場面の硬さはこの上限の 2^-10 程度までしか育たない。
- 単位は 04 §2 の物理の行(変位・回転 2^-32、腕 2^-20 m、硬さ 2^-8 N/m、力 2^-16 N、単位ベクトル Q1.30)。

## 検討した代案と、採らなかった理由
- R-PHYS-2(整数で実装した決定的な浮動小数点): 値の幅の問題が起きなかったので不要。遅さ(未測定)の心配だけが残る。
- 6×6 を 1 つの Q 形式のまま LDLᵀ で解く: 硬さと質量の項の比が 10^9 を超えると、L の要素が大きくなり溢れる/精度が足りない。
- 硬さの上限を絶対値(10^12 N/m)だけにする: 1 kg の物に 10^12 N/m の硬さが付くと条件数が 10^10 を超え、整数の解が溢れる(テストで再現)。

## 影響(何がしやすく/しにくくなるか)
- T-0090 で同じ式(physics_*.hlsli)を GPU に載せれば、CPU とビット一致を狙える(式は HLSL と C++ で共通)。
- CPU の整数版は double の約 10 倍遅い(128bit の積・割り算・平方根を 64bit で組むため。docs/perf.md)。GPU での費用は T-0090 で測る。
- 残る課題は整数ではなくアルゴリズムの側(double でも同じ): 衝突の瞬間の食い込み(山で最大 6〜9 cm)と、
  摩擦の上限で寄りかかった箱がゆっくり滑ること(最後の 5 s に 1〜3 cm/s)。T-0016 の基準のうちこの 2 つは未達 → T-0091(研究、T-0090 の前。2026-10-01 ユーザー決定)。
