# ADR-0095 魔法のパッチは「規則の速さを 2^shift 倍 / 止める」を、範囲と期間つきのコマンドで、表に重ねて評価する

- Status: Superseded(D-493)(2026-10-14 ユーザー決定)
- 日付: 2026-10-11
- 決めた人: Claude。T-0024(02 §5・D-419・D-428・ADR-0018・ADR-0035)

## 背景
- 02 §5: 魔法は反応表へのパッチ(触媒・阻害・転換・増幅・湧き出しと吸い込み)。範囲と期間があり、コマンドとして刻みの境で当たり、再生ファイルに入る。
- D-428: 世界の反応に嘘を入れない。保存則(元素・エネルギー)はビット単位。D-419: 魔法も原則は保存則の中。
- ADR-0018: 速さを変えるものは、変わった刻みを tc として書いてから評価する(古い乱数の待ちを新しい速さで使うと偏る)。
- 多重解像度のルート署名は 64 / 64 語で空きがない。反応の核(reaction.hlsli)は Table 型のテンプレートで表を読む。

## 決めたこと
1. **効き方は速さだけを変える**: 規則 1 つの速さの表の値(仮数 × 2^指数)の指数に shift(−64〜64)を足す(増幅・弱める)か、0 にする(止める = 阻害)。
   進んだ分は反応の核が係数 × 進行度で成分を動かすので、元素の数とエネルギーは今までどおりビット単位で保存される。
   重なったパッチは shift の和、止めるものが 1 つでもあれば 0(重ねる順に依らない)。
2. **形**: `shaders/common/magic_patch.hlsli`(HLSL と C++ で共有)。パッチの列は世界の状態(CPU は MultiresNest::magicPatches、
   GPU は GpuMultires のバッファ。どちらも同じ uint32 の語の並び。16 個まで)。範囲はレベル 0(0.5 m)のセルの単位の直方体で、
   セルが重なれば効く(粗いセルは丸ごと)。期間は [始まり, 終わり)。足すのはコマンド(始まり = コマンドの刻み)。一杯なら断る(CPU と GPU で同じ判定)。
3. **評価**: MrStepCellWait(多重解像度のすべての刻みの道がここを通る)が、セルを覆うパッチの印を求め、MpPatchedTable で表に重ねて
   反応の核に渡す。核は変えない。GPU は u5(外のバッファの枠)を刻みの間だけパッチの列に結ぶ(ルート署名の語は増やさない。
   外のバッファを使う Compute は RecordExternalDispatch で自分のバッファを結ぶ)。
4. **待ちの引き直し**: 速さが変わる刻み(始まり・終わり)に範囲に重なるブロックをつつく(ADR-0018)。終わった後に列から除く。
   今は実験室の箱だけ(lab_box.hlsl の ApplyLabPatchBoundaries と CPU の ApplyLabPatchBoundaries。根を並べた箱〔T-0173〕では
   範囲が重なる根だけ)。世界のコマンドの段・境・世界の保存点は T-0323(T-0287 から分けた)。

## 代わりに考えたもの
- 有理数の倍率(仮数に掛けて正規化): 2 の冪より細かく決められるが、端数の丸めが増える。速さの表は対数で 1 K ごとに変わる量なので、
  まず 2 の冪で始め、遊びで足りなければ足す(判断待ち)。
- 活性化エネルギーを下げる触媒: 温度ごとの表を作り直すことが要る(02 §5「ベイクと同じ整数の計算で GPU 上で表を作り直す」)。T-0288 に分けた。
- パッチの列を u6(木の管理の表)の後ろに置く: 番地を渡す定数の語が無い。u5 の枠を使う方が変更が小さい。

## 影響
- 多重解像度のすべての刻み(Compute・活性のグラフ・伝導・溢れ)の表の型が MpPatchedTable になった。パッチが無ければ各セルで列の数を 1 回読むだけ。
- 規則は名前の鍵(RxRule::key)で持つ(T-0287 の最初の一部。T-0024 の作業役が前倒し)。規則の並びが変わる表の差し替え(T-0218・T-0242)でも
  同じ名前の規則に効き続ける。替えた表に無い名前の規則のパッチは、何にも効かないまま期間が終わる(足す時は表に無い名前を断る)。
- 状態の要約(HashWholeNest)に効いているパッチの語を入れた(T-0024 の続き。列が空なら前と同じ値なので、今までの記録のハッシュは変わらない)。
- 規則の数などの表の大きさは、ルートの SRV に GetDimensions を使わず定数で渡す(ルートの記述子は大きさを持たず、読むと未定義。
  WARP は読めたが NVIDIA の HW は読めず、パッチを当てる段がどのパッチも「規則が表の外」と断っていた。T-0024)。

## 追記(2026-10-11・T-0323): 仮の世界(ProbeSim)のコマンドの段・境・保存点
- **コマンド**: 新しい種類 `PROBE_COMMAND_TYPE_PATCH = 5`(置くコマンドに空きビットが無いので種類の番号を足した)。payload は実験室と同じ MP_COMMAND_*。
  範囲は仮の世界のセルの座標(= レベル 0)で、格子の外にはみ出してよい(重なる所だけ。全部外なら足すがどのブロックも起こさない)。
- **境でつつく**: 適用の単位(1 グループのスレッド 0)が刻みの初めに、始まり・終わりのパッチの範囲が重なるブロックを
  「刻みの直前に変わった」(tc = 刻み t)にして起こす刻みを今にする(置くコマンドと同じ道。WakeDueBlocks が一覧へ 1 回だけ足すので
  活性の一覧の容量は変わらない)。その後で終わったパッチを除き、コマンドを番号順に当てる(足せたらその場で範囲を起こす)。
  CPU リファレンスも同じ順(予定の種と tc を同じに書く)。起こさないと、眠っていたブロックが古い速さで引いた待ちのまま眠り、
  計算したブロックの数とセルが CPU と食い違う。
- **断った数**: ハッシュの表の欄 [14](刻みごと)と、イベント PROBE_EVENT_PATCH_APPLIED(場所 = 列の番号 / PROBE_PATCH_REFUSED)。
- **状態の要約と保存点**: 仮の世界の要約はセルの和なので、列の要約(MpListHash。列が空なら 0)を足す(今までの記録のハッシュは変わらない)。
  列(u14)は保存点の写すものに入れた(VRAM の写しに 212 語増えるだけ)。
- **ルート署名**: UAV を 1 つ(u14)、ルート定数を 1 語(規則の数)足した(52 / 64 語)。
- **多重解像度の世界**: 世界として刻むもの(GpuMultires を世界のコマンドで刻む道)がまだ無いので、境でつつく段は実験室の箱のまま。T-0341 に分けた。

## 追記 2(2026-10-11・T-0288): 触媒 = 活性化エネルギーを下げる(読む温度ごとにその場で求める)
- **効き方の種類 `MP_KIND_CATALYST = 3`**: 効き方の語の 8〜31bit = 下げる活性化エネルギー ΔEa(J/mol。1〜2^24 − 1)。
  語の数は変わらないので、コマンド(実験室・仮の世界)・パッチの列・保存点・記録の形はそのまま。古い記録の効き方(種類 1・2)の意味も同じ。
- **評価**: k' = A·exp(−(Ea − ΔEa) / RT) = 表の値 × exp(ΔEa / RT)。MpPatchedRate が覆うパッチの ΔEa の和を規則の Ea で抑え
  (Ea' ≥ 0 = A より速くならない。D-428)、MpCatalyzeRate で ΔEa / RT をベイク(BakeRate)と同じ整数の式(nJ・Q32 の割り算・log2 e)で求め、
  log2 の整数の部分を指数へ、端数は 2^端数(FxExp2Q32)を仮数に掛けて 32bit に正規化する。止めるものが勝ち、2^shift 倍は触媒の後(順に依らない)。
- **規則の Ea を表に持つ**: RxRule の空き語(padding)を `activationEnergy`(J/mol。uint32。ベイクの上限 1e9 が収まる)にした。
  大きさは 80 バイトのまま。表のハッシュは無い(再生ファイルの形は変わらない)。
- **表を作り直さない理由**(02 §5 は「GPU 上で表を作り直す」と書いていた): パッチは範囲と期間に限るので、作り直すとパッチごとに
  4096 温度 × 8 バイト(16 個で 512 KiB)の表と作る段が要り、ルート署名にも枠が要る(多重解像度は 64 / 64 語)。その場で求めれば、
  覆われたセルの、その規則の速さを読む時だけ割り算 1 回と 2^端数 1 回で済み、物理の法則(温度依存)は同じ。
  Ea を下げてベイクした表との差は端数の丸めだけ(仮数の差 2^8 以内を lab_box_test で確かめた)で、CPU と GPU は同じ関数なのでビット一致。
- **待ちの引き直し**: 触媒も速さを変えるので、始まり・終わりのつつき(ADR-0018)はほかの効き方と同じ。温度が変わって倍率が変わるのは、
  温度が変わる = セルが変わる(ブロックが変わったとみなされる)のでパッチが無い時と同じ。
- **転換(生成物の差し替え)** は T-0359 に分けた(核の生成物と反応熱を差し替えるので、Rule の包みと元素の釣り合いの検査が要る)。

## 追記 3(2026-10-11・T-0359): 転換 = 規則の生成物を元素が釣り合う別の物質に替える(反応熱は H0 で求め直す)
- **効き方の種類 `MP_KIND_CONVERT = 4`**: 効き方の語の 8〜9bit = 生成物の欄(0〜2)、10〜31bit = 替える先の物質 ID(今の表の ID)。
  語の数は変わらないので、コマンド(実験室・仮の世界)・パッチの列・保存点・記録の形はそのまま。古い記録の効き方(1〜3)の意味も同じ。
  MpPatchedRate は転換を読み飛ばす(速さは変えない)。
- **釣り合いの判定(CPU と GPU で同じ)**: ベイクが物質ごとに「組成の型」(元素ごとの数を最大公約数で割った並びに付けた番号。1〜。
  元素を持たない物質は 0)と公約数を RxSpecies に持つ(`elementClass`・`elementUnits`。24 → 32 バイト)。
  c 個の物質 a を d 個の物質 b に替えて元素が全部同じ ⇔ 型が同じ(0 でない)かつ c × 公約数(a) = d × 公約数(b)。d は割り切れる時だけ求まる。
  元素の数の表(元素 × 物質)を GPU に載せる代わりにこの 2 語にしたのは、判定が正確なまま(ハッシュの衝突が無い)で、表の形が
  元素の数に依らず、ルート署名の枠も要らないため。表の物質の数は物質 0(使わない)の elementUnits に置く(ルートの SRV の大きさを
  GetDimensions で読まない。範囲の外の物質 ID を読まない)。
- **どこで判定するか**: 足す時(MpPatchValid。コマンドの段で断る = 断った数・イベントに出る)と、効かせる時(MpConvertedRule)の両方で
  同じ MpConvertedCoefficient を呼ぶ。表を替えた後(規則の生成物や物質が変わったかもしれない)でも、釣り合わない転換は効かない。
  替える先が規則の反応物なら断る(反応物と同じ物を作ると何も変わらない輪になる)。係数・公約数は 2^16 − 1 まで(積を 32bit で割る)。
- **反応熱**: 替えた規則の反応熱を MpRuleEnthalpy(ベイクの ReactionEnthalpy と同じ式 = Σ 生成物の H0 − Σ 反応物の H0)で求め直す。
  セルのエネルギー(熱 + 化学)は核が変えないので、エネルギーは今までどおりビット単位で保存され、吸熱になった転換の熱の取り合い
  (reactionEnthalpy > 0 の道)も正しい値で決まる。
- **核への渡し方**: MpPatchedTable に「覆うパッチのうち転換のもの」の印(converting)を持ち、Rule(id) が印のある時だけ替えた規則を返す
  (核は変えない。印が 0 なら今までどおり)。同じ欄に転換が重なれば列の前のもの(先に足したもの)が勝つ。欄ごとに替える前の規則で
  判定するので、欄の組み合わせはどれでも全体が釣り合う。
- **確かめたこと**: 替えた規則は「生成物を替えてベイクした表」の規則と同じ(反応熱も)で、1 セルを 40 刻み進めた結果もビット単位で同じ
  (lab_box_test の TestMagicConvert)。実験室(gpu_lab_box_test の RunConvert)・仮の世界(gpu_probe_patch_test。規則の ID がずれる
  表の差し替えを跨ぐ)で GPU と CPU が毎刻みビット一致・元素は保存・釣り合わない転換は断る。
- **残り**: 物質を足す・消す表の差し替え(ADR-0065 の付け替え)で、パッチの物質 ID を付け替える(今は付け替えないので、ID がずれると
  別の物質を指す。その場合も釣り合う時だけ効くので保存則は破れない。T-0377)。

## 追記 4(2026-10-12・T-0377): 物質を足す・消す表の差し替えで、転換の替える先の ID を名前で付け替える
- **付け替える所**: セルの付け替え(ADR-0065)と同じ段・同じ刻みの始め(終わったパッチを除く前)。GPU は実験室の RemapLabSpecies・
  仮の世界の RemapSpecies のスレッド 0、CPU リファレンスは RemapLabBox・ProbeReference::RemapSpecies。本体は `MpRemapPatchList`
  (common/magic_patch.hlsli。効き方の語は `MpRemapEffect`)。付け替えの表の読み方(Remap の約束)に `SpeciesCount()` を足した
  (範囲の外の ID を読まない)。転換でない効き方の語・列の順・ほかの語は変えない。物質の一覧が同じ表なら何もしない。
- **消えた物質への転換**: 替える先を 0(「替える先が無い」)にする。効かせる時は MpConvertedCoefficient が 0 を返すので効かず、
  列には期間の終わりまで残る(状態の要約 MpListHash に入るので、CPU と GPU の一致もそれで確かめる)。数は
  `SpeciesRemapReport::conversionsDisabled`(この刻みに終わるパッチと、もう替える先 0 の転換は数えない。実験室は付け替えのログにも出す)。
  仮の世界の GPU はこの数をハッシュの表に出していない(付け替えの段は、欄を 0 にする適用の単位の前にある)。
- **まだ当てていないコマンド**: 実験室の RemapLabCommand(差し替えの時の控え・流し直し)と仮の世界の RemapPlaceCommand(窓の筆の付け替え。
  T-0266)がパッチのコマンドの転換の替える先も付け替える。消えた物質への転換は 0 になり、当てる時に MpEffectValid が断る
  (仮の世界は断った数・イベントに出る)。
- **採らなかった案**: (1) 消えた転換を列から除く — 列から黙って消え、まだ効いているように見えたものが状態の要約からも消える。
  残して 0 にする方が、後から見て「何が効かなくなったか」が分かる。(2) 付け替えない(追記 3 のまま) — ずれた ID が別の釣り合う物質を
  指すと、プレイヤーの魔法が黙って別の物を作る(試験の表では「CO2 → 異性体」が「CO2 → CO2」になり何も起きなくなる)。
- **確かめたこと**: lab_box_test の TestMagicConvertRemap(列・コマンドの付け替え・数え方)、gpu_lab_box_test の RunConvertRemap と
  gpu_probe_patch_test の TestRemapScene(物質を足す・消す表に燃えている途中で替え、異性体への転換は ID がずれても効き続け、消える物質への
  転換は効かなくなり 1 つ数え、差し替えの後に前の表の ID で出した転換は断る。GPU と CPU が毎刻みビット一致)。

## ユーザーの決定(2026-10-14)
- D-493: パッチ(触媒・阻害・転換・増幅)は全部外す(T-0496)。
