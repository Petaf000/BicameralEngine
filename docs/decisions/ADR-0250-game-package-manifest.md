# ADR-0250 ゲーム本体はマニフェストの `game = true` で決める(名前に依らない)

- Status: Proposed
- 日付: 2026-10-15
- 決めた人: ユーザー(Claude が提案した場合も、決めるのはユーザー)

## 背景
標準パッケージの値を書き直せるのはゲーム本体だけ(Mod は足すだけ。ADR-0183 の追記)。ところがゲーム本体の名前はエンジンが
`combustion_test` に決め打ちしていた(`script::DEFAULT_BASE_PACKAGE`)。⑤ の場面(ADR-0240)を自分の名前のゲーム本体として読ませる道が無く、
T-0414 は場面のフォルダを combustion_test と偽って `--world sample` で読ませた(作り心地の記録 1)。エンジンが中身の名前を持つのは D-454 にも反する。

## 決定(仮。ユーザー未確認)
1. **ゲーム本体 = マニフェスト(package.luau)に `game = true` と書いたパッケージ**。名前に依らない。読む一覧(フォルダ・--mix・棚から足した依存)の中に 1 つまで。
   2 つ以上は起動しない(どれが本体か決まらない)。`game` の形の誤り(true/false 以外)はそのパッケージを読まない。
2. **サンプルの世界はゲーム本体が要る**(無ければ「ゲーム本体(package.luau に game = true …)が見つからない」で起動しない)。
   **ブランクの世界(既定)は、game = true があればそれを本体として読み、無ければ全部 Mod**(今までどおり)。
   よって場面は `bicameral --packages data/scenes/<場面>` で開ける(`--world sample` も名前の偽りも要らない)。
3. 見つけたゲーム本体が読めなければ、どちらの世界でも起動しない(今までどおり)。
4. 決め打ちの名前 `DEFAULT_BASE_PACKAGE` と `ReactionTableSource::basePackage` は消した(代わりに `requireGame`)。
   低い層の `PackageLoadOptions::basePackage`(名前で渡す)は試験の道として残す(ほかに game = true があれば誤り)。
   読んだ表はゲーム本体の名前を持つ(`LoadedReactionTable::gamePackage`。起動のログに出る)。
5. サンプル(combustion_test)・場面(grass_fire_river)・試験のパッケージ(packages_atmosphere の *_world など)に `game = true` を書いた。
   T-0414 の場面のフォルダは `data/scenes/grass_fire_river/grass_fire_river` に直した。

## 検討した代案と、採らなかった理由(作り手から見た違い)
- **案 A(おすすめ・仮で実装): マニフェストに `game = true`** — パッケージを見ればゲーム本体か分かる。配る時も同じフォルダのまま。
  起動の仕方は変わらない。1 つのフォルダに本体の候補を 2 つ置いて切り替えることはできない(切り替えたいならフォルダを分ける)。
- 案 B: 起動の引数 `--game <名前>` — 同じフォルダで本体を切り替えられるが、作り手が起動の仕方を覚える必要があり、
  パッケージだけを見ても本体か分からない(配った先で起動の仕方も一緒に配る)。
- 案 C: `--packages` のフォルダにパッケージが 1 つだけならそれが本体 — 書くことは無いが、Mod を 1 つ足しただけで本体が変わる・
  サンプルの世界(data/packages)にほかを置くと本体が決まらない。暗黙の規則が増える。
- 取り消し: B・C へは後で移れる(ゲーム本体を決める所は `ResolveGamePackage` 1 か所)。

## 影響(何がしやすく/しにくくなるか)
- 場面・ゲームを好きな名前で作り、標準パッケージの上に値を書き直せる。ブランクの世界で `--packages` を渡すだけで開ける。
- ブランクの世界に `--packages data/packages` を渡すと、サンプル(combustion_test)が本体として読まれる(前は Mod として読まれ、
  標準の鍵の書き直しで読まれなかった)。
- ゲーム本体のマニフェストが型検査や形で落ちると、本体だと分からないまま「読まなかった Mod」になる。ブランクの世界では起動は続き、
  警告のログに出る(サンプルの世界では「見つからない」で止まる)。
