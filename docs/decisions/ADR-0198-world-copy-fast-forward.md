# ADR-0198 世界の写しの早送り(写しを取る道・回す場所・測り方)

- Status: Proposed(下の「判断待ち」の 2 つは仮の案で実装。ユーザー未確認。T-0412)
- 日付: 2026-10-14
- 決めた人: ユーザー(Claude が提案した場合も、決めるのはユーザー)

## 背景
- D-470: エディタの道具(神の目)で「何分で火が消えるか」を、**世界の写しを早送りして**測る。同じ仕組みで、大魔法や連鎖が予算・
  演出のスローの長さに収まるかを検査する(T-0413)。D-482 ④: 遊びの指標(密室の火が何分で消えるか)を、表を変えるたびに
  写しの早送りで測る(T-0432)。どちらもこの道具の上に乗る。
- D-403: 見るだけなら世界は変わらない。写しは本物に返さない。D-468: 負荷で本物の刻みが遅れるのは不具合。
- 今の本物の世界は仮の世界(sim::ProbeSim。64³ のセル + 物理の物)。巻き戻しの保存点(ADR-0036)が「刻みの境界の状態 S(t) を
  GPU → GPU で写す・戻す」道をすでに持つ。

## 決定
1. **写し = 本物と同じ形の ProbeSim をもう 1 つ**(sim::WorldCopy)。本物が今使っている表(`ProbeSim::Table()`)と、世界を作った時と
   同じ物理の場面で作る。写すのは保存点から戻すのと同じ道(`ProbeFrameInput::adoptFrom`: 写す元の S(t) を 2 世代へ写し、
   GPU のキューのコマンドを捨て、物理のカーソルを写す)。写す元のバッファは読むだけ(D-403)。表は写さない(写しの世界を作った表のまま)。
2. **回す場所: 本物と同じ compute キュー、本物のリストの後ろ**。写しを取るのは本物の最後のリストが刻みの境界で終わっている時だけ
   (キューの順で S(t) がそろう)。早送りの量は、そのフレームのシミュの予算の余り(`SimScheduler::SpareMilliseconds`)に入る
   刻みの数だけ(frame::WorldCopyRunner。D-468)。余りが無ければ進めない(待ったフレームを数えて見せる)。
   写しの世界を作る(パイプラインの作成。キャッシュに当たらないと 10 秒を超える)のは別のスレッドで、フレームのループを止めない
   (フレームのループで待つと本物が 953 刻み捨てた。docs/perf.md 2026-10-14)。
   別のキュー(非同期の compute)は採らない: 写す元の状態がどの時点か決まらない・GPU を取り合って本物が遅れる。
3. **測り方は形だけ(中身を持たない。D-454)**: 刻みごとの要約(ハッシュ・エネルギー・計算したブロックの数)と、決まった間隔の刻みの
   セルと熱のキャッシュの読み戻しを、呼ぶ側の条件(until)に渡す。「火が消えた」の意味は呼ぶ側が書く。小さな道具は物質の量・
   最高温度・しきい値以上のセルの数。答えの細かさは読み戻しの間隔(パネルの既定 60 刻み = 1 秒)。
4. **API(T-0413・T-0432 が使う)**: `WorldCopy::Create` → `RecordInitialization` → `RecordStart(本物, t, 問い)` →
   `RecordNext(最大の刻み数)` を投げて `Complete()` を `Finished()` まで → `Result()`(止めた刻み・条件に着いたか・刻みごとの要約・
   GPU の時間)。問いのコマンドを当てれば、本物に同じ列を当てたのと同じ結果(決定性)。同じ写しは何度でも使い直せる。
5. **エディタ**: パネル「写しの早送り」(editor/copy_panel)。条件は「上限まで(最高温度を測る)」「最高温度がしきい値より下」
   「物質の量がしきい値以下」。写しにはコマンドを当てない(今から何もしなければ)。測った値の道のりを線で出す。
6. 確かめ: gpu_world_copy(写しを取っても本物のハッシュ列が変わらない・同じコマンドなら写し = 本物 = CPU リファレンス・
   使い直した写しが条件で CPU と同じ刻みに止まる)・window_copy_record/play(`--auto-copy`: 窓の中で写しのハッシュ = 本物の
   ハッシュ。記録を写し無しで再生して同じハッシュ列)。

## 判断待ち(作り手から見た違い。仮の案で実装)
- **早送りの間、エディタの世界を止めるか**
  - 案 A(仮): 止めない。写しは本物の予算の余りで回る。作り手は世界を見ながら待てるが、本物が重い(予算を使い切る)と写しが
    進まない・遅い(パネルに「待ったフレーム」が出る)。
  - 案 B: 早送りの間は本物を止める(時間のパネルの「止める」と同じ)。写しが予算をほぼ全部使えて速く答えが出る。世界は止まる。
  - 案 C: パネルにチェック(既定は A)。どちらも作れる(B は WorldCopyRunner が時間の操作を頼むだけ)。
  - おすすめ: C(既定 A)。今は A だけ入れた。B を足すのは小さい。
- **写しの数の上限**
  - 案 A(仮): 1 つ。VRAM は世界 1 つ分(仮の世界 64³ + 積み木で 77 MiB。docs/perf.md)。2 つ目を頼むと前の問いを止めて使い直す。
  - 案 B: 複数(条件を変えた写しを並べて比べる。T-0432 の指標を並べて測る時に速い)。VRAM が写しの数だけ増える。
  - おすすめ: A のまま始め、T-0432 で並べたくなったら上限を設定で(VRAM の予算と一緒に)。

## まだ無いもの・分けたもの
- 実験室の箱(LabSession)の写し: 箱は記録の再生で同じ状態を作れる(RunLabComparison・T-0221)。箱の上の早送りの道具は T-0476 に分けた。
- 多重解像度の本番の世界: 写しの形(同じ形の世界をもう 1 つ・保存点の道で写す)はそのまま使える。VRAM が大きいので、写す範囲を
  区切る(場面の箱だけ写す)必要が出る見込み(未確認)。
- 写しの早送りの重さの検査(1 刻みの GPU 時間・活性のブロック数・VRAM を条件と一緒に出す)は T-0413。

## 影響
- ProbeSim: `ProbeFrameInput::adoptFrom`・`Table()`・`Thermal()`・`DefaultHeapBytes()`。0 の見出し(キューを空にする)は保存点が無くても作る。
- SimScheduler: `SpareMilliseconds()`(最後の TakeUnits の予算の余り)。世界の結果は変えない。
