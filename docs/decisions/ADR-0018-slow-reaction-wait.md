# ADR-0018 遅い反応は、ブロックが最後に変わった刻みからの幾何分布の待ちで丸める

- Status: Accepted
- 日付: 2026-10-05
- 決めた人: Claude(D-429 の実装の細部。CLAUDE.md §5。T-0105)

## 背景
- D-429(ユーザー決定): 遅い反応も起きる。D-424 の下限(1 刻みの進みの期待値が 2^-16 µmol 未満なら 0)を外し、遅い規則は「次に 1 単位進む刻み」を
  決定的に求めて、眠らせたままその刻みに起こす。成功の基準: 何年分が正しい平均の速さで起きる・眠らせても全部を計算した場合とビット一致・眠っている所の費用が今と同程度。
- 今の丸め(02 §3.1): 刻みごとに hash(シード, 刻み, セル, 規則) の 32bit と端数を比べて +1。次に当たる刻みを閉じた式で求められないので、
  眠ったセルをいつ起こせばよいか分からない(だから D-424 の下限で「進めない」セルだけを眠らせていた)。

## 決定
- **進行度 = 整数部 + [t ≥ tc + n]**。tc = セルのブロックが最後に変わった刻み(刻み t の初めに読んだ値。同じ刻みの書き換えは読まない)、
  n = 幾何分布の待ち P(n = k) = (1 − f)^(k−1) f(f = 1 刻みの進みの端数)。全部を計算する側も眠らせる側も、毎回この同じ式で判定する。
- n の乱数は (世界のシード, tc, セル, 規則の鍵) だけで決める(刻みに依らない)。U = (乱数 | 1) ÷ 2^64、n = max(1, ceil(log2 U ÷ log2(1 − f)))。
  log2 は整数(FxLog2U64。R7)。f < 1/16 では −log2(1 − f) を級数 f Σ f^(k−1) ÷ k(16 項)× log2 e で求める。待ちが約 2^61 刻み(約 12 億年)を超える引きは「起きない」。
- 幾何分布は記憶が無いので、ブロックが変わるたびに引き直しても速さは偏らない(Gillespie 1977 の 1 単位ずつの過程を、1 刻みの格子の上で引くのと同じ)。
  毎刻み変わるセルでは n ≤ 1 ⇔ 確率 f で、今の丸めと同じ分布。
- **速さ f が変わるのはブロックが変わった時だけ**にする: f はセル(成分と温度)と規則の表だけで決まる。表を変えるもの(魔法のパッチ・表の差し替え)は、
  範囲のブロックの tc を書いて(「変わった」とみなして)から評価する。こうすれば「古い乱数・新しい f」の偏りは起きない(T-0105 の測定: 引き直さないと、
  f が 256 刻みごとに 1/16 ↔ 1/512 の場面で起きる回数が +2.5%〔+13.6σ〕、7 刻みごとで +72%。引き直せば ±0.3σ)。
- 変わらなかったセルは「次に評価の要る刻み」= min over 規則 (tc + n) を返す(進む規則があったのに変わらなければ t + 1)。ブロックはその最小に起こす。
  起こすまでの刻みでは、全部を計算しても何も変わらない(ビット一致)。
- 端数は 64bit(今は 32bit)、刻みと tc は 64bit(60 刻み/秒で 2^32 刻みは約 2.27 年)。
- 取り合いの丸め(D-431)は今のまま刻みの乱数。取り合うのは進む規則があるセル = 起きているセルだけなので、眠らせ方に関わらない。
- **段階**: T-0105 で CPU リファレンス(reaction.hlsli の RxStepCellWait。今の世界はまだ RxStepCell)。T-0115 で多重解像度と仮の世界を切り替え、
  見出しに 64bit の tc と起こす刻みを持ち、まず見出しを全部なめる compute で起こす。重ければ T-0116 でホイールか木の上の最小値。

## 検討した代案と、採らなかった理由
- 今の丸めのまま、次に当たる刻みを探す: 刻みごとのハッシュは独立なので、次に当たる刻みは 1 刻みずつ調べるしかない(眠らせる意味が無い)。
- D-424 の下限のまま: D-429 で置き換えると決まった(何年もかかる変化が起きない)。
- Anderson の修正次反応法(MNRM): 規則ごとに内部時刻を状態として持ち、速さが変わっても引き直さずに正確。状態がセル × 規則ぶん要る。
  今の設計では速さはブロックが変わった時しか変わらないので、引き直しで足りる。偏りが測れたら移る(T-0105 の代案の順)。
- tc をセルごとに持つ: 1 セル 8 B 増える。ブロックの中の別のセルが変わった時にも引き直すことになるが、記憶が無いので偏らない。今の busyTick がブロックごとなのでそれを使う。
- 待ち n をセルや見出しに持つ(毎回引かない): 状態が増え、全部を計算する側と眠らせる側で同じ値を持つ約束が要る。費用が問題になったら T-0115 の計測で考える。

## 影響(何がしやすく/しにくくなるか)
- しやすく: 室温の木の酸化・石の風化のような遅い反応が、眠ったまま正しい速さで起きる。眠らせる判定が「進める規則が無い」から「次に評価の要る刻み」に変わり、
  起きないセル(反応物が無い)は RX_WAIT_NEVER で今と同じく眠る。
- しにくく: 全部を計算する側も tc を毎刻み正しく持つ必要がある(今の StepNest は busyTick を刻みの印にしていない → T-0115 で直す)。
  端数のある規則ごとに log2 を 2 回(64bit の掛け算の上位 64 回)計算する費用が増える(T-0115 で GPU を測る)。
- 熱の伝導は温度差が約 1 mK になるまで流れが 0 にならない(T-0104・D-430)ので、暖かい物の近くのブロックは眠らない(この ADR では変わらない)。

## 追記(2026-10-06、T-0115。Claude: 世界の CPU を切り替えた時の細部)
- 多重解像度の見出しの busyTick(64bit)を tc に使う。刻みと tc は**印**(MrChangeMark = 刻み + 1)で渡す。初めの状態の 0 は「刻み 0 の前に変わった」。
  見出しに wakeTick(次に評価の要る刻みの印。64bit。0 = すぐ)を足した。
- **つつかれたブロック**(木の変更・影を作った): 刻む前に busyTick = この刻みの印(静かさの判定は今までどおり)、wakeTick = 0。評価はその刻みだけ
  tc = 印 − 1(刻みの直前に変わった = この刻みにも確率 f で進む)とし、次の刻みにもう一度評価する(次からは tc = この刻みの印で引き直す。
  起きなかった後の引き直しなので、記憶が無いことから偏らない)。
- 変わった・頁に広げた・つつかれたブロックは busyTick = この刻みの印・wakeTick = 次の刻みの印。評価して変わらなければ wakeTick = セルの最小。
  活性の種 = 見出しを全部なめて wakeTick ≤ この刻みの印のブロック + 種の印(つつかれた・頁の不足)。種の面の隣も起こす(今までどおり。伝導のため)。
- 一様なブロックは wakeTick が来た時だけ、刻むセルを 1 つずつ評価する(待ちはセルの ID ごとに違うので値 1 つでは決まらない)。1 つでも変われば頁に広げる。
- 移行の間、MultiresStepOptions::cutoffRounding で今までの丸めを残す(GPU と仮の世界がまだ今までの丸め。T-0121 で消す)。
- 残り(T-0121): 許容差つきで畳んだ時と影の引き戻しで tc を書き直す(値が変わるので)。

## 追記(2026-10-06、T-0121。Claude: GPU の細部)
- GPU にも移行の間だけ今までの丸めを残す(stepFlags の MR_STEP_CUTOFF_ROUNDING = MultiresStepOptions::cutoffRounding。ルート定数は足さない)。
- 全部を刻む GPU は 起こす段(WakeDue。1 スレッド = 1 枠で見出しを全部なめ、つつかれたブロックに busyTick = 印・wakeTick = 印 + 1)→ StepWait(1 グループ = 1 枠)→
  TreeExpand → StepExpandedWaitPass。一様なブロックは「起こす刻みが来た か busyTick = 印」の時だけ評価する(CPU は ResolvePokes で wakeTick = 0 にするので同じ)。
- 活性の刻みは WakeDue が起こす刻みの来た世界の本物のブロックを種の一覧に足す形にする(部品はある。活性のグラフへの組み込みはハードウェアで止まったので T-0124)。
- WARP は CPU と毎刻みビット一致。ハードウェア(NVIDIA RTX 3070 Ti)では評価したセルの wakeTick の上位 32bit が落ちる(T-0124。原因は未確認)。
