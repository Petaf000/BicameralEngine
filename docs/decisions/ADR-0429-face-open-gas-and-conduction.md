# ADR-0429 気体が面の開き具合を同じ口で読む・熱の伝導は読まない(T-0976)

- Status: Proposed(形は Claude の仮。T-0976 の 1 チャット目。CPU だけ)
- 日付: 2026-10-22
- 決めた人: Claude(T-0976 の作業役)。前の決定: ADR-0420(面の開き具合の欄 `face.blocked`・`FoFaceOpen`)・D-615・ADR-0268(気体のセルの空き)・ADR-0312(陰の圧力の空き)
- 設計書: docs/design/21-motion-case-b.md §2.7・docs/design/23-radiation.md §7・docs/design/20-transport-substrate.md §2.3・§8

## 背景
- T-0937 で面の開き具合の欄と読む口 `FoFaceOpen(両側のセルの空きの小さい方, b) = min(…, 1 − b)` を作り、液体だけが読んでいた。
  ほかの運ぶ家族(気体・熱・放射・案 B)が同じ口を読むのが T-0976。

## 決定(仮)
1. **気体**: 気体の箱に面の塞ぐ割合の表 `GasBox::faceBlockedQ16`(軸ごと・セルの + 側の面。空 = 塞がない)を持たせ、面の開きを 1 か所(`FaceOpen`)で
   `FoFaceOpen` にする。陽解法の面の流れ(`GfFaceFlowOpen`。面の開きを引数で受ける形を足し、`GfFaceFlow` は今の形のまま呼ぶ)・一部だけ開いた面の力積・粘りと、
   陰の圧力の面の係数 K_f(`GfPressureFaceCoefficient(K, 開き)`)・予測の流れ F* が同じ開きを読む。C-0 の部品(`EquilibriumSystem`)の型は変えない
   (面の係数に開きを掛けるのは法則の側)。
   - 欄の持ち主は面の − 側のセル(液体と同じ)。箱の外(開いた境界・壁)が − 側の面は塞がない。
   - 多重解像度の 1 段の気体(`MultiresGas`)は欄を名前で引き、気体の箱の軸の順(`WeAxisUpLast`)に写す。全部 0 なら写さない(今とビット単位で同じ)。
     塞ぐ面がある時は空きを読む箱にする(空きが全部 1 でも)。
   - GPU の気体(`GpuGas`)は表の入った箱を断る(T-0975 で上げる)。
2. **熱の伝導は欄を読まない**: 今の欄は表面の細かい形(セル自身の固い物)から作る。固い物は熱を通すので、伝導に (1 − b) を掛けると溝の横の石と石の間の伝導が
   ほぼ 0 になる(法則が嘘になる。D-428)。伝導はセル全体の熱を運ぶ(相ごとではない)。気体・液体が運ぶ熱は流れと一緒に絞られる。
   伝導を絞るべきなのは、セルの物質でない物(物の塞ぐ面。T-0977)が面を塞ぐ時。欄を形と物の 2 つの値に分けるかは【エンジン】の問い(チケット T-0976)。**2026-10-24 ユーザー決定 D-638: 分ける(値 3 → 6)。運ぶ家族は両方の大きい方を読み、熱の伝導は物の分だけを読む。T-0977 はこの形で。**
3. **放射・案 B** は同じ口の使い方をチケット T-0976 に書いた(放射: 透過に 1 − b。案 B: 相ごとの開き = `FoFaceOpen(その相の空きの小さい方, b)`)。

## 採らなかった案
- 伝導にも `FoFaceOpen(1, b)` を掛ける: 上の 2 の理由(固い物が熱を止める)。
- 気体の面の開きを GPU と共有の `GfFaceFlow` の中で欄から読む: GPU の段の引数が増える(T-0975 でまとめて上げる)。CPU は開きを引数で渡す形にした。

## 結果
- 試験 `face_open_gas`(tests/face_open_gas_test.cpp): 欄が全部 0 で多重解像度の気体が毎刻みビット一致 / 気体の箱の両方の道で塞ぐ割合 0 の表と表なしが同じ /
  溝の場面で煙と気体が運ぶ熱が溝に沿って運ばれ溝の外の地面の中は 0(欄なしは溝 2 へ漏れる)/ 塞いだ面は両方の道で 1 µmol も通さない・隙間は通す /
  保存 0・決定的。数値はチケット T-0976。
