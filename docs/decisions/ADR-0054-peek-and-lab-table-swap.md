# ADR-0054 覗き窓は影の鎖を作り直し、実験室は操作を初めから新しい表で流し直して、ホットリロードの表へ替える

- Status: Accepted(実装の細部。CLAUDE.md §5)。**決定 3(実験室の替え方)は ADR-0055 で置き換えた**(D-439 でユーザーが Q29 の案 B を選んだ。流し直しはボタンに残る)
- 日付: 2026-10-09
- 決めた人: Claude。T-0194

## 背景
- ADR-0047: 世界(ProbeSim)の表は刻みの境界で替わる(印のコマンド + 表の写し + RefreshTable)。記録と再生で同じ刻みに替わる。
- 覗き窓(T-0096)は世界の 1 点の周りを観察の影の鎖(多重解像度の入れ子)にする道具で、世界の結果に入らない(D-403)。
  実験室(T-0142・ADR-0037)は世界とは別の小さな箱で、GPU と CPU リファレンスを刻みごとに比べる。どちらも起動時(実験室は試験の C++ の表)の表のままだった。
- 多重解像度の入れ子の待ちの丸め(ADR-0018)は「表を変えるものは範囲のブロックを『変わった』にしてから評価する」約束。
  入れ子に RefreshTable に当たる段(待ちの予定と熱を新しい表で作り直す)はまだ無い。

## 決定
1. **表を持ち替える道具**: `GpuMultires::ReplaceTable(table)` は新しいアップロードのバッファに表を写して持ち替え、前のバッファを返す
   (それを読んだリストが GPU で終わるまで呼ぶ側が持つ)。表は BindRoot が記録のたびに結ぶので、次に記録するリストから効く。
   物質の一覧は今の表と同じこと(script::CheckHotReloadCompatible。ADR-0047 の 2)。
2. **覗き窓**: 世界が刻み s の始めに替えたら `QueueTableSwap(s, 表)`(表は写して持つ)。s より後の境界 S(t)(t > s。新しい表で進んだ世界)を
   初めて抽出するフックで表を替え、**影の鎖を捨てて今の世界の写しから作り直す**(移った時と同じ道)。前の表で作った影の待ちの予定と熱を
   持ち越さないので、入れ子の RefreshTable を作らずに ADR-0018 の約束を満たす。前の表のバッファはそのフレームのリストの keepAlive
   (`ProbeExtractContext::keepAlive`。キューは順に終わるので、前のリストが読んだものも入れてよい)。CPU リファレンスも同じ順。
   覗き窓は記録に入らない(世界のハッシュ列は変わらない)。
3. **実験室**: 表は世界が今使っている表(フレームのループが毎フレーム渡す。T-0172 の「パッケージの表を読む」もこれで満たす)。
   版が替わったら `LabSession::ChangeTable`: 箱の表を替え、**今までの操作(コマンドの列)を初めの箱から新しい表で同じ刻みまで流し直す**
   (置いてまだ刻んでいない操作は残す)。1 つの実験 = 1 つの表。記録 `BLAB` は版 2 で表の版を持ち、違う版の記録は再生しない
   (版 1 の古い記録は表の版 0 = 確かめない)。箱は刻みごとに待っているので、前の表のバッファはすぐ捨ててよい。
4. **窓の確認**: `--auto-reload`(frame/auto_reload。T-0195)が `--packages` の写しを壊す → 古い表のまま → 直す → 差し替わる を人なしで確かめ、
   `--record` の再生ファイルを別の起動で写しのフォルダ無しに再生してハッシュ列の一致を見る(ctest window_hot_reload_*)。

## 検討した代案と、採らなかった理由
- **覗き窓の入れ子にも RefreshTable を作る**(影を残して待ちの予定と熱を作り直す): GPU の段と CPU リファレンスが要る。覗き窓の影は数フレームで
  世界に従い直すので、作り直しで足りる。費用に見合わない。
- **実験室も世界と同じく、刻みの途中で替える**(箱に表のコマンドを入れ、その刻みから新しい表): 入れ子の RefreshTable が要り、記録が
  複数の表を持つ形になる(再生ファイルの版 2 と同じ仕組みが要る)。実験室は「同じ置き方で法則を比べる」道具なので、初めから流し直す方が
  比べやすい。必要になったら足せる(判断待ち。T-0194)。
- **表が替わったら箱を空に戻す**: 置いた操作を人がもう一度やり直すことになる。流し直しは自動で同じ実験を新しい表で見せる。

## 影響(何がしやすく/しにくくなるか)
- しやすい: 反応表を書く人が保存すると、世界・覗き窓・実験室が同じ表になる。実験室は同じ置き方の実験を新しい法則で見直せる。
- しにくい: 実験室で「刻み t までは古い表、そこから新しい表」は試せない。流し直しは刻みの数だけ GPU を待つ(数百刻みで数秒。debug は長い)。
