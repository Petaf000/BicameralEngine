# ADR-0347 陰解法の系に開いた世界の端の面を入れる: 外のセルは温度を固定した境(Dirichlet)、流れは当てる段で帳簿の「世界の端」へ

- Status: Proposed(2026-10-19。T-0790。一旦の決定〔ユーザー未確認〕)
- 日付: 2026-10-19
- 決めた人: Claude(T-0790 の作業役)
- 関係: ADR-0337(世界の端)・ADR-0019(細かいレベルの熱の陰解法)・ADR-0334(当てる段。7・8)・ADR-0017(違うレベルの面)・T-0721(陽の端)・T-0715(陰の伝導の出力)・T-0773(GPU の端)

## 背景
- 陰解法で解くブロック(MarkImplicitBlocks。基準より細かい本物のブロック)は、陽の流れ(ComputeConduction の TxFlowCell)を飛ばし、
  陰の系(multires_implicit_conduction.cpp)は SAME・COARSER の面だけを入れていた。開いた世界の端(MR_NEIGHBOR_EDGE。T-0721)の面は誰も流さず、
  陰解法のブロックの端は wall と同じだった(T-0790 の場面: 上だけ open の根を全部陰解法で解くと、帳簿の世界の端が 0 のまま)。

## 決定(仮)
1. **外のセル = 温度を固定した境**: 未知数のセルの端の面ごとに `ImplicitEdge`(係数・外の温度・陽の端の流れ)を系に入れる。外のセルは陽の端と同じ
   見立て(`CellViews::Outside`。自分と同じレベル)で、系の未知数ではない(外は変わらない = 陽の端と同じ約束)。後退 Euler の式は
   `(C + Σ g + Σ g_端) T* = C T0 + Σ g T*_j + Σ g_端 T_外`。段 0 の節の自分だけの係数を `C + Σ g_端` にし(対角・自分の重み・粗い段の縮約・
   収束の判定に入る)、右辺を `(C ÷ D) T0 + Σ (g_端 ÷ D) T_外`(`implicit_conduction.hlsli` の `ImEdgeRhsStart`・`ImEdgeRhsTerm`)。
   係数は面と同じ `min(G) × HC_LIMIT_PER_CONDUCTANCE × 4^k`(上限なし)。端の面を持たない節は今まで通り(ビット一致)。
2. **流れと帳簿**: 解いた後の流れ `F = g_端 (T* − T_外)`(`ImEdgeFlow`。外へ出るのが正)を当てる段の端の形 `TxApplyEdgeFlow`
   (`transport_apply.hlsli`。TxFlowCell の端の面と同じ: 自分から引き、帳簿の「世界の端」へ。世界の `AddEdge` は陽の面と同じ `AddConductionEdge`)。
3. **安全網**: 範囲(刻みの初めの温度の最小〜最大)に外の温度も入れる。範囲を出たセルの端の面は、陽の端と同じ流れ
   (`TxEdgeFaceFlow` = 陽の当てる段の端の式。刻みの初めの見立てから)に戻す。
4. **GPU**: 同じ形を GPU の陰解法に写すのは T-0773(wt3)。共有の式は上の .hlsli の関数。GPU の系はまだ端を持たないので、open の端と陰解法を
   一緒に使う場面の GPU と CPU の比べは T-0773 まで合わない(今の GPU の試験の場面は端が全部 wall)。

## 結果
- 上だけ open の根を全部陰解法で解く場面で、熱が上の端から逃げ(上の層 < 下の層)、保存量(帳簿込み)が毎刻み一定・帳簿は世界の端・出だけ。
  細かくした場面(レベル 1・2 が陰解法・根は陽解法)で保存量が一定・活性 = 全部(multires_edge_test)。端の無い場面の陰解法の試験はビット一致のまま。

## 代案
- 端の面だけ陽の当てる段で流す(陰の系に入れない): 簡単だが、陰解法にするのは陽の係数が熱容量の上限(C/8)で頭打ちになるレベルなので、
  端から逃げる熱がそのレベルで本当より遅くなる(陰解法を入れた理由と同じ遅れが端にだけ残る)。
- 外のセルを熱容量のとても大きい未知数として系に入れる: 式は変えずに済むが、外の温度が少し動き(流れが少し小さくなる)、縮約で外の節が親を作る。
  固定した境なら外は厳密に変わらない(陽の端と同じ)。
