# ADR-0036 巻き戻しは「VRAM の保存点(GPU → GPU のコピー)+ コマンドの足し直し」で作る

- Status: Accepted(実装の細部。ユーザー未確認の点はチケット T-0143 の「判断待ち」)
- 日付: 2026-10-09
- 決めた人: Claude(CLAUDE.md §5。T-0143)

## 背景
- 14 §2 の時間の操作に「巻き戻す(保存点 + 再生)」がある。世界の結果は「初期状態 + 刻みの番号の付いたコマンドの列」だけで決まる
  (06 §1・ADR-0008)ので、途中の状態 S(t) を持っていれば、そこから t 以降のコマンドを流し直すと同じ世界に戻れる。
- 世界の状態は VRAM にあり、CPU は書き換えない(原則 1・D-107)。巻き戻しのために世界を CPU へ読み戻す・CPU から書くのは避けたい。

## 決定
- **保存点 = 刻み t の境界の状態の写しを VRAM に置いたもの**(sim/probe_save_point.cpp)。写す・戻すはどちらもフレームのリストの先頭で
  `CopyBufferRegion`(GPU → GPU)。CPU への読み戻しは無い。
  - 写すもの: セルと熱のキャッシュは **S(t) の世代だけ**(予定していないブロックは 2 世代が同じ値なので、戻すときは同じ写しを 2 世代に書く。
    1 つ約 33 MiB。2 世代なら倍)・予定の印・活性の一覧 2 組・ハッシュの表・刻みのイベントの一時置き場・物理の u0〜u13 と CPU の控え(刻み・組の枠)。
  - 写さないもの: GPU のコマンドキュー(戻すと空にする)・抽出・イベントのリング・カウンタ・トレース(出力で、世界の結果に入らない)。
- **戻す = 保存点を世界へ書き戻し、コマンドキューを空にして、刻み t 以降のコマンドを足し直す**。足し直すのは、再生ファイルを流していれば
  そのファイルの列(ReplayPlayer::Rewind)、窓の操作なら「今の流れで足したコマンドの控え」(frame_loop の m_commandHistory)。
  戻した後の新しいつつきは足し直しに刻みの順で混ぜる。戻した刻みより先の保存点は捨てる(先の流れが変わりうる)。
- 保存点は `--save-interval` の倍数の刻みの境界で写す(既定 120 刻み・`--editor` なら 6 個)。SimScheduler がその境界でフレームを切るので、
  境界は必ずどれかのフレームの先頭になる(ADR-0011 の予算は変わらない。1 フレームが少し短くなるだけ)。
- 確かめ方: `gpu_probe_rewind`(写しながら進む → 刻み 20・100 へ戻して足し直す → 最初から流した時とハッシュ列が全部一致。足し直さないと違う)と
  `window_replay_rewind`(再生中に保存点へ戻しても、記録のハッシュ列と一致)。

## 検討した代案と、採らなかった理由
- **最初から流し直す(保存点なし)**: 正しいが、長く遊んだ後ほど遅い(10 分 = 36,000 刻み)。保存点の間隔ぶん流し直すだけで済ませたい。
- **保存点を CPU のメモリに読み戻す**: VRAM を使わないが、1 回 33 MiB の読み戻しと書き込みになり、原則 1(CPU は世界を書き換えない)に近づく。
  セーブ(ディスクへの書き出し)は別の話(15 §2)で、そちらは読み戻しが要る。
- **2 世代とも写す**: 安全側だが 2 倍の VRAM。予定していないブロックの約束(probe_sim.hlsli)で 1 世代で足りることをテストで確かめた。
- **コマンドキューも写す**: 戻した時点でキューにあるのは「先の刻みのコマンド」で、どうせ足し直す。空にする方が簡単で、二重に足す誤りが起きない。

## 影響(何がしやすく/しにくくなるか)
- しやすい: 実験の前に戻ってやり直す・不具合の直前に戻って何度も見る(エディタ)。本物の世界(M3 以降)でも「状態のバッファの一覧」を
  写せば同じ道で巻き戻せる。
- しにくい: VRAM を使う(世界が大きくなると保存点が重い。多重解像度の世界では「変わったブロックだけ写す」差分の保存点が要る。未着手)。
  記録中(`--record`)・`--check-physics`・トレースの間は巻き戻さない(刻みが一度ずつ進む前提の道具なので)。
