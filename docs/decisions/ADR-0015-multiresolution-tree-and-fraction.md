# ADR-0015 多重解像度の木は比 2 のブロック、粗くした余りは 64bit の端数で疎に持つ

- Status: Accepted
- 日付: 2026-10-03
- 決めた人: ユーザー(Claude が提案、T-0017 の着手時)

## 背景
- 17 §1 は「レベルが 1 つ細かくなると一辺が 1/2」としながら、同じ節で「セル 1 つを 1 つ下のレベルの 8³ のブロックに置き換える」としていた。
  一辺 1/2 なら子は 2³、8³ なら一辺 1/8(3 レベル先)で、大きさが合わない。
- 量の単位をレベルごとに 1/8(体積と同じ比)にすると、細かくする時は正確(子は親と同じ数)だが、粗くする時に「子の合計 ÷ 8 の余り」が出る
  (BACKLOG 2026-09-30)。D-206 は保存量の正確な一致を求める。

## 決定
- **木は比 2 のブロック**: ブロックはどのレベルも 8³ セル。子ブロック(k+1)は親ブロックの 4³ セル(1/8 の範囲)を覆う。親のセル 1 つ = 子のセル 2³。
  細かくする単位は 4³ セル(レベル 0 で 2m 角)。粗密の境界は常に 1:2。
- **単位**: レベル k の物質量 = 8^-k µmol、エネルギー = 8^-k mJ。同じ濃度・温度ならどのレベルでも同じ数になり、反応の核はレベルを知らない。
- **余りは端数で持つ**: 量とエネルギーを「整数部 64bit + 端数 64bit(2^-64 単位)」とみなす。反応・輸送は整数部だけを使い、端数は細かく/粗くする時だけ動く。
  粗くする = 子 8 つの合計を 3bit 右へ。**21 段(0.5m → 0.24µm)までの往復はビット一致**。それより深くから粗くした時に落ちる分
  (1 回で粗い側の単位の 2^-64 未満)は世界の帳簿に足し、「世界 + 帳簿」を一致させる(帳簿は T-0018 で作る。T-0017 では数えるだけ)。
- **端数は疎に持つ**: 端数が 0 でないブロックだけが端数のブロックを持つ(セル本体とは別の配列。1 世代)。一度も粗くしていない所は持たない。

## 検討した代案と、採らなかった理由
- 1 セル → 8³(3 レベル飛び): 文のとおりだが、細かさが 8 倍ずつしか変えられず、粗密の境界が 1:8 になって段をまたぐ輸送の精度が落ちやすい。
- 1 セル → 2³(八分木): 細かくする単位が最小だが、節が小さく木が深く、GPU では遅い。
- 余りを帳簿に捨てる: セルは今のままだが、粗くするたびに物質がわずかに世界から消える(「世界 + 帳簿」は一致)。
- 端数を全セルに持つ: 単純だがメモリが今のセル(2 世代)の +30%(32bit なら +15%)。疎なら一度も粗くしていない所は 0。
- 単位をレベルで変えない: 粗くするのは足し算で正確だが、細かい段で量が 0 に潰れる(1 µmol なら 0.12mm で空気が 0)。D-401 と合わない。

## 影響
- 17 §1・§5、04 §2 を直した。05 §3 のセルに「端数のブロックの番号」が加わる(T-0018 で置き場所を決める)。
- 細かくする時に子へ端数を写すので、端数のある所を細かくすると端数のブロックが増える。数は T-0017 で記録し、T-0018 で予算に入れる。
- 端数は反応しない(レベル 0 で 1 µmol 未満)。物理的には無視できるが、保存量の検査には必ず含める。
