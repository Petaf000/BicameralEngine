# ADR-0052 GPU のセルの溢れは「インライン 8 で先に刻み、溢れるセルだけ上限なしの形で刻み直す」・頁ごとに 2 面を入れ替える

- Status: Accepted(実装の細部。CLAUDE.md §5)
- 日付: 2026-10-09
- 決めた人: Claude。T-0176(02 §3・17 R-MULTI-4。関係: T-0175・T-0187・T-0124・T-0211)

## 背景
- CPU の多重解像度の世界は T-0187 で「インライン 8(RxCell)+ 頁ごとの溢れ(セルの番号の順に詰める)」を持ち、9 種目の生成物を待たせない。
  GPU も同じ中身を毎刻みビット一致で持つ必要がある(原則 4)。
- 今の GPU の刻み(StepPagedWait)は 1 グループ = 1 ブロックで、セルをその場で書き換える。溢れの並びはブロックの全部のセルの溢れの数が
  分かるまで決まらない(プレフィックス和)ので、書き始める前に別のセルの古い溢れを上書きしてしまう恐れがある。
- ルート署名は 63 / 64 語で、UAV を 1 本も足せない。上限なしの形のセル(成分の配列が長い)はレジスタを食うので、空気だけの世界の刻みを遅くしたくない。
- HW の Work Graph のノードに反応の核を足すとドライバが誤って下ろす(T-0124)。

## 決定
1. **インラインで先に刻む**: 成分が 8 種に収まるセル(溢れが無く、インラインの核で 9 種目の生成物を待たせなかった)は今の核の結果をそのまま書く。
   8 種以下の間は上限なしの形とビット単位で同じ(T-0175)なので、結果は CPU の上限なしの世界と同じ。溢れを持つセル・待たせたセルだけ、
   上限なしの形(RxGpuWideCell。RX_GPU_WIDE_SPECIES = 24 種まで)で ① 溢れの数を数え → ② セルの番号の順のプレフィックス和(スレッド 0)→
   ③ 刻み直して書く。刻み直しはそのセルだけなので、ふつうのセルの費用は変わらない。
2. **頁ごとに 2 面**: 溢れは [今の面][面 0][面 1]。刻むブロックは今の面を読み、もう片方の面へ書き、全部書いてから面を入れ替える。
   読む前に別のセルの溢れを上書きしない(グループの中の書く順に依らない)。溢れのある頁だけが面を入れ替える。
3. **置き場所は u6(木の管理の uint32 の表)の後ろ**: UAV を足さない。始まりの語はルート定数の最後の 1 語(g_overflowBase。溢れを使う変種だけが宣言する)。
4. **溢れを使う世界だけの変種**: 全部を刻む Compute を MR_WIDE_CELLS 付きでもう 1 組コンパイルする(multires_step_wide_*)。既定の世界は今のシェーダーのままで、
   VRAM も ns/セル も変わらない。活性のグラフ(Work Graph)には入れない(ノードに核を足さない約束。活性は T-0212)。
5. **当座の上限**: 頁ごとの溢れの枠は 1 面 MR_WIDE_PAGE_ENTRIES = 1024 成分(1 頁 約 28 KiB を VRAM に先に取る)・1 セル 24 種まで。
   超えるブロックの溢れるセルは書かずに待たせて MR_COUNTER_LIMIT_PRODUCTS に数える(CPU の上限なしの世界と食い違う)。
   足りない時に大きい溢れを配って同じ刻みにやり直す・空きを使い回す(VRAM を使う分だけにする)のは T-0211。

## 捨てた案
- 頁を 2 世代にしてブロックの全部のセルを写す: 空気だけのブロックも 56 KiB を写すことになり、ns/セル が増える。
- 溢れるセルの結果をグループ共有メモリに置く: 1 グループに置ける数が少なく、溢れるセルが多いブロックで足りない。
- 新しい UAV: ルート署名の語が足りない。

## 追記(2026-10-10、T-0211。決めた人: Claude〔実装の細部。CLAUDE.md §5〕): 伝導の段も同じ ①②③ で溢れを読む
- **熱(印と流れの段)**: セルの熱(MrCellThermal。熱容量・伝導率)は、溢れを持つセルだけ溢れまで読んだ上限の無い形で計算する(BlockCellThermal)。
  8 種以下のセルは成分の並びが同じなので、インラインのまま計算してもビット単位で同じ。隣のブロックのセル(ThermalAt)も同じ関数で読む。
- **変化を足して反応(ConductApplyBlock)**: 決定 1 と同じ「インラインで先に」。セルは伝導の変化を足してから、溢れが無ければインラインの核で刻む。
  溢れを持つセル・9 種目を待たせたセルは、変化を足したインラインだけ書いて(反応はまだ)溢れの数を数え(①)、プレフィックス和(②。PlanWideSide)の後に
  上限の無い形で刻み直してもう片方の面へ書き(③。RestepWideCell)、面を入れ替える(SwapWideSide)。全部を刻む Compute(StepPagedWaitWide)と同じ関数を使う。
  入らない時は変化だけ足した値のまま待たせる(当座。やり直しは T-0236)。
- **配った頁(ConductPrepareBlock)**: 一様の値で埋める時に、溢れの今の面を面 0 にして空にする(前に使った頁の溢れを読まない)。
- **小刻みの終わり(ConductEndBlock)**: 変えるのはインラインのエネルギーだけなので、溢れはそのまま残る(変えない)。
- 伝導の段は 6 つとも MR_WIDE_CELLS の変種(multires_wide_conduct_*)をもう 1 組コンパイルし、溢れを使う世界だけが使う(既定の世界は今のシェーダー)。
  陰解法の段はまだ溢れを読まないので、溢れを使う世界で陰解法を入れると FX_ASSERT で止める(T-0238)。
- 捨てた案: ApplyCell を 1 スレッド 8 セル(64 スレッド)にして StepPagedWaitWide をそのまま呼ぶ — 伝導の段は 1 スレッド 1 セル(T-0111)で、
  既定の世界と同じ数え方・同じ順の変種にしておく方が食い違いを探しやすい。上限の無い形のセル(約 300 B)を 512 スレッドで持つのでレジスタは溢れうるが、
  費用は溢れを使う世界だけ(計測は T-0236)。

## 追記 2(2026-10-10、T-0236。決めた人: Claude〔実装の細部。CLAUDE.md §5〕): 溢れは使う分だけの塊・足りない刻みは同じ刻みのうちに刻み直す
- **置き場**: 決定 5 の「頁ごとに 1 面 1024 成分を先に取る」をやめる。溢れの領域は [頁ごとの見出し 72 語][塊の置き場: 塊の数・空きの数・
  塊 × 1024 語(4 KiB)・空きのスタック]。面の中身(始まりの表 513 語 + 成分 × 3 語)は論理の語で、見出しの面ごとの塊の表(最大 25 個)が
  置き場の塊を指す。溢れの無い面は塊を持たない(始まりの表も 0 と読む)ので、空気だけの頁は見出しだけ。塊の数は GpuMultiresOptions::wideChunks
  (既定 = 頁の数 × 2 と 50 の大きい方)。
- **足りない刻み**: ②(PlanWideSide)で書く面の塊が足りなければ書かずに、見出しに要求(要る塊の数・書く面)・刻み直すセルの印・刻みの初めの busyTick を残す。
  刻みの段(全部を刻む・頁に広げて刻む・伝導の足す段)のすぐ後に WideAllocate(1 グループ)が、先に全部の頁の余る塊を空きのスタックに積み
  (頁の番号の順)、次に頁の番号の順のプレフィックス和で上から配る(前の頁と合わせて空きに入る頁だけ)。WideRetryBlock(1 グループ = 1 枠)が
  印のセルだけ ①②③ をやり直す(印のセルは刻みの段で書いていないので、刻む前の値〔伝導の段は変化を足した値〕が残っている)。
  見出しは刻みの段が印のセルを除いて書き、刻み直しで変わったら busyTick = 印・wakeTick = 印 + 1、変わらなければ wakeTick を合わせる。
  上限の印(MR_COUNTER_LIMIT_*)も刻み直しの時に足す。書いた面の塊が余れば、同じ要求の語で返させる。
- **順番に依存しない理由**: 配る順・返す順は頁の番号の順のプレフィックス和で決まり、刻む順に依らない。どの塊を使うかは結果(読み戻した溢れ)に出ない。
  置き場が尽きた時だけ、頁の番号の若い頁から配り、配れなかった頁の溢れるセルを待たせて MR_COUNTER_LIMIT_PRODUCTS に数える(CPU と食い違う。
  置き場の大きさは頁の数と同じく世界の容量)。
- 頁を空きに返す時も塊は頁に付けたまま(頁を次に使う時に始まりの表を 0 にし〔ClearWideSideWords〕、要らなければ次の刻みで返す)。
- 捨てた案: 足りない頁にだけ全部の溢れが入る大きい面(98 KiB)を配る — 配る単位が大きく、1 刻みに足りなくなる頁が多いと置き場がすぐ尽きる。
  刻みの段の中で atomic で塊を取る — どの頁が尽きて待つかが刻む順で変わる。

## 追記 3(2026-10-11、T-0248。決めた人: Claude〔実装の細部。CLAUDE.md §5〕): 1 セルの上限を 24 → 32 種に上げる(上限を無くすのは T-0272)

## 追記 6(2026-10-11、T-0237。決めた人: Claude〔実装の細部。CLAUDE.md §5〕): 細かくする要求は子の頁へ溢れを写す・塊は木の管理の段で要求の順に配る
- **変種**: 溢れを使う世界だけ、Work Graph を MR_WIDE_CELLS 付きでもう 1 つコンパイルし(multires_graph_wide)、木の管理の段に TreeWideReserve
  (multires_tree_wide_reserve)を足す。既定の世界のシェーダーは #ifdef の外を変えない(VRAM・結果・費用は同じ)。グラフの変種は反応の核を含まない(T-0124 の約束の外)。
- **塊を配る(TreeWideReserve。TreeAllocate の後・グラフの前・1 グループ)**: 許可した細かくする要求ごとに、段ごとの子の頁に写す溢れの数を数え
  (子のセルを段の八分の一でたどって一番上の親のセルへ。親の頁の今の面の溢れの数を足す)、子の頁の面 0 が持つ塊で足りない分を要求の順の累積和で
  空きのスタックの上から付ける。足りない要求には付けない(置き場が尽きた時だけ。写す時に溢れを写さずに MR_COUNTER_OVERFLOW に数える = CPU と食い違う)。
- **写す(RefineWideTails。512 スレッド)**: 子のセルの溢れの数 → プレフィックス和(スレッド 0)→ 子の頁の面 0 に始まりの表と成分を書く(CPU の CopyWideToChild)。
  鎖の次の段は前の段の子の頁から写す(Barrier の後。g_treeWords は globallycoherent)。
- **親を覆う(CoverWideTails。スレッド 0)**: 覆った八分の一のセルの溢れを今の面の中で前へ詰める(写す先は読む所より前なので上書きしない)。
  別の面へ書き直すと、その面の塊が要る(配る段が増える)ので、まれな細かくする時だけ 1 スレッドで詰める。
- **頁を返す・配る**: 粗くする時に返す子の頁と、一様な親を広げた頁の今の面を空にする(ClearWideSideWords。CPU の ClearPageOverflow)。
  影の子(観察の枠の頁)も空にするだけ(影の溢れは T-0312)。
