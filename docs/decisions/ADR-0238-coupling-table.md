# ADR-0238 流れどうしの結合(引きずり・押す構造)をエンジンの表へ: 1 つの型・1 つのベイク・1 つの検査

- Status: Accepted(2026-10-17 ユーザー決定。D-503。QUESTIONS Q66・Q70 を閉じた)
- 日付: 2026-10-15
- 決めた人: ユーザー(Claude が提案した場合も、決めるのはユーザー)

## 背景
T-0493(ADR-0220)の交差(結合の強さ q)と T-0495(ADR-0228)の押す構造は、同じ 2 × 2 の結合の形(L_XY = q √(L_XX L_YY))で一つの芯になった。
違いは係数の出どころだけ(物質の伝導率・拡散 ⇔ 構造の費用 w と速さ P)。模型(tests/drag_model_test・push_model_test)はそれぞれ試験の中に
ベイクの押さえを持っていた。これをエンジンの反応表と同じ読み込み(分類 → 型 → ベイク → パネル → ホットリロード)に入れる。

## 決定(案)
1. **一つの形**: 作り手の書き方は 2 つの分類 `drags`・`machines`(仮。チケット T-0493・T-0495 の問い 1 の案 A)に見えるが、
   読み手(script/coupling_package の ReadCouplings)・型(sim::CouplingDefinition → sim::Coupling。`form` が Drag か Machine かだけ)・
   ベイク(sim::BakeCouplings。BakeReactionTable の最後)・検査(sim::ClampCouplingQ16: |q| > 1 を警告して ±1 に押さえる)は 1 つ。
   模型の 2 本の試験も同じ関数で押さえる(継ぎはぎの 2 本にしない)。
2. **流れの書き方**は 1 つの文法: `"heat"`・`"work"`・`"gas"`・`"species:<物質>"`。分類ごとに使える種類だけが違う
   (drags: heat・species。machines の蓄え X: work・heat・species、押す Y: gas・heat・species)。X = Y は誤り。知らない物質は誤り。
3. **q の書き方**: 10 進の文字列(`"0.9"`・`"-0.25"`。A と同じく誤差なしで読む)か整数(−1・0・1)。Q16 へ **0 の向きに切り捨て**
   (|q| が書いた値を超えないので、押さえの保証を丸めが崩さない)。小数の数(`0.9`)は形の誤り(Luau の数は倍精度。R7)。|q| ≤ 1000 だけ読む。
4. **押す構造の数**: `cost_j_per_mol`(w)→ mJ/µmol の Q16、`speed_w`(P)→ mJ/刻み(模型と同じ単位)。費用 ≤ 0・速さ < 0 は警告して止めた構造(ADR-0228 の 3)。
5. **表に入るだけで、刻みはまだ読まない**: ベイクした結合は BakedReactionTable::couplings(CPU だけ。GPU の表とハッシュの形は変えない。
   ただし合わせた表の分類なので表の版〔TableVersion〕は変わる)。パネルの「結合」のタブに書いた q → 効く q・η_max(q)・費用と速さ・止まる坂を出す。
   世界の刻みへの組み込みは、気体の中の成分の拡散(T-0186・T-0210)と構造の置き場所(T-0555)の後(T-0554)。

## 検討した代案と、採らなかった理由
- **drags と machines を別々の仕組み(別の型・別のベイク・別の検査)にする**: 同じ式なのに検査が 2 か所になり、片方だけ直すずれが出る。D-466「魔素に固有の形は足さない」と同じ理由。
- **1 つの分類 `couplings` に `kind` の欄で書く**: 仕組みは 1 つにしたので見せ方の違いだけ。作り手から見て「物質の法則(どこでも効く)」と「置いた機械(そこだけで効く)」が
  分かれて見える方を仮のおすすめにした(T-0495 の問い 1)。1 つの分類にしても読み手の入口を変えるだけで済む。
- **q を ppm などの整数で書く**: 「数は整数・単位は欄の名前に」の約束には合うが、−1〜1 の数を百万倍で書くのは読みにくい。A(頻度因子)と同じ 10 進の文字列にした。

## 影響(何がしやすく/しにくくなるか)
- 作り手はパッケージに `drags`・`machines` を書けば、ベイクの警告(押さえた値)とパネルの一覧がすぐ見え、ホットリロードで読み直される。まだ世界は動かない(表示だけ)。
- 分類や欄の名前が変わっても(ユーザーの答え)、変えるのは script/coupling_package と data/types の型だけ。sim の型・ベイク・検査はそのまま。
- 実装: engine/src/sim/coupling_table・engine/src/script/coupling_package・engine/src/editor/coupling_rows・tests/coupling_table_test(ctest coupling_table)。
