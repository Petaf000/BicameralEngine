# ADR-0333 セルの見立て: 流れが読むセルの値を、刻みごとに 1 つの共有の関数 MakeCellView で作る(永続しない)

- Status: Proposed(2026-10-17。T-0713。土台の設計〔2026-10-17 ユーザーの決定 1〜6〕の §2.2 を形にした。細部は仮〔ユーザー未確認〕)
- 日付: 2026-10-17
- 決めた人: Claude(T-0713 の作業役)
- 関係: 運ぶ計算の共通の土台(段 1 ③)・ADR-0268(セルの体積を相で分け合う)・ADR-0015(多重解像度の単位)・07 §1・§2.8・17 §1・T-0710(相 `phase` 1 本)・T-0714(置き換え)・T-0716(液体の芯の共有)

## 背景
- 流れの種類(熱・気体・液体)ごとに、セルから相・空き・熱容量・温度・圧力を別々に数えていた(相の判定 10 か所・空き 10 か所・熱のキャッシュの後始末 11 か所。survey-engine)。
  式は同じでも CPU と GPU の写しが分かれ、体積の定数(0.125 m³)はレベルを知らない。

## 決定(仮)
1. **1 つの関数**: `shaders/common/cell_view.hlsli` の `MakeCellView(表, セル, レベル, 基準の圧力)` が `CvCellView` を作る。HLSL と C++ が同じ源を include する。
   1 成分ずつ足す形(`CvMakeViewSums`・`CvAddSpecies`・`CvViewFromSums`)も同じファイルに置く(GPU の溢れを持つセル。MrThermalSums と同じ考え)。
2. **作る値**: 相ごと(気体・液体・固体)の物質量・質量(ng)・体積(pL)・熱容量 / 液体の空き・気体の空き・液体の入れる体積・液体の満ち具合 /
   セル全体の熱・熱容量・温度・コンダクタンス・熱容量の上限・このレベルの面の係数 / 気体の圧力と基準の大気との差 / 液体の質量(mg)と空きで直した質量。
   どれも今の仕組みの値とビット単位で同じ(MrCellThermal・MrFaceLimit・熱のキャッシュ HcThermalCache・ShareCellVolume・LiquidOpenQ16・GasOpenQ16・
   ProbeLiquidField の液体の質量と体積・ReadState の式・DeriveOpenCell の圧力の式。cell_view_test)。
3. **表の約束に `Phase(id)` を足す**: 物質ごとの `CvSpeciesPhase { モル体積, モル質量, 相 }`(相は gas / liquid / solid の 1 本)。
   CPU は `sim::MakeSpeciesPhases(ベイクの表)` が 1 か所で作る(今は speciesCondensed・speciesLiquid から。T-0710 の `phase` 1 本が入ったらここだけ直す)。
   GPU の表は T-0714 で同じ 16 バイトの配列を持つ。
4. **レベル**: 物質量はレベル k の単位(8^-k µmol)なので、体積もレベルの単位で数えるとセルの体積はどのレベルでも同じ数(`CV_CELL_VOLUME_LEVEL_UNITS` = 0.125 m³)。
   空き・満ち具合・圧力はレベルによらない。レベルが効くのは面の係数(× 4^k)と本当の体積(`CvCellVolumePicoliters(k)` = 0.125 m³ × 8^-k)だけ。
5. **永続しない**: 見立てはセルから毎回作る。保存点・ハッシュ・写しに入れない。段の外でセルを変えても作り直しの後始末は要らない(置き換えは T-0714)。
6. **気体の圧力の温度はセル全体の温度**(セルの中は熱が釣り合っている見方)。今の区画の気体は気体のぶんのエネルギーから気体だけの温度を出すので、
   凝縮相のあるセルでは値が違う(式は同じ。温度の入力が違う)。置き換え(T-0714・段 3)で基準を取り直す。運動のエネルギー(気体の運動量)はまだ引かない(登録の欄 T-0711 の後)。

## 費用(未確認の数を測った。docs/perf.md)
- CPU(release・1 スレッド)の 1 セルあたりの時間を、今の別々の数え方(MrCellThermal + ShareCellVolume + 空き 2 つ + 液体の質量と体積)と比べた。GPU は未確認(T-0714)。

## 代案
- 見立てを熱のキャッシュのように持ち越す: 後始末(11 か所)が残るので採らない(土台 §2.2)。
- 相ごとの和を配列 `[3]` で持つ: HLSL で書き換えた構造体の配列を動的な添字で読むと HW の Work Graph が止まった(T-0397)ので、相ごとの名前の欄にした。
