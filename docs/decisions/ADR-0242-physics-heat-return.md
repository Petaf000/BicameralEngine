# ADR-0242 物理で失った力学的エネルギーをセルの熱へ返す(返し先・借り・帳簿)

- Status: Accepted(帳簿の式・整数の分け方・CPU の道)/ Proposed(返す元を世界で 1 つにすること・両側の分を接触点のセルへ返すこと: 仮・ユーザー未確認)
- 日付: 2026-10-15
- 決めた人: Claude が提案(T-0542)。根拠は D-465(保存則)・D-466(坂を下る散逸の行き先)・ADR-0232

## 背景
- ADR-0232 で物ごとの散逸(PxBody::dissipatedEnergy)を数えた。物ごとの値は運動量のやり取りを含む(当てられた物は負)ので、物ごとには返せない。
- ADR-0232 の Proposed は「島(接して動く物の組)ごとの合計を接触点の仕事の重みで分ける」だった。GPU で島を作るには連結成分の繰り返し
  (回数が実行時に決まる)が要り、回数を固定すると島が途中で切れる(D-428 に触れる)。

## 決定
1. **入口**: 小刻みごと、最後の本反復の λ が決まり速度がまだ小刻みの初めの値の所で、接触点ごとに仕事の重み
   w = Σ 行 |λ| × |行の向きの相対の速さ|(2^-16 W)と点の位置(A と B の点の真ん中)を「熱の入口」に積む(common/physics_heat.hlsli の PxMakeHeatEntry)。
   当たった瞬間は近づく速さ × 法線の力、滑る間は滑る速さ × 摩擦の力、静止は 0 に近い。
2. **返す元は世界で 1 つ(仮)**: 刻みの終わりに 返す元 = Σ 物の dissipatedEnergy − 1024000 × 返した mJ の累計。正なら mJ に切り捨て(1 刻み 2^31 mJ まで)、
   入口の重みの割合で切り捨てて分ける(PxHeatShare。重みは和が 31 桁に収まるよう同じだけ右へずらす。分の和は返せる量を超えない)。
   **どこへ返すかは重み(局所)が決め、量だけを 1 つの帳簿で持つ**。島を作らないので、GPU でも固定の回数の和(64bit の原子的な足し算)で済む。
3. **借り**: 返す元が負(解き方が生んだエネルギー)なら返さず、次の正の散逸から差し引く(世界を冷やさない)。端数も同じ帳簿の残りに入る。
   帳簿: Σ dissipatedEnergy = 1024000 × 返した mJ + 残り が毎刻みビット単位で成り立つ(PxHeatLedger)。
4. **返し先のセル**: 物はまだ温度を持たない(08 §1)ので、接触の両側の分とも接触点のセルへ(ProbeCellOfPhysicsPoint。格子の外は端のセルに寄せる)。
   物に温度ができたら半分を物へ返す(帳簿の式は変わらない)。
5. **世界へ足す時**: 物理の刻み t の入口は、刻み t + 1 の初め(コマンドの適用の後)にセルのエネルギーへ足し、つついたセルと同じくブロックを起こす
   (ProbeReference::Advance の heat)。GPU の世界は T-0561。
6. **GPU の物理**: 入口は決まった枠 [小刻み][組の枠][点](u14。点の無い所は重み 0)、帳簿は u15(PxHeatLedger + 刻みの中の和)。
   和は 64bit の原子的な足し算(整数なので順番に依らない)。CollectHeat・HeatSum・HeatShare・HeatFinish の 4 パスで CPU と同じ値(gpu_physics_test)。

## 島ごとにしないことの影響(作り手から見た違い)
- 1 か所で物が滑って熱を出している時に、別の所の積み木が解き方の誤差でエネルギーを生むと、その分は滑っている所の熱から差し引かれる。
  量は試験で最大 107 J(崩した積み木 69 kJ のうち)・56 J(落とした物 24.5 kJ のうち)。熱の場所(どのセルが温まるか)は変わらない。
- 島ごとにしたくなったら、返す元の和を島の番号ごとの和に替えるだけ(入口・重み・帳簿の式は同じ)。島の番号を固定の回数で作れる形が見つかるまでは世界で 1 つ。

## 影響
- 仮の世界(物理あり)のセルの状態とハッシュは、GPU が熱を足すようになった時(T-0561)から変わる(物が接して動いた刻みの次の刻みから)。
  物の状態のハッシュ(PxHashBody)は変わらない(数えて分けるだけで、動きの式は変えない)。
- ブランクの世界(物質の無いセル)へ熱を足すと熱容量が 0 のセルにエネルギーが入る(温度の扱いは T-0561 で確かめる)。

## 追記 1(2026-10-15・T-0561): GPU の世界へ足す
- 仮の世界(ProbeSim)の適用の単位で、ApplyCommands の後(RefreshTable・WakeDueBlocks の前)に 2 段: AddPhysicsHeat(入口ごとにセルの energy へ
  64bit の原子的な足し算)→ FinishPhysicsHeat(足し終わったセルから熱のキャッシュ・ブロックの changed = 印 − 1・起こす刻み = 今の印)。
  CPU の ApplyPokes → ApplyPhysicsHeat → 表の作り直しと同じ順。入口のバッファ(GpuPhysics の u14)は仮の世界のルート署名の u14 に UAV で結ぶ
  (物理のパスが UAV で書くので状態の遷移が要らない。物理なしなら仮の置き場)。
- ハッシュの表の空きの [14,15] に「その刻みの初めに足した物理の熱」(ProbeTickHash::physicsHeatEnergy)。保存則の検査は
  energy(t + 1) = energy(t) + つつき + 物理の熱。
- 物理ありの仮の世界のセルの状態とハッシュは、この時から変わる(物が接して動いた刻みの次の刻みから)。CPU と比べる試験(gpu_probe_physics 系・
  gpu_world_copy)は CPU リファレンスに PhysicsWorld の熱を足して比べる。ハードコードした期待値の試験は無かった。
- 熱容量 0 のセル(物質の無いセル)に熱が入ると、エネルギーはセルに残り温度は 0 のまま(RxThermalFromSums)。帳簿は合う。
  物質の無いセルは伝導もしないので、そこに入った熱は動かない(ブランクの世界に物を置いた時。物が温度を持つまでの仮)。
