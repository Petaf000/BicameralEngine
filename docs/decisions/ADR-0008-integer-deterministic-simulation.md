# ADR-0008 シミュレーションは整数で、機種が違っても完全に同じ結果にする

- Status: Accepted
- 日付: 2026-09-30
- 決めた人: ユーザー

## 背景
ユーザーの要求: 「研究しつくしたら、この条件・この環境・この場所なら完全に再現できる。化学が作れるエンジンとして、論文が出せるくらい」。
GPU の浮動小数点は、メーカー・ドライバ・コンパイラの最適化で結果が変わる。Work Graphs はレコードの処理順を保証しない。

## 決定
- シミュ(反応・輸送・物理・生き物・アニメーション・生成)は**整数(固定小数点)または整数で実装した決定的な数値表現**で計算する。浮動小数点は描画(と音)だけ。
- 結果が実行順に依存しない書き方の規則(04-numerics-determinism.md R1〜R8)を守る。
- SI 単位で、質量・エネルギー・元素の数を正確に保存する(D-206)。
- CPU リファレンスと GPU はビット一致。機種間は AMD の機械でも確かめる(D-207)。
- 物理の整数化は研究(R-PHYS)。新しいアルゴリズムを作ってもよい。

## 検討した代案
- 物理だけ浮動小数点(崩れ方だけ機種で変わる)→ 採らない(ユーザー: できる限り物理も含めてすべて)。
- 浮動小数点の厳密モード(FMA 化の禁止など)で揃える → 仕様として保証されず、確かめきれないので採らない。

## 影響
- シミュのシェーダーは DXIL を検査して float があればビルドを落とす。
- 再生ファイル(初期状態 + コマンドの列)で世界が完全に再現でき、発見の共有(D-110)の形式になる。
