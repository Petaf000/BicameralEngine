# ADR-0055 実験室は刻みの途中で表を替える(表を替えた印のコマンドで、次の刻みから新しい表)

- Status: Accepted(方向は D-439〔ユーザー決定: Q29 の案 B〕。形は実装の細部で Claude が決めた。CLAUDE.md §5)
- 日付: 2026-10-10
- 決めた人: ユーザー(方向)・Claude(形)。T-0218
- 置き換えるもの: ADR-0054 の決定 3(表が替わったら操作を初めから流し直す)

## 背景
- ADR-0054 は、実験室(T-0142・ADR-0037)の表が替わったら今までの操作を初めの箱から新しい表で流し直した(1 つの実験 = 1 つの表)。
- D-439: 実験室は刻みの途中で表を替えられるようにする(Q29 の案 B)。「途中で法則が変わった時に世界がどう追いつくか」
  (魔法で反応則に介入した瞬間の様子に近い)を試せるように。
- 待ちの丸め(ADR-0018)の約束: 表を変えるものは範囲のブロックを「変わった」にしてから評価する。多重解像度の入れ子で表に依る状態は
  ブロックの待ちの予定(wakeTick)だけ(温度はセルのエネルギーから毎回求める。熱のキャッシュを持たない)。

## 決定
1. **表を替えた印のコマンド** `LAB_COMMAND_TYPE_TABLE`(common/lab_box.hlsli。payload = 表の版 64bit)。`LabSession::ChangeTable` が次の刻みに置く。
   刻む前にもう一度替えたら印は最後の 1 つ(今の表に戻したなら印を消す)。版 0(分からない)には替えない。
2. **印のある刻み**: その刻みのコマンドを当てる前に、GPU(GpuMultires::ReplaceTable)と CPU リファレンスの表を替える(世界の差し替え
   ADR-0047 と同じ「刻みの始めから新しい表」)。印そのものはセルを変えず、箱を**つつく**(`busyTick = MR_BUSY_POKED`。lab_box.hlsl と
   ApplyLabCommands が同じ)。次の評価は「刻みの直前に変わった」として新しい表で待ちを引き直す。入れ子の RefreshTable を別に作らない。
3. **記録** `BLAB` 版 3: 刻み 0 の表の版 + コマンドの列の中の印(形は版 2 と同じ。古い読み手が印を黙って飛ばさないよう版を上げた)。
   実験室は今まで見た表を版ごとに持ち(メモリだけ)、記録の表を全部持っていれば再生する。持たない版があれば流す前に断る。
   表の中身をファイルに残す(別の起動で再生する)のは T-0217。
4. **実験室の表は世界の表**(ADR-0054 の 3 の前半は変えない): 再生を終えて最新の表と違えば、次の刻みから最新の表に戻す印を置く。
   `Reset` は最新の表で初めの箱を作る。
5. ADR-0054 の流し直しは `RerunWithLatestTable`(パネルのボタン「最新の表で初めから」)に残す。

## 検討した代案と、採らなかった理由
- **入れ子の RefreshTable を GPU の段と CPU で作る**(ADR-0054 の代案): 入れ子の表に依る状態は wakeTick だけで、つつけば同じことになる。
  コマンドの道(lab_box.hlsl)に 1 つ足すだけで、GPU と CPU が同じ関数で済む。世界(ProbeSim)の RefreshTable は熱のキャッシュを
  持つので要るが、入れ子には要らない。
- **印をコマンドにせず、LabSession が別の列で持つ**: 記録に別の欄が要り、刻みの中の順(表を替える → コマンドを当てる)を 2 か所で
  守ることになる。コマンドにすれば記録・再生・比べ合わせが今の道のまま通る。
- **表の中身も BLAB に入れる**: T-0217 の仕事。T-0218 は同じ起動の中で替える・比べる・再生するのに要る分だけにした。

## 影響(何がしやすく/しにくくなるか)
- しやすい: 反応表を書く人が保存すると、実験室の箱は今の状態から新しい法則で続く(途中で法則が変わった時の追いつき方を見られる)。
  同じ置き方で法則だけ比べたい時はボタンで初めから流し直せる。
- しにくい: 途中で表を替えた記録は、別の起動では(T-0217 まで)再生できない。1 刻みに置ける操作は 63 個(1 つは印に空けておく)。
