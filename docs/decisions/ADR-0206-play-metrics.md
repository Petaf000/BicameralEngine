# ADR-0206 遊びの指標の自動テスト(書き方・いつ測るか・前の版の置き場所)

- Status: Accepted(2026-10-14 ユーザー決定)
- 日付: 2026-10-14
- 決めた人: ユーザー(Claude が提案した場合も、決めるのはユーザー)

## 背景
- D-482 ④: 法則が一つの表でつながっている(D-463)ので、値を 1 つ変えると関係する全部に効く。作り手の調整の負担を減らすため、
  ゲームが登録した遊びの指標(「密室の火が何分で消えるか」など)を、法則(表)を変えるたびに写しの早送り(T-0412・ADR-0198)で測り、
  前の版との差を出す。決定性(ADR-0008)があるので毎回同じに測れる。
- エンジンは中身を持たない(D-454・D-464): 何を測るかはゲーム(パッケージ)が書き、エンジンは書き方と測る道具だけを持つ。

## 決定
1. **書き方 = パッケージの分類 `play_metrics`**(1 つの鍵 = 1 つの指標。反応表と同じ読み込み = T-0398 の共有の決め事)。
   欄: `label`・`max_ticks`(上限)・`sample_interval_ticks`(量を測る間隔 = 答えの細かさ)・`pokes`(場面に当てるつつき)・
   `quantity`(`max_temperature`・`cells_at_or_above`〔+ `temperature_mk`〕・`species_amount`〔+ `species`〕)・
   止め方 `at_most` / `at_least`(どちらも無ければ上限の刻みの量を測る)。読み手は script/play_metrics_package、ベイクは
   sim::BakePlayMetrics(物質の名前 → ID・上限は間隔の倍数・格子の外のつつき・上限より後のつつきは誤り)。型は data/types の PlayMetric。
   表の版(TableVersion)に入る(指標だけ変えても版が変わる。世界は変わらない)。
2. **場面 = 表の世界の組み立て(world_cells)の初めの世界 S(0)**(今の世界ではない。前の版と同じ場面で比べるため)。
   sim::PlayMetricMeasurer が、S(0) を持つ元の世界(進めない)と写し(sim::WorldCopy)を作り、指標ごとに S(0) を写して
   つつきを当て、止め方まで早送りする。同じ写しを指標の数だけ使い直す(VRAM は世界 2 つ分。サンプルで 77 MiB × 2)。
   本物の世界には触らない(D-403)。
3. **判定はつつきを全部当てた後の測る刻みだけ**(火をつける前の「火が無い」で止まらないように)。値は「何刻みで止まったか」と
   「止めた刻みの量」と量の道のり。答えの細かさは sample_interval_ticks。
4. **CPU リファレンス**(sim::MeasurePlayMetricReference): ProbeReference で同じ場面を全部のセルで刻み、同じ判定(PlayMetricObserver)
   をする。値・量の道のり・刻みごとのセルのハッシュが GPU とビット一致(tests/gpu_play_metric_test)。
5. **見る所は 2 つ**:
   - エディタのパネル「遊びの指標」(editor/play_metric_panel・frame/play_metric_runner): 本物の刻みの合間の予算の余りで測り(D-468。
     写しの早送りが走っている間は譲る)、測り終えたら写しを捨てて VRAM を返す。前に測った版との差を表で出す。
   - コマンドライン `bicameral --measure-metrics [--metrics-baseline <file>] [--metrics-save]`: 窓を開かずに全部測り、差をログに出す
     (`--log-level debug` で量の道のり)。終了コードは測れない指標があれば 1(差があっても 0)。
6. 前の版の値のファイルはテキスト(1 行目 `bicameral-play-metrics 1`、続いて `<測れた 0/1> <着いた 0/1> <刻み> <量> <鍵>`)。

## 判断待ち(作り手から見た違い。仮の案で実装)
- **A. 指標の書き方**
  - 案 1(仮): パッケージの分類 play_metrics(Luau)。作り手は反応表と同じ書き方・型検査・Mod の足し方で書ける。指標を直すと表の版が変わる
    (記録に「表の差し替え」が残る。世界は変わらない)。指標がゲームと一緒に配られ、Mod も足せる。
  - 案 2: エディタの設定(パネルで作ってファイルに保存)。表の版は変わらないが、書き方が別になり、Mod で足せない。
  - おすすめ: 案 1。
- **B. いつ測るか(エディタ)**
  - 案 1(仮): 表を変えたら(ホットリロード・反応表のパネルの書き戻し・環境ミキサー)自動で測る + 「今の表で測る」ボタン。
    パネルのチェック「表を変えたら測る」(既定 入)で切れる。余りの予算だけ使うので本物は遅れないが、指標が長いと答えが遅い。
  - 案 2: ボタンだけ。重い指標を何個も登録しても普段の操作を邪魔しないが、測り忘れる。
  - おすすめ: 案 1(チェックで案 2 にもなる)。
- **C. 前の版をどこに残すか**
  - 案 1(仮): エディタ = その起動の中で前に測った版(メモリだけ。起動の初めに 1 回測るのが基準)。コマンドライン = 指定したファイル
    (`--metrics-baseline`。`--metrics-save` で書き直す)。作り手はファイルをゲームのリポジトリに入れれば版の歴史と一緒に残せる。
  - 案 2: パッケージのフォルダの横に自動で置く(エディタの起動をまたいで差が見える。ファイルが勝手に増える)。
  - 案 3: 再生ファイル・セーブの置き場に版ごとに全部残す(どの版とも比べられる。置き場が育つ)。
  - おすすめ: 案 1 で始め、要れば案 2 をエディタの設定に。

## まだ無いもの・分けたもの
- 場面を指標ごとに書く(今は表の世界の組み立ての 1 つだけ。実験室の箱・場面のパッケージを名指しする)。実験室の箱の写しは T-0476。
- 場所を区切った量(箱の中の酸素など)・量の組み合わせ(A かつ B)・つつき以外のコマンド(置く・押す)。要る場面(⑤)が出たら足す。
- 指標を並べて測る(写しを複数)。ADR-0198 の写しの数の上限の判断と一緒に。

## 影響
- ReactionTableDefinition・BakedReactionTable に `playMetrics`(T-0398 の印の節)。frame_loop.h に `LoadLoopReactionTable`。
- sim::WorldCopy の API は変えない(T-0413 と合わせた)。
