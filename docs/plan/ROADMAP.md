# ロードマップ(L5)— ゴールから逆算した道筋

決定: DECISIONS.md / 設計: docs/design/ / 運用: CLAUDE.md(ADR-0007)

## ゴールから逆算
```
正式版(販売)
 ← 早期アクセス(売りながら広げる: 8km・Mod・発見の共有)
   ← 体験版(1km の地域。Steam で配る)
     ← P2 友人テスト 2: 1km の縦切りで「発見・生き物・目標」が遊べる
       ← M10 ゲームの Model(進行・発見の記録・NPC)  ← M9 音と UI
       ← M8 生き物とプレイヤー  ← M7 描画の本番
       ← M6 物と物理(燃えた木が倒れる)  ← M5 世界(生成・ストリーミング・粗い層・セーブ)
       ← P1 友人テスト 1: 実験室で「法則を発見する」が面白いかを確かめる
         ← M4 流れ(気体・水・放射: 延焼が風下と斜面に広がり、湿った帯で止まる)
           ← M3 場と反応(疎な格子・熱・Luau・反応表・保存則)
             ← M2 見る・触る(窓・デバッグ表示・エディタの殻)
               ← M1 土台(整数の数学・決定性・GPU デバッグ・刻みのループ・Hello Work Graph)
```

## 並べ方の理由
1. **一番の賭け(「法則を発見する」は面白いか)を早く確かめる**: P1 を M4 の直後に置く。描画・生き物・物理より前。見た目は仮で、実験室の中だけ。
2. **決定性は後から足せない**: M1 で整数の数学・状態のハッシュ・CPU とのビット一致を最初に作り、以後すべてのチケットの完了条件にする。
3. **一番大きな研究(R-PHYS)は早く小さく試す**: M1 の最後に CPU だけの小実験(T-0014)を入れ、方向を早く知る。本研究は M6。
4. **描画(M7)は、場と物が決まってから本番にする**。それまでは M2 のデバッグ表示で見る。
5. **ゲームの中身(ユーザー)は並行して進める**(下の「中身の道」)。エンジンの段が中身を必要とする時点を期限にする。

## 合計の見積もり(粗い)
体験版まで約 140〜240 チャット。1 チャットの長さと週の作業量(週 20 時間以上)から暦に直すのは、M1 の実績(1 チャットに何時間かかったか)を測ってから行う。
正直な見立て: 範囲は大作のオープンワールドに近い。体験版までで年単位になる前提で考える。

## この計画の直し方
- マイルストーンが終わるたびに、実績のチャット数を書き、残りの見積もりを直す。
- 研究の結果で道が変わったら(打ち切り条件に当たったら)、DECISIONS.md に決定を足し、このロードマップを直す。
- 途中の思いつきは BACKLOG.md へ(CLAUDE.md の運用)。
