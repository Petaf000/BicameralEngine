## ゴールから逆算
```
正式版(販売)
 ← 早期アクセス(売りながら広げる: 世界の全域・Mod・発見と魔法具の共有)
   ← 体験版(1 地域。Steam で配る)
     ← P 友人テスト: 縦切りで「発見・魔法・魔法具・生き物・目標」が遊べる
       ← M10 ゲームの Model と魔法具  ← M9 音と UI(自作)
       ← M5 世界(生成・ストリーミング・セーブ)  ← M6 物と破壊の本番
       ← ⑦ 魔素(物質として・坂の原理で押す)→ 生き物が魔素を操る → 電気と金属
            → M4 多重解像度の本研究 → M7 描画 → M8 生き物 …(⑦ の途中で先の順を決め直す)
       ← ⑥ 全部を合わせた重さの見積もり(D-458)
       ← ⑤ BotW の現象を場面ごとに遊べる形で(火の延焼 / 水と温度 / 物の物理の小さい版)
       ← ④ 測る道具(写しの早送り・重さの検査・遊びの指標の自動テスト)
       ← ③ 坂の原理の研究(D-466)
       ← ② 中身の器(ブランクの世界・物理定数)
       ← ① 片付けと反映(2026-10-13 済み)
       ← M2 場と反応・M3 流れ(エンジンの道。②〜⑥ の下支えとして要る順に挟む)
       ← M1 原理の確認(完了)
```

## 並べ方の理由
1. **原理が成り立つかを最初に確かめる**(D-412): 完全 GPU 駆動で、クリックした点から Work Graphs で自動的に伝播し、
   化学(燃える)・物理(角ばった箱)・多重解像度(細かくして戻す)が、整数で決定的に動くか。ここが成り立たないと理想(D-414)が成り立たない。
2. **決定性は後から足せない**: M1 から整数・状態のハッシュ・CPU とのビット一致を全チケットの完了条件にする。
3. **研究には時間の打ち切りを置かない**(D-411)。M1 で原理を確かめ、本研究は各マイルストーン(M4 多重解像度・M6 物理・M7 描画)で深める。
4. **友人テストは、プレイヤー・地形・世界・物理・生き物・描画ができてから**(D-413)。
5. ゲームの中身(ユーザー)は並行して進める(下の「中身の道」)。
6. **2026-10-12 から、着手の順は「今の順」(D-471。① 〜 ⑦)で決める**(D-459 を置き換え)。現象を作り込む前に坂の原理を確かめ、測る道具を作り、
   BotW の現象を場面ごとに遊べる形で面白さを確かめる。魔素・魔法は現実の元素が現実どおりに動いてから(⑦)。

## 今の順(D-471。2026-10-12 ユーザー決定。D-459 を置き換え)
指針(D-462〜D-470): 一番は面白さ、二番は美しさ。世界は独自の法則を持つ一つの宇宙で、法則は一つの表だけ(現実 + 嘘の二層にしない)。
エンジンは法則の形・どんな規模でも正確に走らせること・法則を調べる道具、ゲームは「何があるか・何が何になるか・値」。すべての流れは坂の原理の上に置き、
魔法は筋肉と同じ法則(魔素を押す)。負荷で遅れない(収めるのはゲーム、エンジンは測る道具と警告)。
**マイルストーン(M1〜M10)は「何ができるか」の区切りとして残し、着手の順はこの ① 〜 ⑦ で決める。** M2・M3 の残り(エンジンの道)は、下の「エンジンの道の置き場所」のどこかに入る。
