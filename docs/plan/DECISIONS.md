# 決定台帳 — ゴールから全部決める(2026-09-30 開始)

何かを作る前に、ゴールから一番下(データ構造・マイルストーン・チケット)まで決める(ユーザー 2026-09-30)。
上の層から順に決める。上が変わったら、下の依存する決定を見直す。
測らないと分からないものは「どう測り、結果がどうならどちらへ進むか」を先に決めておく(= それも決定)。

層: L0 目的 / L1 ゲームの形(エンジンへの要求) / L2 数値要件 / L3 アーキテクチャ / L4 サブシステム詳細 / L5 マイルストーン・チケット / L6 運用

**役割分担**: ゲームの中身(面白さ・設定・生態系・言語・文化・背景・反応表・魔法の内容)は**すべてユーザーが決める**。
Claude はそれを載せるためにエンジンが何をできる必要があるかと、計画・設計を出す。中身の案を先回りして決めない。

## L2 数値要件

| ID | 決定 | 日付 |
|---|---|---|
| D-201 | **シミュレーションに上限を設けない**(規模・連鎖の深さを予算で打ち切らない)。描画は 30fps 以上でよく、シミュは描画のフレームと切り離す | 2026-09-30 |
| D-202 | 計算が GPU の力を超えたら**世界の時間が遅くなる**(Factorio 型)。計算は必ず最後まで正しく行う。描画と操作は止めない | 2026-09-30 |
| D-203 | 世界は **8km 四方**。体験版はその中の 1km 四方 | 2026-09-30 |
| D-204 | 細かいシミュは **0.5m のセル**、疎な格子(物がある所・動いている所だけ持つ)。範囲は D-208 | 2026-09-30 |
| D-205 | **機種が違っても完全に同じ結果**(条件・環境・場所が同じなら再現できる。論文にできる水準)。シミュの計算は物理も含めて**全部整数(固定小数点)または決定的な自前の数値表現**で行い、浮動小数点は描画だけ。物理の整数化は研究(新しいアルゴリズムを作ってもよい) | 2026-09-30 |
| D-206 | **物理的に正しい**: SI 単位で、質量・エネルギー・元素の数をエンジンが正確に保存する。魔素などのファンタジーの法則も同じ枠で書き、保存則を破るなら明示的な出入り(湧き出し・吸い込み)として書く | 2026-09-30 |
| D-207 | 機種間の一致は、いずれ AMD の GPU(RX 7000 以降)の機械を用意して確かめる | 2026-09-30 |
| D-208 | **観測者で法則が変わらない**: 反応・物理・水が動いている所は、誰が起こしても・どこでも 0.5m で計算する。静かな所だけ粗く(8m)持ち、活動が始まったら細かくする(粗→細の復元は決定的に行い、保存量は正確に引き継ぐ)。生き物だけは例外で、近くでは個体、遠くでは数と密度 | 2026-09-30 |
| D-209 | 予算の初期値(測って直す): フレーム 33ms の中で描画 ≤ 12ms、残りをシミュへ。VRAM(最低機 8GB): 描画の素材 3.5GB / 世界のシミュ 1.5GB / 生き物と物理 0.5GB / Work Graphs の作業領域 0.5GB / 描画のバッファ 1GB / 余裕 1GB。近くで細かく動く生き物 256 体、世界全体 10 万個体、粗いシミュは 8m 格子 | 2026-09-30 |
| D-210 | 最低機: Work Graphs 対応で VRAM 8GB(RTX 3060 / RX 7600 級、未確認)。推奨機: RTX 3070 Ti 相当(開発機) | 2026-09-30 |

## ユーザーが決めるゲームの中身(設計チャットで)
- 大きな目標の中身、世界の設定・歴史・言語・文化
- 生き物と植物の生態(魔素を含む)、敵、ダンジョン
- 反応表(元素・状態量・規則・例外・中間生成物)、魔法の体系と解禁、最初の発見の導線、観測の道具
- NPC と会話、料理・生命の魔法などの寄り道の中身
